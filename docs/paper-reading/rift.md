# RIFT 精读：评分标准的八类失效与自动诊断

**论文：** RIFT: A RubrIc Failure Mode Taxonomy and Automated Diagnostics

**阅读版本：** arXiv v2，2026 年 4 月 20 日

**原文：** [阅读全文](https://arxiv.org/html/2604.01375v2) · [PDF](https://arxiv.org/pdf/2604.01375v2)

文章围绕评分标准自身的缺陷如何影响评测，以及如何发现这些缺陷展开。重点解释失效类型的判断边界、分类体系的建立过程，以及自动诊断实验的证据范围。

## 摘要翻译

以下为 Qi 等人 v2 摘要的中文译文，原文采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)，改动为翻译。[原文与许可](https://arxiv.org/abs/2604.01375v2)

基于评分标准的评估广泛用于语言模型基准和训练流程，尤其适合开放式、较难直接验证的任务。尽管已有研究利用强化学习结果等下游信号展示了评分标准的有效性，但仅凭这些汇总信号或下游信号，仍缺少一种有原则的方法来诊断评分标准本身如何失效。

为弥补这一缺口，我们提出 RIFT，即 RubrIc Failure mode Taxonomy，用于系统描述评分标准在构成和设计方面的失效模式。RIFT 包含八种失效模式，归入三个大类：可靠性失效、内容效度失效和后果效度失效。

RIFT 采用扎根理论构建：对来自五种不同数据来源的评分标准反复标注，这些来源覆盖通用指令遵循、代码生成、创意写作和专家级深度研究，直到不再发现新的失效模式。我们通过测量独立人工标注者之间的一致性来评估分类的一致性，观察到总体上尚可的一致程度：两两一致率为 87%，平均 Cohen’s kappa 为 0.64。最后，为支持规模化诊断，我们提出自动化评分标准质量指标，并表明它们与人工失效模式标注相吻合，最高 F1 达到 0.925。

## 1. 从一个评分失效的例子开始

### 邮件写作中的要求遗漏

论文附录 D 用一个邮件写作示例说明评分标准可能遗漏任务要求。下面是该示例的中文翻译。论文将其标为说明性示例（illustrative example），未注明具体数据来源。[附录 D：Missing Criteria](https://arxiv.org/html/2604.01375v2#APPENDIX4)

| 项目 | 内容 |
| --- | --- |
| 用户要求 | 写一封 200 词的邮件，并包含主题行。 |
| 评分项一 | 语气专业，10 分。 |
| 评分项二 | 语法和拼写正确，5 分。 |

用户明确提出了长度和主题行要求，但两条评分项都没有检查它们。设想一封只有 80 词、没有主题行的邮件：如果语气专业，语法和拼写也没有问题，严格按这两项标准评分，它仍可能获得全部 15 分。这里的 80 词回答是为解释原例而作的假设，论文没有提供对应的模型回答或实测分数。

**满足全部评分项，并不一定意味着满足用户要求。** 在这个例子中，即使评分者准确执行了每一条标准，最终分数仍可能掩盖回答对任务要求的遗漏。换一个能力更强的评分模型，也不能保证补上评分标准里没有写出的检查项。

### 任务、回答、评分标准与评分者

这个过程包含四个不同的对象：用户要求规定要完成的任务；模型回答是被评价的内容；rubric 将任务目标转化为具体评分项；评分者则依据这些评分项判断回答，人和 LLM 都可以承担这一角色。

RIFT 将这类遗漏称为 **Missing Criteria**：任务中存在可以检查的必要要求，rubric 却没有提供对应的评价条目。对邮件例子而言，诊断方法很直接——逐项列出用户要求，再检查评分标准是否覆盖了每一项。

| 用户明确提出的要求 | 原评分标准是否覆盖 |
| --- | --- |
| 邮件长度为 200 词 | 未覆盖 |
| 包含主题行 | 未覆盖 |

这也说明了检查 rubric 本身的必要性。回答质量、评分者能力和标准质量都会影响评测结果；要定位问题，需要检查任务要求在转化为评分项时发生了什么。RIFT 进一步把这种检查扩展为一套失效分类，并研究如何辅助人工诊断这些问题。

## 2. 研究背景：对 rubric 本身进行质量检查

### 将开放式任务的目标转化为评分标准

研究报告、邮件和创意写作等任务，通常允许多种合理回答，也很难仅靠一个标准答案判断质量。评测需要明确哪些内容应当出现、哪些要求必须满足，以及什么样的表现可以获得更高评价。Rubric 将这些目标组织成具体标准，让人或模型有据可依。

这些标准既用于评测，也可能参与训练。在 benchmark 中，评分帮助比较模型的表现；在训练中，评分还可能成为奖励信号，影响模型学习的方向。因此，标准的设计会影响我们如何判断模型，也可能影响模型如何改进。[论文第 1 节](https://arxiv.org/html/2604.01375v2#S1)

### 评分标准也需要接受检查

论文回顾的已有研究涵盖专家标注流程、自动生成 rubric，以及模型评分与 benchmark 的可靠性。RIFT 进一步关注产出的评分标准本身：要求是否有遗漏，表述是否足以支持一致判断，是否加入了任务没有要求的限制，以及分数能否反映回答质量。[论文第 1—2 节](https://arxiv.org/html/2604.01375v2#S2)

前面的邮件示例展示了一个直接的问题：任务要求在转化为评分项时发生了遗漏。即使评分者准确执行所有条目，最终得分仍可能没有反映回答是否符合用户要求。检查 rubric，就是要把这些设计缺陷找出来，并指出它们具体出现在何处。

### 最终结果难以单独定位标准的缺陷

作者指出，rubric 的质量常通过下游结果间接判断，例如训练后的模型表现，或使用 rubric 的模型评分与人类偏好的一致程度。但这些结果同时受到任务设置、模型能力和评分者行为等因素影响。结果变好可以说明整个流程取得了进展，却不足以确认评分标准的每个部分都设计合理；结果变差也无法直接告诉我们应当修改哪一条标准。[论文第 1 节](https://arxiv.org/html/2604.01375v2#S1)

沿用邮件示例作一个推演：两名评分者都严格按照语气、语法和拼写打分，可能一致地给出高分，但两人都没有检查主题行和长度。**评分者之间达成一致，并不能单独证明评分标准完整。** 这个推演用于解释问题，并非论文报告的评分实验。

RIFT 因此将 rubric 本身作为诊断对象：先归纳常见的设计缺陷，形成能够描述问题的分类；再检查不同标注者能否一致地使用这些分类，以及自动方法能否识别相应缺陷。这为质量检查提供了具体的诊断标签，也让后续修改有了明确方向。下一节将展开这套分类中的八类失效。[论文第 3—4 节](https://arxiv.org/html/2604.01375v2#S3)

## 3. RIFT 的八类失效：定义、例子与判断边界

### 3.1 三个维度的含义

可以把 rubric 理解为一种测量工具：它把回答的表现转化为分数。RIFT 借用测量理论中的概念，从可靠性、内容效度和后果效度三个维度组织评分标准的失效类型。它们分别关注标准能否被一致执行、是否准确表达任务要求，以及评分在实际使用中能否发挥预期作用。[论文第 2—3 节](https://arxiv.org/html/2604.01375v2#S2)

**可靠性（Reliability）：评分能否保持一致。**

同一份回答交给不同评分者，或者重复评分，标准应当支持相对一致的判断。例如，标准只写“回答足够详细”，评分者就需要自行决定详细到什么程度。有人认为三句话已经充分，有人认为还应包含背景和例子。这种解释空间可能导致同一份回答获得不同分数。

RIFT 在这个维度下归纳了三类问题：主观措辞缺少具体参照，多个要求捆绑而难以分别评分，以及缺少核验依据。它们都可能让评分者自行补充判断规则。这里关注的是 rubric 对一致评分的支持程度；实际评分分歧还可能受到评分者能力等因素影响。**评分一致，也不意味着标准所评价的内容正确或完整。**

**内容效度（Content Validity）：评分内容是否对应任务目标。**

内容效度关注标准是否充分覆盖应当评价的要求，以及是否引入了偏离任务的内容。前面的邮件示例正属于这一维度：用户要求 200 词和主题行，rubric 却只检查语气、语法和拼写。即使评分者一致地执行标准，评分也没有充分覆盖任务要求。

这个维度包含两个方向：该检查的要求被遗漏，以及加入了错误的目标或不必要的限制。RIFT 分别用 Missing Criteria 和 Misaligned or Rigid 描述这些问题。判断时需要将 rubric 与任务上下文对照；一项严格要求是否合理，取决于它是否确实来自任务。

**后果效度（Consequential Validity）：分数能否发挥预期作用。**

RIFT 在这一维度下关注整套标准的区分能力、可被利用的得分漏洞，以及重复计分造成的影响。重点在于，使用这些标准后，分数是否能反映与任务有关的质量差异，评分规则又会鼓励怎样的回答。

例如，附录 D 的一个推荐任务示例，按优点和缺点的数量给分，却不检查相关性与重复内容。这样的标准允许回答者通过凑数量提高得分，而不必改善建议本身。若将得分用作训练奖励，这种设计还可能鼓励模型追求数量。后者是对评分用途的解释，并非论文针对该示例报告的训练结果。

RIFT 将可被钻空子、区分能力不足和重复计分归入这个维度。诊断时既要看单个条目，也要看条目组合与分值分配。论文主要研究这些缺陷能否被识别；诊断后修改标准是否改善下游结果，仍需要进一步验证。[附录 D 与局限性说明](https://arxiv.org/html/2604.01375v2#APPENDIX4)

| 维度 | 检查重点 | 失效类型 |
| --- | --- | --- |
| 可靠性（Reliability） | 标准能否被一致地执行 | 主观且缺乏明确参照（Subjective）、评分项不可拆分（Non-Atomic）、缺乏核验依据（Ungrounded） |
| 内容效度（Content Validity） | 标准是否准确、充分地表达任务要求 | 偏离任务或限制过严（Misaligned or Rigid）、遗漏必要标准（Missing Criteria） |
| 后果效度（Consequential Validity） | 分数是否有助于区分质量并形成合理激励 | 可被钻空子（Hackable）、区分能力不足（Low Signal）、重复计分（Redundant Criteria） |

三个维度提供了不同的观察角度，彼此可能关联。例如，遗漏正确性检查属于内容效度问题；如果其余评分项又允许低质量回答轻易拿到高分，就可能同时存在可被钻空子的漏洞。**同一份 rubric 可以具有多个失效标签**，但每个标签都需要依据相应的判断条件确认，不能从一种缺陷直接推定另一种缺陷。[论文表 1 与附录 D](https://arxiv.org/html/2604.01375v2#S3)

### 3.2 八类失效的例子与判断边界

以下依据论文附录 D 整理。各类的任务与评分片段采用原文的说明性示例，以中文翻译或概述呈现；论文未逐条注明这些示例的数据集出处。例子后的分析用于解释判断规则，不代表额外的模型实验。原文采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可。[附录 D 原文](https://arxiv.org/html/2604.01375v2#APPENDIX4)

#### 1. Subjective：主观措辞缺少具体参照

标准使用“清晰”“恰当”“专业”等评价词，却没有说明怎样的表现符合要求，评分者便需要依赖各自的理解。

**论文示例。** 任务是总结一项研究，评分项为“总结清晰且足够详细，10 分”。标准没有交代应覆盖哪些内容，也没有提供达标与不达标的例子。对于同一份总结，评分者可能因为对“详细”的理解不同而给出不同判断。

**判断边界。** 需要检查的是评价词是否有足够的参照。具体清单、示例、反例或明确的判断规则，都可以帮助限定含义。即使标准仍使用“清晰”一词，只要解释了其含义，也不应仅凭这个词标记 Subjective。附录中的正例将一封专业的拒会邮件拆成是否表达拒绝并提出替代时间、是否包含问候和落款、是否避免侮辱性语言等检查项，使抽象要求有了具体依据。

#### 2. Non-Atomic：要求捆绑，缺少一致的评分结构

一项分数同时对应多个可以独立判断的要求，却没有分项分数或部分得分规则。回答只满足其中一部分时，评分者难以确定应给多少分。论文也将缺乏可解析、可一致执行的评分结构纳入这一类。

**论文示例。** 总结文章的标准只有一个 10 分项，要求总结清晰、准确、全面、简洁且有吸引力。如果总结准确而全面，但不够简洁，标准没有说明这种表现对应多少分。

**判断边界。** 一句话包含多个要求，并不必然构成 Non-Atomic。如果标准已经说明每个子要求各得几分，或给出明确的等级条件，就能够处理部分满足的情况。Subjective 关注要求的含义，Non-Atomic 关注要求怎样组织成可评分的结构；上述例子可以同时涉及两种问题。

#### 3. Ungrounded：缺少核验依据或核验范围

有些要求原则上可以检查，但标准没有提供必要的参考答案、允许的变体、误差范围、判断规则或核验程序。评分者知道要检查什么，却缺少一致完成检查的依据。

**论文示例。** 任务要求计算 30 张发票的合计，评分项只有“合计正确，10 分”。标准提到了正确性，却没有给出应当核对的结果或明确的核验规则。

这个例子并不意味着评分者无法自行重算。问题在于，核验工作被留给了评分者自行决定。对开放世界中的要求，这种缺口可能更明显：例如要求所有事实为真，却不规定核查范围、允许使用的来源，以及证据冲突时的处理办法。

**判断边界。** Ungrounded 不要求所有任务都配一个唯一标准答案，可执行的验证程序也可以提供依据。它与 Missing Criteria 的区别是：前者已经提到了要求，但缺少核验条件；后者根本没有覆盖要求。它与 Subjective 的区别是：前者侧重可核验事项的证据和程序，后者侧重主观评价词的含义缺少参照。

#### 4. Misaligned or Rigid：偏离任务或施加不必要的限制

标准评价了错误的目标，加入了任务没有提供的假设，或限定了过窄的解决方式，导致本来符合任务的回答受到扣分。

**论文示例。** 用户要求写一首关于冬天的俳句，标准却要求至少五篇学术引用，并使用 APA 格式列出参考文献。评分内容与写诗的任务发生了明显偏离。

更一般地，当多种方法都能完成任务时，标准如果无依据地强制使用某个工具、库或表达形式，也可能属于这一类。

**判断边界。** 严格要求是否合理，要结合完整任务上下文判断。如果用户明确指定 JSON 键名、某个库或固定格式，标准检查这些要求是合理的。附录中的正例评价 Python 解析 CSV 的正确性、引号内逗号的处理和使用说明，同时允许不同实现方法。

#### 5. Missing Criteria：必要要求未被覆盖

任务提出或明确隐含了某项可检查的必要要求，整份 rubric 却没有任何条目能够评价它。

**论文示例。** 第一部分的邮件任务要求 200 词并包含主题行，标准只检查语气、语法和拼写。长度与主题行没有对应评分项，因此属于 Missing Criteria。

**判断边界。** 判断时先列出任务的必要交付物、格式和必须遵守的约束，再逐项检查是否有标准覆盖。这里也包括任务明确期待的核心品质，例如代码的功能正确性。不能把评审者个人偏好的额外内容一概当成遗漏。如果要求已经出现，只是描述模糊或缺少验证条件，应进一步检查 Subjective 或 Ungrounded。

#### 6. Hackable：迎合评分项就能获得不合理的高分

整套标准存在容易利用的得分路径：回答者可以强化被奖励的表面特征或替代指标，拿到很高的分数，而不必实质改善正确性、相关性或任务完成情况。

**论文示例。** 推荐任务按“至少列出十条优点”和“至少列出十条缺点”各给 5 分，却不检查内容是否相关、是否重复。凑够条目就可能满足评分条件，建议本身的质量没有得到充分约束。

**判断边界。** 数量要求本身并不构成漏洞。如果每条内容都必须不同、与任务相关，并具备必要的依据，简单堆砌就未必有效。诊断 Hackable 时，应能说明一条具体的利用路径，以及这条路径为何允许低质量回答拿到高分。它也不局限于显式数字要求：附录 E 进一步讨论了模型漏检“通过详细讲解掩盖任务未完成”的情况，留待第五部分展开。

#### 7. Low Signal：整套标准难以区分回答质量

标准过于通用、容易满足，或与当前任务的关键差异联系很弱，使质量明显不同的回答得到相近分数。

**论文示例。** 用户要求只返回一条 SQL 查询，标准却按“回答有帮助”和“语气恰当”各给 5 分。这两项很难为 SQL 查询的质量差异提供具体的评分依据。

**判断边界。** 论文建议设想三到五份从较差到优秀的回答，检查标准及其权重能否反映与任务目标有关的差异。这是在审视标准的区分能力；实际分数接近，也可能因为被测回答本来就相近，不能仅凭这一现象认定 Low Signal。它与 Hackable 的侧重点不同：Low Signal 关注不同质量的回答难以拉开分数，Hackable 关注能够被利用的高分路径。某个明确要求的遗漏，应首先按 Missing Criteria 检查。

#### 8. Redundant Criteria：同一要求被重复计分

两个或更多条目实质评价同一属性，使同一种表现被多次奖励或惩罚，却没有增加新的评价信息。

**论文示例。** 一份作文 rubric 分别为“写作清晰”“行文清楚”“文字容易理解”各给 5 分。这些条目缺少明确区分，可能是在重复计算同一项表现。

**判断边界。** 可以检查删去其中一项后，评价内容是否发生变化，还是只改变了分值分配。标准之间有关联或依赖，并不足以认定冗余。例如，“代码能够编译”和“代码通过测试”可以检查不同层面的表现；“包含引用”和“引用支持论点”也提供不同信息。判定 Redundant Criteria 的关键，是额外条目是否带来独立的评价内容。

#### 容易混淆的几组情况

| 需要区分的类型 | 判断重点 |
| --- | --- |
| Missing Criteria 与 Ungrounded | 必要要求是否完全缺席；若已出现，是否缺少核验依据或程序。 |
| Subjective 与 Ungrounded | 评价词的含义是否缺少参照；可核验的要求是否缺少验证条件。 |
| Subjective 与 Non-Atomic | 要求是否难以解释；多个要求是否难以分别计分。 |
| Low Signal 与 Hackable | 标准整体是否难以区分质量；是否存在具体可利用的高分路径。 |
| Redundant Criteria 与条目依赖 | 相关条目是否仍提供不同信息，还是重复计算同一属性。 |

这些边界帮助我们为每个标签寻找具体依据。同一份 rubric 可以同时存在多种问题，但不能因为整体感觉“写得不好”，就将相近标签全部加上。[判断规则来源：附录 D](https://arxiv.org/html/2604.01375v2#APPENDIX4)
