# PCCL：让全球训练节点在故障和变化中保持同步

原文：[*Prime Collective Communications Library — Technical Report*](https://arxiv.org/abs/2505.14065v1)，2025 年 5 月 20 日 v1。

## 0. 作者与机构背景

第一作者 **Michael Keiblinger** 和第二作者 **Mario Sieg** 均署名 Prime Intellect，论文没有共同第一作者标记。公司在[发布公告](https://www.linkedin.com/posts/primeintellect-ai_introducing-pccl-the-prime-collective-communications-activity-7331197788178784256-4my1)中明确说明，Keiblinger 牵头开展了约六个月的 PCCL 研究。他也参与过 INTELLECT-1；公开资料尚不足以确认其完整教育背景，因此不补充学历信息。

Sieg 的[本人 GitHub 主页](https://github.com/MarioSieg)介绍其工作涉及机器学习、CUDA、高性能计算和编译器，并列出 Prime Intellect 内核研究工程师身份。他开发的项目包括机器学习框架和量化内核，这些工作与 PCCL 的底层通信及计算实现相关。

其余三位作者 Jack Min Ong、Sami Jaghouar 和 Johannes Hagemann 也全部来自 Prime Intellect。PCCL 是公司直接开发的训练基础设施，延续了此前通过互联网组织协作训练的工作，并以开源库形式发布。（原文首页；[公司项目介绍](https://www.primeintellect.ai/blog/pccl)）

## 1. 摘要翻译

以下按原文顺序翻译 Michael Keiblinger 等人的摘要；论文采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可，改动为中文翻译。

本报告介绍 Prime Collective Communications Library（PCCL），这是专门面向公共互联网上的分布式机器学习工作负载设计的新型容错集体通信库。PCCL 引入一种支持节点动态加入和故障恢复的新编程模型。该库实现了全归约等高效集体操作，同时提供稳健的容错机制，使系统即使在操作进行期间有节点故障或加入，也能继续运行。

我们表明，对于重复执行操作且状态以确定方式推进的工作负载，PCCL 的设计能够实际解决成员动态变化的问题。我们的实现通过了所有主要操作系统上的广泛压力测试，即使节点频繁进出且集体操作并发执行，也能可靠运行。

通过将通信分派给多条连接，我们能够有效利用跨洲、带宽大且延迟高的 TCP 广域网链路；实验中，西欧范围内的带宽利用最高达到 45 Gbit/s，北美与欧洲之间达到 25 Gbit/s。

PCCL 的架构使 DiLoCo 等分布式低通信优化策略易于实现，这些策略能够显著减少通信频率。结合量化，可以明显降低分布式训练工作负载所需的带宽。PCCL 还允许并发执行集体操作，从而支持异步 DiLoCo 等优化策略；通过延迟一步更新参数，这些策略可以完全隐藏通信开销。

对于节点正常退出或突然离开引起的各种情况，PCCL 都能支持各节点共享状态的逐位完全一致。PCCL 提供 C99 API，同时也提供兼容 PyTorch 并可配合 FSDP 使用的 Python 绑定。PCCL 以开源 MIT 许可发布。

## 2. 研究背景与相关研究

分布式训练需要多个节点交换参数或梯度。例如，全归约会把所有参与者的数据合并，再将相同结果返回给各个参与者。传统通信库通常面向高速、稳定的数据中心网络；在互联网环境中，连接延迟较大，节点可能随时退出，原先固定的参与者关系就难以维持。（原文 §1）

Related Work 讨论了 Gloo、Hivemind 和 Elastic Horovod。作者将 Gloo 定位为面向共同部署集群的通信库，并回顾 INTELLECT-1 通过 VPN 接入时需要人工管理节点的经历。Hivemind 采用分散的节点发现与协调方式，Elastic Horovod 则通过上层恢复和回滚支持成员变化。

PCCL 选择在通信库内部处理故障，并明确维护共同状态。它利用机器学习优化通常重复执行相似步骤的特点，限定新成员加入与共享状态推进的方式，而不是试图处理任意控制流程的分布式程序。（原文 §1、§7）

## 3. 核心贡献

**核心要解决的问题。** 在节点动态进出、网络操作可能随时失败的条件下，让集体通信可以恢复，并使参与者对已经完成的操作与共享状态保持一致。

**核心方案。** 一个轻量主节点负责成员管理与操作协调，训练节点直接交换数据。新成员先登记，再在协调阶段加入；一次集体操作拆分为多个可恢复阶段，故障后由仍在运行的节点重试。共享状态通过哈希检查，发现不一致时再传输所需状态。（原文 §2）

通信实现根据节点间带宽调整环形连接顺序，并利用多连接与流水线传输提高广域网利用率。它还支持并发操作，使通信能够与下一步计算重叠。报告以数据并行、DiLoCo 和异步 DiLoCo 说明如何将这些基础操作接入训练。（原文 §3—§5）

**结论。** 压力测试覆盖频繁节点变化和并发操作，广域网测试也显示多连接可以提高链路利用率。摘要中的 45 与 25 Gbit/s 是论文所测网络配置的通信指标，不能直接当作训练速度或任意网络中的保证值。（原文 §6）

这项工作的主要成果是通信基础设施。共享状态的一致性还依赖应用以确定方式推进状态；“隐藏通信”也需要计算与传输满足相应时间关系。PCCL 为跨云和临时算力训练提供基础操作，报告并未通过这些通信测试证明所有训练算法的收敛效果。（原文 §2.4、§3、§8—§9）
