# Prime Agent：用持久状态与子智能体支持长期任务

原文：[*Prime Agent: A Self-Improving RLM Harness*](https://arxiv.org/abs/2608.23552v1)。项目于 2026 年 8 月 5 日发布，本文依据 8 月 24 日的技术报告。

## 0. 作者与机构背景

第一作者 **Seth Karten** 署名普林斯顿大学和 Prime Intellect，第二作者 **Alex L. Zhang** 署名 MIT 和 Prime Intellect。两人为通讯作者，没有共同第一作者标记。

Karten 在普林斯顿攻读计算机科学博士，导师为 Chi Jin；此前获得卡内基梅隆大学机器人学硕士学位，研究多智能体通信与决策。他的[个人主页](https://sethkarten.ai/)说明，他于 2026 年 5 月以研究实习生身份加入 Prime Intellect，研究方向包括多智能体系统、开放环境中的决策和智能体运行框架。

Zhang 在 MIT CSAIL 攻读博士，导师为 Omar Khattab 和 Tim Kraska，此前毕业于普林斯顿计算机科学专业。他的[个人主页](https://alexzhang13.github.io/)列出 Prime Intellect research fellow 身份，以及 Recursive Language Models、KernelBench 和 GUI 智能体评测等工作。

全部作者均有 Prime Intellect 署名。公司直接开发并发布 Prime Agent，将研究中的上下文处理、持久记忆和多智能体协作方法整合进同一套运行系统。（原文首页）

## 1. 摘要翻译

以下按原文顺序翻译 Seth Karten 等人的摘要；论文采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可，改动为中文翻译。

语言模型是顺序处理器，但长期智能体活动需要模型权重和当前上下文之外的信息与计算。Prime Agent 是一个用于长期评测和编码智能体工作流程的开源运行框架。

持久化的 IPython 交互执行环境遵循递归语言模型抽象，用于程序化处理上下文和安排测试时计算；Continual Harness 则跨执行轨迹保留历史、记忆、技能、提示和子智能体定义。递归子智能体通过直接通信进行协调，Agents View 让人类能够检查和管理由后台服务维持的会话。

Prime Agent 将执行、恢复、验证和资源统计标准化，同时把策略构建交给模型。这层低阻碍、表达能力强的交互接口避免框架故障演变为模型失败，并推动评测更接近模型真正能够达到的最大能力。

Prime Agent 将 ARC-AGI-3 的 RHAE Best@1 从 30% 提高到 95.5%，并在长上下文编程、GPU 内核生成、模拟器构建和自主 nanoGPT 速度优化中，达到或超过原生及常用运行框架的表现。在 Factorio 中，我们发现持续修订能够支持技术进程不断推进，专门的子智能体则支持并行工作。代码公开于 [PrimeIntellect-ai/prime-agent](https://github.com/PrimeIntellect-ai/prime-agent)。

## 2. 研究背景与相关研究

模型处理长期任务时，当前上下文无法容纳所有历史。运行系统需要决定哪些内容放回上下文、哪些保存到文件、何时运行程序，以及怎样让多个工作过程配合。即使模型本身能够推理，丢失状态、无法恢复会话或错误统计预算，也可能让任务提前失败。（原文 §1）

Related Work 讨论了几条相关路线。程序化推理和 Recursive Language Models 让模型通过代码处理长信息，并递归调用子任务；记忆与技能方法保存可复用的经验；Continual Harness 进一步把提示、记忆、技能和子智能体定义变成可修订的状态。编码智能体和多智能体系统则提供工具执行、任务分工与消息通信的基础。

Prime Agent 将这些能力结合起来，不预先规定一张固定的工作流程图。模型可以根据任务选择直接计算、查阅历史、串行分工或并行调用，并在后续任务中复用保存的结果。（原文 §2、§4）

## 3. 核心贡献

**核心要解决的问题。** 为长期任务提供能够保存、恢复和修订工作状态的运行系统，让模型灵活组织计算，同时完整记录执行结果和资源消耗。

**核心方案。** 每个会话拥有持久的 Python 执行环境，模型可以通过代码搜索或处理大量材料，只把需要的内容放回上下文。子智能体使用相同机制，有独立上下文和历史，能够互发消息；后台服务保存会话，使前端断开或上下文压缩不必终止整个任务。（原文 §2.1—§2.4）

Continual Harness 将执行中得到的经验写入版本化的记忆、提示、技能和角色定义。这里的“自我改进”指修改外部状态，底层模型权重保持不变。系统还统一管理停止条件、恢复过程和根会话及子会话的成本，便于比较不同运行配置。（原文 §2.5—§2.6）

**结论。** 在所测交互推理、编程和长期实验任务中，这套系统支持了不同形式的测试时计算。ARC-AGI-3 上 Prime Agent 与 Opus 5 的组合达到 95.5%；但图中的原生框架参考成绩来自外部报告，不能把从约 30% 到 95.5% 的全部差距当作严格控制其他条件后测得的框架因果收益。（原文 §3.1）

长期运行案例说明会话持久化、程序化处理和协作能够支撑连续改进；同时，作者也观察到模型仍不善于充分使用这些机制，例如怎样分配子任务、保留信息和修订技能。论文提出今后让模型与运行框架共同训练，这仍是后续方向，不能视为本次已经完成的权重学习成果。（原文 §3—§5）
