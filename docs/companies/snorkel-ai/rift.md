# RIFT：诊断评分标准本身的八类问题

一个模型给研究报告打了高分，可能因为报告确实好，也可能因为评分标准只检查篇幅和引用数量，漏掉了结论是否有证据。换一个更强的评判模型，未必能补上评分标准里不存在的要求。

RIFT 把诊断对象放在 rubric 本身。Rubric 是面向具体任务的一组评分条件，可能附带权重或分值。论文从专家对评分标准的审查出发，归纳八种失败模式，再测试语言模型和统计信号能否自动发现这些问题。

最高 0.925 F1 对应 Gemini 3 Pro 多数投票检测“缺少客观锚点的主观标准”这一类别；同一主表中，两种语言模型对“标准可被钻空子”这一类别的 F1 都为零。它没有提供一个能以 92.5% 准确率判断所有评分标准质量的通用检查器。

## 评分标准和评判模型是两个环节

为说明两者的关系，可以把常见的 rubric 评分写成：

$$
R(x,y)=\sum_{j=1}^{m}w_j\,g_j(x,y;r_j),
$$

其中 $x$ 是任务，$y$ 是待评回答，$r_j$ 是第 $j$ 条评分条件，$w_j$ 是权重，$g_j$ 是评判模型对该条件的评分。这是教学记法，RIFT 没有要求所有来源使用同一种加权公式。

如果条件 $r_j$ 含糊，不同评判模型可能理解不同；如果关键条件没有进入列表，所有模型都可能漏评；如果权重主要奖励篇幅，回答可能通过堆砌内容获得高分。这些问题分别涉及标准的可靠性、内容覆盖和使用后果。

仅查看最终分数与人工偏好的相关性，难以确定问题来自哪个环节。RIFT 因此先给评分标准贴诊断标签，再检查这些标签能否被一致识别。标签是多选的，一份 rubric 可以同时存在主观、要求遗漏和冗余等问题。[第 1–3 节](https://arxiv.org/pdf/2604.01375v2#page=1)。

## 八种失败模式及其边界

### 可靠性：相同标准能否稳定执行

**Subjective，缺少锚点的主观要求。** 评分条件使用“清晰”“充分”“专业”等词，却没有说明对应的可观察行为。并非出现主观词就算失败：如果给出具体要求、例子或判定规则，这些词可以具有可执行含义。

**Non-Atomic，不可分项评分。** 一条得分条件捆绑多个可以独立满足的要求，却没有子分值或部分得分规则。问题是评判者难以稳定处理“只满足其中一部分”的回答。把每个维度拆开计分，或定义清楚的分级锚点，都可以避免这一问题。

**Ungrounded，缺少核验依据。** 条件已经提出，而且原则上可检查，但没有给出参考事实、可接受答案、误差范围、时间范围或有边界的检查流程。“所有事实都准确”措辞可以很明确，执行起来仍可能没有标准。

### 内容效度：检查的内容是否对应任务

**Misaligned or Rigid，目标错位或过度限制。** 评分标准检查了用户没有要求的目标，加入未经说明的前提，或把一种可行答案错误地当作唯一答案。如果用户已经明确要求特定格式、方法或库，按该要求评分不属于过度限制。

**Missing Criteria，遗漏必要要求。** 用户提出的某个可检查要求，在评分标准中完全找不到对应条目。这里需要区分“没有检查这件事”与“提到了，但没有说明怎样检查”：前者是 Missing，后者可能是 Ungrounded 或 Subjective。

### 后果效度：高分是否对应有用的任务表现

**Hackable，可通过代理指标获得不当高分。** 标准主要奖励篇幅、条目数、引用数或看起来专业的表达，而缺少正确性、相关性和去重等条件，导致低质量回答也能接近满分。要求一定数量本身不是问题，关键在于数量奖励有没有受到实质质量条件约束。

**Low Signal，区分能力弱。** 一整套标准对明显不同质量的回答也容易给出近似分数。例如任务要求输出 SQL，标准却主要检查语气友好。它描述整体缺乏区分度，不等同于某一个可利用的计数漏洞。

**Redundant Criteria，重复计分。** 多条标准测量相同性质，导致同一行为被重复奖励或惩罚。相关性或依赖关系不等于冗余：“JSON 能解析”和“包含必要字段”有关联，但测量不同要求；“代码能编译”和“通过测试”也不能直接合并。

以下例子为本文自拟，用于解释标签边界，不是论文实验样本。

| 问题类别 | 有问题的评分条件 | 对应修改方向 |
| --- | --- | --- |
| Subjective | “分析足够深入：10 分” | 明确需要比较哪些因素、说明哪些证据与限制 |
| Non-Atomic | “准确、简洁、有引用：总计 10 分”，不允许分项判断 | 分别给出分值，或定义部分满足时的规则 |
| Ungrounded | “计算结果正确”，但没有答案、容差或验证方法 | 提供参考计算、可接受误差与检查步骤 |
| Misaligned or Rigid | 用户允许任意 Python 实现，标准只接受 pandas | 检查任务行为；只有用户要求时才限定库 |
| Missing Criteria | 用户要求时间顺序，标准完全不检查顺序 | 增加对应条目 |
| Hackable | 每增加一条引用加分，不检查是否支撑正文 | 要求引用与具体论断对应，并排除重复和无关引用 |
| Low Signal | 对技术方案只检查“态度积极、排版整齐” | 加入方案是否满足关键技术约束的区分性条件 |
| Redundant Criteria | 分别奖励“语言清楚”和“表述易懂”，实际检查相同内容 | 合并重复项，重新确定权重 |

## 分类体系怎样形成

### 五种来源，开发集与测试集分开

研究选择两个人工来源和三个合成来源，覆盖不同长度、格式和任务类型。表中的平均词数仅对应所采样 rubric。

| 来源 | 形成方式 | 主要形式 | 平均词数 |
| --- | --- | --- | ---: |
| AdvancedIF | 专家整理 | 检查清单 | 88 |
| ResearchRubrics | 专家编写 | 检查清单 | 1,059 |
| WildChecklists | 模型生成 | 检查清单 | 111 |
| OpenRubrics | 模型生成 | 原则列表 | 145 |
| AutoRubrics | 模型生成 | 叙述式标准 | 68 |

分类体系开发分四轮。每个来源前三轮分别抽 5 份，第四轮抽 2 份，所以总数为：

$$
5\times(5+5+5+2)=85.
$$

三位专家独立标注，共形成 255 份专家标注记录。独立测试集再从每个来源抽 10 份，共 50 份，与开发样本不重叠。附录说明按来源分层、轮次之间不放回抽样，并为每轮固定随机种子，但没有公开具体种子值和逐条样本标识。

85 是 rubric 数，不是评分条目总数；255 是专家标注记录数，不是 255 个不同任务。样本来源分层相等，也不意味着可以代表真实业务中不同来源的占比。[附录 A、表 5–6](https://arxiv.org/pdf/2604.01375v2#page=9)。

### 从开放式批注到稳定标签

第一轮专家先自由描述 rubric 的问题，GPT-5.2 根据批注提出候选分类。后续轮次让专家用当前分类贴标签，同时记录无法归类的新问题、类别重叠和定义不清之处。三位专家讨论并修改定义，再进入下一轮。作者把“新样本不再产生新类别或重大修改”作为停止条件。

GPT-5.2 在这个过程中是分类整理助手，最终修订由专家决定。它的提示还要求分类尽量保持 7–10 类，优先合并相近类别，并尽量避免超过 12 类。因此最终八类既来自样本中的观察，也受到分类紧凑、易用这一设计目标约束；不能当成已证明穷尽所有 rubric 问题的自然分类。

测试集与开发集分离支持对新 rubric 的验证，但样本仍来自相同五个来源。论文没有用一个完全不同的行业来源验证分类的完整性。[第 3 节、附录 C.2](https://arxiv.org/pdf/2604.01375v2#page=4)。

## 专家一致性与人工、合成来源的差异

### 一致率和 kappa 衡量不同方面

论文使用三种标注一致性指标：成对一致率 PWA、Cohen’s kappa，以及 Krippendorff’s alpha。为帮助理解，二分类的 kappa 可写为：

$$
\kappa=\frac{p_o-p_e}{1-p_e},
$$

$p_o$ 为实际一致率，$p_e$ 为按双方标签分布计算的偶然一致率。类别很少出现时，两位标注者即使都倾向于判“没有问题”，也可能得到很高的一致率；kappa 尝试扣除这部分影响。

表 1 报告的总体汇总是 PWA 87.4%、kappa 0.64、alpha 0.60。逐类中，“目标错位或过度限制”的 PWA 最低，为 80.0%；“可利用”和“低区分度”为 93.3%。这些数据描述专家对标签的理解是否一致，不是自动检测器的准确率。

表 1 的汇总存在一个待解释之处：按八行打印值做简单算术平均，kappa 为约 0.678，alpha 为 0.675，与 Overall (mean) 行的 0.64、0.60 不一致。没有原始标注和聚合代码，无法判断是聚合方式不同还是表格修订未同步。本文保留作者报告值，并明确它不能由打印行直接重算出来。[表 1](https://arxiv.org/pdf/2604.01375v2#page=3)。

### 两类来源呈现不同问题，不能直接推成优劣排名

表 2 中每个数字表示某来源子集中，被标记为该问题的 rubric 比例；同一 rubric 可以贡献多个标签。

| 失败模式 | 人工来源 | 合成来源 |
| --- | ---: | ---: |
| Subjective | 52.6% | 86.7% |
| Non-Atomic | 26.3% | 60.0% |
| Ungrounded | 42.1% | 46.7% |
| Misaligned or Rigid | 63.2% | 20.0% |
| Missing Criteria | 47.4% | 36.7% |
| Hackable | 0.0% | 13.3% |
| Low Signal | 21.1% | 40.0% |
| Redundant Criteria | 26.3% | 23.3% |

在这个样本中，合成标准更常出现主观和分项不清，人工标准更常有目标错位或过度限制。表中的类别平均值是同一大类内部各标签发生比例的平均，不是“至少出现一个该大类问题”的比例。

这不是同一任务上人工与模型分别编写标准的配对实验。两组的任务、长度和格式不同，表 2 的实际统计分母也没有明确列出。因此不能将差异单独归因于编写者是人还是模型。

作者还在 OpenRubrics 与 AutoRubrics 的人类偏好资料上进行外部关联分析，报告失败标签数与评判模型偏离人类偏好的 Pearson $r=0.162$。不一致案例平均 3.66 个问题，一致案例为 3.15 个。论文同时报告显著性和 “effective size = 20”，但没有充分展开观察单位、配对层级与有效样本量的计算；这一结果支持弱关联，不能代替修改 rubric 后的因果验证。[表 2、第 3 节](https://arxiv.org/pdf/2604.01375v2#page=4)。

## 自动诊断的五种方式

### 直接让模型按八类定义检查

LLM-as-Judge 分类器接收原始任务、完整 rubric、失败类别定义与正反例，输出命中的标签、理由及问题所在的原文片段。主表使用 GPT-5.2 和 Gemini 3 Pro。

正文称其为 trained classifier，但公开的具体方法是提示驱动的分类；论文没有给出微调损失、参数更新或训练超参数，不能将其介绍成已经训练好的专用分类模型。附录中的模板还显示，注入的示例上下文与 rubric 分别截取前 150 和 200 个字符；复现时需要核对实际展开方式。

多数投票版本对每份 rubric 运行五次，逐标签至少三次命中才保留：

$$
\widehat z_f
=\mathbf 1\left[\sum_{t=1}^{5}z_f^{(t)}\ge3\right],
$$

其中 $f$ 是失败类别，$z_f^{(t)}$ 是第 $t$ 次是否预测该类别。投票处理的是每种问题是否存在，不是把五次解释拼接成一个总评分。[第 4 节、附录 C.1](https://arxiv.org/pdf/2604.01375v2#page=5)。

### 三种间接信号观察 rubric 的评分行为

**IRR，评判者间一致性。** 六个模型生成候选回答：GPT-5 mini、GPT-5.2、Claude Haiku 4.5、Claude Sonnet 4.5、Gemini 3 Flash、Gemini 3 Pro。随后由四个偏好评判者——GPT-5 mini、Haiku 4.5、Gemini 3 Flash、GPT-5.2——依据 rubric 对回答对给出偏好，统计成对一致率。

设回答对集合为 $P$，四个评判者给出的偏好为 $\ell_a(p)$，相应统计可以整理为：

$$
\operatorname{IRR}
=\frac{1}{|P|\binom42}
\sum_{p\in P}\sum_{a<b}\mathbf1[\ell_a(p)=\ell_b(p)].
$$

这是根据文字定义整理的表达，具体平局、缺失结果和回答次序处理未提供实现。模型间同意得多，可能源于标准明确，也可能源于共同偏差。

**Alignment，与强参考评判者的一致性。** 使用相同回答对，统计三个较弱评判者与 GPT-5.2 偏好的相符程度。若记强参考为 $s$，可以写为：

$$
\operatorname{Alignment}
=\frac{1}{3|P|}\sum_{p\in P}\sum_{a=1}^{3}
\mathbf1[\ell_a(p)=\ell_s(p)].
$$

这里的参考标签仍由模型生成，不是人工真值。Alignment 只是候选诊断信号。

**Reward variance，回答得分的方差。** GPT-5 mini 针对同一输入独立生成四个回答，再让 GPT-5.2 根据 rubric 打分，观察总分的方差。用 $r_1,\ldots,r_4$ 表示这些分数，可以用 $\frac14\sum_i(r_i-\bar r)^2$ 说明它的含义，但论文未交代代码采用总体方差还是样本方差，也没有完整说明跨 rubric 的分数归一化。

四个回答本身不同，因此这不是固定答案、重复打分时的纯评判噪声。方差同时受生成模型的回答差异和 rubric 的区分度影响；方差低也可能只是四个回答质量相近。[第 4 节](https://arxiv.org/pdf/2604.01375v2#page=5)。

## 主要结果：哪些问题容易检测

表 3 的指标是对每种失败标签的 F1：

$$
F_1=\frac{2TP}{2TP+FP+FN}.
$$

它同时考虑漏检与误检。下面完整列出直接分类器结果，并将三种间接信号压缩为该行最优者；各行的最优者不一定是同一种方法。

| 问题 | GPT-5.2 单次 | GPT-5.2 五次投票 | Gemini 单次 | Gemini 五次投票 | 最佳间接信号及 F1 |
| --- | ---: | ---: | ---: | ---: | --- |
| Subjective | 0.861 | 0.892 | 0.909 | 0.925 | Alignment，0.854 |
| Non-Atomic | 0.644 | 0.702 | 0.630 | 0.679 | IRR，0.667 |
| Ungrounded | 0.444 | 0.529 | 0.634 | 0.651 | 方差，0.717 |
| Misaligned or Rigid | 0.750 | 0.778 | 0.737 | 0.718 | 方差，0.562 |
| Missing Criteria | 0.686 | 0.706 | 0.452 | 0.483 | IRR，0.585 |
| Hackable | 0.000 | 0.000 | 0.000 | 0.000 | IRR / Alignment，0.400 |
| Low Signal | 0.667 | 0.625 | 0.400 | 0.316 | IRR，0.525 |
| Redundant Criteria | 0.643 | 0.500 | 0.417 | 0.435 | 方差，0.467 |

多数投票改善了多个类别，但不是统一增益。例如 GPT-5.2 对冗余的 F1 从 0.643 降为 0.500，对 Low Signal 从 0.667 降为 0.625。五次运行可能减少随机差异，也可能强化稳定存在的错误判断。

正文还说 Low Signal 由非直接分类信号表现最好，但表 3 中最高值明确是 GPT-5.2 单次的 0.667。本文以表格为依据。引言贡献列表及官方页面保留“最高 0.86 F1”，v2 摘要与表 3 则是 0.925；这些不能当成同一个设置下的相同结果。[表 3](https://arxiv.org/pdf/2604.01375v2#page=6)。

## 阈值与类别不平衡改变 F1 的含义

### 最优阈值在测试集上选择

IRR、Alignment 和方差是连续数值，需要通过阈值转成失败标签。论文对每种“信号—类别”组合扫描阈值与方向，报告在同一测试集上最大化的 F1。

这说明表中结果包含测试集内选择阈值的收益。它不能直接当作一个预先固定检测器在全新数据上的效果；真正上线前还需要独立校准数据选择阈值，并在另一批数据上验证。

附录为此补充 ROC-AUC，但报告的是：

$$
\operatorname{AUC}_{\mathrm{reported}}
=\max(\operatorname{AUC},1-\operatorname{AUC}).
$$

这个数值允许翻转信号方向，因此至少为 0.5；它衡量不预设方向的排序关系。虽然去掉了具体阈值，方向选择仍使用评估标签，不等同于已固定方向的部署结果。

### 高 F1 可能接近“全部判有问题”

附录 B.2 的间接信号分析使用 48 份成功合并的数据记录，主实验则描述为 50 份，未解释少掉两份的原因。在这 48 份中，Subjective 有 35 个正例。

如果简单地把所有 rubric 都判为 Subjective，则：

$$
TP=35,\quad FP=13,\quad FN=0,
\qquad F_1=\frac{70}{83}\approx0.843.
$$

这是本文根据表 8 计数计算的基线，未执行模型调用。它与该类 IRR 的最佳 F1 0.843 几乎相同。该类间接信号的最高 AUC 只有 0.640，因此不能仅凭约 0.85 的 F1 认定这些信号有很强的区分能力。

Hackable 则只有四个正例，Alignment 的方向可翻转 AUC 为 0.807，最佳 F1 为 0.400。少量错误就会明显改变 F1，两类表现不能脱离正例数量比较。

| 类别 | 正例数（48 份中） | 最佳间接信号 AUC | 最佳间接信号 F1 |
| --- | ---: | ---: | ---: |
| Subjective | 35 | 0.640 | 0.854 |
| Non-Atomic | 22 | 0.581 | 0.667 |
| Ungrounded | 21 | 0.644 | 0.717 |
| Misaligned or Rigid | 18 | 0.537 | 0.563 |
| Missing Criteria | 19 | 0.599 | 0.585 |
| Hackable | 4 | 0.807 | 0.400 |
| Low Signal | 16 | 0.543 | 0.525 |
| Redundant Criteria | 12 | 0.556 | 0.467 |

本表按附录表 8–9，AUC 与 F1 可以来自不同信号。Misaligned 一行附录打印 0.563，主表为 0.562，保留各自数值。不同间接信号与总失败标签数的相关性也很弱，论文报告分别为 0.247、0.222、0.052；它们不能替代总体质量分数。[附录 B.2、表 8–9](https://arxiv.org/pdf/2604.01375v2#page=9)。

## 模型替换实验与具体漏检案例

### 替换参考评判者

附录保持回答对及三个弱评判者不变，把 Alignment 的参考从 GPT-5.2 换成 Gemini 3 Pro Preview；方差实验保持生成模型与协议不变，只替换评分模型。

Subjective 两种信号的 F1 都没有变化，分别为 0.854 和 0.843。Hackable 的 Alignment 从 0.400 降为 0.276，方差则从 0.267 升到 0.400；Ungrounded 的方差信号从 0.717 降为 0.618。不同类别对评判者替换的敏感程度不同，不能概括成完全不依赖模型选择。

另一个实验比较三个模型五次投票后的分类一致性。表 4 的宏平均成对一致率在 0.730–0.812 之间，kappa 在 0.239–0.494 之间。GPT-5.2 与 Gemini 对 Hackable 的一致率为 0.920，kappa 却为零，说明高表面一致率并不等于对稀少正例有一致识别能力。[表 4、表 7](https://arxiv.org/pdf/2604.01375v2#page=6)。

### 漏检来自对类别定义的狭窄理解

附录 E 分析一个将 JSON 联系人写入 SQLite 的任务。评分标准奖励详细步骤、解释和新手友好表达，却没有检查程序是否实际完成导入。模型识别了主观、非原子与遗漏要求，但没有识别 Hackable：它把可利用性理解成“必须有明确的数量奖励”。

作者随后让模型专门构造钻空子的回答，模型才意识到，一篇格式完整、解释充分但代码错误的教程也可能获得高分。这是同一个案例上的提示比较，没有报告在完整测试集上采用该提示后的提升。

另一个 C# 死锁例子已经要求“避免死锁”，但没有提供测试场景、执行条件或通过标准。模型只判断语言主观、标准笼统，漏掉了“要求存在但缺乏验证流程”这一 Ungrounded 问题。

附录 E 开头的两项 F1 与主表不同，也没有完整交代子集与运行版本。这里使用其案例解释错误行为，不用这些数字替换主实验。[附录 E](https://arxiv.org/pdf/2604.01375v2#page=17)。

## 公开材料与复现范围

截至核对时，论文和官方研究页提供了分类定义、提示模板、样本分布与结果表；在检索到的官方资源中，没有找到含完整标注、逐题输出和评估脚本的 RIFT 发布包。因此可以依据论文重新实现流程，但尚不能直接复跑并核对原始数字。

| 复现环节 | 已有信息 | 仍需要补齐 |
| --- | --- | --- |
| 样本 | 五种来源、各轮数量与测试集分层 | 样本 ID、来源版本、随机种子、实际 rubric 文本 |
| 专家标签 | 八类定义、三位专家、部分一致性统计 | 逐人标签、最终真值聚合方式、分歧处理 |
| 直接分类器 | 模型名称、提示模板、五次投票 | API 快照、温度、输出长度、实际展开示例与原始输出 |
| 间接信号 | 生成与评判模型、主要聚合定义 | 回答对、平局规则、评分范围、方差实现、缺失记录处理 |
| 指标 | F1、方向可翻转 AUC、部分正例计数 | 阈值扫描代码、方向选择、独立校准集与置信区间 |
| 结果核查 | 论文表格 | 50 到 48 份的过滤记录及表中不一致的说明 |

一种按论文思路实施的流程，是先用分类器标出问题和原文证据，再由专家确认，针对性修改标准，最后重新检查标签及实际评分行为。这是论文提出的使用方式；研究没有报告完整的“修改前后 rubric → 下游模型训练或评测收益”实验。

本次精读核对了全文、附录 A–E、关键表格和指标计算，没有调用收费模型，也没有进行参数训练。RIFT 当前支持的是有边界的诊断：它给出了可解释的类别与初步自动信号，而修改标准能否改善真实评测，还需要在具体任务上验证。
