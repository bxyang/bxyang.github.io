# SpeedrunBench：让智能体反复改进游戏速通路线

原文：*SpeedrunBench: Challenging LLM Agents on Speedrunning Games*（[官方论文](https://cdn.patronus.ai/SpeedrunBench.pdf)）。

## 0. 作者与机构背景

第一作者 **Yoshinari Fujinuma（藤沼祥成）** 来自 Patronus AI。他的[个人主页](https://akkikiki.github.io/)记录了科罗拉多大学博尔德分校计算机科学博士背景，研究方向为跨语言自然语言处理，曾在 AWS AI Labs 和 Cantina Labs 工作。

第二作者 **Keisuke Kamahori（釜堀惠辅）** 来自华盛顿大学。[个人主页](https://kamahori.org/)介绍，他在 Paul G. Allen 计算机科学与工程学院攻读博士，导师为 Baris Kasikci，研究智能体、模型推理系统与计算机架构；2023 年获得东京大学信息科学学士学位。

论文首页列出 Patronus AI 与华盛顿大学，没有共同一作标记。[共同作者 Varun Gangal 的介绍](https://www.linkedin.com/posts/varungangal_game-evals-for-llms-tend-to-center-on-the-activity-7501421920278487040-uY6U)明确提到 Yoshinari 牵头，Keisuke 以华盛顿大学研究者身份与公司团队合作。公司发布了基准及[配套运行记录](https://huggingface.co/datasets/PatronusAI/speedrunbench)，研究重点是智能体在可重复环境中持续改进方案的能力。

## 1. 摘要概述

目前未确认这份官方 PDF 授予完整译文的公开传播许可；本节提供概述，不冒充逐句翻译。

SpeedrunBench 将游戏任务的目标从“能够完成”进一步推进到“尽量快速完成”。它通过十款游戏与多种模型，观察智能体能否发现更短路线、反复修改操作序列，并保留已经有效的部分。结果显示，一些简单任务可以接近人工纪录，但较长、较复杂的任务仍有明显差距，多数已有路线也只得到有限改进。

## 2. 研究背景与相关研究

游戏适合评测智能体，因为目标和反馈较明确，也可以反复重置。但只用是否通关评分，会把效率差异很大的解法看成同样成功；当模型已经能通关时，这个指标也不再容易区分进一步进步。（论文 §1）

论文回顾了 LMGame-Bench、VideoGameBench 等直接测试语言模型玩游戏的工作，以及 MineDojo、Voyager 这类强调开放世界探索和技能积累的研究。与它们相比，SpeedrunBench 关注的是反复优化同一目标：已经找到一个能成功的路线之后，还能缩短多少。（论文 §2）

Pokeagent Challenge 已经将速通用于宝可梦任务。本文在游戏类型和使用方式上进一步扩展，除直接看画面操作外，还允许智能体编辑整段操作记录并回放。这与长流程编程都涉及试验、反馈和保留有效修改，但论文没有直接证明游戏训练能提高编程能力。（论文 §2—§3）

## 3. 核心贡献

**核心要解决的问题。** 测量智能体是否能超越完成任务本身，持续发现和验证更高效的解法，并区分看画面操作、从头探索和修改已有方案这些能力。

**核心方案。** 基准覆盖平台跳跃、角色扮演、竞速等类型，以到达指定目标所需的游戏帧数或游戏时间衡量速度。目标可以是完成一关、跑完一圈或获得首枚徽章，并非每个项目都要求完成整部游戏。（论文 §3—§4）

在线模式让模型根据当前画面决定下一步操作。离线模式则把一次尝试写成逐帧操作序列，由智能体修改、回放、读取结果并继续优化；它又分为提供参考路线和从头构造路线两种情况。离线测量减少了逐步视觉反应的要求，更集中观察搜索与修改完整方案的能力。（论文 §3.2）

**结论。** 在论文的宝可梦蓝版实验中，能够获得首枚徽章的模型仍有很大速度差异；最好结果所需游戏帧数约为人工参考纪录的四倍。这是游戏过程的帧数比较，不是模型服务的响应延迟。（论文 §4.3）

参考路线的作用取决于模型能力。SuperTux 实验中，能独立找到成功路线的模型从头探索时往往更快，而部分较弱模型需要种子路线才能完成任务。增加一次优化过程中的回放机会也能明显改变结果，因此得分需要结合搜索预算理解。（论文 §4.4—§5）

SpeedrunBench 提供的是一种持续优化评测。它表明能完成游戏并不等于能有效改进路线，但不同游戏、种子和预算条件下的结果不能混为一个无条件的能力排名。（论文 §4—§5）
