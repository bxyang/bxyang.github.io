# BLUR 精读：根据零散记忆寻找具体对象

用户记得一本书的封面、出版时间和作者参与过的另一部作品，却想不起书名。助手需要把这些线索连起来，寻找候选，再检查它是否同时符合描述。BLUR 把这种“名字就在嘴边”的检索整理成 573 道题，包含图片、音频、视频和跨语言线索。论文测试中，最好的系统答对约 56%，人工验证者首次作答约为 98%；这个差距同时受到检索策略、工具能力和数据筛选方式影响。[论文摘要、§3–4](https://arxiv.org/pdf/2503.19193v1)

## 任务要识别一个具体对象

BLUR 研究的是 known-item retrieval：提问者心中有一个想找回的对象，但提供的只有局部描述。系统最后应给出能唯一识别对象的短答案，例如书名、歌曲名，或银行名称及地址。

这与推荐任务的判断标准不同。符合“2017 年出版、雪人封面”的某一本书，未必就是同时满足全部记忆线索的那一本。检索到一个相关网页也不等于完成任务，助手还需把候选和原始约束逐项对应。

论文图 1 的书籍例子包含三类线索：出版年份、封面内容、作者与另一部书的关系，标准答案是 *Hho the Snowman: The Great Journey*。这类题可以先沿作者关系寻找候选，再核对年份和封面；这条流程是对题目的解释，并非论文规定所有系统必须执行的固定算法。

模型拿到的是英文为主的提问和可选附件。统一提示还说明提问日期，要求记录搜索过程，最后以 `Final Answer:` 给出短字符串。图 4 的日期是 2024 年 12 月 15 日；它是示例的时间条件，不能直接替代每条数据自身的提问时间。（§3、图 1、图 4）

### 单轮任务仍可能包含很多次工具调用

这里的“单轮”指用户只给一次问题，不再帮助手补充记忆或纠正猜测。助手内部可以反复搜索、读取网页、识图、翻译和核验，形成多步工具轨迹。

BLUR 没有规定统一工具集合，也没有把网页搜索当成唯一入口。人类验证者会使用地图、街景、反向图像搜索、视频、音频播放、OCR 和翻译工具。这些是观察到的解题方式，不是每题都必须调用的工具清单。论文没有评估通过追问用户逐步消除歧义的对话策略。（§3.1–3.2、Limitations）

## 数据从真实回忆与独立验证中产生

作者没有直接抓取论坛帖子作为整个测试集，而是请标注者回想自己最近遇到的识别困难，写成向朋友或网上求助的描述。可以提供附件，也可以涉及不知名或不以英语呈现的对象。

构建过程分为以下步骤：

1. 写题者先记录自己记得的线索，再利用浏览器寻找原本想找的对象，并保留搜索步骤与短答案。
2. 另一位验证者只看最初的问题及附件，独立查找对象，记录搜索轨迹和耗时。
3. 两人的答案相同，则接收该题；不同则向验证者展示写题者的答案与过程。
4. 若验证者能够确认自己哪里出错，并接受预期答案，则仍可接收；若分歧无法消除，则丢弃。
5. 对保留题目做最小程度的格式与错字修订。

这套流程允许首次没答对、但事后能确认解法的题进入数据集。它也意味着“通过验证”不等于两名标注者一开始就独立答对。论文没有公布最初收集多少题、各阶段淘汰多少题，以及事后认可占最终数据的比例，不能据最终 573 题反推完整筛选漏斗。（§3.1、附录 A）

### 唯一答案是人工核验结论

标注者需要确认已找到的对象是描述下唯一合理的答案。这降低了歧义，但并不是穷尽互联网所有候选后的数学证明。建筑可能改变用途，新作品可能重复旧作品的情节，网页也会消失。

作者通过提问日期约束和保存验证来源缓解这些问题，并定期检查来源；限制部分写明，如果来源链接失效，就移除受影响的题目。复现时因此需要同时固定数据版本和访问时间，不能假设外部网络环境永久不变。（§3.1、Limitations）

### 12 名标注者的覆盖范围

共有 12 名标注者：10 人为 26–35 岁，2 人为 18–25 岁；7 人自报为女性，5 人为男性；11 人拥有学士学位，1 人拥有硕士学位。报酬为每小时 20 美元。作者报告对数据进行了人工检查以去除个人身份信息。（附录 A、Ethical Considerations）

这些背景使研究过程更可理解，但样本不是所有用户的随机抽样。题目来源于这一组人的经历、文化背景和工具习惯；不能把总体分数解释为全球所有“想不起名字”需求的成功率。

### 难度按人的解题时间划分

Easy 为不足 10 分钟，Medium 为 10–20 分钟，Hard 为超过 20 分钟。计时者是验证者；这个标签既可能反映推理步骤，也可能受到个人知识、网络搜索熟练度和网页可访问性的影响。

因此 Hard 不表示模型必然需要更多 tokens，也不表示其使用了更多工具。图 3 展示了时间分布，论文没有据此规定 agent 的统一运行时限，本文也不把图形中的柱高读取成精确样本计数。（§3.2、图 3）

## 评分是实体是否对应，而非字符串逐字相同

尽管论文使用 weak string match 这个名称，正文实际描述的是基于 Llama 3.2 的 LLM judge。它接收问题、标准答案和系统答案，判断二者在问题语境中是否明确指向同一实体。

附录 B 允许措辞不同或省略非必要信息；若答案含糊、不完整，或者可能对应多个对象，则判错。判断有一段理由和 Correct / Incorrect 标签。因此这不是简单的 `prediction == answer`，也没有把包含答案词语的长段落自动当作通过。（§4、附录 B）

用下面的记号可以说明论文的三次运行平均；它是对评测协议的整理，不是论文提出的训练目标：

$$
c_{i,r}=J(q_i,a_i,\hat a_{i,r})\in\{0,1\},\qquad
\widehat A=\frac{1}{3N}\sum_{i=1}^{N}\sum_{r=1}^{3}c_{i,r}.
$$

其中 $q_i$ 是第 $i$ 题，$a_i$ 是标准答案，$\hat a_{i,r}$ 是第 $r$ 次系统答案，$J$ 是评分器，$N$ 是该次评测所含题数。分数范围是 0–1，越高越好。子集结果只在相应题目上计算，不能对文本、附件、简单、中等、困难五列再次平均得到 Overall，因为这些分组存在交叉。

三次运行取平均与“三次至少成功一次”不同。说明示例：某题三次只有一次答对，平均得分是 $1/3$，而不是 1。论文报告每个系统在每题运行三次，没有报告 best-of-three 或多数投票系统。

### 两个 98% 衡量不同事情

论文中的**人工答题约 98%**是验证者第一次尝试识别对象的成功率；**评分器约 98%**是人工核对 LLM judge 判断的准确程度。后者没有充分披露审核样本数、类别比例、评审者一致性和具体模型 checkpoint，不能据此计算每个系统分数的严格误差上界。（§4）

人工基线还参与了数据收录过程：持续存在分歧的题被删除，事后能够认可答案的题才保留。因此这是经过可解性筛选的集合上的人工表现，不能解释为任意新用户在未知题目上都能达到 98%。它仍然提供了这一集合可由人完成的证据，但不是独立于构建流程的随机对照组。

最终评分只检查答案是否正确。题目要求记录轨迹，人工也留下验证链，但论文没有给每个中间步骤单独打分或提供部分成功奖励。猜对实体、正确使用全部工具、给出可靠证据，是不同层面的结果。

## 实验比较的是整套系统配置

底座模型包括 Llama-3.1-405B、Claude-3.5-Sonnet-20241022、GPT-4o-2024-11-20、o1-2024-12-17 和 DeepSeek-R1。带工具系统包括 ChatGPT-4o、Perplexity Pro Search、Mistral Le Chat、Microsoft Copilot、HuggingFace Agents + Claude 3.5 Sonnet、DynaSaur + GPT-4o 和 Operator。

作者使用各系统的默认设置和工具集；除已经有最终答案模板的系统外，加入统一提示。HuggingFace Agents 的实现指向其 GAIA 高分方案。论文没有给所有系统提供相同的搜索接口、附件适配、最大工具步数、费用或 token 预算，也未固定完整软件提交和每次调用日期。（§4）

附件支持还不相同：Llama 与 DeepSeek 的表项标记为不支持上传；Claude、GPT-4o API、o1 和若干产品只支持部分文件类型；ChatGPT-4o、DynaSaur 的表项表示支持全部类型。缺乏上传能力的模型仍可能根据题中文字猜出对象，因此附件子集得分并不必然为零。原文没有完整披露各类不支持附件的处理过程，不能据该列直接测得纯粹的多模态感知差距。（表 1）

搜索引擎基线将原问题直接输入搜索页面，检查第一页结果是否包含正确答案。这衡量的是这一简化用法，不是熟练用户经过多轮查询、识图与地图核验后的搜索能力。

### 56% 与 49% 相差 7 个百分点

最好 agent 的 0.56，比最好无工具模型 o1 的 0.49 高 0.07，即 **7 个百分点**；相对增幅约为 $0.07/0.49=14.3\%$。原文以“+7%”描述这一区别，阅读时需要区分百分点和相对比例。

这个比较换了底座模型、框架和工具，不能把 7 个百分点全部归因为“打开工具”的净收益。较接近同一家族的比较还有 Claude 基础调用 0.40 与 HuggingFace Agents + Claude 0.56，以及 GPT-4o API 0.38 与 DynaSaur + GPT-4o 0.50；仍然没有统一所有提示、推理预算和访问环境。

同样，HuggingFace Agents 的文本题 0.61、附件题 0.41，相差 20 个百分点；Operator 的附件题 0.46 比前者高 5 个百分点，但总体反而低 2 个百分点。这说明系统相对表现随任务组成变化，不能只看最高总分来判断附件处理能力。

### 地点题和高难度题的结果

图 6 对五个常见领域分组，地点类总体较难；作者认为这类问题更依赖地图、图像及实时信息。图中展示 95% 置信区间，但正文没有完整给出区间构造方法、重采样单位或逐次结果，无法依据公开图表精确复算这些区间。

许多模型在人工耗时更长的题上下降，例如 DynaSaur 从简单题 0.61 降至困难题 0.44。下降不是所有相邻难度档都严格发生：GPT-4o API 的中等题 0.43 高于简单题 0.39。难度是人的时间分类，不能据少数平均值推断每题存在统一的模型推理难度等级。（表 1、图 6）

## 一条地点题的完整验证过程

图 4 的用户希望找回自己去过的银行，只记得在 Ibadan，并提供了银行对面建筑的照片。人类验证链记录了约 15 分 45 秒的过程：

1. 用 Google Lens 检索照片，在结果中找到一段视频。
2. 对比视频和照片，识别出 Challenge Bus Terminal。
3. 在 Google Maps 查找该地点，再比对图片。
4. 用 Street View 确认对面是 Zenith Bank。
5. 搜索银行地址并核对网页，得到 `108, Lagos bye-pass Challenge, Ibadan`。

同一题的 ChatGPT-4o 回答则指向 First Bank 的另一家分行，因此被判错。案例中的地址与解法来自论文记录，本文没有重新执行当年的地图搜索，也不将其作为当前出行信息。（图 4–5）

这条轨迹串联了对象识别、地点定位、空间关系和文字地址核验。图像识别出错会把后续搜索带向别的地点；即使最终生成一个格式完整的银行地址，也不能弥补最初实体没有对应上的问题。

## 失败分析提供观察，尚未形成受控消融

作者从轨迹中归纳了四类问题：

- **漏读描述约束**：把“黑色顶部”误当成“黑色按钮”，候选只匹配部分外观。
- **过早停止搜索**：找到局部匹配后便结束，没有继续检查其余线索。
- **工具失败后反复重试**：网站访问限制或 API 问题发生后，没有寻找替代来源。
- **长流程中遗失原始目标**：搜索越来越长，模型忘记约束或陷入循环。

附录 C 还展示了把餐馆招牌识别错后连续进行错误搜索，以及 Operator 多次看到某旅行网站创立年份不符合题意却仍选择该网站的案例。这些说明了具体失败路径，没有提供四类错误的全量频次、互斥标注规则或归因一致性。（§5、附录 C）

论文没有做固定底座与预算下的“去掉工具”“去掉图片”“去掉时间条件”“增加核验步骤”消融。因此无法量化某个模块单独贡献多少，也不能由几条轨迹证明所有同名产品都会以相同方式失败。对参数知识能否拼接出答案的分析同样基于案例，不是对模型内部知识表示的直接测量。
