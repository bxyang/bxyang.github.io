# HalluWorld 精读：用可检查的环境状态分析模型幻觉

终端日志显示一个模型已经保存了训练产物，但脚本里没有优化器、反向传播或训练循环。读这些日志的模型需要区分“文件已生成”和“权重经过训练更新”。HalluWorld 把这类问题变成受控评测：先保存环境状态及历史，再在指定位置提问，用明确答案检查模型对世界的描述。它覆盖网格世界、象棋和终端任务，发现直接读取信息、追踪变化、推演结果和承认证据不足会呈现不同的错误分布。[论文 §1、§3、附录 A.3](https://arxiv.org/pdf/2605.19341v1)

本文精读 2026 年 5 月 19 日的 v1，共 37 页。它是 [统一幻觉定义论文](/companies/patronus-ai/hallucination-definition) 的配套 benchmark，拥有独立的作者名单、数据和实验；不是定义论文中的一个结果章节。

## 从固定答案转向状态、视图与规则

HalluWorld 采用参考世界结构：

$$
W=(\mathcal S,\mathcal H,\mathcal R).
$$

$\mathcal S$ 是世界状态，$\mathcal H$ 是交互历史，$\mathcal R$ 是状态变化与一致性规则。网格世界里，它们包括物体位置、门是否打开、动作序列和河流等机制；象棋里是棋盘、行棋历史和规则；终端里是文件、进程、命令与输出记录。（§3、表 1）

模型看到的只是视图 $V(W,x)$。相同世界可以用对象列表、ASCII 图或历史记录呈现，也可以只展示部分区域。来源冲突时，政策 $P$ 规定哪个优先。例如牌子与直接观察冲突时，以观察为准；错误 FEN 与棋盘不一致时，以棋盘所表示的状态为准。

按照关联定义，输出 $y$ 是否包含幻觉可以写成：

$$
H(y;W,P,x)=\mathbf1\left[
\exists c\in C(y):T_{W,P}(x,c)=\mathrm{false}
\right].
$$

$C(y)$ 是可观察陈述，$T$ 依据参照返回 true、false 或 unknown。这是判断依据，不是对模型内部神经表示的直接测量。HalluWorld 实际用限制答案形式的探针，将许多问题变成可自动比对的状态查询，而没有让通用 judge 对长篇解释自由打分。

### 正确答案为“未知”与陈述为假需要区分

说明示例：一间房从未被观察，问题要求依据已见信息判断里面有几把钥匙。模型回答“无法确定”符合任务；断言“三把”则超出了证据。若模拟器恰好真的放了三把钥匙，这个断言仍可能违反“根据可见信息判断”的协议，但不能因此直接认定它在完整世界中为假。

因此，需要分清两种评价：一是陈述与世界事实冲突，二是回答未满足当前视图下的证据或弃答要求。定义论文明确不把 unknown 自动视为 false；本 benchmark 的闭式答案比较则还涉及可回答性、格式和证据限制。未取得评分器代码前，不能假定所有非匹配答案都已经被逐项证明为事实幻觉。

不确定性类别也不等于每道题都必须拒答。附录终端例子的 U 问题包含 `status=contradicted`：给定证据足以否定某项主张，正确做法是指出矛盾。下文的 U 错误率是这类探针的整体错误率，不能直接当作“该拒答却没拒答”的比例。

## 五类探针测量不同要求

| 类别 | 需要完成的判断 | 典型问题 |
| --- | --- | --- |
| P：感知读取 | 从当前观察中找出信息或关系 | 眼前有几颗球、文件列表出现了哪个路径 |
| M：记忆追踪 | 保留并更新此前观察 | 某个物体是否已移动、文件在最近修改前是什么状态 |
| C：因果推演 | 按规则计算动作结果 | 移开压板上的物体后门是否关闭 |
| U：证据与不确定性 | 判断能否确定，以及应该肯定、否定还是保留未知 | 未观察区域的内容是否有充分证据 |
| X：复合推理 | 联结多个区域、阶段或记录 | 把命令、文件变化和历史输出结合起来解释当前状态 |

这是任务设计者赋予探针的类别，不是通过模型内部实验测出的五个独立模块。“感知”在本文主要是读取文本和 ASCII 表示，也不能直接等同于图像模型的视觉识别能力。（§3、图 1）

同样的类别在不同领域难度不相同。棋盘上的 P 探针包含合法吃子和防守关系，已经需要运用规则；终端上的 P 探针可能只需要在长日志中找到明确值。跨领域比较时应看具体任务，而不只看类别字母。

## 三个领域怎样构建

### 网格世界：控制物体、机制和观察格式

HalluWorld-GRID 基于 MiniGrid，论文列出 **33 个关卡、839 个探针问题**。关卡为人工设计，不是从现实工作中随机采样。附录 C 的分类是 P 六个、M 六个、C 九个、U 五个、X 七个；其中有些“关卡”是同一机制的时间点或条件变体。（§3.1、表 13）

| 关卡组 | 具体变化 | 主要区分 |
| --- | --- | --- |
| P1、P4 密集数组 | 规则排列中插入颜色变化、缺项和状态差异 | 真正读取例外，还是补全常见图案 |
| P3 朝向变化 | 保持场景、变化模型所处朝向 | 全局坐标与自身左右的转换 |
| M1 河流 | 物体随时间向东移动，告示保留初始状态 | 最新状态与旧文字记录 |
| M2、M3 多次观察 | 多房间属性、两个时刻的颜色或物体变化 | 对象身份、时间和属性绑定 |
| C1a、C1b 压板与门 | 同一布局中分别使用持续触发和一次触发机制 | 移除触发物后效果是否保留 |
| C2、C3、C6 火与洪水 | 湿物体灭火、洪水逐步封路、机制组合 | 按步推算可通行状态 |
| U1、U2、U4 | 未观察房间、不同可信度的牌子、缺失历史 | 证据是否足以支持确定答案 |
| X1–X7 多区域行程 | 三至八个区域，包含重访、错误证词和变化 | 长历史整合与状态更新 |

河流方向和速度、洪水激活时刻、压板效果都属于环境规则。物体带有 DRY/WET/SOAKED 状态和剩余湿润时间，离开河流后逐步减少；湿物体可以灭火，干燥诱饵不行。牌子可以准确、过时或故意错误，但“牌子内容是什么”与“牌子说的是否真实”仍是不同问题。（附录 D）

### 序列化改变模型接收状态的方式

论文设计三个 serializer，即把状态变成模型输入的方式：

| 表示 | 输入形态 | 主要负担 |
| --- | --- | --- |
| Symbolic | 结构化对象列表或文字说明 | 读取关系、计数和属性 |
| Grid | ASCII 网格 | 解析位置、方向和布局 |
| Memory | 组合文字、网格及此前观察 | 追踪变化和整合历史 |

这不只是替换几个分隔符：Memory 还涉及历史信息。主表不同表示覆盖的关卡组合不完全相同，很多因果难题主要使用 Memory。因而把 Memory 列与 Symbolic 列直接相减，不能单独识别“表示格式本身”的因果影响。更接近配对比较的实验在附录 I，仍需保留其轨迹和聚合条件。

网格探针的答案有六种形式：yes/no、整数数量、状态或属性、坐标、动作后结果，以及是否能够确定。P1 和 P3 的非确定性关卡使用十个固定种子。**839 是问题规模，不是所有模型、种子、表示和实验变体相乘后的 API 调用总数。**（§4）

### 象棋：从明确棋盘读出关系，再追踪隐藏棋局

HalluWorld-CHESS 从 Lichess 棋题抽取局面，考虑不同难度与主题。默认先执行 14 个随机合法后续着法，减少直接依赖熟悉开局或原题续着的机会。观察可包含带坐标的 ASCII 棋盘、行棋方和 FEN；错误 FEN 条件通过交换两个棋子制造辅助信息冲突。（§3.2）

七类探针分别要求：

| 探针 | 输入与判断 |
| --- | --- |
| `can_capture` | 从棋盘判断下一步能否合法吃掉指定棋子；部分反例涉及被牵制的棋子 |
| `defended` | 判断受攻击棋子是否也被己方保护 |
| `hanging` | 判断棋子是否受攻击且无防守，不把王列入该类对象 |
| `hypothetical_in_check` | 应用一个指定着法，再判断后继局面是否将军 |
| `after_move_undefended_count` | 应用一至两个着法，数出失去全部己方防守的棋子 |
| `hidden_side_capture_stats` | 不给当前棋盘，阅读 25–88 步序列并追踪吃子数量 |
| `san_legal_move` | 从 40 步以上 SAN 棋谱重建局面，输出一个合法 UCI 着法 |

最后一项名为 SAN，是因为输入棋谱采用标准代数记谱法；输出示例却要求 UCI，例如以起点和终点坐标表示着法。它检查合法性，不是在每个局面寻找最强着法或计算 Elo。（附录 B、表 11–12）

论文还设置 CHATCONTEXT，先放入 4–16 步旧对局与评论，再呈现真实观察，考察能否忽略无关历史。棋类没有 U 探针，因为所给当前状态或完整合法历史旨在确定相关答案；“不显示棋盘”并不自动意味着题目不可回答。

每个探针计划使用 50 个局面，正文称总计 350。但表 4 图注写约 348，M 列的 2.1%、8.3% 等数值与 48 个样本的步长相符。论文没有解释缺少的两条；本文保留这项不一致，不能对所有表格强制使用 350 作为分母。表 11 又把 SAN 探针归 M，主表归 X；本文按主表用 M 表示纯记忆计数、X 表示 SAN 复合推理。

### 终端：先收集轨迹，再生成状态探针

HalluWorld-TERMINAL 来自 **110 个 Terminal-Bench 任务、132 条执行轨迹、529 个探针**。作者使用 GPT-4o-mini 操作真实 Linux 环境收集轨迹，目的是获得较长、较杂乱、包含错误与修正的过程，而不是只保留最强 agent 的成功路径。（§3.3、附录 E）

运行时记录器保存命令、工作目录、终端输出、命令前后窗格状态与文件快照，包括 SHA-256、修改时间和目录列表等。之后由 GPT-5.4 high 生成问题与答案，并给可回答性及难度打 1–5 分，只保留可回答性为 5、难度至少 4 的题。

**这些质量分由生成问题的模型自己提供。** 最终评分可以不用 LLM judge，但数据制作仍含 LLM 生成、标签整理与质量判断，不能写成全部标签都来自没有模型参与的纯程序推导。尤其终端的反事实因果题，还需要核对 gold 是怎样从记录或规则得到的。

探针在收集后用于评测，不向原任务 agent 提问，所以不会改变原来的任务轨迹。被测模型接收日志和问题，回答受约束的键值字段，而不是重新执行 Terminal-Bench 的完整任务。因此该成绩不是 agent 的任务完成率，也不是修复程序成功率。

#### 一个训练产物案例

附录 A.3 的 `hf-train-lora-adapter` 轨迹中，脚本先因字面换行和参数问题报错；修复后能创建 adapter 和结果 JSON。但最终代码只读取数据来计数，随后保存模型，没有训练循环。元数据仍记录一个已经从实际配置删除的参数。

在这个例子中，模型需要分别回答“当前代码与元数据哪里不一致”“之前修了什么”“权重是否经过训练”。文件创建成功不能证明发生了梯度更新，结果 JSON 存在也不能证明元数据准确。论文给出这些标准答案，但没有附上每个被测模型在该题的完整回答轨迹。（表 10）

另一类问题检查命令、工作目录和相对路径快照是否来自相同位置。缺少某个相对路径的文件记录，不一定证明编译所在目录中没有该文件。这样的题依赖跨段信息，而不是关键词搜索。（表 9）

#### 类别数量与错误机制数量不是同一张表

论文为五类认知探针安排大致相近的覆盖；同时另按失败机制统计：旧记忆 187 条、跨类别推理 110 条、不确定性过度断言 107 条、因果捷径 104 条、版本/API 错误 21 条，总计 529。这组数字不能直接当成 P/M/C/U/X 五列的样本数。特别是 U 类别与“过度断言 107 条”不应只凭名称相近就视为同一个分母。（§3.3）

## 实验预算与评分口径

论文测试闭源和开放权重模型，在支持温度设置时使用 temperature 0。默认推理强度为 medium，通常为最终回答预留 256 tokens、思考预留约 16k tokens。终端部分进一步说明，思考模型设置 `max_output_tokens=16384`，普通模型上限 256，计算预算明显不同。（§4、§7）

输入终端日志通常约 30k–60k **字符**。更长轨迹采用中间截断，保留开头和结尾，不是 60k tokens。终端深度指探针触发前执行了多少条 shell 命令，不等于输入 token 数，也不等于 elapsed time。

模型版本在表中也需保留：网格表写 DeepSeek-V3-0324，棋类和终端表写 DeepSeek-V3.1；GPT-5.4 与 GPT-5.4-mini 也有不同条目。它们不能仅按相似显示名合并成同一个模型跨领域统计。

### 探针错误率与任务成功率不同

用 $q_i$ 表示探针、$a_i$ 表示标准答案、$\widehat a_i$ 表示模型输出，$\operatorname{Eval}$ 为该探针的闭式检查，可将实际统计过程表达为：

$$
e_i=1-\operatorname{Eval}(a_i,\widehat a_i),\qquad
\widehat H_{\mathrm{micro}}=\frac{\sum_i e_i}{N}.
$$

这是对论文报告口径的数学整理，不是从尚未公开的评分代码提取的实现。$e_i=1$ 表示该探针答错；对限定格式且完全可判定的题，作者将其统计为幻觉。全局 micro 平均让每个有效探针等权，题目多的关卡影响更大，不等于五类平均，也不等于每个关卡等权。

说明示例：A 关卡有 100 题、错 10 题；B 有 10 题、错 5 题。探针 micro 错误率为 $15/110\approx13.6\%$，两个关卡错误率的平均却是 $(10\%+50\%)/2=30\%$。读表时必须先看聚合单位。

Hard 子集按 12 个“关卡×表示”组合报告平均，附录 I 的部分表示分析又先平均同一轨迹中的探针，再平均轨迹，最后比较世界。它们都不是主表 micro 的简单子列。论文没有公开完整的大小写归一化、坐标解析、非法答案、超时和拒答处理代码；本文没有补造这些规则。

GPT-5.5 总体错 5.0%，但因果类为 25.3%。Kimi 的总体 9.3% 比若干开放模型低，C 类却高达 47.4%。这些数字说明汇总分可能掩盖特定机制下的失败，不能仅凭总体分数说模型已经解决状态理解。

来源冲突也不只是“文字有错才会误导”。在 C1a 中，Opus 4.6 有准确告示时错误率为 42.0%，移除告示后为 28.4%。作者据此提出文字规则可能干扰已有的因果推演，但这个对比没有单独定位神经机制，也不证明加入正确说明普遍有害。（§5.5、表 16）

### 主表的表示差异不能直接当作配对增益

GPT-5.5 在 Symbolic、Grid、Memory 三列为 1.1%、3.1%、21.3%；Opus 无思考为 3.8%、5.1%、15.5%。由于关卡覆盖、历史内容与任务难度同时不同，21.3% 与 1.1% 的差不是仅改变输入格式造成的受控效应。

更细的观察是某类题对表示特别敏感：例如跨房间属性追踪在 Grid 下容易失败，物体是否存在的判断却可能仍正确。论文的一些概括没有在主表中逐题展示，完整核查还需要公开每个关卡、种子及表示的输出记录。（§5.2）

### Hard 子集按本批模型表现挑选

HalluWorld-Hard 选出满足“至少五个模型错误率不低于 20%”的 12 个关卡×表示组合，集中于因果链、河流记忆、密集网格和多区域冲突。这是依赖所测模型成绩的难例筛选，不是独立随机抽样的第二份测试集。（§5.4、附录 H）

平均错误率为 o3 15.5%、o3-mini 17.0%、GPT-5.5 17.1%、Opus (T) 17.8%、Sonnet (T) 17.9%、GPT-4o 31.1%、Kimi 53.9%。GPT-5.5 主表总体 5.0% 与 Hard 17.1% 不使用同一聚合分母；两者差值不能直接解释成每条题平均增加了 12.1 点难度。

## 推理强度消融要同时看方向、类别与分母

### 网格：更多思考未带来稳定改善

表 15 中，GPT-5.5 的 none、low、medium、high 总体错误率为 4.8%、5.0%、5.0%、4.8%，基本相近；C 类为 24.5%、25.9%、25.3%、24.7%。

Sonnet 4.6 的 none、low、medium、high、max 总体为 7.2%、8.1%、7.7%、8.0%、8.1%；C 类从无思考的 19.7% 到 max 的 27.1%，增加 7.4 个百分点。但感知类在 high 下从 2.8% 降至 1.0%。同一个预算变化，对不同类别可以产生不同方向。

作者提出，延长推理可能增加编造中间状态的机会。这是对现象的机制假设；论文没有给出针对中间状态的因果追踪，不能只凭最后答案把它当作已经定位的原因。

### 终端：总体提高，不代表每一列单调提高

## InNav：共享轨迹下的对话呈现，不是每个模型独立探索

主文将 In-Navigation 写成模型边导航边回答问题；附录 I 补充了关键控制：**所有被测模型的导航轨迹，由同一个 GPT-5.4-mini high 生成**。动作和观察被放进连续聊天历史，探针以随后消息提问；CtrlStatic 则在同轨迹条件下给出静态观察。（附录 I，第 24–25 页）

所以，当前证据适合解释为“共同动作—观察历史的对话式呈现与静态呈现有何差别”，不能称为各模型自行选择动作、探索不同世界后的任务成功比较。它控制了导航能力差异，但也限制了对自主 agent 表现的外推。

令同一评测范围中的错误率分别为 $H_{\mathrm{InNav}}$ 和 $H_{\mathrm{Ctrl}}$，论文的导航效应为：

$$
\Delta_{\mathrm{nav}}=H_{\mathrm{InNav}}-H_{\mathrm{Ctrl}}.
$$

负值表示 InNav 错误更少。表 17 的代表结果如下，单位为百分比或百分点：

| 模型 | InNav | CtrlStatic | 报告的差值 |
| --- | ---: | ---: | ---: |
| GPT-5.5 | 27.4 | 40.7 | −13.2 |
| GLM-5 | 37.0 | 41.5 | −4.4 |
| o3-mini | 36.1 | 40.5 | −4.4 |
| o4-mini | 37.6 | 41.3 | −3.8 |
| o3 | 37.8 | 41.0 | −3.2 |
| GPT-4o | 38.9 | 40.2 | −1.3 |
| Opus 4.6 | 36.8 | 35.7 | +1.1 |
| Sonnet 4.6 | 37.3 | 36.1 | +1.2 |
| GPT-5.4-mini | 40.1 | 37.2 | +2.9 |

显示值经过舍入，报告差值未必等于两列一位小数直接相减。作者为前五个模型标注 95% 区间不含零，但没有给出足够的区间计算方法、重采样单位和完整原始记录，本文不能独立重算其显著性。

这一表使用 **31 个世界、12 个模型条目**，主实验是 33 个关卡，后面的深度分析又写 13 个模型。论文没有完整列出这些分析之间的包含与排除关系。GPT-5.5 的 CtrlStatic 40.7% 也不是主表中的 5.0%；不能把它们拼成“同一数据只改为导航后从 5.0% 升到 27.4%”。

### 深度效应依赖分析层级

附录 I 将轨迹位置分为五个等比例区间，并拟合每个区间对应的错误率斜率。总体分析报告 CtrlStatic 的模型中位斜率为每区间 +5.1 个百分点，InNav 为 +6.6 点；按世界类别分析，感知和因果却分别为 −1.0、−1.8，X 多区域任务为 +6.5。

这些结果来自不同分组和聚合，不能强行解释成每个模型在每个类别都越走越差。类别随轨迹深度的组成、观察新增信息、任务难度和历史长度同时变化；“认知负担”和“接地收益”是作者的解释框架，不是已经分别测量的两个潜变量。

论文还从斜率讨论自主部署策略，但共享轨迹实验没有直接测试无人干预的导航成功率、事故率或生产任务成本。本文不据这些相关趋势建议某个模型独立运行得更久。

### 表示配对实验使用分层平均

附录 I.7 覆盖 30 个世界、229 个模型层面的表示比较，仅纳入同一世界两个表示都被测过的模型。为了减少轨迹长度影响，先对同一 episode 的探针求平均，再对轨迹等权平均，最后比较世界。

可写成：

$$
\widehat H_{w,s}=\frac1{|E_{w,s}|}
\sum_{e\in E_{w,s}}\left(\frac1{|Q_e|}\sum_{q\in Q_e}e_q\right).
$$

$w$ 是世界，$s$ 是表示，$E$ 是轨迹集合，$Q_e$ 是该轨迹中的探针。这个表达式按附录聚合步骤整理；不同表示的导航轨迹可能不同，所以它控制了平均权重，却没有保证逐步完全相同的观察内容。

论文表 19 报告原先选定的表示仅在 15/30 个世界胜出：感知类 1/6、不确定性类 1/5、因果类 5/8、记忆类 2/4、X 类 6/7。说明没有一个表示在这些条件下普遍最好。表中的平均优势与后面逐世界列出的差值无法在未给定权重时直接重算，因此本文使用明确的胜出计数，不把 14.3、12.8 等概括当作已独立核实的统一收益。

## 自动标签也需要检查实例是否自洽

论文附录 A 的网格展示例存在可直接看到的冲突：表 6 的图中，三行蓝球分别有 8、8、9 个，合计 25；标准答案却写 14。它还把 R1、ahead 2 的球标为红色，但图中该位置是蓝色，红球位于左侧。按图和表给出的信息，两者无法同时正确。（PDF 第 16 页）

本次已经检查原 PDF 版面，不是仅由文字提取造成的列错位。不过，这只能证明**论文展示图与所附答案不一致**，不能据此断定未公开数据集里的全部 P1 标签都错了。没有原始关卡、种子、轨迹和探针文件，无法确定是图示替换、坐标标注还是实际 gold 的问题。本文不把这个例子照抄为正确教学题。

附录 J 的 C6 说明又同时出现洪水相关的第 4 步和灭火第 14 步，可能涉及不同阶段或计时起点，但没有代码可核对。本文因此解释其机制组合，不给出一个声称可直接执行、时序已经统一的完整案例。

## 编辑器与记录器提供怎样的扩展流程

论文展示了 Web 与终端 ncurses 两种关卡编辑器，可以放置墙、门、钥匙、河流、火、洪水和牌子，设置位置与属性，导出文本关卡。轨迹记录器则让操作者实际走过世界，并在选定时刻插入探针。（附录 J）

记录器同时显示全局状态与模型所见观察，操作者根据状态填写或检查标准答案。论文称最终 JSON 包含：

- `segments`：关卡文件、种子和动作序列。
- `probes`：所属片段、触发步、探针类型、问题、标准答案及元信息。

同一关卡、种子和动作可以用于确定性回放。它有助于不同模型回答同一状态下的问题，但探针放置与答案核验仍包含人为设计。应把“无需事后请人逐条评判模型输出”与“数据制作完全无人参与”区分开来。

论文给出 `BaseProbe`、`Serializer` 等接口思路，也提到 250 条以上导航轨迹。当前固定仓库只有 README，尚不能查看这些类、轨迹文件或运行 `run_trajectory_eval.py`。本文不将论文里的界面截图和代码路径写成已经验证可用的公开工具。

## 可复现范围与尚缺的材料

本次可实际核对的材料是 v1 PDF、版本记录及固定 README。没有运行环境、数据或评测代码可用，因此没有执行模型推理、复现排行榜或为其编造训练参数。HalluWorld 是评测工作，也没有提出新的模型损失或权重训练流程。

| 终端任务版本、容器、原始轨迹及快照 | 核对路径、进程、文件和时间线事实 |
| GPT-5.4 探针生成提示、质量分与筛选日志 | 检查终端标签和难度筛选的可靠性 |

新环境可降低模型直接记住现成答案的机会，但并不等于已经完成污染审计。象棋来自公开棋题，终端来自公开任务，模型也可能熟悉游戏和软件规则。论文没有报告对完整训练语料或所有模型做数据重叠检查。

HalluWorld 的证据表明，不同状态查询会呈现明显不同的错误分布，增加推理预算也不会在所有领域和类别中产生相同收益。它尚未证明这些错误都来自同一种内部世界模型缺陷，更没有用一个总错误率覆盖所有真实 agent 行为。参考世界、观察视图、来源政策和评分解析保持明确，才能把这些结果用于后续比较。
