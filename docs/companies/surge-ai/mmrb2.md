# Multimodal RewardBench 2：评审图像、编辑与图文推理

Multimodal RewardBench 2，简称 MMRB2，把多模态奖励评测从“图片是否符合一句描述”扩展到四种任务：文生图、图像编辑、图文交错生成，以及需要检查推理过程的视觉问题。每种任务包含 1,000 组候选回答，人类先选出较好的一项，评审模型再做相同选择。

这里的准确率衡量的是**评审器与人工偏好的吻合程度**，不是候选生成模型完成任务的比例。论文没有训练一个新的奖励模型，而是构建数据、比较现有评审器，并研究这些评审器用于候选筛选时的表现。主表中，Gemini 3 Pro 的四任务平均准确率为 76.3%，GPT-5 为 72.2%；这个汇总背后，各任务的困难来源不同。[论文 v3](https://arxiv.org/abs/2512.16899v3)

## 论文版本与 Surge 的参与

论文由 Yushi Hu、Reyhane Askari-Hemmat、Melissa Hall、Emily Dinan、Luke Zettlemoyer 和 Marjan Ghazvininejad 署名，作者单位是 Meta 的 FAIR / Meta Superintelligence Labs，前两位共同一作。Surge 提供专业标注人员与标注平台；论文致谢列出了 Surge 团队成员，并注明标注报酬为每小时 85 美元。不能据此将 Surge 写成论文作者单位，或说它训练了文中的奖励模型。

时间线保留首发日期 2025 年 12 月 18 日。本文精读的是 2026 年 1 月 19 日提交的 arXiv v3，共 45 页；PDF 内部另标注 1 月 21 日。v2 提交于 1 月 3 日。下面的实验数字以 v3 为准，公开代码和数据则另行固定版本，不默认它们完整保留了论文实验时的环境。[版本记录](https://arxiv.org/abs/2512.16899) · [官方项目](https://github.com/facebookresearch/MMRB2)

## 四类任务分别要求评审器检查什么

文生图需要同时检查指令遵循和图片本身的质量。例如“六个人站在地下通道”既包含人数，也包含场景；图片清晰、构图自然，不能替代人数正确。附录的例子中，一个候选只画了五个人，另一张满足六人的要求。

图像编辑的输入还包含一到三张原图。评审器需要检查要求修改的部分是否修改，以及没有要求改变的部分是否保留。对海报增加文字时，漏掉整段指定文字和个别字母失真是不同程度的问题；只给最终图片打美观分无法覆盖这种判断。

图文交错生成的输出由多段文字和多张图片组成。它不仅要求单张图片正确，还要求前后人物、场景、动作与文字相互对应。附录展示了同一场景依次呈现黄昏、雾天和春天的要求：一个回答虽然有三张图片，却没有完成条件变化。另一例要求猫做不同动作，重复同一姿态也会影响整体偏好。

多模态推理比较的是回答和推理过程。两个候选即使最终选项相同，仍可能一个真正分析了图片，另一个用错误的数数过程碰巧得到答案。该任务还允许推理过程中生成、裁剪或标注图片，因此评审器必须在纯文字推理和图文推理之间做比较。[正文 §2–3、附录 D](https://arxiv.org/pdf/2512.16899v3)

## 从来源任务到 4,000 组偏好对

候选来自 23 个生成模型或 agent，覆盖 21 个来源任务条目。后者不是 21 个互不相关的数据集名称：例如 RealUnify 分别提供了生成和推理任务。作者从来源基准的测试部分取题，并按难度和任务类型组织采样。使用测试部分不等于能够保证这些题从未进入任何模型的预训练数据。

| 任务 | 来源及最终偏好对数 |

| 文生图 | EvalMuse 390、OneIG 278、R2I 128、RealUnify-UEG 93、WISE 111 |
| 图像编辑 | DreamBench 242、Emu-Edit 329、HQ-Edit 53、多图合成编辑 178、RISEBench 84、重文字编辑 114 |

编辑任务的新增部分有两种。重文字编辑要求图片中出现约 10–50 个单词，最终保留 114 对；多图编辑要求结合多个输入，最终保留 178 对。这些数量已经包括在编辑任务的 1,000 对内，不能再额外相加。附录记录了真实图片与合成图片结合的构建过程，以及人工质量检查，但没有给出一套保证所有来源难度一致的自动规则。

不同任务分别使用约 7–11 个回答生成器。除直接生成模型外，作者还构建了结合文字模型、Python 工具和图像生成/编辑服务的 agent，例如 GPT 系列模型配合 FLUX、Imagen、GPT Image 或 Gemini 图像工具。工具返回的图片会被编号，后续文字或工具调用再引用这些图片，最终输出保留图文次序。

附录给推理 agent 的指令限制是最多 10 次工具调用，运行过程另设最多 15 轮；这两个数字分别约束工具使用和交互轮次，不能当成评审器每题的调用预算。大部分回答生成使用默认设置，温度通常为 1.0。论文并未为所有生成器提供足以逐项恢复的时间戳、服务端快照和总生成成本。[附录 A、C.1–C.2](https://arxiv.org/pdf/2512.16899v3)

## 人工金标不是直接对随机候选投票

### 生成与编辑先排除容易区分的候选

前三类任务先使用九个多模态模型组成评审集合：GPT-5、GPT-4.1、GPT-4o、Gemini 2.5 Flash、Gemini 2.5 Pro、三个规模的 Gemma 3，以及 Qwen2.5-VL-7B。每对回答交换顺序各评一次，共产生 18 个判断。若至少 90% 的判断支持同一候选，则视为较容易区分，予以排除。在 18 个判断均有效的情况下，这个阈值至少需要 17 票。

筛选后，每对交给三名专业标注者独立盲评。标注不只有一个总选择，还包括 0–3 分的分项评价和文字解释：指令遵循、原图保留、图片质量、跨图一致性、图文对应、生成文字质量，以及适用时的文字渲染。哪些维度出现，取决于任务。

之后还要过滤分歧：总偏好评分跨度大于 4、平均落入平局区间、或多数人选择平局的样本被排除。平台标记和后续人工检查用于发现需要复审或纠正的标注。因此最终数据偏向“模型不容易判断，但人类比较一致”的配对，不能用它估计任意实际请求中模型与人类的平均分歧率。

原文对这部分数量的表述混用了 judgment 单位：出现 17,700 和 5,900，并同时说明三人标注。按人数关系可以读成 5,900 对、17,700 次个人判断，最终保留 3,000 对，即约 50.8%；这属于对原文单位关系的解释，不是额外公开的完整筛选日志。

另一个需要保留的细节是偏好刻度不完全一致：正文称七点量表，附录 B.1 写 5–7 对应 A、1–2 对应 B、3–4 对应平局；但标注界面和部分附录说明呈现六个选项，评审提示词也使用 1–6。仅凭 PDF 不能把这些表述自动统一成一套确定的原始录入规则。

论文报告，过滤后的前三类任务在排除平局时，人工一致性分别为 95.3%、96.3%、95.2%，总体 95.6%。这是经过筛选的标注一致性，不能直接当成独立人类参赛者在全部四任务上的准确率；原文也没有给出足以重建其置信区间的完整独立评测设计。

### 推理任务先拆开答案正确和过程正确

推理任务采用不同金标流程。作者先检查最终答案和是否存在推理，然后由三名标注者检查过程。被选中的回答需要答案正确，且三人一致认为没有重大推理错误；允许存在不影响主要推理的改进空间。较差回答可以是答案正确但过程存在重大错误，也可以是答案本身错误。

附录表 11 将 1,000 对分成两组：324 对的较差回答属于推理错误，676 对属于答案错误。按输出模态又可分为两边均为文字 350 对、两边均含图片 353 对，以及一边文字一边图文的 297 对。官方 JSON 的图片内容字段也得到这三个数量。这里“均为文字”指回答，不代表问题输入没有图片。

附录中的视觉推理例子说明了这种区分：两个回答最终都选 C，但其中一个在解释中错误统计了特定圆形；只验最终选项会把两者同时判对，偏好金标仍可以区分推理质量。

## 评测公式与交换顺序

评审器看到题目、相关输入图片和候选 A/B，按任务提示词输出比较理由及 `better_response`。为减少位置偏好，每一对都以正序和逆序评判，逆序结果先映射回原始 A/B，再计分。

设第 $i$ 对的人工选择为 $y_i$，正序预测为 $\hat y_i^F$，逆序预测映射回原编号后为 $\hat y_i^R$。所有判断完整时，任务准确率是：

$$
\mathrm{Acc}=\frac{1}{2N}\sum_{i=1}^{N}
\left[\mathbf{1}(\hat y_i^F=y_i)+\mathbf{1}(\hat y_i^R=y_i)\right].
$$

每类 $N=1000$，对应 2,000 次方向判断；四类合计 8,000 次。两个方向分别贡献分数，并不要求一对的两个方向都对才给分。例如一个总是选择屏幕上第一个候选的二元评审器，在完整正反序评测中会得到 50%。但正反序来自同一对内容，统计上不能当成两个独立抽样的题目。

四任务样本量相同且判断完整时，四类准确率的算术平均等于合并所有方向判断的准确率。后面的代码核查会说明，输出缺失时两者不一定相同。

## 进一步分析：内容质量之外的偏好

### 同模型配对与跨模型配对

正文笼统写同模型候选对占 57.4%；这个比例与公开文件中前三类生成任务的数量吻合。官方文件对应文生图 573、编辑 540、图文交错 610，共 1,723/3,000；推理另有 239 对同模型配对，不能把 57.4% 写成全部 4,000 对的比例。

表 4 显示，前三类任务中不同模型的候选通常更容易区分。例如 Gemini 3 Pro 的文生图同模型准确率为 70.4，跨模型为 79.7，差 9.3 个百分点；GPT-5 的图文交错分别为 69.4 与 82.1，差 12.7 个百分点。这与模型风格可能提供额外线索相容，但比较本身没有单独移除风格，也不能证明模型只依靠风格。

推理不是所有模型都遵循相同方向：Gemini 2.5 Pro 在同模型组为 70.5，跨模型组为 65.4。因此不能概括为四任务上跨模型配对一律更容易。

### 图文回答可能得到额外偏好

表 5 专门检查 297 对模态不同的推理回答，并进一步按较差回答的错误类型拆分。当人工偏好图文回答时，GPT-5 在两类错误上的正确选择率为 88.64% 和 88%；当人工偏好纯文字回答时，则为 36.79% 和 40%。这种不对称意味着生成图片可能影响评审，但不能仅凭该表把全部差值归因于图片本身，因为两组内容并未做逐对受控替换。

两个方向的样本数也不相等。用附表 11 的数量加权，GPT-5 在人工偏好图文的 144 对上约为 88.20%，在人工偏好文字的 153 对上约为 38.89%，差约 49.31 个百分点，接近正文报告的 49.3。

Gemini 3 Pro 存在一处不能直接重现的汇总：正文报告模态差距 17.9 个百分点，但按表 5 的四个分数和表 11 的样本数加权，得到约 16.1。这里只指出公布表格不能重现正文汇总，不能据此确定是分母变化、表格更新还是其他原因。

### 增加评审采样次数

测试时扩展实验对每任务随机抽 300 对，共 1,200 对，用 $K=1,3,5,7,9$ 次判断多数投票。它不是对全量 4,000 对的重复主实验，也不是增加回答生成器的候选数。

图 5 中，Gemini 2.5 Pro 的平均准确率约从 71.3 提高到 72.5，提升 1.2 个百分点；不同评审器的曲线变化不相同，不能把正文的概括写成所有模型都有相同幅度的收益。论文没有报告足以区分这些小幅变化与抽样波动的完整置信区间。公开评分脚本默认只读取每个方向的第一条判断，也不会自动执行这里的 $K$ 次多数投票。

## 与下游候选筛选的关系

作者在四个外部基准 GenAI-Bench、GEdit-Bench、ISG-Bench 和 EMMA 上进行 best-of-8 实验。每题生成八个候选，用评审器按淘汰赛方式选出一个，再交给外部任务指标评分。这里的八个是生成候选数；前一节 $K$ 是同一候选对的评审采样数，两者不能互换。

每种任务选用两个能力不同的生成器，并比较七个评审器。GPT-4o 和 GPT-4.1 因参与下游指标评估而不作为这组候选筛选的评审器，但这不意味着 GPT-4o 不会作为回答生成器出现。图文交错相关性分析还从 MMRB2 中排除 ISG 来源，减少与下游 ISG 测试的重合。

图 4 的八组 Pearson 相关系数介于 0.803 和 0.995，说明在这些设置下，MMRB2 分数与候选筛选后的任务分数相关。相关性只来自所选评审器、生成器与基准，不能外推成“用此奖励训练一定得到相同提升”，也没有替代强化学习实验。

筛选并非对每个组合都提高分数。例如 EMMA 上 o3 Visual Sketchpad 的随机选择基线为 69.47，一些评审器筛选后的结果反而更低。保留这个例外，才能准确表达评审器既可能找出好候选，也可能将它丢弃。论文未提供完整的逐题候选、淘汰赛比较记录和所有服务端版本，本文没有重新运行这组实验。

原始 JSON 保留候选内容、生成模型名、来源、人工标注和 `chosen` 金标，但文件名中的 `response_only` 表示它不是已经补齐题目与输入图片的可直接运行数据。官方提供两条构建路径：从 Hugging Face 还原完整数据，或从各来源基准补齐输入，再合并输出图片。不能把四份元数据文件的读取成功写成完整视觉数据已经验证。

实际字段是 `id`、`chosen`、`model_name`，与 README 示例中的部分字段命名不同；应以当前文件和执行代码为准。图片按内容列表中的顺序出现，复现时需要检查路径、图片数量及图文顺序，而不是只检查 JSON 行数。

当前注册的评审器只有 GPT-4o、Gemini 2.5 Flash 和 Qwen3-VL-8B 三种，不覆盖主表的全部十五行。API 使用的名称也不都是固定日期快照。因此当前仓库是可继续运行和扩展的评测实现，不能称为主表全部结果的一键精确复现。

### 缺失判断会改变评分分母

`compute_task_accuracy` 对每个 pair 只读取 `forward[0]` 和 `reverse[0]`。只有非空判断才计入分母；缺失 pair、空列表、空判断不会像错误答案一样计分。若只成功得到一个正确方向，另一个方向缺失，该 pair 仍会产生 100% 的有效判断准确率。

本次直接调用这个纯评分函数做了四个不涉及模型的离线检查：双向正确得到 2/2；只有一个正确方向得到 1/1；每方向两条判断、第一条错误而第二条正确时仍得到 0/2；双向空列表不贡献判断分母。最后一种情况下，`evaluated_pairs` 仍增加，`missing_pairs` 不增加，所以只看这两个字段不足以发现全部缺失方向。

四任务总体在代码中按有效判断数量合并。如果失败数不均衡，它不再等于四类准确率的等权平均。重新评测时应另外报告有效方向数、解析失败数、缺失率及处理规则，并保存原始判断。这是当前公开实现的行为，不是证明论文实验中一定出现了缺失或偏差。

### 复现仍需补齐的记录

要重做完整实验，除了固定数据和代码，还需要固定模型权重或 API 日期版本、图片预处理、输出 token 上限、温度、推理设置、失败重试及解析规则。重做测试时扩展，需要额外实现多数投票；重做 best-of-8，需要保存候选池与淘汰赛路径。当前公开代码不能独自填补这些历史记录。

数据许可还应单独阅读：项目采用 CC BY-NC 4.0，并明确标注数据用于 benchmarking、不得用于模型训练；原始来源另有各自条款。本文只做文献、公开元数据与静态实现核查，没有进行模型推理、奖励训练或下游任务重跑。[项目说明与许可](https://github.com/facebookresearch/MMRB2/tree/7ff0552cf298441af5ebbabea634b682ef04afee)

## 结果的适用范围

MMRB2 覆盖单轮图片和文字任务，不覆盖音频、视频、多轮交互，也没有把安全性或公平性作为这套分数的评测目标。任务来自已有基准，人工筛选又排除了容易区分和高度分歧的配对；评审集合与被测模型还有部分重合。这些选择共同定义了分数适用的数据分布。

论文支持的是：在这套经过人工筛选的配对上，评审器的表现随任务、候选来源和输出模态而明显变化；最终答案正确并不足以保证推理过程获得人工偏好。至于把某个评审器用于其他真实请求、用于训练或用于长期 agent 交互，需要在相应分布和流程下另外评估。
