# ComplexConstraints：多项要求的评测与强化学习奖励

一份排班表可以看起来完整，却同时存在几个问题：员工总工时不符合合同、休假日被排班、关店时没有具备资格的员工，或汇总工时与表格对不上。ComplexConstraints 将这种多条件任务拆成逐条可判定的标准，既测量模型漏掉了哪些要求，也把满足要求的比例用于强化学习。

论文最直接的训练结果是：Qwen3-4B 在保留任务上的平均标准通过率从 57.9% 提高到 73.4%，增加 15.5 个百分点；AdvancedIF 和 MultiChallenge 的任务通过率也有所提高。这里的 73.4% 不是“73.4% 的任务全部做对”，也不是公开榜单的同一项指标。公开榜单要求一题所有标准同时满足，最高记录为 40.4%。[论文 v3](https://arxiv.org/abs/2606.09118v3)

## 版本与公司参与

论文全名为 *ComplexConstraints and Beyond: Expert Rubrics for RLVR*，作者 Sushant Mehta、Liudas Panavas、Suhaas Garre、Edwin Chen 均署名 Surge AI。这是公司的基准构建与训练研究，而不只是给外部项目提供标注。

## 公开题的具体结构

ComplexConstraints 有两个互不相交的集合：公开的 75 道测试题，以及用于训练实验的 1,000 道配套题。两者都是单轮指令，并非对话历史逐渐累积要求的多轮测试。

公开测试共有 1,559 条标准，每题 10–40 条，中位数 19。标准可涉及显式与隐式要求、客观与主观判断。约束之间还可能存在依赖或条件：有些要求只有在某种情况发生时适用，有些安排必须同时满足多个人的条件。

本次按固定 Hugging Face 版本逐行核查，确有 75 个不同 ID、1,559 条非空标准，范围和中位数均与论文一致。公开集合的场景分布如下，不能与论文给出的训练类别比例混用：

| 公开题场景 | 题数 |
| --- | ---: |
| 物流、排班与活动计划 | 34 |
| 数据处理、格式与数学 | 22 |
| 工作沟通 | 10 |
| 教育计划与课程设计 | 6 |
| 健康、饮食与个人照护计划 | 1 |
| 技术设计与产品管理 | 1 |
| 创意写作 | 1 |

训练集合另按商业写作 39%、排期 22%、数据分类 11%、个人计划 10%、数值处理 7%、创意写作 6%、信息抽取 4% 描述。这些百分数相加为 99%，应视为论文给出的类别概况，不能据此恢复每类精确题数。

### 一道真实排班题的标准

公开题 `CIF-001` 要求为六名员工安排一周酒吧轮班：两位全职每周 26–34 小时，四位兼职每周 16–24 小时；周三关门；每个营业日关店时必须有全职员工；未成年兼职不能单独值班；特定员工还有限定休假日与开始、结束时间。回答需要给出安排、工时和工资汇总。

它有 19 条标准。其中工时限制要求评审器根据排班表重新相加工时，不能只相信回答末尾声称的合计；另一条单独检查合计是否算对。因此“排班超过工时限制”和“加法错误”可以分别定位。对未成年员工的标准还要求整个值班时段都有成年员工同时在场，而不只是某个交接时刻出现成人。

这些标准是可检查的业务要求，但并不都能靠字符串匹配解决。公开实现使用语言模型逐条判断，没有给这道排班题配一个已公开的约束求解器作为最终金标。[固定公开数据](https://huggingface.co/datasets/surgeai/ComplexConstraints/tree/e9625c6f635f42b72cb85a04c2be64746f945126)

## 专家怎样编写和校准标准

数据采用三阶段流程：专家从头写题并提供参考回答，围绕参考回答编写 rubric，再由第二名专家独立审查；出现分歧时交给资深审核人员裁定。作者还通过前沿模型试答调整难度。论文没有披露各阶段人数、报酬、耗时分布或标注一致性统计。

第一项设计原则是找到“最小但仍有完整意义的检查单位”。不是把一句要求拆得越碎越好。如果拆出的标准只奖励出现某个措辞，却不再检查它是否表达了正确内容，就可能让错误回答获得无意义的部分分数。论文提出这一原则，但没有给出不同拆分粒度在同一批任务上的受控数值比较。

第二项是从语境理解意图。原文的语言学习例子中，用户已经能流利地用西班牙语概述经济文章；即使用户说希望提高西班牙语，也不意味着初级词汇清单是合适回答。专家会先阅读若干模型响应，用自己的话重述用户想做什么以及目的，再编写标准。这里标准不只复述明说的词句，还包含专家对意图的解释。

第三项是校准评审器。专家先手工判定参考回答，再检查 LLM verifier 是否同意；如果不同意，检查标准是否含糊并修改。随后编辑回答，使正确结论应该翻转，再检查 verifier 是否也翻转。原文举例，一条“避免头韵”的要求将普通词组也误判为诗歌头韵，后来通过限定定义降低歧义。涉及事实的标准则尽量内嵌答案，减少评审器依赖记忆作答。

这套流程检查的是一些正反样例上的评审一致性。论文没有公布完整校准样例集、翻转成功率或人工一致性区间，因此不能将它写成“评审器已经完全可靠”。

第四项是难度与标准密度。整题全部通过可能很少发生，但逐项分数仍能区分部分进展。论文所说的“连续训练信号”应理解为比整题 0/1 更细的多档奖励；标准本身仍为二元判断，一道 20 项标准的题，其纯通过率奖励只能按 0.05 的步长变化。[§3–4](https://arxiv.org/pdf/2606.09118v3)

## 三种指标需要分别计算

设任务 $i$ 有 $m_i$ 条标准，第 $j$ 条是否满足记作 $s_{ij}\in\{0,1\}$。判断完整时，一题的标准通过率为：

$$
q_i=\frac1{m_i}\sum_{j=1}^{m_i}s_{ij}.
$$

论文表 3 的 mean per-criterion pass rate 是先对每题求比例，再对任务平均：

$$
Q=\frac1N\sum_{i=1}^N q_i.
$$

因此每个任务等权，不是直接把所有通过的标准除以全部标准数。**说明示例：**一题有 10 条、通过 10 条；另一题有 40 条、通过 20 条。任务平均为 $(1+0.5)/2=75\%$，逐条合并则为 $30/50=60\%$。二者不能互换。

整题通过率要求所有标准满足：

$$
P_{\rm all}=\frac1N\sum_{i=1}^N
\mathbf1\!\left[\sum_{j=1}^{m_i}s_{ij}=m_i\right].
$$

上一例的整题通过率只有 50%。即使每题大部分标准都对，只要每题漏一项，整题通过率仍可以是零。

论文讨论了多条件同时成立的难度。若作一个**仅用于说明的独立同分布假设**，每项通过概率为 0.95，20 项都过的概率是 $0.95^{20}\approx35.8\%$。实际约束有依赖，论文没有估计它们独立，因此不能用这个式子推算真实榜单或各条标准的通过概率。

### 用于训练的非对称奖励

式 1 进一步将标准分成必需项 $C_{\rm req}$、只加分项 $C_{\rm bonus}$、只惩罚项 $C_{\rm pen}$：

$$
r=\frac1{|C_{\rm req}|}\sum_{c\in C_{\rm req}}s_c
+\frac{\alpha}{|C_{\rm bonus}|}\sum_{c\in C_{\rm bonus}}s_c
-\frac{\beta}{|C_{\rm pen}|}\sum_{c\in C_{\rm pen}}(1-s_c),
\qquad\alpha,\beta\ge0.
$$

空集合对应的整项定义为零，避免除零。必需项按比例给基础分；加分项满足时增加奖励、未满足时不直接扣分；惩罚项在 $s_c=0$、即标准未满足时扣分，满足时不额外加分。不能把最后一项误写成惩罚 $s_c=1$。

**说明示例：**必需项通过 8/10，加分项通过 2/2，惩罚项有 1/2 未满足，取 $\alpha=0.2,\beta=0.3$，则 $r=0.8+0.2-0.15=0.85$。一般奖励不必限制在 $[0,1]$；在三类非空的通常情形下，范围可到 $[-\beta,1+\alpha]$。

但 ComplexConstraints 的指令训练**实际全部使用必需项，$\alpha=\beta=0$**，奖励就是该题标准通过比例。本文的 +15.5 个百分点结果不能作为 bonus/penalty 设计有效的实验依据。论文也把更广泛的非对称奖励研究列为后续工作。[式 1、§5.3](https://arxiv.org/pdf/2606.09118v3#page=6)

## 指令训练使用的模型、数据和预算

训练模型为 Qwen3-4B（Thinking）。1,000 道配套题按 90:10 划分，约 900 道训练、约 100 道保留测试；这份保留集与公开 75 道榜单题不是同一分母。每条标准由 GPT-5-mini 判断，构成 RLVR 奖励。作者说明外部基准没有参与训练、超参数调整、检查点选择或奖励设计。

结果来自单一训练种子，论文明确未量化种子间方差。它没有完整披露该指令训练的优化器实现、学习率、组内采样数、总更新步数、token 预算和 GPU 小时。§5.3 提及的 GRPO、解耦裁剪和每题 16 条 rollout，明确出现在 CoreCraft 的 agent 训练配置，不能自动移植成 Qwen3-4B 指令训练的配置。

| 保留集模型 | 每题标准通过比例的均值 |
| --- | ---: |
| Qwen3-4B，训练前 | 57.9% |
| Qwen3-4B，训练后 | 73.4% |
| Qwen3-235B-A22B-Instruct，对照 | 73.9% |

4B 模型提高 15.5 个百分点，训练后距较大对照为 0.5 个百分点。论文所说“约 60 倍”使用总参数量，$235/4=58.75$；235B 模型是激活约 22B 参数的 MoE，不能把这个比值解释为推理成本、训练成本或激活参数的 60 倍。

对照中的“未训练”仅表示没有接受这次 ComplexConstraints 微调，不表示 Qwen3-235B-A22B-Instruct 从未接受预训练或指令训练。这个结果限于一份保留集上的标准通过比例，没有证明两个模型在所有能力上接近。[表 3](https://arxiv.org/pdf/2606.09118v3#page=7)

## CoreCraft 结果是另一条证据线

论文引用 CoreCraft 研究，使用 GLM 4.6（总参数 355B、激活 32B）在有状态 Docker 企业环境中训练一个 epoch，采用 GRPO 和解耦裁剪，每题生成 16 条交互轨迹，GPT-5-mini 判断标准。本篇将总参数写为 355B，CoreCraft 原文 §5.1 则写 357B；两处表述不同，不据此推断换过训练模型。引用的变化为：

| 基准 | 训练前 | 训练后 | 提高 |
| --- | ---: | ---: | ---: |
| CoreCraft 保留任务 | 25.4% | 36.8% | 11.4 个百分点 |
| BFCL Parallel | 91.0% | 95.5% | 4.5 个百分点 |
| $\tau^2$-Bench Retail | 68.7% | 76.1% | 7.4 个百分点 |
| Toolathlon Pass@1 | 18.8% | 25.6% | 6.8 个百分点 |

另有 Toolathlon 连续三次都成功的 $\mathrm{Pass}^{3}$ 从 9.3% 提高到 17.6%，差 8.3 个百分点，约为原值的 1.89 倍。它衡量三次全部成功，不能写成三次至少一次成功的 pass@3。

这些数字支持另一种场景下的奖励训练与迁移；它们不扩大 ComplexConstraints 本身的公开数据量，也不是本篇独立重复 CoreCraft 实验所得。能力层级的五类错误同样引用前期轨迹分析，不能把本篇的论述当成新增的五类失败数量统计。[§5.2、5.5、表 5](https://arxiv.org/pdf/2606.09118v3)

## 哪些设计尚未通过独立消融

本篇没有分别移除专家编写、意图重述、原子性调整、正反样例校准或难度调整，再保持其他条件固定的实验。因此可以报告整套训练流程有效，却不能将 +15.5 个百分点逐项归因给某一个设计。

作者对训练前后保留样本做过定性检查，关注空洞措辞满足标准和利用评审器的冗长偏好，未看到随奖励提高而系统性下降的回答质量。没有公布该子样本数量和可统计的误判率，这不等于证明不存在 reward hacking。使用不同于策略模型的 judge，也不自动保证它们没有共同偏差。

论文还将 AdvancedIF 的 +8.4 与 RIFL 报告的 +6.7 个百分点比较，但明确指出基础模型和训练流程不同，不能当作专家 rubric 对合成 rubric 的受控胜负。引用其他论文的 rubric 差距、judge F1 和多轮性能下降，也分别属于外部证据，不是本篇新做的实验。[§5.3、5.6–7](https://arxiv.org/pdf/2606.09118v3)

## 公开代码实际如何执行

核查固定官方代码提交 `9ef1dd73d20030be94bdc399fd1c6ef7970f68d1`、数据提交 `e9625c6f635f42b72cb85a04c2be64746f945126`。数据公开且非 gated，许可 CC BY 4.0；该快照只有 README 与 75 题 CSV，没有配套 1,000 题训练集。代码提供 Inspect AI 评测 harness，未提供本文训练配置和训练后权重。[固定代码](https://github.com/surge-ai/complex-constraints/tree/9ef1dd73d20030be94bdc399fd1c6ef7970f68d1)

`task.py` 让待测模型针对一个提示生成一次完整回复，不调用工具。`dataset.py` 把 rubric 放进评分元数据，不作为用户题面发给模型。随后 `scorer.py` 对每条标准分别调用 judge：输入只有候选回答和这一条标准，**不包含原始题面**。因此标准是否自足会直接影响评审；这也是为何事实答案和必要语境需要写进标准。

当前默认 judge 是 `google/gemini-3.5-flash`，与论文训练所用 GPT-5-mini 不同。改变命令行 judge 参数可以开展新评测，但不能由默认入口直接声称重现了论文训练分数。一轮完整测试名义上需要 75 次作答、1,559 次逐项判断；重试和多次 epoch 会增加调用数，token 与费用还取决于模型和回答长度。

### 评分失败的处理会改变分母

每条 judge 输出应为含 `score` 与 `rationale` 的 JSON，schema 要求分数是字符串 `0` 或 `1`。解析失败最多额外重试四次，即总计五次；若仍失败，该项记为 unscored。

代码随后按以下规则汇总：

- 逐项比例只用已经得到评分的标准作分母；缺失项不按失败计算。
- 只要一题有任意未评分项，整题 `all_pass` 输出 NaN，排除出相应聚合，而不是记零。
- 完全没有 rubric 的任务在加载时拒绝，避免空集合被误当成全部满足。

所以前面固定 $N$ 和 $m_i$ 的公式只描述判断完整的情形。复跑时还应报告未评分项、被排除任务和重试数量，不能只看最终两个均值。

解析代码比请求 schema 更宽松：它接受可转为 Decimal 的数字或字符串，再将分数四舍五入到四位，判断是否至少为 1。本次从原文件抽取纯解析函数做离线检查，`0.99999` 会通过、`0.9999` 不通过，字符串 `2` 也会通过。规范输出应只有 0/1，但本地解析没有独立限制分数范围；这是当前实现的边界，不是论文实验已经出现这些输出的证据。这里未调用模型或运行在线评测。

### 数据加载与复现入口

官方入口为 `src/complex_constraints/task.py`，项目要求 Python 3.11 及以上、Inspect AI；运行前需要选定待测模型与 judge，并提供相应服务凭据。代码的 `hf_hub_download` 没有固定数据 revision，严格复查应另行固定本页记录的 SHA 或使用本地快照。

Hugging Face 数据卡还有旧占位信息：示例仓库名是 `USERNAME/...`，声明的 CSV 大小写与实际文件不同。实际文件为 `ComplexConstraints_benchmark_set.csv`，官方 harness 使用的是这个正确名称。复现应以固定文件和当前加载器为准，不能直接复制占位示例期待加载成功。

本次完成了全部 75 行与 1,559 条标准的结构统计、三个核心 Python 文件和离线测试源码阅读，以及解析函数边界和表格差值复算。没有重新训练 Qwen3-4B，没有下载私有训练数据，没有调用在线 judge。要重现训练结论，还需要配套训练题、拆分、完整超参数、检查点及评测运行记录；现有公开 harness 主要支持对发布基准进行新的评分。
