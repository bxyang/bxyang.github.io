# Relational Abstractions：先理清数量关系，再进行计算

论文：*Learning to Reason With Relational Abstractions*，2022。原文：[arXiv v2](https://arxiv.org/abs/2210.02615v2)。

## 1. 摘要翻译

[原文](https://arxiv.org/abs/2210.02615v2)采用 [CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/) 许可，含有禁止分发改编作品的限制。因此此处提供**摘要概述，而非完整逐句译文**。

论文研究数学应用题中的关系表达对语言模型解题的作用。作者把确定数量之间的关系与执行具体计算分开，制作新的标注数据，并比较多种组织解题步骤的方法。实验显示，这种结构在部分训练方式和任务中有帮助；直接给出正确关系计划时，模型的计算表现改善更明显。研究由此将关注点放在识别解题关系这一环节。

## 2. 研究背景与相关研究

数学应用题不仅要求会计算，还要求先判断哪些量有关、需要按什么顺序使用。模型即使能够执行乘除法，也可能把“每件价格”和“商品总数”的关系理解错，从一开始就列错计算步骤。（原文 §1—§2。）

Introduction 和 Related Work 回顾了几类数学推理方法：直接从题目生成答案；生成中间算式或程序；用包含自然语言步骤的解答训练模型；以及通过思维链提示、验证器和多数投票挑选更可靠的答案。GSM8K、MATH、Minerva 等工作体现了这些方向，但普通解答往往把具体数字、解释语句和关系判断混在一起，不便单独研究模型究竟学会了哪一部分。（原文 §1、§3。）

本文作者提出，把关系从数值中抽离出来，可以更清楚地观察解题过程。以卖鸡蛋为例，“可卖的数量等于产蛋量减去自用数量”“收入取决于可卖数量和单价”都是不依赖特定数字的关系；换一组数量，这个计划仍可使用。

论文沿用逐步求解的方向，但新增了能够明确区分**关系计划**与**具体计算**的数据表达，再通过真实应用题与合成任务比较它们的作用。（原文 §2—§3。）

## 3. 核心贡献

### 核心要解决的问题

作者要弄清楚，显式学习题目中的抽象关系是否有助于多步数学推理，以及模型的主要困难是在制定计算计划，还是执行计划中的数值运算。

### 核心方案

第一项工作是 **GSM8K-R**：在已有小学数学应用题数据 GSM8K 上增加人工关系标注。例如，一道题涉及每天产蛋、早餐消耗、烘焙消耗和出售收入。关系标注先说明如何得到剩余鸡蛋，再说明如何得到收入，数值运算则单独记录。这样，同一道题可以被改写成不同的训练序列。（原文 §2、§4.1、表 2。）

作者比较四种安排：只生成数值运算；先写完整关系计划再计算；每写一步关系就紧接着计算；让同一模型分别学习关系生成和数值计算两种任务，测试时只要求计算。这些对比用来区分关系表达在训练阶段的作用，以及在实际求解过程中持续使用关系的作用。（原文图 1。）

第二项工作是 **合成单位换算任务**。系统得到一组单位之间的换算关系，需要找到从起点单位到目标单位的路径并逐步计算。这个环境减少了自然语言表达带来的干扰，使作者能够更集中地观察关系选择和运算能力。（原文 §4.2。）

### 结论

实验结果需要按任务区分。在 GSM8K-R 上，关系学习作为辅助任务能带来一定提升，但让模型自己先生成关系计划，并不总是更好。**如果直接提供正确的关系计划，准确率会显著提高**；这说明模型在已知如何解题时，能够完成不少原本答错的问题，但不等于它已经能够自主找到那些计划。（原文 §4.1、表 1、表 3。）

在合成单位换算任务中，把关系步骤与数值步骤交替生成的优势更明显，尤其在需要更多步骤时。作者据此认为，正确识别关系是多步推理的重要环节，而训练数据如何组织这些关系，也会影响模型能否利用它们。（原文 §4.2、§5。）

这项研究提供了关系标注数据和一种分析解题过程的方法。其结果支持继续研究“模型如何识别正确关系”，但尚不能证明某一种关系模板能普遍提高所有数学任务，也没有消除从自然语言题目中提取正确计划的困难。
