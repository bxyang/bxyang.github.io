# GAIA：通用助手综合任务

拿到一份表格，按指定条件选出商品，再算出销售总额，对人而言可以是一项普通工作。对 AI 助手而言，它需要先理解附件、找到合适的读取工具、选对列和行，最后按要求返回一个数字。GAIA 把这类任务做成了 466 道有明确答案的问题，评测模型能否把检索、文件处理、多模态理解和推理连起来。论文在 2023 年的实验中报告，带插件的 GPT-4 总体正确率约为 15%，人工回答约为 92%；这两项结果的生成方式和统计分母并不完全相同，下面分别展开。

## 用短答案检验一段完整工作流程

GAIA 的输入是一道自然语言问题，部分问题附带文件；输出是一个简短字符串、数字或列表。中间可以搜索网页、打开文档、看图、听音频、运行代码，但最终只根据答案是否匹配评分。论文没有提出新的训练损失，也没有规定一种统一的 agent 架构。

例如，论文图 2 展示了一个 Excel 附件任务：助手读取表格，选出问题指定的食物商品而排除饮料，再计算总销售额，最后输出数字。这里同时包含文件访问、表格结构理解、条件选择和计算。即使模型记得相关领域知识，也不能直接替代对具体附件的处理。该案例是论文公开的示例；它没有说明模型在所有表格问题上都能采用同一段程序。（原文 §2、图 2。）

作者选择短答案，是为了减少开放式答案评审中的歧义。一个答案可以直接判对错，而一篇长报告通常还需要人或另一个模型评价。不过，这也意味着 GAIA 不给中间正确步骤部分分数，不检验搜索过程是否高效，也不直接评价推理文字的可信度。错误路线偶然得到正确答案，仍可能得分；正确路线末尾格式不符合评分规则，也可能失分。

任务允许访问网络信息和本地计算，但没有要求向外部网站上传内容、发表评论或替用户预约。论文讨论的是获取和处理信息的助手能力，不是执行所有现实世界事务的完整权限系统。（原文 §3.1、§5。）

## 466 道题的能力分布与难度

作者希望题目对人而言概念清楚，但需要组合若干操作。难度由人工解题路径估计，分为三个等级：

| 等级 | 论文的概括性标准 | 全集题数 |
| --- | --- | ---: |
| Level 1 | 通常不需要工具，或只需一种工具；一般不超过 5 个步骤 | 146 |
| Level 2 | 通常需要约 5–10 个步骤，组合多种工具 | 245 |
| Level 3 | 可能需要很长的操作序列，使用多种工具与外部信息 | 75 |

这些是宽松的划分规则，不是运行时的最大动作预算。附录表 1 就有一个标为 Level 1、人工记录为 8 步的例子。模型也可能利用已有知识缩短路径，或因搜索失败多走很多步。因此，不能把 Level 2 的“5–10 步”写成评测器强制在第 10 步终止。（原文 §3.2、图 3、附录表 1。）

能力标签同样来自标注人员解题时使用的工具。466 题中，355 题涉及网页浏览，154 题涉及代码或计算，138 题涉及多模态，129 题涉及文件处理，32 题没有这些工具需求。标签可以重叠，不能相加作为题目总数。“代码”标签也包括计算器、解码等操作，不表示全部 154 题都要求生成程序；使用街景的题目可以同时属于网页和多模态任务。（原文图 3、附录 C。）

附录图 6 列出 17 种附件格式，以 XLSX、PNG、PDF 和 TXT 为主，另有音频、压缩包、演示文件及专门格式。图中的格式计数合计为 109，和“129 题需要文件处理”不是同一个口径：文件处理能力并不限于题目自带附件，也可能涉及网上取得的文件。本文没有访问受限题库，因此不把这两组统计扩写成当前全部数据文件的逐项审计结果。

## 出题、独立复核与人工参考分数

### 题目从人工构造开始

研究团队先提供示例，再由标注人员制作新的问题，要求不是对示例作简单替换。题目应有明确、稳定、能验证的答案，所需资料可以来自相对稳定的网站，也可以放入附件。作者希望答案不能在网上原样直接搜到，而要经过信息组合、计算或其他处理。

时间相关问题需要指定日期或版本，附件应足以支持解题。创建者同时提交答案、解题步骤、所用工具和耗时。这些记录帮助判断题目是否可解、属于哪个等级，并为后续复核提供依据。网站的机器人访问限制也是后续检查内容之一。（原文 §3.3–3.4、附录 D。）

这种设计降低了简单背诵整道问答的机会，但不是污染检测证明。模型仍可在预训练中见过所需的中间知识，公开后的题目也可能被传播。网站内容与工具接口还会变化，使同一道题在不同时间不一定具有相同的访问条件。

### 每道新题由另外两人验证

验证者不是原出题者。两名新标注人员分别尝试解题，再与原答案对照：双方一致时可以确认；只有一人一致时，还要判断另一人的失败是否属于人为错误；题目本身有问题则修订或丢弃。

附录表 3 报告了 623 道新构造题目的验证情况，两次独立验证对应 1,246 条标注记录：

| 两名验证者与原答案的关系 | 占比 |
| --- | ---: |
| 两人都与原答案一致 | 55% |
| 只有一人与原答案一致 | 27% |
| 两人都不一致 | 18% |
| 最终被判为有效的题目 | 68% |

68% 不是把前两行直接相加。只有一人答对的题目，还需要区分题目问题和验证者错误。按等级统计的有效率为 Level 1 的 75%、Level 2 的 68%、Level 3 的 47%。这反映了出题和验题中的筛选，不能直接解释为模型能力差异。（原文附录 D、表 3。）

论文没有给出从 623 道候选到最终 466 道题的完整逐项流转账目，包括修订、保留和种子题各有多少。因此不能用 $623\times68\%$ 反推最终数据集数量。

### 92% 是筛选后有效题目上的人工回答表现

论文的人工正确率，来自新验证者在被认定为有效的题目上的回答。它不是 623 道候选题全部 1,246 次尝试的直接准确率，也不是原出题者复述自己答案的成绩。按难度报告为 93.9%、91.8%、87.3%，摘要概括为约 92%。

有效题目的筛选本身使用了这些验证信息，所以这不是另请一组人、在完全独立的测试集上进行的盲测。论文没有公开足以还原每个百分比的整数分子分母，本文保留其原报告口径，不重新拼出一个“精确的人类总分”。

标注人员位于美国，题目为英文；这不是随机抽样的全球普通人群。作者还估计，创建、验证并在需要时修复一道题，总共约需两个人工小时。这是数据制作劳动量，不能与下面“人类解一道题用几分钟”的时间表混为一谈。（原文 §3.4、附录 D、表 4。）

## 评分器实际如何判定答案

论文使用经过有限规范化的答案匹配。当前官方排行榜公开的 `scorer.py` 进一步给出了可核对的分支。设第 $i$ 题的提交答案为 $a_i$、标准答案为 $y_i$，评分函数为 $s(a_i,y_i)\in\{0,1\}$，题集 $D$ 的正确率为：

$$
\operatorname{Accuracy}(D)=\frac{100}{|D|}\sum_{i\in D}s(a_i,y_i).
$$

每题权重相同，分等级成绩则只在该等级内取平均。总体成绩按题目数加权，不是三个等级百分比的简单平均。以下细节依据官方 Space 固定版本的实现，不意味着其每一行代码都已证明与 2023 年实验完全相同。

### 数字：去掉部分符号后精确相等

如果标准答案可直接转换为浮点数，代码先从模型输出去掉美元符号、百分号和逗号，再转为浮点数并比较相等。不设近似误差容限，也不做一般单位换算。

例如，标准答案是 `1000` 时，输出 `1,000` 可以通过；标准答案是 `4.6` 时，`4.6%` 也通过，但 `0.046` 不通过。后者说明评分器删除百分号，不会自动进行百分比与小数的换算。浮点近似值也不是普遍允许的。

### 列表：保留顺序，逐项比较

如果标准答案不能直接转成数字、但包含逗号或分号，就按这两种分隔符拆成列表。预测与标准列表长度必须相同，并按位置逐项比较，不先排序。

数值项使用数字规则；文字项去掉空白并忽略大小写，但保留标点。因此 `White, Orange` 与 `white,orange` 一致，换成 `orange,white` 则不一致。列表内部文字的标点处理，比单个字符串更严格。

### 单个字符串：规范化范围有限

其余答案会删除空白、转换为小写，并删除 Python `string.punctuation` 定义的标点。它不会判断同义词，也不会普遍接受简称、增补说明或另一种语言的相同含义。

论文统一提示模型把简短结果放在 `FINAL ANSWER:` 后，并对数字、字符串和列表作格式要求。但当前 `question_scorer` 本身不从长回答里抽取该字段；提交方需要先生成合适的 `model_answer`。本文只用自拟字符串离线运行了评分函数，核对了上述边界，没有提交或评测任何真实题目。[固定版本评分器](https://huggingface.co/spaces/gaia-benchmark/leaderboard/blob/9f133d71362e77b3539f1514f31b9c101a545fec/scorer.py)

## 2023 年基线的运行设置

论文比较了 GPT-4、GPT-4 Turbo、以 GPT-4 为基础的 AutoGPT、带插件的 GPT-4、搜索引擎和人工回答。

直接模型基线通过 API 回答问题；带插件的 GPT-4 使用当时的 ChatGPT 界面。研究人员按问题选择 Advanced Data Analysis，或至多三个第三方插件。作者把这种选择称为 oracle 设置，指研究人员预先选择看起来合适的工具，并不是把标准答案提供给模型。它也不等于一个完全自主选择工具的 agent。

AutoGPT 固定到论文脚注给出的提交 `ed172dec1947466cc0942abf75bb77b027cd433d`。该提交固定了软件版本，但论文没有完整列出所有模型检查点、温度、token 上限、工具调用上限以及逐题插件选择，不能仅凭模型名称和一个提交号恢复全部实验条件。

搜索引擎基线由人输入整道问题，查看第一页结果并尝试得到答案。它不是多轮改写查询、逐个访问来源的搜索 agent。这个定义解释了为什么其成绩不能代表“人类利用网络能达到的上限”。

能够重复的 API 实验运行三次，表中报告均值；插件等设置没有同样的重复统计。表 4 的 `±` 数值没有清楚定义为标准差或置信区间，本文按原样保留。论文也没有给所有系统设置相同的 token、调用次数或美元预算，因此以下比较不是等计算成本下的工具消融。（原文 §4、附录 D.1。）

## 主要结果与时间的分母

表中为正确率，单位为 %，越高越好。模型名均指论文当时的系统，不是同名产品的当前版本。

| 系统 | Level 1 | Level 2 | Level 3 |
| --- | ---: | ---: | ---: |
| GPT-4 | 9.1 ± 2.5 | 2.6 ± 0.6 | 0 |
| GPT-4 Turbo | 13.0 ± 2.1 | 5.5 ± 1.4 | 0 |
| AutoGPT + GPT-4 | 14.4 | 0.4 | 0 |
| GPT-4 + 插件 | 30.3 | 9.7 | 0 |
| 搜索引擎基线 | 7.4 | 0 | 0 |
| 人工回答 | 93.9 | 91.8 | 87.3 |

来源：原文附录表 4；正式版保留相同的关键结果。

插件系统相对直接 GPT-4，在 Level 1 和 Level 2 分别高 21.2 和 7.1 个百分点。用表中经过取整的等级成绩和 146、245、75 的题量加权，可得到约 14.59%，与摘要“约 15%”一致；这只是依据表格的复算，不是新的完整精度实验。

AutoGPT 的 Level 1 分数高于直接 GPT-4，Level 2 则低于直接 GPT-4。正文对 AutoGPT 的概括不能替代表格中的具体方向，更不能由此得出“agent 在所有难度都更差”。所有这些模型在 Level 3 的得分均为零，表示该次实验未解出此级题目，不代表后来的工具系统也只能达到零分。

论文还记录了回答耗时，单位为分钟：

| 系统 | Level 1 | Level 2 | Level 3 |
| --- | ---: | ---: | ---: |
| GPT-4 | 0.19 | 0.15 | N.A. |
| GPT-4 Turbo | 0.24 | 0.12 | N.A. |
| AutoGPT + GPT-4 | 7.6 | 11.7 | N.A. |
| GPT-4 + 插件 | 0.65 | 0.53 | N.A. |
| 搜索引擎基线 | 7.4 | N.A. | N.A. |
| 人工回答 | 6.8 | 10.5 | 17.7 |

这些耗时不能作为统一硬件上的速度排名。API 耗时来自 20 道题的一次性平均测量；人工和界面工具使用的计时方式不同，插件人工选择等开销也没有完整说明。N.A. 表示没有报告，不能替换为零。论文尤其没有证明更快返回答案就具有更高的有效工作效率。（原文附录 D.1、表 4。）

## 工具成功案例与失败分析的边界

附录案例展示了几种不同情况。一个问题需要从论文中定位具体事实，不能浏览时模型未能给出答案，开启网页工具后才找到资料；另一个电影细节问题通过迭代修改查询得到正确答案。后者依赖当时的插件版本，作者明确指出版本变化后不能原样复现。

还有需要空间关系推理的例子，即使输入信息可用，模型仍因推导错误给出错误的颜色组合。工具能提供信息，并不自动保证组合这些信息的推理正确。（原文附录 D.1，图 9–11。）

这些是定性案例，没有附带覆盖全部失败的计数表。论文没有把失败统一拆成检索、感知、规划、计算和格式错误后统计比例，也没有逐项固定其他条件、只移除某个工具的受控消融。因此，可以说实验揭示了多步工具使用和推理中的困难，不能进一步给各类错误编造发生率，或把插件系统的提升全部归因于某一个组件。

GAIA 的覆盖也有明确边界：英文、人工构造、短答案和有限的外部操作。它不直接测试持续数天的工作、多人协作、长文质量或带有多个合理答案的决策。关于通用智能的论述是作者对评测方向的主张，466 道题本身不能建立“达到某个分数便等同于通用智能”的判定标准。

## 当前公开资源与论文版本的差异

本次核查固定了以下官方资源：

| 资源 | 核查版本与范围 |
| --- | --- |
| GAIA 数据仓库 | `682dd723ee1e1697e00360edccf2366dc8418dd9`；核对公开 API 元数据和网页说明，没有取得受限数据访问权限 |
| 官方排行榜 Space | `9f133d71362e77b3539f1514f31b9c101a545fec`；读取 `app.py`、`scorer.py`、`content.py`、依赖与 Space 配置 |
| AutoGPT 基线 | 论文固定 `ed172dec1947466cc0942abf75bb77b027cd433d`；本次没有复跑该基线 |

论文写的是 166 道题公开答案、300 道题保留答案。当前 Space 则声明 validation 为 165 题、test 为 301 题，等级数量分别为 53/86/26 和 93/159/49。两者总量仍为 466，各等级合计也仍是 146/245/75，但验证与测试划分已经不完全相同。公开材料没有在本次核查范围内解释这一题调整的原因，不能把当前分母直接套回历史实验。

当前数据说明还记录了 2025 年 10 月的 Parquet 格式更新，以支持不再运行自定义加载脚本的 `datasets` 4.x。字段包括任务 ID、问题、等级、最终答案、文件名、相对文件路径和标注元数据；全量与分等级元数据文件分开提供。旧教程里的加载方式和文件组织不能未经检查地用于这个快照。[官方数据说明](https://huggingface.co/datasets/gaia-benchmark/GAIA)

数据集属于需要申请访问的 gated 数据。公开可见的网页和 API 元数据，不代表已经获准下载问题、附件或答案；本次未登录同意条款，也未通过镜像绕过限制。对固定版本文件的未认证请求返回 401 后没有继续尝试下载题库。因而本文的 466 题分布来自论文，当前 165/301 来自公开应用配置，都不冒充对实际受限记录的逐行核验。

官方 Space 还加载带令牌访问的内部金标数据。获准访问公开数据集，与拥有排行榜内部测试答案权限是两件事。当前说明将验证集排行榜视为已缺乏比较意义，并保留测试集提交通道；排行榜展示最佳提交与论文 API 三次均值也不是同一统计方式。[官方排行榜及源码](https://huggingface.co/spaces/gaia-benchmark/leaderboard/tree/9f133d71362e77b3539f1514f31b9c101a545fec)

## 复现所需准备与本次完成范围

当前提交接口接收 JSONL，核心字段为 `task_id` 和 `model_answer`，可以附带 `reasoning_trace`。应用检查任务 ID、重复题目和各等级题量，再对答案逐题评分；不能只挑容易的题目提交后按这部分结果计算完整测试成绩。推理轨迹不是上述准确率公式的评分对象。

重建实验需要先取得允许使用的数据，固定题目与附件版本，再选择模型版本、浏览器和文件处理工具。还需要主动记录论文没有完整披露的温度、token 限额、动作上限、重试、超时、查询时间和费用，保存每题最终答案，并区分一次运行、重复均值和挑选最佳运行。当前评分器可用于检查允许使用的本地答案，但完整运行官方应用还需要内部数据权限。

公开依赖文件中部分库没有锁定精确版本，历史 ChatGPT 插件也已变化。固定 Space 提交只能固定这部分应用代码，不能恢复 2023 年的完整工具环境。

本次完成了 24 页原文及全部附录阅读、关键图表视觉核对、正式版关键章节对照和官方评分代码静态检查，并用 8 个自拟输入检查数字、列表、字符串的评分行为。没有访问受限题目、调用模型、运行 AutoGPT、提交排行榜或复现论文成绩。全文阅读和这些离线检查支持对方法与口径的解释，不构成对原始模型结果的独立重复实验。
