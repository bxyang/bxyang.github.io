# ALCE：带引用回答的自动评测

回答末尾出现了来源编号，并不代表来源支持回答。ALCE 把这件事拆成三个可以分别检查的环节：回答是否通顺、是否覆盖问题需要的信息、每句话是否得到所引资料的支持。作者在三类问答任务上比较检索与生成策略，发现生成前读取证据通常比生成后补引用更容易得到有依据的回答；但检索到答案、把答案写出来和正确引用，仍然是不同的能力。论文同时用人工标注检验自动评分，其中 Surge AI 提供了人工评估支持。

## 从一段带来源的回答开始

可以用一个自拟例子说明任务。用户问某座图书馆何时建立、后来何时搬迁。检索得到的资料 A 记载建立年份，资料 B 记载搬迁年份。模型需要把两项信息写成自然语言，并在相应位置引用 A、B。

这里可能出现几种不同结果：两个年份都写对，但引用指向无关资料；引用都支持句子，却只回答建立年份；或者照抄一段有出处的文字，但没有回答用户的问题。ALCE 分别检查这些情况，因此没有用一个“是否附带引用”的判断代替完整评价。

输入是问题 $q$ 和文本语料库 $D$。输出 $S$ 被切分为陈述 $s_1,\ldots,s_n$，每条陈述关联引用列表 $C_i$。ASQA 和 ELI5 以句子为单位，QAMPARI 则以答案列表中的实体为单位。引用指向约 100 词的资料片段，而非整张网页；编号如 `[1][2]` 对应该次检索提供的片段。论文设置每条陈述最多三条引用。

这与普通检索增强生成的差别在于，模型需要明确指出哪些证据支持哪些陈述。仅把资料放进上下文，并不能保证生成内容忠实于资料。ALCE 的主实验研究提示与检索流程，没有训练一种新的引用生成模型。[§2、§4，第 2—6 页](https://arxiv.org/pdf/2305.14627v2)

## 三类问答任务与公开数据

### 问题类型决定正确性的判断方式

| 数据集 | 问题与答案形式 | 检索语料 | 主要正确性指标 |
| --- | --- | --- | --- |
| ASQA | 含歧义的问题，需要覆盖不同解释下的短答案，并组织成长回答 | 2018-12-20 Wikipedia 快照，约 2,100 万个片段 | 短答案精确匹配召回率 |
| QAMPARI | 一个问题对应多个实体，例如符合条件的作品列表 | 同一 Wikipedia 快照 | 实体精确率与 recall-5 |
| ELI5 | Reddit “Explain Like I’m Five” 中的解释性问题 | Sphere，约 8.99 亿个片段，来自过滤后的 Common Crawl | 参考主张召回率 |

ASQA 的参考长答案平均 65 词，QAMPARI 每题平均约 13 个答案，ELI5 的参考答案平均 131 词。Sphere 检索语料排除 Reddit 网页，减少直接检索到原回答的机会；这不等于检查过被测语言模型的训练数据污染。

论文 §2 称从三个数据集的开发集各随机选择 1,000 题。没有发布带逐句引用监督的 ALCE 训练集；提示中的少量示范与后文 FiD 使用的原始 ASQA 训练集，需要同这一点区分。[表 1、§2、附录 B，第 2—3、14 页](https://arxiv.org/pdf/2305.14627v2)

## 正确性评分先检查答案覆盖

### ASQA：不同解释下的答案是否出现

设某题有 $m$ 组短答案，每组 $A_j$ 包含同一答案的不同别名。将文本转为小写并规范化标点、冠词和空白后，检查某个别名是否作为子串出现在生成文本中：

$$
\operatorname{EMRecall}(S)=\frac{1}{m}\sum_{j=1}^{m}
\mathbf 1\{\exists a\in A_j:\operatorname{norm}(a)\subseteq\operatorname{norm}(S)\}.
$$

它奖励覆盖多个正确答案，但不直接惩罚回答中额外写出的错误内容。子串匹配也不是语义验证，不能独立判断答案周围是否出现否定或错误关系。论文正是把它与引用支持评分一起使用。[§3.2、附录 C](https://arxiv.org/pdf/2305.14627v2)

### QAMPARI：正确列表项与 recall-5

预测由逗号分隔，每个项目与标准答案及其别名精确匹配。正确性精确率是预测项目中命中标准答案的比例；普通召回率是标准答案组中被覆盖的比例。

设标准答案组数为 $g$，命中组数为 $h$，代码中的 recall-5 为：

$$
R_5=\frac{\min(5,h)}{\min(5,g)}.
$$

例如有 13 个标准答案，模型列出四项、其中三项正确，则精确率为 $3/4=75\%$，普通召回率为 $3/13\approx23.1\%$，recall-5 为 $3/5=60\%$。这个例子用于说明公式，不是论文样本。命中至少五项就获得满分 recall-5，但乱列大量项目仍会降低精确率。标准答案不到五项时，分母采用实际答案数。

实现按预测列表逐项计算精确率、按标准答案组计算召回率，没有先对预测列表去重。因此，复现时还需保留其列表解析规则，不能默认使用另一套集合 F1。[§3.2；官方 `compute_qampari_f1`](https://github.com/princeton-nlp/ALCE/blob/246c476a4edfc564266b7346b6e29ef4861ae937/eval.py)

### ELI5：从参考答案提取三条主张

解释性问题没有统一的短实体答案。作者用 `text-davinci-003` 把参考答案拆为三条主张，提示中包含三个由研究者手写主张的训练集示范。评分时以模型回答为前提、每条参考主张为待检验命题，调用 TRUE 自然语言推断模型：

$$
\operatorname{ClaimRecall}(S)=\frac{1}{|G|}\sum_{g\in G}\phi(S,g),
$$

其中 $G$ 是该题参考主张，$\phi(p,h)=1$ 表示推断模型认为前提 $p$ 支持命题 $h$。这里是在问“回答覆盖了多少参考信息”，后面的引用评分则反过来问“来源是否支持回答”。

附录 A 做了两项人工检查：随机查看 40 个参考答案及其 120 条自动主张，其中 112 条与问题相关且忠实于参考答案，即 93.33%；另检查相同问题的 40 个生成回答与主张，共 120 个推断判断，TRUE 与人工标签的一致准确率为 80.0%。两项比例分别衡量主张生成质量和推断判断质量，不能混用。

参考主张来自原始回答，不是覆盖该问题所有合理解释的完整事实清单。生成内容可能有用却没有命中这三条主张；反过来，参考答案自身有错误时，忠实于参考也不能保证现实正确。附录示例同时展示了这一评估边界。[附录 A、表 22、表 30—31，第 14、21、23—24 页](https://arxiv.org/pdf/2305.14627v2)

## 引用评分检查来源和陈述之间的关系

### 引用召回率以陈述为分母

TRUE 是基于 T5-11B 的自然语言推断模型，公开检查点为 `google/t5_xxl_true_nli_mixture`。输入包括前提和待验证命题，输出 `1` 才计为支持。引用证据以标题加正文的形式组织，多条引用用换行连接。

对第 $i$ 条陈述，定义：

$$
r_i=\mathbf 1\{C_i\ne\varnothing\}\cdot
\phi\bigl(\operatorname{concat}(C_i),s_i\bigr),
\qquad R_{\mathrm{cite}}(S)=\frac{1}{n}\sum_{i=1}^{n}r_i.
$$

即使一句话里只有一小部分没有来源支持，该句也应计零；多条资料可以共同支持一个句子，不要求每条资料单独涵盖整句。没有引用的句子也计零。

指标先在每个回答内按句子平均，再对回答平均。它不是全数据集所有句子的统一微平均，也不是“整篇回答每句话都得到支持”的通过率。因此，ELI5 的 51.1 分应理解为这种逐回答平均的句子支持比例，不能换写成“51.1% 的回答完全有据可查”。论文摘要中“约一半生成缺乏完整引用支持”的概括，不能替代具体分母。[§3.3、图 3，第 4—5 页](https://arxiv.org/pdf/2305.14627v2)

### 引用精确率不要求最小引用集合

一条资料可能单独支持整句，也可能必须与另一条资料合起来才支持整句。ALCE 要排除的是无关引用，而不是所有冗余引用。

对引用 $c_{i,j}$，定义无关标记：

$$
u_{i,j}=\mathbf 1\{\phi(c_{i,j},s_i)=0\}
\cdot\mathbf 1\{\phi(\operatorname{concat}(C_i\setminus\{c_{i,j}\}),s_i)=1\}.
$$

只有当它单独不能支持整句，而且去掉它之后剩余证据仍能支持整句时，算法才把它判为无关。该引用的分数为 $p_{i,j}=r_i(1-u_{i,j})$；一个回答的引用精确率为：

$$
P_{\mathrm{cite}}(S)=
\frac{\sum_i\sum_j p_{i,j}}{\sum_i|C_i|}.
$$

在有效引用的通常情形下，分母是回答中的引用出现次数，之后再对回答平均。没有引用时，公开实现将精确率记为零。只要一句话没有通过联合支持检验，它的所有引用精确率也为零。

例如，自拟陈述包含建立和搬迁两个年份，A 只支持前者，B 只支持后者。A、B 合起来支持整句，而且去掉任一条都会失去完整支持，两条都可以得分。若 C 独立也支持整句，增加 C 不会因为冗余而自动失分。但若另一条 D 仅重复 A 的部分信息，A、B 已足以支持整句，D 可能被规则误判为无关。这就是附录 E 讨论的“部分支持”缺口。

人工评估可以直接选择完全支持、部分支持或不支持。自动 TRUE 判断主要区分完整支持与否，二者能力不同。原文完整提示要求尽量使用充分且最小的引用子集，但自动精确率本身并不严格惩罚所有多余引用。[§3.3、附录 E—F](https://arxiv.org/pdf/2305.14627v2)

### 引用可靠不等于现实世界事实正确

这里的推断关系以给定资料为依据，没有独立验证资料的真实性、时间有效性或来源权威性。一段过时资料可能充分支持一句过时陈述。高引用分表示可追溯、与来源一致的程度，不能单独解释为事实正确率。

ALCE 也没有将三类指标合成为一个固定总分。流畅性使用 MAUVE，比较模型和人类答案的文本分布；公开实现将问题与答案拼接后截到前 100 词，再用 GPT-2-large 提取特征。作者主要将其用作异常检查，因为 MAUVE 对长度和风格敏感。QAMPARI 输出实体列表，不报告这项流畅性指标。[§3.1、附录 C](https://arxiv.org/pdf/2305.14627v2)

## 生成流程的几种变体

全部策略以检索、证据组织和生成后处理为基本环节。Wikipedia 使用 GTR 或 DPR；Sphere 使用 BM25。每题先取最多 100 个候选片段。

| 方法 | 模型实际看到什么 | 额外工作及限制 |
| --- | --- | --- |
| VANILLA | 最靠前的若干完整片段，以及两个带引用的示范 | 2K 上下文通常放三段，4K 通常放五段 |
| SUMM | 问题相关的片段摘要 | 由 ChatGPT 预先生成，过滤返回“不相关”的片段；主设置放十段 |
| SNIPPET | 从资料抽出的相关片段，必要时消解指代 | 同样需要预处理；并非保证逐字不改动的机械截取 |
| INTERACT | 先看摘要或摘录，可以请求完整片段 | 每次最多查看三段，查看后强制输出，完整片段只保留一轮 |
| INLINE SEARCH | 在生成中提出新检索词，再读取一个结果 | 只在原始 top-100 候选内重检索，不重新搜索整个语料库 |
| CLOSED BOOK + POST CITE | 先不看资料生成答案，再为每句找最近似片段 | 后处理用 GTR 匹配；并不修改原陈述来适应证据 |
| RERANK | 对同题生成四个候选，再按自动引用召回分选择 | 增加生成和验证开销，不能作为等调用预算比较 |

SUMM 的提示要求摘要不超过 50 词，并保留重要日期、数字和名字；在 ASQA 上，摘要或摘录平均将片段缩短约六倍。这样可以放入更多来源，也可能丢失支持一句话所需的条件。

INTERACT 的动作是检查资料、输出、结束；INLINE SEARCH 将检查编号改为产生检索词。后者调用 GTR 在候选集合中找最匹配的片段，读取后下一轮删除该完整片段以节省上下文。它提供的是受限候选内的交互式访问能力，没有探索实时网页的完整浏览流程。[§4、表 23—29，第 5—6、21—22 页](https://arxiv.org/pdf/2305.14627v2)

## 历史模型、采样与预算

主模型 ChatGPT 固定为 `gpt-3.5-turbo-0301`，上下文 4K；长上下文对照为 `gpt-3.5-turbo-16k-0613` 和 `gpt-4-0613`，分别为 16K 和 8K。开放模型包括 LLaMA、Alpaca、Vicuna、Oasst、LLaMA-2-Chat 和 Stable Beluga 2，结果对应 2023 年的检查点，不能读作当前产品排名。

OpenAI 模型采用温度 0.5 的采样；开放模型使用 nucleus sampling，`top_p=0.95`，所核对的 LLaMA 配置温度为 1.0。每次运行从四个示范中抽取两个。附录 C 概括为多数设置重复三次，附录 G.6 给出更完整的例外：ChatGPT RERANK、ChatGPT-16K 和 GPT-4 各只有一次运行。表 19—21 括号内是跨运行标准差，破折号不是零方差。

公开 `run.py` 默认每次生成最多 300 个新 token，同时受剩余上下文限制；交互模式默认最多十个动作。因此，交互调用次数与一次性生成不同，四候选重排又会增加约四次候选生成及额外 NLI 检查。摘要生成也有独立成本。论文没有提供覆盖全部策略的统一等 token 或等费用实验。[§5、附录 C、G.6](https://arxiv.org/pdf/2305.14627v2) · [固定生成入口](https://github.com/princeton-nlp/ALCE/blob/246c476a4edfc564266b7346b6e29ef4861ae937/run.py)

| CLOSED BOOK + POST CITE | 38.3 | 26.7 | 26.7 |

闭卷生成后补来源的答案覆盖率距离 VANILLA 只有 2.1 分，但引用召回少 46.9 个百分点。原文将后者概括为约 47%，这里明确是绝对分数差，不是相对下降 47%。后补最近似来源并不保证该来源真正支持已经写出的陈述。

SUMM 将答案覆盖提高 2.9 分，却使引用精确率下降 10.7 分。它同时改变了材料数量、长度和内容完整性，不能单独归因于“摘要”或“检索更多”。重排使引用召回提高 11.2 分，答案覆盖基本不变；后面的人工评估检查这种提升是否仅来自同一个评分器的偏好。[表 4，第 6 页](https://arxiv.org/pdf/2305.14627v2)

### QAMPARI：列出更多正确实体仍可能缺少对应证据

| ChatGPT 方法 | recall-5 | 实体精确率 | 引用召回 | 引用精确率 |
| --- | ---: | ---: | ---: | ---: |
| VANILLA | 20.8 | 20.8 | 20.5 | 20.9 |
| RERANK | 22.8 | 21.4 | 21.2 | 21.4 |
| SUMM | 23.6 | 21.2 | 23.6 | 25.7 |
| SNIPPET | 24.5 | 21.5 | 22.9 | 24.9 |
| CLOSED BOOK + POST CITE | 32.9 | 19.8 | 10.0 | 10.0 |

闭卷方法的 recall-5 最高，但平均输出 17 项，VANILLA 约五项。更长的答案列表更可能覆盖若干正确实体，也更可能带入不匹配的答案。因而需要同时看精确率和引用支持，不能只依据 32.9 分判断整体更好。这个任务上重排的引用提升也远小于 ASQA。[表 5、20，第 7、19 页](https://arxiv.org/pdf/2305.14627v2)

### ELI5：覆盖参考主张和支持生成句子是两个方向

| ChatGPT 方法 | 主张召回 | 引用召回 | 引用精确率 |
| --- | ---: | ---: | ---: |
| VANILLA | 12.0 | 51.1 | 50.0 |
| RERANK | 11.4 | 69.3 | 67.8 |
| SUMM | 12.5 | 51.5 | 48.2 |
| SNIPPET | 14.3 | 50.4 | 45.0 |
| SNIPPET + INTERACT | 13.3 | 47.8 | 45.0 |
| INLINE SEARCH | 13.4 | 45.6 | 43.7 |
| CLOSED BOOK + POST CITE | 18.6 | 15.5 | 15.5 |

闭卷回答覆盖更多参考主张，却很难在候选资料中补到充分来源。重排提高引用召回 18.2 分，但主张召回没有随之提高。这两个结果说明，筛出更容易由资料支持的文本，与覆盖参考答案中的所有信息并不是同一目标。[表 6，第 7 页](https://arxiv.org/pdf/2305.14627v2)

正文与附录存在少量不一致。比如表 4 的 ASQA SUMM 引用召回为 68.9，表 19 为 68.8；闭卷 EM 召回分别为 38.3、38.2。表 6 的 ELI5 闭卷引用分为 15.5，表 21 为 15.4。另有表 11 将 ChatGPT 引用精确率写作 63.0，而主表为 72.5。这里保留明确表号，不将不同表的数值拼成一次更精确的复现结果。

## 检索、上下文和提示消融

### 检索到的材料仍未充分转化为答案

在 ASQA 上，GTR 的检索 EM 召回从 top-5 的 56.8 上升到 top-100 的 78.4；QAMPARI 的 recall-5 从 31.6 上升到 65.6；ELI5 的主张召回从 9.6 上升到 31.8。

作者还构造五段 oracle：先根据标准答案覆盖排序，取五段，再通过贪心替换改善整体覆盖。这五段在实验中达到原 top-100 的覆盖水平。它使用答案信息，并不是可以直接部署的检索器。即便给定这五段，ChatGPT 的正确性仍分别只有 ASQA 48.9、QAMPARI 37.0、ELI5 21.3，说明材料中的答案未全部写进输出。[图 4、表 12—14、19—21](https://arxiv.org/pdf/2305.14627v2)

图 4 将检索召回称为模型性能上界，更准确的适用范围是只依靠这些资料回答时的证据覆盖上限。模型还可能利用参数知识；ELI5 的 VANILLA 主张召回 12.0 就高于 top-5 检索的 9.6。因此不能将它理解为任何生成策略都不得超过的数学上界。

### 更长上下文的收益依模型和配置而变

ASQA 上 GPT-4 从五段增至二十段，EM 召回由 41.3 升到 44.4，引用召回由 68.5 升到 73.0。ChatGPT-16K 在同样五段至二十段的比较中，EM 召回均为 36.1，引用召回从 76.2 降到 73.7。后者不是把 `0301` 模型仅扩展窗口后的受控实验，而是另一个 `0613` 检查点；解释模型间差异时要保留版本因素。[表 7，第 8 页](https://arxiv.org/pdf/2305.14627v2)

### 指令、示范与训练基线

完整指令相比短指令，将 ASQA 引用召回从 69.6 提高到 73.6，引用精确率则为 73.2 对 72.5。完整指令并未让全部指标同时提升。示范从零个变为一个，引用召回从 69.3 变为 74.6；两个示范为 73.6，不能概括成示范越多越好。

附录还训练 T5-base FiD：ASQA 训练集、五个 epoch、batch size 64、学习率 $10^{-4}$、五段证据，再用 POST CITE 补引用。在 ASQA 上，FiD 的正确性与引用召回为 28.4、58.1，ChatGPT 为 40.4、73.6；跨到 ELI5 后分别为 4.4、39.3，对照为 12.0、51.1。这项比较同时改变模型规模、训练方式和数据条件，作者也注明它不是相同监督预算下的直接比较。[表 15—18、附录 G.2—G.4](https://arxiv.org/pdf/2305.14627v2)

附录 D 另做复制检索片段的检查：直接返回 top-1 片段，在 ASQA 上引用召回 99.4，但 MAUVE 仅 20.8；只返回其前两句，MAUVE 67.2、引用召回 98.7，答案覆盖却只有 18.9。这验证了两种具体的指标利用方式会在其他维度暴露问题，没有证明所有可能的取巧策略都能被识别。

## Surge 人工评估与自动指标的可靠性

### 人工任务和自动任务并不完全相同

附录 F 说明通过 Surge AI 组织标注，平均报酬为每小时 20 美元。ASQA 和 ELI5 各抽取 100 个问题，主表展示 ChatGPT VANILLA、RERANK 和 Vicuna-13B 的输出。人工效用评分是 1—5 分；引用召回要求判断一组资料是否完整支持一句话；引用精确率逐条判断完全支持、部分支持或不支持，并要求该句整体先通过支持检验。

ASQA 的平均效用评分在 3.7—3.9 之间，ELI5 为 3.5—3.6。回答看起来有用，并不能替代逐项核查证据。论文未披露每条样本的标注人数、分歧裁决流程或完整标注总费用，不能将模型与人工的 κ 当成人工之间的一致性。

| 任务与方法 | 人工引用召回 | 人工引用精确率 | 同子集自动引用召回 | 同子集自动引用精确率 |
| --- | ---: | ---: | ---: | ---: |
| ASQA：VANILLA | 74.7 | 76.6 | 75.3 | 74.4 |
| ASQA：RERANK | 79.3 | 81.9 | 83.9 | 80.8 |
| ASQA：Vicuna-13B | 51.6 | 51.5 | 50.3 | 50.1 |
| ELI5：VANILLA | 50.8 | 52.4 | 52.8 | 50.4 |
| ELI5：RERANK | 59.7 | 60.6 | 63.0 | 60.6 |
| ELI5：Vicuna-13B | 13.4 | 19.2 | 13.6 | 18.1 |

表内自动值是在人工评估子集上计算，所以不应要求它们与全量主表相同。重排在人工判断下仍然提高引用召回：ASQA 为 4.6 分，ELI5 为 8.9 分；但自动评分器给出的提升更大。这支持重排改善该批样本的引用质量，也提醒使用同一个评分器选择答案和报告成绩可能带来偏好。[§6、表 8—9、附录 F](https://arxiv.org/pdf/2305.14627v2)

### 公开标注可以复算判定准确率

官方 `human_eval` 实际保存八组各 100 个回答：除主表六组外，还有每个任务的一组交互式结果。每组额外有一个 `overall_results` 汇总字段，不能把它计为第 101 条回答。本次逐项读取这些记录，并按官方分析脚本的口径重新计算了全部八组的 2,604 个句子判断及 2,896 个引用判断。

| 自动判定任务 | 与人工一致的准确率 | Cohen’s κ | 将“存在问题”视为正类时的召回率 | 相应精确率 |
| --- | ---: | ---: | ---: | ---: |
| 句子引用不足 | 85.1% | 0.698 | 82.3% | 84.2% |
| 引用不满足支持要求 | 77.6% | 0.525 | 75.6% | 66.1% |

复算与 §6、附录 G.5 一致。第二行的负标签还会受到句子整体不受支持时将所有引用置零的规则影响，不能只理解为资料内容完全无关。这里的精确率、召回率描述检测器发现问题的能力，分母与前文“生成回答的引用精确率、召回率”不同。[固定人工数据与分析程序](https://github.com/princeton-nlp/ALCE/tree/246c476a4edfc564266b7346b6e29ef4861ae937/human_eval)

## 公开实现与论文协议的差别

本次固定官方仓库 commit 为 `246c476a4edfc564266b7346b6e29ef4861ae937`，检查了生成、评分、检索、后补引用、摘要、重排、提示与人工分析路径。下面是这个公开版本中影响复现的具体细节，不能据此推断作者历史实验必然以同一实现运行。

**重排使用的证据范围不同。** 论文将 RERANK 描述为按候选回答的引用召回评分，但 `tools/rerank_outputs.py` 在读出引用编号后，实际把 `item['docs']` 的全部文档拼成 NLI 前提，没有按引用编号选取。默认 VANILLA 输出保留的是当时提供给生成器的若干文档，其他流程可能保留更多，范围取决于输入结果文件。这与 `eval.py` 只验证实际所引片段的逻辑不同。重排还支持 token `1` 的概率或其 0.5 阈值，而最终评估依据解码结果是否严格等于 `1`。当全部候选得零分时，当前重排代码会留下空输出，因为最佳初值为零且只接受严格更高的分数。

**评分的边缘情况需要记录。** `eval.py` 先截取回答的第一个非空白起始行，再进行评分。对于 ASQA、ELI5，分句后为空的回答在引用评分函数中被跳过；这与为每条输入都分配零分不同。引用编号超过文档上限时整句引用召回置零，但该句的引用未加入精确率分母；代码也未拒绝编号零，会把它转成 Python 的负索引。本次用固定返回值代替 NLI 做了隔离函数检查，确认这些分支行为，没有加载模型，也没有测量它们在论文结果中出现的频率。

**交互检索的候选范围也依赖配置。** 论文描述在原始 top-100 内搜索，但所核对的 ASQA、ELI5 `interact_search` 配置没有启用 `retrieve_in_all_docs`；`run.py` 默认会将可搜索文档裁为 `ndoc` 指定的列表，并可能按摘要相关性过滤。因此按这些配置直接运行，未必得到论文描述的 top-100 搜索范围，需要显式核对该参数。

**执行入口依赖历史配置。** README 的 ASQA 示例加入 `--qa` 会额外运行问答模型评分，但论文主指标 EM 召回由 `str_em` 给出，附录明确没有采用 QA 评分作为主结果。任务是否属于 QAMPARI 则由结果文件名中是否出现 `qampari` 决定。运行文件应保留任务标识。

另外，当前 `run.py` 对非 Azure 的 `gpt-4-0613` 会进入旧 Completion 分支，而不是 ChatCompletion 分支；公开配置本身没有设置 Azure。这个入口需要核对后才能尝试复现，不能直接把 README 命令视为已验证可运行。程序中的 NumPy seed 控制示范抽取，未等价设置所有生成后端的随机状态。[固定评分代码](https://github.com/princeton-nlp/ALCE/blob/246c476a4edfc564266b7346b6e29ef4861ae937/eval.py) · [固定重排代码](https://github.com/princeton-nlp/ALCE/blob/246c476a4edfc564266b7346b6e29ef4861ae937/tools/rerank_outputs.py) · [生成代码](https://github.com/princeton-nlp/ALCE/blob/246c476a4edfc564266b7346b6e29ef4861ae937/run.py)

## 可复现的范围与成本

公开资料包含问题、参考答案、检索片段、部分摘要与摘录、oracle 材料、提示配置和人工判断。使用这些检索结果，可以检查生成和评分阶段，而无需先建立完整 Wikipedia 或 Sphere 索引；但这只能验证固定候选条件下的流程。

若重做检索，README 要求额外准备语料及索引。作者介绍其 GTR 索引约 31GB，构建时使用 80GB 显存的 GPU；Sphere 全语料检索也有较高内存与时间成本。NLI 评分依赖 T5-11B，MAUVE 依赖 GPT-2-large，候选重排又增加多次验证。代码内的价格是历史记录，不是当前 API 报价，论文没有完整报告全套实验的累计成本。[官方复现说明](https://github.com/princeton-nlp/ALCE/tree/246c476a4edfc564266b7346b6e29ef4861ae937)

复现入口依次为 `download_data.sh`、`run.py --config ...`、必要的 `post_hoc_cite.py` 或重排脚本，再调用 `eval.py`。真正运行前应固定数据和模型版本、核对当前数据分母、修正或明确采用上述代码差异，并记录候选数、输出长度、重复次数和评分规则。新的修正版实验应单独命名，不能直接覆盖论文原数字。

本次完成了全部正文、参考文献和附录阅读，视觉核对关键评分图与实验表，下载审计八个公开数据文件，并离线复算人工评估统计、检查评分函数边缘分支。没有调用生成模型、下载模型权重、运行检索索引或重新计算 NLI 结果。因此，这是一份原文与公开实现的深入核查，不是模型实验复现。
