# Inverse Scaling：规模增长下的任务退步

让模型原样复述一句带错字的话，模型却把错字改了；临时重新定义一个符号，模型仍按常规定义作答。这些任务所需的知识并不多，但在论文考察的一些模型系列中，投入更多预训练计算后，答对它们的概率反而下降。Inverse Scaling Prize 通过公开征集找到 11 组这样的任务，再比较不同模型系列、训练进度和提示示例数量。结果既有持续退步，也有先降后升，以及先升后降：某段规模区间的趋势不能直接外推到更大的模型。

## 这里的“规模”包含模型参数和训练数据

论文讨论的 inverse scaling，指模型在语言建模目标上改善时，某个下游任务表现反而变差。实验横轴主要使用**预训练 FLOPs**，即训练所用的浮点运算量，而不是单独使用参数量。

没有直接公开 FLOPs 时，附录 C 使用近似式：

$$
C\approx 6ND
$$

其中 $N$ 是参数量，$D$ 是训练 token 数，$C$ 是预训练计算量。增加参数或增加训练数据都可能增大横轴。论文没有把后续指令微调、上下文蒸馏和 RLHF 的计算量加进去；因此图中位置不能当作每个最终模型的完整训练成本。

例如，按同一近似式，OPT 的 125M 参数和 180B 训练 token 对应 $1.35\times10^{20}$ FLOPs。表 3 的这一格印为 `0.1.35`，单位为 $10^{21}$；正文不沿用这个无法解析的数字，而明确给出上述近似重算值。跨模型家族还存在训练语料、架构及参数与数据配比差异，所以相同 FLOPs 不等于受控条件完全一致。[论文 §1 脚注 1、附录 B–C、表 3]

这也解释了论文与常见缩放规律的关系：平均语言建模损失下降，并没有在数学上要求每个下游任务都单调改善。本文测的是具体任务上的反例，没有推翻所有任务的平均进步。

## 两类评分要分开读

### 分类任务按完整答案串计算概率

除 Prompt Injection 外，10 项任务使用分类形式。设题目为 $x_i$，候选答案集合为 $\{c_{ij}\}_{j=1}^{K_i}$，正确索引为 $y_i$。完整候选可能包含多个 token，其条件对数概率是：

$$
\ell_{ij}=\sum_{t=1}^{|c_{ij}|}\log p_\theta(c_{ij,t}\mid x_i,c_{ij,<t})
$$

再只在给定候选内归一化：

$$
q_{ij}=\frac{\exp(\ell_{ij})}{\sum_{k=1}^{K_i}\exp(\ell_{ik})},\qquad
L_{\mathrm{cls}}=-\frac1n\sum_i\log q_{i,y_i}
$$

准确率则是选择概率最高的候选后，计算选对的比例：

$$
A=\frac1n\sum_i\mathbf1\!\left[\arg\max_j q_{ij}=y_i\right]
$$

这些式子是对论文 §2.2 评测规则的展开。损失越低越好，准确率越高越好；它们不是本文训练一个新模型的损失函数。比如模型仍选错，但把正确答案概率从 0.4 降到 0.1，准确率都为 0，分类损失却从约 0.916 升至 2.303。这是说明例，不是论文实验数值。

完整序列概率会受候选长度影响，不能擅自改成按 token 平均的长度归一化得分。官方说明建议使用长度相近、最好单 token 的标签，并保留必要的前导空格。候选归一化也会掩盖候选以外的概率质量：模型可能对所有给定答案都不看好，却仍在它们之间选出一个。[论文 §2.2；官方仓库 Evaluation metrics]

随机基线应写成 $\frac1n\sum_i1/K_i$，而不是一律 50%。本次数据检查发现，Sig Figs 有 8,897 条二选一、9,480 条三选一、2,520 条四选一，合计 20,897 条。对完整发布集逐题均匀猜测的准确率为：

$$
\frac{8897/2+9480/3+2520/4}{20897}\approx39.42\%
$$

这是公开全量数据的离线重算；若某项历史实验抽取子集，基线也应按实际子集重新算。其余 9 项分类数据都是二选一，但标签不一定平衡。例如 Modus Tollens 的 1,236 个正确答案全是 `Yes`：固定回答 Yes 可得满分，这不代表完成了一般的逻辑能力评测。

### Prompt Injection 测目标续写损失

该任务要求复制或首字母大写，输入句子内部可能又包含另一条指令。评测模型是否仍给正确的复制续写分配概率，使用目标续写的负对数概率，不使用上述候选分类准确率。

图 4 画的是**负损失**，统一成向上更好；接近 0 较好，向更负的方向移动较差。附录图 10 又提供目标概率视角。损失升高可能表示模型对正确续写更不自信，不能直接转换成“攻击成功率提高多少个百分点”。该任务也没有在真实外部系统中执行攻击或验证信息泄漏。[论文 §3.1.4、图 4、附录 E.2]

## 11 项任务分别测试的行为

### 强先验：记忆与当前输入发生冲突

**Resisting Correction** 要求原样复述，即使句子里有错字、语法错误或被改动的名句，也不应该替用户纠正。作者观察到许多较大模型更常恢复常见说法；Anthropic RLHF 和 GPT-3 FeedME 系列中的退步尤为明显。部分系列出现回升，但论文指出，所测 Chinchilla 系列是这里最大模型优于最小模型的例外。不能由此概括所有指令微调都会使复制能力下降。[§3.1.1、图 2 左]

**Memo Trap** 让模型改写常见短语，例如开头容易触发熟记的下一词，但指令指定另一种结尾。多数系列随规模增大更倾向熟悉续写，OPT 和 PaLM 有局部回升，但最大规模仍低于随机基线。作者也指出一个任务表述问题：若选项没有明确句尾，模型可能打算先写熟悉的词、再接新的结尾，单个续写位置不一定完整表达其意图。[§3.1.2、图 2 右]

**Redefine** 临时改变符号或词语含义，再要求用新定义回答。可用一个自拟例理解：题目约定某符号表示 583，问其首位，正确答案应来自约定值，而不是符号的常见含义。论文各系列的最大模型都低于最小模型，但中间点并非严格单调。它测的是使用上下文定义的能力，不能据此推断模型无法使用任何检索信息。[§3.1.3、图 3 左]

**Prompt Injection** 把后出现的句内命令与前面要求复制或变换文本的规则放在一起。图 4 显示不少系列先改善，再在约 $10^{21}$ 训练 FLOPs 之后退步。作者的解释是：极小模型连初始任务也做不好，中等模型学会复制模式，更强模型又开始服从输入中的新命令。这是与曲线相符的行为解释，本文没有通过内部机制干预证明因果链条。[§3.1.4]

### 不期望的模仿：逻辑规则与常见判断方式

**Modus Tollens** 使用有效的否定后件推理：

$$
(P\Rightarrow Q)\land\neg Q\Rightarrow\neg P
$$

模型判断结论是否成立。很多系列从接近全对降到接近全错，而 GPT-4 的所测版本接近全对。作者提出训练文本可能含有人的推理错误，模型因模仿而学到错误倾向；但论文并没有追溯各模型实际训练语料中的相关例子。

更直接的混杂是全 Yes 标签：某种回答偏好就能显著影响准确率。发布后发现 104 条语法有问题的记录，占 1,236 条约 8.41%；官方发布包仍保留它们，另提供索引。删掉后剩 1,132 条，附录图 9 显示主要趋势不变。本文核查了索引数量，未重新运行这些模型。[§3.2.1、附录 E.1；数据发布 Caveats]

### 干扰任务：熟悉的操作替代了真正要求

**Pattern Match Suppression** 给出重复或交替序列，要求结尾打破模式。大模型更熟练地续写模式，反而可能选错。多数大模型准确率很低，GPT-4、GPT-4 RLHF 和 GPT-3 FeedME 有非零表现。作者同时承认“出人意料”这种指令存在不充分明确之处；人工能理解并不消除措辞边界。[§3.3.1、图 5 左]

**Into the Unknown** 给出一个情境和仍需解释的问题，让模型选择哪条新信息有助于解答。错误选项重复已有信息，正确选项引入相关的新证据。很多系列越大越偏向上下文已经提到的内容，GPT-4 的所测版本则表现较好。这里测试的是信息选择，模型没有实际浏览或开展调查。[§3.3.2、图 5 右]

**NeQA** 从 OpenBookQA 筛选含 `is` 的问题，在其后插入 `not`，改变应选答案。模型若只完成原来的知识关联、漏读否定词，就会更有把握地答错。许多系列在约 $10^{22}$ FLOPs 后低于随机，GPT-3 FeedME 出现 U 形；这是一种特定构造的否定问答测试，不覆盖所有自然语言否定结构。[§3.3.3、图 6 左]

**Sig Figs** 区分有效数字与小数位数，例如把 48,321.876 保留两位有效数字应得到 48,000，而不是 48,321.88；这是自拟说明例。公开 21 个部分还包含测量精度、计算结果表述等变体，不只有论文展示的简短二选一题。PaLM 的曲线明显回升，Chinchilla 和 OPT 大体保持在随机附近，其他多条系列曲线落到随机以下。[§3.3.4、图 6 右；公开数据]

### 误导性的少样本示例：示例都正确，也可能展示了错误规律

**Hindsight Neglect** 让模型依据期望收益判断一个抽象赌局是否值得选择。提示示例中，实际输赢与期望值符号一致；最后一题故意让二者不同。于是“只看最终输赢”能解释前面的例子，却不能完成目标任务。

按这个数据集的标签规则，若收益为 $g$、损失为 $l$、获胜概率为 $p$，则：

$$
\operatorname{EV}=pg-(1-p)l
$$

期望值正负决定数据集所要求的答案。实际某次赢了或输了不能替代这个计算。它是论文的简化决策规则，不是对现实人的风险偏好建模。Anthropic 和 DeepMind 系列有明显退步，PaLM 出现强 U 形；GPT-4 技术报告中的对应结果很好，但本文脚注明确不能确定那项结果所用 GPT-4 是否经过 RLHF。[§3.4.1、图 7 左、脚注 12]

**Repetitive Algebra** 在最终方程之前放 9 个答案相同的正确例子，再放 1 个答案不同的正确例子；最终题答案与前 9 个相同。模型可以真正解方程，也可能复制高频答案或最近答案。不同系列表现分化：Anthropic、GPT-3、Gopher 有反向缩放，PaLM 呈正常缩放，OPT 和 FeedME 多为正常或 U 形。小模型答对并不自动证明它会计算，也可能只是复制了出现最多的数字。[§3.4.2、图 7 右]

上述四类是作者提出的**可能原因**，不是通过四组正交干预确认的机制分类。一项行为也可能受标签偏好、提示格式和模型训练方式共同影响。

## 实验比较的范围与关键结果

论文比较 GPT-2、GPT-3、OPT、Gopher、Chinchilla、Anthropic LM 等预训练系列，以及 Anthropic Context Distilled、Anthropic RLHF 和 GPT-3 FeedME。FeedME 指对人工高评分生成样本微调的模型；上下文蒸馏则训练模型去匹配带特定助手提示的输出分布。这些方式不能都简称 RLHF。

| --- | --- | --- |
| GPT-2 | 124M–1.5B | 预训练计算量使用语料规模估计 |
| GPT-3 / FeedME | 350M–175B | 各 4 个规模点；后训练成本未加进横轴 |

Anthropic 系列是早于 Claude v1 的未发布研究模型；虽然部分后训练模型面向对话，实验没有把任务输入统一改成其对话格式。这是论文明确披露的适用条件，不能把曲线直接写成当前同名厂商产品的能力排名。[§2.1、脚注 2–4、附录 B]

## 增加示例或继续训练，并不产生同一种变化

### 提示中的额外示例

实验从额外 0-shot 测到最多 72-shot，或模型上下文能容纳的上限。这里的 0-shot 不一定意味着提示里完全没有示例：Resisting Correction、Hindsight Neglect 和 Repetitive Algebra 等任务原始题目本身就包含示范；额外 few-shot 是在这些完整题目之外再追加已解答样本。

公开说明规定，从任务数据中排除当前待测题，再无放回抽取示例，补上正确答案，用三个换行连接。因而提高 shot 数也改变输入长度和实际可用预算；达到上下文限制的模型并不都接收相同数量示例。[§5.2；数据发布说明]

多数任务趋势有所改善，例如 Pattern Match Suppression、Prompt Injection、Repetitive Algebra 和 Modus Tollens。但 Hindsight Neglect、Memo Trap 在一些系列中即使绝对成绩提高，反向缩放仍存在。Sig Figs 的额外示例可能有害；Resisting Correction 随示例数增加先改善，在最高两档又退步。正文没有提供一组能够独立分离示例数量、选择、长度、位置等因素的统一因果消融。

### 同一模型的训练检查点

Anthropic LM 还在 15 个训练检查点上评测，token 数大体按对数间隔增加，最终到 400B。这样固定参数规模，观察继续训练的效果。[§5.3、表 3]

Hindsight Neglect、NeQA、Pattern Match Suppression 在各参数规模上表现出反向缩放；Redefine、Memo Trap、Repetitive Algebra 在小模型中更常随训练改善，而大模型中可能先升后降。Modus Tollens 在训练过程中多次翻转，作者认为全 Yes 标签使小幅回答偏好变化被放大。它们说明“多训练一些”与“增大参数”不能被视为同一个无条件改善过程。

附录还提供 Modus Tollens 去除语法错误后的曲线，以及 Prompt Injection 的平均概率曲线。它们分别检查数据瑕疵与指标视角，没有构成对所有提出原因的完整机制验证。

## 公开数据与复现入口

本次固定核查官方数据仓库提交 `920f17de85f2a7f2415b097bc49e6a7fbf17b0b2`。`data-release/isp-data-release.zip` 内有 11 个 JSONL，分类任务使用 `prompt`、`classes`、`answer_index`，续写任务使用 `prompt`、`completion`，另有 `part` 和 `round`。`classes` 实际是 Python 列表形式的字符串，需要安全解析，不能当成已经结构化的数组直接索引。[固定版本数据说明](https://github.com/inverse-scaling/prize/blob/920f17de85f2a7f2415b097bc49e6a7fbf17b0b2/data-release/README.md)

发布说明记录了版本处理：部分任务去重；Resisting Correction 另删掉 21 条候选重复的记录，这发生在比赛评测之后，因此早期比赛公告图不能与发布数据逐行等同；Resisting Correction 和 Redefine 只保留第二轮更新；Memo Trap 只保留第 1、3 部分。本文遍历全部发布行，未发现同一文件中的重复 prompt 或完全相同的候选项，但这不代替语义去重和标签复核。

数据采用 CC BY 4.0，并附两个防训练污染标记。作者明确提醒，没有记住标记不等于未接触数据，因为部分任务可能以其他形式公开。原始全量内容是评测数据，不应因为容易下载就混入模型训练，再把该评测集上的改善解释为迁移。


比赛提供的 GPT-3 Colab 指向另一份评测代码 `naimenz/inverse-scaling-eval-pipeline`。本文取得公开 notebook，并固定阅读代码提交 `34c8c7b066c5134fd26d6658ffa1522d2785d1d4` 的数据加载、模型评分、API 请求和绘图流程。这个参赛评测入口不包含论文所有私有模型与检查点的可运行环境。[评测代码](https://github.com/naimenz/inverse-scaling-eval-pipeline/tree/34c8c7b066c5134fd26d6658ffa1522d2785d1d4)

代码层面需要保留以下细节：

- `main.py` 接受 CSV 或 JSONL，分类会同时保存损失、是否选对、预测标签和候选总对数概率。题目不是交给另一个 LLM 打分。
- GPT-3 路径把每个候选接在 prompt 后，以 `max_tokens=0`、`echo=True` 取得给定文本的 token 概率，再在正确的字符边界切出候选。若候选起点不是 token 边界，代码报错。这里不需要多次自由生成答案，也不存在用采样温度修正一个已算好的分类损失。
- Hugging Face 路径按目标 token 累加 log probability；公开实现只允许 batch size 1。它设置 `model_max_length=1023`，编码时启用截断。长提示如果被截掉末尾，而后续仍按最后若干 token 当作答案评分，就可能改变被测内容；重新运行前要检查每条拼接后的实际 token 边界与长度，不能只确认程序没有报错。这是代码检查发现的风险，没有证据证明论文的私有评测因此出错。
- 绘图脚本对样本求均值，非准确率图使用 `np.std / sqrt(n)` 的标准误；准确率分支不画误差条。它默认横轴为参数量，论文图主要使用训练 FLOPs，因此原样运行 notebook 不会自动得到论文同口径的全部图。
- Colab 从可变的 `main` 安装，依赖文件使用较旧的 Transformers 等版本范围。要做可追踪实验，应固定代码、依赖与模型 revision。代码中的历史 API 名称和接口也不构成今天可用的保证；本文没有调用付费 API，也没有下载并重跑模型。

一个局部复现入口是：先解压发布包，保留题目文本和候选空格，然后对可获得的同系列模型逐个评测。例如以下命令按已读代码参数整理，**尚未执行模型实验**：

```bash
python -m eval_pipeline.main \
  --dataset-path /absolute/path/isp-data-json/neqa_classification.jsonl \
  --exp-dir /absolute/path/results/neqa \
  --models gpt2 gpt2-medium gpt2-large gpt2-xl \
  --task-type classification --batch-size 1 --use-gpu

python -m eval_pipeline.plot_loss /absolute/path/results/neqa \
  --task-type classification_acc --no-show
```

这样只能复现指定公开系列的局部比较。恢复论文全图还需要私有模型访问、准确的历史版本、few-shot 选择与上下文处理、训练检查点，以及模型级原始输出。公开提交指南还允许大数据集在私有评测时均匀抽样至最多 10,000 条，不能把 Sig Figs 发布的 20,897 条直接当成所有历史模型都实际评测过的分母。

本文已完成的验证是：全文及附录阅读；表 1、表 3 和图 4 的视觉核查；公开全部数据的行数、分部、候选数量、标签及重复检查；评分和绘图代码静态阅读；随机基线、语法问题比例与公式说明例的离线重算。没有将这些检查称为模型结果复现。

## 这些结果支持的结论范围

论文给出了跨多个系列出现的具体任务反例，也表明一些反例会在更大规模或更多示例下缓解。它没有证明四类原因是互斥或完备的，没有证明所有训练阶段都会沿同一方向变化，也没有建立预测下一次趋势反转位置的公式。

作者没有授予高等级奖项的一个原因，是不少任务尚未充分展示真实应用中失败的影响。文中关于检索、助手控制和训练目标的讨论，应与这些简化任务上的直接证据分开。对于使用这些数据的人，最可核对的是具体模型、提示、候选评分与曲线；将其扩展到现实应用，仍需相应的任务实验。[论文 §3.5、§5、附录 D]
