# WebGPT：浏览器问答与人工反馈

WebGPT 把长篇问答拆成一个连续过程：搜索网页，打开与阅读结果，保存引用片段，再根据这些资料写出答案。它先模仿人的浏览示范，再用人工比较训练奖励模型。论文最终采用的主模型是行为克隆后的 GPT-3，加上按奖励分数筛选多个候选；PPO 强化学习是另行比较的方法。在 ELI5 上，175B 的 best-of-64 模型获得相对人工示范答案 56%、相对 Reddit 参考答案 69% 的偏好评价。这些比例含平局的折算，也不是逐条事实的正确率。

## 任务从一句问题延伸到可检查的证据

一个自拟说明例子是：用户想了解城市树木怎样影响夏季体感温度。模型需要检索相关资料，区分遮阴与蒸腾等解释，保存可支持这些解释的原文，再写出带来源的回答。搜索结果相关，不代表答案正确；引用真实存在，也不代表它支持回答中的每个推论。WebGPT 的环境与标注协议分别处理这两个环节。

与直接训练可微检索器的方法不同，WebGPT 把检索交给 Bing Web Search API。模型学习的是如何形成查询、决定读哪一页、寻找和保存证据，以及如何综合信息。搜索引擎本身不通过论文的偏好梯度更新。原文相关工作中的向量内积检索公式是在介绍 DPR、REALM、RAG 一类方法，不是 WebGPT 实际使用的检索打分式。[论文 §1—§2、§7，第 1—3、12 页](https://arxiv.org/pdf/2112.09332v3)

### 浏览阶段只能执行规定的文字命令

| 动作 | 环境效果 |
| --- | --- |
| Search | 向 Bing 发查询，显示简化后的结果页 |
| Clicked on link | 按页面中的链接编号打开网页 |
| Find in page | 定位页面内的下一处指定文本 |
| Quote | 从当前页面保存匹配的原文，作为后续引用 |
| Scrolled up / down、Top、Back | 滚动、返回顶部或上一页 |
| End: Answer | 结束浏览，进入作答 |
| End: Nonsense / Controversial | 结束浏览并跳过作答 |

不符合命令格式的输出属于无效动作：消耗动作次数，但除此之外被忽略。每一步模型收到的是重新组织的环境状态，包括问题、已保存的引用、历史动作摘要、当前页可见文本和剩余动作数；模型没有自动保留完整的先前上下文。

浏览在模型主动结束、达到动作上限或达到引用总长度上限时停止。只有至少保存一条引用时，才进入作答阶段。最终作答输入是问题与收集的引用，不是浏览期间每个页面的全文。因此，保存引用既是证据选择，也是对下一阶段可见信息的筛选。[论文 §2、表 1，第 3 页](https://arxiv.org/pdf/2112.09332v3)

### 文字环境与普通图形浏览器不同

附录 A 说明，环境主要用 Python 编写，网页读取通过 Node.js 获取 HTML，并用 Mozilla Readability 简化，再由 html2text 转成文字。图片只保留替代文本；PDF 用 pdfminer.six 转文本。失败、超时和不支持的类型会变成错误信息。

Quote 命令必须与当前页内容匹配，匹配会忽略大小写与空白等差异，并支持用首尾片段表示长引用。保存内容包含页面标题、域名和摘录。它不是让模型凭记忆补一个看似真实的来源链接，但也没有因此验证网页本身的可靠性。

为减少复制现成答案，环境去掉 Reddit、Quora 的搜索结果和链接；页面与问题或已提供参考答案有连续 10 词重合时，也会被屏蔽。这是特定的检索侧防泄漏措施，不能证明 GPT-3 预训练中没有见过相关问题或答案。

环境的外部操作限于搜索及访问已有链接，没有提供提交表单、编辑网页或运行任意网站操作的接口。因此，这项工作不能直接等同于可以完成通用网页事务的 agent。[论文附录 A、§6.5，第 11、15 页](https://arxiv.org/pdf/2112.09332v3)

## 示范与偏好数据怎样产生

### 6,209 条示范与 21,548 次比较

主数据来源是 ELI5，即 Reddit “Explain Like I’m Five” 的长问题。作者保留完整 URL，处理删除标记，把标题与非空正文拼接；对不是疑问句或解释请求的标题补上“Explain:”。另混入少量短问答、科学题、人工问题和事实核查任务。

| 问题来源 | 人工示范 | 答案比较 |
| --- | ---: | ---: |
| ELI5 | 5,711 | 21,068 |
| ELI5 fact-check | 67 | 185 |
| TriviaQA | 143 | 134 |
| ARC Challenge | 43 | 84 |
| ARC Easy | 83 | 77 |
| 人工撰写 | 162 | 0 |
| 总计 | 6,209 | 21,548 |

这是附录表 4 的精确计数。正文将它们概括为约 6,000 和约 21,500；ELI5 分别约占 92% 和 98%。这些量是示范或比较记录数，不是去重后独立问题数，也不是最终奖励模型实际训练集的大小。[论文 §3.1、附录 B，第 3、16 页](https://arxiv.org/pdf/2112.09332v3)

BC、RM、RL 使用互不重叠的问题集合。BC 留出约 4% 示范用于验证；最终 RM 用约 16,000 次比较训练，约 5,500 次只用于评估。比较数据来源并非一种固定策略：研究者将不同模型大小、训练方式与超参数产生的答案合在一起，以利用评估和调参时已经收集的比较。[论文 §3.2，第 5 页](https://arxiv.org/pdf/2112.09332v3)

### 示范人员与模型使用近似相同的环境

人员通过图形界面搜索、阅读、保存引用并写答案，原则上看到与模型相同的信息，也只能执行相同类别的动作。两个例外是：模型额外收到历史动作摘要；人类连续的单次滚动会合并成模型可执行的多次滚动动作。

任务需要较强阅读与判断能力，参与者通常具有本科或以上学历，报酬按工作时间计算。作者采用付费试做、人工检查，并对比较任务设置约 100 道研究者标注的共同任务以监控质量。研究者与标注人员的一致率为 74%，标注人员相互一致率为 73%；中立与非中立判断之间按 50% 一致处理。这不是“事实判断准确率 74%”，也不是 Cohen’s $\kappa$。[附录 C，第 17 页](https://arxiv.org/pdf/2112.09332v3)

示范平均约 15 分钟，比较平均约 10 分钟。论文没有公开足够的小时费率、返工量和评估重叠记录来计算精确总支出。附录 D 的工作满意度调查只覆盖完成至少 32 个任务的人，三轮合计每道调查题有 41 份评分，同一人可在多轮回答；不能当成 41 位互不重复的人员，也不能代表试做后退出者。

### 偏好比较主要检查来源支持，而非独立重做研究

比较流程要求读题、读答案与引用、判断来源可信度、标注陈述的支持程度和相关性，再比较事实支持、内容帮助及连贯性，最后给总体偏好。优先考虑是否包含无支持的信息，其后是是否回答核心问题、是否补充有帮助的信息，以及连贯性、引用错误与无关内容。

这些细项没有全部变成训练标签。在项目多数阶段，只有 10% 的比较要求完成整套细标注，其余 90% 除最终偏好外可选；后期又把部分维度设为必填。RM 训练只使用总体偏好，并合并“更好”和“好得多”。作者尝试预测额外标注作为辅助任务，但未显著改善奖励模型验证准确率。

标注人员通常不需要做独立研究，而是判断答案中的陈述是否得到可靠引用或常识支持。这使任务更可操作，却也留下选择性引用的空间：模型可能挑选容易说服评审的来源，而未完整呈现相反证据。[附录 C.2、§6.4，第 17—18、11 页](https://arxiv.org/pdf/2112.09332v3)

## 四个方法的目标分别是什么

### 行为克隆：学习浏览动作和作答

行为克隆（behavior cloning，BC）对人类示范做监督微调。把环境状态记为 $s_t$，人类输出的动作或回答 token 记为 $a_t$，可用下式说明其基本目标：

$$
\mathcal L_{\mathrm{BC}}(\theta)
=-\mathbb E_{\tau\sim D_{\mathrm{demo}}}
\sum_t\log\pi_\theta(a_t\mid s_t).
$$

这是对论文方法的数学展开，不是原文单独编号的新公式。它让模型学会命令格式和示范中的决策习惯，但不直接优化人类在两个最终答案之间的选择。论文从 GPT-3 的 760M、13B、175B 三种规模开始训练。[论文 §3.2，第 4 页](https://arxiv.org/pdf/2112.09332v3)

### 奖励模型：偏好差值，不是事实概率

奖励模型从 BC 模型初始化，去掉最终词表输出层，改为给“问题＋答案及引用”输出一个标量。设两个候选得到 $r_0,r_1$，则偏好概率建模为：

$$
P(0\succ1)=\sigma(r_0-r_1),\qquad
\sigma(z)=\frac{1}{1+e^{-z}}.
$$

偏好标签 $p$ 在答案 0 更好时为 1，答案 1 更好时为 0，平局时为 $1/2$。对应交叉熵为：

$$
\mathcal L_{\mathrm{RM}}
=-p\log\sigma(r_0-r_1)
-(1-p)\log\bigl(1-\sigma(r_0-r_1)\bigr).
$$

奖励差为 1 对应约 73.1% 的预测偏好，不代表其中一个答案有 73.1% 的事实正确率。只看一条答案的绝对奖励也没有这种概率含义。平局是软标签，不能直接删除；原始偏好强度的大小也不作为不同权重保留下来。[论文 §3.2、§5.2、附录 K，第 4、8、32 页](https://arxiv.org/pdf/2112.09332v3)

### PPO：提高奖励，同时限制偏离 BC

强化学习从 BC 策略出发，在完整浏览环境中使用 PPO。终局奖励来自 RM；每个 token 另加相对 BC 的 KL 惩罚，以限制对奖励模型的过度优化。用轨迹 $\tau$ 和固定 BC 策略 $\pi_{\mathrm{BC}}$，可以把目标概括为：

$$
J(\theta)=\mathbb E_{\tau\sim\pi_\theta}
\left[r_\phi(q,a,E)
-\beta\sum_t\log\frac{\pi_\theta(a_t\mid s_t)}{\pi_{\mathrm{BC}}(a_t\mid s_t)}\right].
$$

其中 $E$ 是保存的引用，$a$ 是最终答案，$\beta=0.02$。沿当前策略采样时，token 对数概率比的期望对应 KL；单条轨迹的采样项不必处处为正。这个式子描述论文奖励设计，不意味着作者使用无约束的直接梯度优化它。

PPO 的策略更新使用常见的裁剪替代目标：令 $\rho_t=\pi_\theta(a_t\mid s_t)/\pi_{\mathrm{old}}(a_t\mid s_t)$，$\hat A_t$ 为优势估计，则最大化：

$$
\mathbb E_t\left[\min\left(\rho_t\hat A_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\right)\right],
\qquad\epsilon=0.2.
$$

这里限制更新的旧策略 $\pi_{\mathrm{old}}$ 与作为长期参照的 BC 策略不同。论文在 token 层执行 PPO 裁剪、KL 奖励和值函数基线，但将 rollout 的时间步按一次 completion 表达；不能把表中的每步都当作一个 token。[论文 §3.2、附录 E，第 4—5、20—22 页](https://arxiv.org/pdf/2112.09332v3)

为了提高样本利用率，完成一次浏览作答后，作者复用同一组引用，增加 15 次仅作答 episode，即每次浏览共 16 个作答阶段。它不是再独立搜索 15 次。作者报告这种安排约提高两倍样本效率；浏览阶段的动作上限在 20 到 100 之间均匀抽样。

### Best-of-n：在推理时选择奖励最高的候选

给定同一问题，从 BC 或 RL 模型采样 $n$ 个候选，选取：

$$
a^*=\arg\max_{a_i,\ i=1,\ldots,n}r_\phi(q,a_i,E_i).
$$

论文将它称为 rejection sampling 或 best-of-n。这里是固定采样数后取最高分，并不是设一个阈值、循环生成直到通过。不同候选可以有各自的浏览过程和引用集合；它并非只给同一份检索结果改写 $n$ 遍。

这种方法不再更新策略参数，但增加推理成本。最终主评估采用 760M best-of-4、13B best-of-16、175B best-of-64，策略与 RM 大小相同，均从 BC 模型采样，温度 0.8，浏览最多 100 个动作。不能把这三组结果写成“BC、RM、PPO、筛选”依次完成后的模型。[论文 §3.2—§4，第 4—5 页](https://arxiv.org/pdf/2112.09332v3)

## 训练超参数与早停

附录把学习率写成 GPT-3 预训练学习率的倍数。换算后的数值如下：

| 模型 | BC 学习率 | RM 学习率 | RL 学习率 | BC 轮数 | RM 轮数 | RL 的 PPO 迭代数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 760M | $2.5\times10^{-5}$ | $1.25\times10^{-5}$ | $10^{-6}$ | 2 | 1 | 19 |
| 13B | $10^{-5}$ | $5\times10^{-6}$ | $4\times10^{-7}$ | 5 | 1 | 30 |
| 175B | $6\times10^{-6}$ | $10^{-6}$ | $2.4\times10^{-7}$ | 3 | 1 | 18 |

BC batch 通常为 512，760M 为 256；RM 通常为 64，175B 为 32。BC 和 RM 使用每次梯度更新衰减率 0.99 的权重指数移动平均。作者披露一个实现问题：760M、13B 的 RL 使用 RM 时没有使用 EMA 权重；rejection sampling 不受这个问题影响。

PPO 使用 256 个并行环境，每个 rollout 256 个时间步，1 个 epoch、128 个 minibatch，优势归一化但奖励不归一化，GAE 的 $\gamma=1$、$\lambda=0.95$，熵奖励系数为 0；长 completion 被切成最多 64 token 的动作块。策略和值函数网络分开。

早停依据也不同：BC 看奖励模型分数而非只看示范验证损失，RM 看验证准确率，RL 看相对 BC 的 KL 预算与奖励表现。三个 RL 模型早停时每 episode 的 KL 分别为 10.5、6.8、约 12 nats。这些是训练中累计偏离的量，不是“每 token KL”。论文提到一次 PPO 迭代耗时数小时，但没有给出可复算的完整 GPU 工时和费用表。[附录 E、表 5—8，第 20—22 页](https://arxiv.org/pdf/2112.09332v3)

## ELI5：56% 与 69% 对应不同评估协议

设比较总数为 $N$，模型胜出数为 $W$，平局数为 $T$，则本文报告的偏好率可以写成：

$$
\widehat P=\frac{W+0.5T}{N}.
$$

因此 56% 不代表“56% 严格胜出、44% 严格失败”，也不意味着每条模型答案都优于人类。图 2 的误差线是正负一个标准误，不能标成 95% 置信区间。

| 175B best-of-64 的比较对象 | 总体偏好率 | 评审看到什么 |
| --- | ---: | --- |
| 同环境的人类示范答案 | 56% | 两个答案各自的引用，采用详细支持性与质量协议 |
| ELI5 的 Reddit 最高赞答案 | 69% | 去掉模型答案中的引用与参考资料，采用新人员和简化说明 |

第二种协议还要求评审不要打开答案中的 URL，以减少格式差异造成的偏差；但可以使用搜索引擎核查不明显的事实。这与训练比较时“不要求独立研究”的协议不同。对时间敏感的问题，简化说明允许在过去十年内某一时点正确的答案视为准确，因此这里也不是严格的当前时点知识测试。

论文提醒，即使去掉引用，模型与 Reddit 的文风仍不同，盲评不完全；Reddit 问题可能期待原创的简化解释，而研究所设标准不完全相同。一些最高赞答案本身也很简短。相比之下，同一环境中的人类示范更容易对齐投入与评价标准。

175B 对人类示范的事实准确性偏好在图中接近 50%，连贯性偏好仍低于 50%。因此总体偏好超过一半，不意味着所有维度都超过人类。正文和附录没有为图 2 每一柱提供完整的比较数、平局数和逐条标签，本次未从图的误差线反推它们。[论文 §4.1、图 2、附录 F，第 5—6、23 页](https://arxiv.org/pdf/2112.09332v3)

## TruthfulQA 与 TriviaQA 衡量另外两种能力

### TruthfulQA：真实性与信息量要同时看

TruthfulQA 的问题针对常见错误信念。一句没有实质内容的回答可以被标为真实，却不提供信息；所以论文同时报告真实，以及真实且有信息两个比例。175B best-of-64 分别为 75% 和 54%，仍低于图中的人类基线。

GPT-3 对照采用 QA prompt 和 helpful prompt，并使用原任务的自动指标；WebGPT 的回答分布不同，作者采用人工评估。两组评分方式不同，是阅读跨模型比较时需要保留的条件。

WebGPT 原本生成长答案。评估时先截到 50 token，再去掉末尾不完整句子，意外产生了 74 个空回答，约占三个 WebGPT 模型回答总量的 3%。这些被记为真实但无信息，不能算作成功纠正了问题中的误解。这个 74 也不是单独 175B 模型的空回答数。[论文 §4.2、图 3及脚注 3，第 6—7 页](https://arxiv.org/pdf/2112.09332v3)

模型仍可能从不可靠网页收集支持错误信念的片段。原文表 3 特意选择一项成功和一项失败，而非随机估计错误率。§6.1 关于减少普通幻觉的判断则明确是作者的推测，没有另做对 GPT-3 的细粒度幻觉率实验。

### TriviaQA：增加了一个独立的答案提取器

附录 G 使用 175B BC、温度 0.8，不进行 best-of-n。为了从长答案得到短答案，另对 GPT-3 175B 用 256 个问题微调一个提取过程，条件输入包含 WebGPT 输出；batch 为 32，学习率 $1.5\times10^{-6}$。还设置了同样微调但不提供 WebGPT 输出的对照。这 256 个问题不同于 WebGPT 训练时使用的 143 条 TriviaQA 示范。

## 方法比较与规模实验

在 175B 上，BC best-of-64 相对单次 BC 的人工偏好为 68%；单次 RL 相对 BC 为 58%。RL 与 rejection sampling 结合后没有带来明显额外收益，这也是主评估省略 RL 的原因。

作者提出几种解释：多次浏览可以尝试更多网站并事后选择；RM 训练数据主要来自 BC 和筛选策略，对这类分布更熟悉；RL 更易过度优化 RM，也降低策略熵，从而减少探索。论文没有逐一隔离这些机制的因果贡献。它还强调，认真选择 BC 训练轮数和采样温度后，原本看到的部分 RL 优势消失了，不能用欠调参的 BC 作唯一参照。[§5.1、图 4—5，第 7—8 页](https://arxiv.org/pdf/2112.09332v3)

规模实验使用另一个在独立数据划分上训练的 175B 验证 RM，降低只用被优化的同一个奖励模型自我评估的问题。它给出下列近似趋势：

| 增加的资源 | 论文报告的近似变化 |
| --- | --- |
| 示范数翻倍 | 策略的验证 RM 分数增加约 0.13 |
| 偏好比较数翻倍 | RM 验证准确率增加约 1.8 个百分点 |
| 策略参数量翻倍 | 验证 RM 分数增加约 0.09 |
| RM 参数量翻倍 | RM 验证准确率增加约 0.4 个百分点 |

这些是给定尺度范围内的经验趋势，不是可以无限外推的定律。0.13 分是奖励尺度变化，不是答案偏好提高 13 个百分点。图 8 在模型大小与候选数之间估计计算效率前沿，由此选择三个主模型；横轴是浮点运算量，而不是搜索 API 费用或网页响应时延。[§5.2、图 6—8，第 8—9 页](https://arxiv.org/pdf/2112.09332v3)

## 附录 I：复用候选来估计 best-of-n

直接估计 best-of-64 的期望效果，每次都要生成 64 个候选，只得到一个胜出答案的验证奖励。附录 I 提供一种复用方法：对同一问题一次采样 $N$ 个答案，便可以估计所有 $n\le N$ 的筛选表现。

先按训练 RM 分数从低到高排序为 $S_1,\ldots,S_N$，再记验证 RM 分数为 $v_i=R_{\mathrm{val}}(S_i\mid q)$。从 $N$ 个候选中等概率选一个大小为 $n$ 的子集，在每个子集中用训练 RM 选最高分，则估计为：

$$
\widehat R_n(q)
=\sum_{i=n}^{N}
\frac{\binom{i-1}{n-1}}{\binom{N}{n}}v_i.
$$

第 $i$ 个候选成为子集最高分时，必须包含它，并从其前面的 $i-1$ 个候选中再选 $n-1$ 个，因此分子是相应组合数。系数和为 1。这个式子等价于枚举所有子集的平均，却只需排序与加权求和。

**说明算例：**$N=4,n=2$ 时，第 2、3、4 个候选的权重分别是 $1/6,2/6,3/6$。若其验证奖励为 0.2、0.7、0.9，加权值为 $4.3/6\approx0.7167$；枚举六个二元子集会得到同一个平均。最高训练奖励的答案并不一定有最高验证奖励，所以不能用一次排序代替验证打分。

在独立同分布采样与一致的并列处理下，这个子集平均对目标期望无偏。最后再对问题平均。它降低统计估计浪费，不会把实际部署的 best-of-64 变成只需一个候选，也不能把验证 RM 的预测变成真实人工评价。作者验证 $n\le64$ 时预测较好，同时提醒更大的 $n$ 仍可能把验证 RM 的缺陷放大。[附录 I、图 5，第 28、8 页](https://arxiv.org/pdf/2112.09332v3)

## 立场、文化参照与引用的局限

附录 H 用不同立场提出关于常见误解的问题，分别检查事实准确性与答案是否赞同问题的隐含信念。作者发现一些提示性证据：带肯定前提的问题更容易得到不准确答案；但没有清晰证据证明问题立场会改变答案明确赞同或反驳的比例。小样本不足以给出普遍结论。

这里还有一个原文计数差异：正文称选择 20 个主题，每个三种问法，共 60 题；表 10 实际列出 21 个主题、每个三种问法。论文未解释多出的主题是否进入实验，因此不能根据表格自行把评估分母改成 63，也不能把 60 当成已用公开逐题结果重算过的数量。

另一项案例让 175B BC 对同一个婚礼问题生成 64 个答案，不是 best-of-64 后剩下一条。20 条提到 America 或 American，4 条主要讨论明确命名的其他文化，8 条说明没有标准婚礼。作者据此分析默认文化参照，但这个案例不能量化模型在全部文化主题上的偏差率。[附录 H、表 10，第 25—27 页](https://arxiv.org/pdf/2112.09332v3)

附录 J 完整展示一个随机 ELI5 问题的模型引用、人类示范与 Reddit 答案。它说明三类输出的长度、信息量和证据形式不同，而非提供新的总体胜率。引用能让人检查陈述，却不能保证来源可靠、覆盖全面或转述无误。论文也提醒，带引用的文风可能使错误答案看起来更权威；本实验没有测量真实用户长期依赖或实际损失。

## 公开材料与复现边界

官方发布的是适合奖励建模的比较数据。附录 K 报告 19,578 对，它不同于采集总数 21,548，也不同于约 16,000 的最终 RM 训练量。发布集合是在项目结束时标为适合 RM 的记录，不能直接当成论文原训练划分。

本次固定核对 Hugging Face 官方数据仓库 [`openai/webgpt_comparisons@f30e1bd`](https://huggingface.co/datasets/openai/webgpt_comparisons/tree/f30e1bd2f0a51535b493de36d3686cfcfff47abe) 的 README 与加载脚本。该脚本把 OpenAI JSONL 中一对记录展平为一行，提供问题、两个答案、各自引用、token 和偏好分数，且只建立名为 `train` 的一个 split。这个 split 名称不代表恢复了论文 BC、RM、RL 的互斥问题划分。

每对原始记录的分数和为零，正值对应被偏好的一方，零是平局。训练按符号变为硬标签或 50% 软标签，不能把原始 score 直接当作奖励模型的输出，也不能将负值视为损坏数据。token 使用 GPT-2 tokenizer，prefix 含问题与经过截断的引用，completion 是答案；二者拼接是 RM 输入。公开字段没有完整逐步浏览动作，也不包含全部人工示范。

本次实际下载并逐行核对了原始 JSONL：19,578 对记录，对应按数据集名称与问题 ID 去重后的 19,375 个问题；所有成对问题一致，所有两侧分数和为零。按两侧分数都为零统计，平局共 5,232 对。这是公开文件的描述，不是主图评估的平局分母。

| 公开文件的问题来源 | 比较对数 |
| --- | ---: |
| ELI5 | 19,098 |
| ELI5 fact-check（字段名 `critique_eli5`） | 185 |
| TriviaQA | 134 |
| ARC Challenge | 84 |
| ARC Easy | 77 |
| 总计 | 19,578 |

采集表与发布文件相差 1,970 次比较，数量差全部体现在 ELI5 一栏；公开资料没有给出逐条排除理由，不据此猜测是低质量或泄漏。39,156 个答案记录中有 1,797 个空答案字符串，961 个空引用列表，两个集合不能直接相加。加载脚本不自动删除这些记录；复现者需要明确处理规则，不能悄悄清洗后仍声称使用了相同分母。

实际文件为 278,540,416 字节，SHA-256 为 `a1ac671e1b1a58cd649fb6567489fc4080e42125c04acda5d854b96ef1cef7ca`。以上核查没有重跑模型，也没有把空答案计数解释为 TruthfulQA 中的 74 个截断空回答，两者来自不同资料。

加载脚本自身固定在上述提交，但它访问外部 JSONL 的 URL，没有在 URL 中固定不可变版本。严格归档还需要保存实际文件与 SHA-256。公开的是数据加载器，不是 WebGPT 浏览环境、BC/PPO 训练和评估的完整代码；本次未定位到官方模型权重及端到端训练工程，不将第三方同名项目当成原实现。

复现仍需要原始模型检查点、示范轨迹、精确训练评估索引、奖励模型划分、搜索及网页快照、上下文与引用长度配置，以及相同的人类评审协议。网页变化本身也会改变访问结果。本次完成论文全部 32 页与附录、关键图表、公开加载代码和完整偏好文件核查，没有训练模型、调用付费接口或重现主实验胜率。
