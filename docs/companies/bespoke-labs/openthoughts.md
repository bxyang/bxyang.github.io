# OpenThoughts：用系统实验寻找推理数据配方

训练一个能解数学和编程题的小模型，可以让较强的教师先写出推理过程，再让学生学习这些回答。训练材料涉及几组相互关联的选择：不同题目与同题多解的比例、答案验证与轨迹保留的取舍，以及教师自身能力和学生学习效果的关系。OpenThoughts 用一千多次数据与训练实验研究这些选择，最终形成 120 万条问答的 OpenThoughts3-1.2M，并仅通过监督微调训练 OpenThinker3-7B。论文报告其 AIME 2025、较新时间段 LiveCodeBench、GPQA Diamond 得分分别为 53.3%、51.7%、53.7%。这些是 2025 年论文设置下的结果，不代表后续模型榜单。[论文 §1、表 1](https://arxiv.org/pdf/2506.04178v2)

## 训练材料怎样变成推理能力

一个监督微调样本包含问题 $x$ 和教师生成的回答 $y$。回答通常由推理文本与最终答案两部分组成，训练时都作为学生需要预测的输出。教师给的是具体文本，不是整个词表上的概率分布，所以这是以生成序列为目标的蒸馏。

下面的形式只用于说明数据结构，不是论文中的实际题目：

```text
用户：一个数列满足给定递推关系，求第 n 项。
助手：<think>推导、检查边界条件、验证结果……</think>
最终表达式与必要说明。
```

对应的标准监督目标可以写为：

$$
\mathcal L(\theta)=-\frac{1}{Z}
\sum_{(x,y)\in\mathcal D}\sum_{t\in\mathcal T_y}
\log p_\theta(y_t\mid x,y_{<t}).
$$

$\theta$ 是学生参数，$\mathcal T_y$ 是回答中参与训练的 token 位置，$Z$ 为有效目标 token 数，用来归一化。该式是对公开 SFT 实现的概括，不是论文提出的新损失函数。仓库内 LLaMA-Factory 的默认 `train_on_prompt=False` 会把用户提示对应标签设为忽略，只学习回答；论文的配置采用全参数微调，没有在这一步加入奖励模型或强化学习更新。[训练预处理代码](https://github.com/open-thoughts/open-thoughts/blob/e86cf2dbbe69ae178aec302be33a3454a7183457/open_thoughts_3/dcft/train/llamafactory/src/llamafactory/data/processors/supervised.py)

因此，配方改变的是学生反复学习的文本分布。题目过易、与评测领域不匹配，或者推理文本缺少有效的中间步骤，即使都来自一个强教师，也可能得到较弱的学生。论文用训练后的结果衡量数据，而不是先给每条文本一个主观“质量分”就认定它有效。

## 小规模实验如何选择最终配方

主实验大多为每种策略构造 31,600 条数据，用同一个 Qwen2.5-7B-Instruct 起点微调。这一规模位于 10K 与 100K 的对数中点附近，便于在预算内比较大量策略。每完成一个阶段，就选出得分最高的方法，再继续下一阶段。它是顺序选择流程，不是把所有参数组合穷举一遍，因此无法排除某个早期未胜出的策略与后续方法搭配后反而更好的可能。[论文 §4](https://arxiv.org/pdf/2506.04178v2)

数据生成按数学、代码、科学三个领域分别探索，但每个候选策略的选择依据是八个开发基准的整体平均表现。数学有三项、代码三项、科学两项，因此平均值为：

$$
A_8=\frac{3A_{\mathrm{math}}+3A_{\mathrm{code}}
+2A_{\mathrm{science}}}{8}.
$$

这里三个领域均值分别由所属基准平均得到。它不是三领域各占三分之一，也不是把所有评测题合并后统计正确率。一套代码数据可能主要提高了数学或科学，从而在整体排名上获胜，即使它的代码分数不是最高。

| 用途 | 基准 | 题数与重复评测 |
| --- | --- | --- |
| 配方选择：数学 | AIME24、AMC23、MATH500 | 30、40、500 题；前两者各重复 10 次，MATH500 单次 |
| 配方选择：代码 | CodeElo、CodeForces、LCB 05/23–05/24 | 391、453、511 题；分别重复 3、3、6 次 |
| 配方选择：科学 | GPQA Diamond、JEEBench | 198、515 题；各重复 3 次 |
| 完成配方后再测 | AIME25、HMMT 02/25、HLE 文本选择题子集、LCB 06/24–01/25 | 30、30、512、369 题；分别重复 10、10、3、6 次 |

评测使用 Evalchemy，统一温度 0.7、`top_p=1.0`、最多生成 32,768 个新 token。表中报告多次完整评测的平均准确率和标准误；这是重复采样后的平均单次表现，不是多次中挑对一次的 Pass@k，也不是多数投票得分。代码任务虽然名称包含 CodeElo，主表仍按准确率列示，不能把 31.0 写成 Elo 等级分。[论文附录 E、表 13](https://arxiv.org/pdf/2506.04178v2)

论文常把距最高值两个标准误以内的值加粗。这种展示规则不等同于对一千多次实验做过多重比较校正；反复使用八个基准选择配方也存在适应这些开发基准的可能。四个未参与配方选择的测试集用于进一步检查迁移，但不能证明所有任务都得到同样改善。

## 第一步：选择问题来源

来源分成三类：直接由模型生成的问题、从网页或教材等材料转换的问题、人类在论坛或竞赛中写的问题。来源实验把原答案替换为同一教师 R1 的回答；某来源不足 31,600 条时重复问题补足，避免直接把原数据集大小等同于配方效果。[论文 §4.1、附录 R.1](https://arxiv.org/pdf/2506.04178v2)

正文称比较 27 个代码来源、21 个数学来源、14 个科学来源；附录表 33 实际列出 22 行数学策略，其中包含不同生成变体。本文按表中具体策略解释结果，不把这些口径差别抹平为精确的唯一来源总数。

| 领域 | 最后选中的来源 | 数据性质 |
| --- | --- | --- |
| 数学 | `ai2-adapt-dev/openmath-2-math` | OpenMathInstruct2 的 MATH 相关子集，以合成问题为主 |
| 代码 | StackExchange CodeGolf、OpenCodeReasoning | 编程谜题与竞赛编程问题 |
| 科学 | StackExchange Physics、有机化学 PDF 流程 | 物理社区问答，以及从教材、解答材料等提取并补齐上下文的题目 |

科学 PDF 不是简单抽取一段文字就直接训练：流程先用 Gemini 做文字提取，再用 GPT-4o-mini 提取独立问题及选项、补齐上下文、去掉不可回答或不属于目标领域的题目，最后筛出有机化学问题。问题构建中可能利用原资料，但最终推理回答重新由选定教师生成。[论文附录 R.1.3、图 20–26](https://arxiv.org/pdf/2506.04178v2)

来源差异很大。代码来源实验中，CodeGolf 的八项平均为 38.8，SQL 问题来源为 21.6，相差 17.2 个百分点；这两个值不是“代码领域平均”，它们包括其他领域的迁移表现。OpenCodeReasoning 的代码平均 27.5 高于 CodeGolf 的 25.3，但整体平均为 38.4，略低于 CodeGolf。[论文表 3、表 32](https://arxiv.org/pdf/2506.04178v2)

这些结果说明，在这套竞赛式评测下，来源与任务形态有很大影响。它们没有证明 SQL、软件维护或业务编程数据对各自应用不重要，因为对应实际任务并未作为选择目标。

## 第二步：少数来源混合与问题筛选

### 增加来源数量未必增加有效信息

混合实验按上一阶段排名取前 $N$ 个来源，每个来源抽取 $31,600/N$ 条，固定总量 31,600，扫描 $N\in\{1,2,4,8,16\}$。代码前两个来源的整体平均为 41.3，前 16 个为 36.4，相差 4.9 个百分点；数学单一来源为 37.6，16 来源为 33.8；科学两个来源为 33.7，单个为 33.6，差别较小。[论文表 4、表 35–37](https://arxiv.org/pdf/2506.04178v2)

增加来源时，也引入了排名较低的来源，并减少每个强来源的份额。因此，这个实验支持“当前固定样本预算下，选少量高分来源”，不单独证明多样性本身有害。

### 过滤问题与过滤答案是不同步骤

问题过滤发生在昂贵的教师生成之前，目的是从大量候选题中选出更值得生成答案的题。最终代码使用 GPT-4o-mini 按 ICPC 难度标尺给出 1–10 分，优先保留难题；数学和科学让 GPT-4.1-mini 先试答，再按回答长度选题。[论文 §4.3、附录 R.2](https://arxiv.org/pdf/2506.04178v2)

这里的“长度筛选”没有把 GPT-4.1-mini 的试答直接作为最终训练推理。它只是用一个较便宜的模型估计题目所需的展开程度，随后让教师重新作答。公开 `get_lengths` 用 Python `len()` 计算字符串长度，因此该实现的排序量是字符数，不应未经核实写成 token 数。[长度计算代码](https://github.com/open-thoughts/open-thoughts/blob/e86cf2dbbe69ae178aec302be33a3454a7183457/open_thoughts_3/dcft/data_strategies/InstructionFiltering/gemini_length_filtering/utils.py)

附录完整表比正文概括更容易核对：

| 领域 | 最终选题方式的整体平均 | 随机选题 | 直接差值 |
| --- | ---: | ---: | ---: |
| 代码：难度筛选 | 43.0 | 39.7 | +3.3 个百分点 |
| 数学：GPT-4.1-mini 回答长度 | 41.9 | 35.2 | +6.7 |
| 科学：GPT-4.1-mini 回答长度 | 35.9 | 33.8 | +2.1 |

数据来自表 38–40。正文把数学与代码改善概括为约 4% 和 6%，与完整表直接相减不一致，因此本文采用上表的明确数值。代码难度筛选的代码领域平均为 27.7，还低于随机选题的 28.6；它胜出主要体现在其他领域得分提高，符合前述按八项整体平均选择的规则。

此外，长度代理依赖试答模型，不能一概说越长越好。数学表 39 中 GPT-4.1-mini 策略平均为 41.9，而 GPT-4o-mini 的长度策略只有 6.8；论文未给出这一异常下降的充分机制分析。FastText 与嵌入相似度方法也参与比较，但在最终选中的策略里没有胜出。

## 第三步：给同一个问题生成多个回答

来源数据中可能存在重复问题，研究因此同时扫描去重强度与每题采样数：不去重、精确去重、模糊去重，配合每题 1、4、16 个回答。固定训练行数时，每题回答越多，可覆盖的不同问题就越少；这把问题多样性与回答多样性放进同一预算中比较。[论文 §4.4、附录 S.4](https://arxiv.org/pdf/2506.04178v2)

最终选择数学、科学精确去重，代码不额外去重，每题生成 16 个回答。这是一个便于扩大数据量的配方，但不是所有领域在小规模实验中的绝对最高值。

| 领域 | 部分关键策略 | 八项平均 |
| --- | --- | ---: |
| 数学 | 精确去重，每题 1 个回答 | 41.7 |
| 数学 | 精确去重，每题 16 个回答 | 40.1 |
| 数学 | 精确去重，每题 4 个回答 | 39.2 |
| 代码 | 精确去重，每题 4 个回答 | 41.3 |
| 代码 | 不去重，每题 16 个回答 | 41.3 |
| 科学 | 精确去重，每题 16 个回答 | 36.2 |

这里特意采用表 41–43 和附录 S.4 的口径：正文 §4.4 说数学“4 次最好”，但表 42 明确列为 **1 次最好**，附录文字也承认这一例外。数学最终采用 16 次，是接受较小规模得分差异以换取扩展空间，不能解释成实验已经证明每题 16 次普遍优于 1 次。

最终 120 万条中的“条”也不是不同题目数。按每题 16 条换算，总计约 75,000 个采样问题位置；同一问题会反复出现，代码来源还可能含已有重复。若数据中一题有 16 条不同回答，训练五轮也不等于看过 80 个不同问题。

## 第四步：回答过滤实验与最终选择

回答过滤实验先生成 63,200 条，再通过各策略取出 31,600 条训练，包括随机、保留较长或较短答案、多数一致、模型判断正确性、FastText、语言与段落过滤。它还比较一个保留全部 63,200 条的“不筛选”版本。[论文 §4.5、附录 R.4](https://arxiv.org/pdf/2506.04178v2)

| 领域 | 全部 63,200 条 | 随机 31,600 条 | 具有代表性的过滤策略 |
| --- | ---: | ---: | --- |
| 数学 | 41.9 | 41.6 | GPT 正确性验证 40.0；最长回答 40.5 |
| 代码 | 42.2 | 39.8 | FastText 42.3；GPT 验证 40.7 |
| 科学 | 38.3 | 36.5 | 最长回答 37.5；GPT 验证 35.6 |

单位为八项基准平均准确率，来自表 44–46。代码 FastText 相对随机子集有改善，与全部数据接近；数学不同筛选大多不及随机；科学仍是保留全部数据最好。作者据此选择不做最终回答过滤。

“不筛选”使用两倍样本，训练量没有完全控制，所以可得结论是：**在这些实验里，筛选没有提供足以抵消丢弃一半数据的稳定收益**。这不是对“正确答案不重要”的证明，也没有比较同等总 token、同等训练时间下所有可能的验证方法。最终训练集未经过答案正确性过滤，不意味着其每条推理与答案都由专家确认正确。

附录的补充实验也限制了概括的范围。第一代数据上，7B 未验证模型平均 45.0，高于验证版 41.9；32B 则是验证版 64.5，高于未验证版 62.1，方向并不相同。另一个代码实验让 GPT-4o-mini 生成 Python 单元测试，再比较各 16K 条数据，过滤版 LCB 为 36.0，随机版为 38.5；这只检验了这一套自动生成测试，不能等同于使用完整人工测试套件。[论文表 15、表 18](https://arxiv.org/pdf/2506.04178v2)

附录还比较了数学答案提取器：同一个用 LLM 验证数据训练的模型，表 17 在 MATH500 上用默认提取器得 84.4，改用 Math-Verify 得 89.0。评分端的解析差异会改变结果，不能只记录模型名称而不保存评测实现。

## 第五步：教师自身能力与教学效果

最终教师改为 QwQ-32B。论文表 29 中，R1 的十二项平均为 65.3，QwQ 为 64.2；但在相同学生起点上，QwQ 生成的数据更有利于学生训练。这里比较的是数据对学生的作用，与教师直接答题的排名不是同一指标。[论文 §4.6、表 29](https://arxiv.org/pdf/2506.04178v2)

正文表 8 与附录表 47–48 存在需要保留的数值差别：

| 数据领域 | QwQ 教师得到的学生平均 | R1：正文表 8 | R1：附录完整表 |
| --- | ---: | ---: | ---: |
| 代码 | 44.2 | 42.3 | 38.0 |
| 数学 | 44.2 | 41.6 | 40.6 |
| 科学 | 39.1 | 未在表 8 列出 | 35.9 |

两组都支持 QwQ 优于 R1 的方向，但代码增益分别是 1.9 与 6.2，数学分别是 2.6 与 3.6 个百分点。论文没有在这些表之间明确交代运行或样本变化，因此本文不挑选其中一组冒充唯一确定的效应大小。公开代码的单项实验配置也各有数据路径，不能只按相同教师名称合并结果。

作者同时测试 Phi-4-reasoning-plus。它在代码评测里极低，表 29 明确指出一部分原因是模型输出没有代码围栏标记，Evalchemy 无法按预期提取代码。由此得到的低分包含格式兼容问题，不能直接解释为模型完全不具备编程能力。[论文附录 K](https://arxiv.org/pdf/2506.04178v2)

QwQ 作为教师更有效的机制没有被单独确定。论文没有通过控制正确率、长度、语言风格等因素的完整实验，证明是某一个因素导致差异；可核实的结论限于这些教师、数据和学生组合。

## 120 万条数据与最终训练

最终领域配比为数学 850,000、代码 250,000、科学 100,000，约占 70.8%、20.8%、8.3%。比例沿用前一代的经验，没有在本文里做完整的三领域权重优化。[论文 §5](https://arxiv.org/pdf/2506.04178v2)

图 4 把大规模流程画成：约 290 万数学候选题筛到 180K，代码筛到 60K，科学筛到 60K；数学、科学精确去重后约为 80K、50K，代码保持 60K；再抽取约 53K、16K、6K 个问题位置，各生成 16 次回答。图中这些整数 K 是近似展示，不能用 53,000×16 强行推出精确 850,000。精确发布行数以数据卡的 1,200,000 为准。

训练使用 LLaMA-Factory、DeepSpeed ZeRO-3、AdamW，学习率余弦下降，预热比例 0.1，权重衰减为零，Adam 的两个动量参数为 0.9、0.999。不同数据规模使用不同超参数：[论文附录 D、表 9](https://arxiv.org/pdf/2506.04178v2)

| 规模档 | 代表数据量 | 学习率 | 全局批量 | 训练轮数 | 样本拼接 |
| --- | --- | ---: | ---: | ---: | --- |
| Micro | 约 316 | 1e-5 | 32 | 13 | 关闭 |
| Small | 1K、3.16K | 2e-5 | 96 | 7 | 关闭 |
| Medium | 10K、31.6K | 4e-5 | 128 | 5 | 关闭 |

因此图中的扩展曲线同时伴随按规模选择的训练超参数，不是只增加数据、其他设置完全不变。对比不同数据配方时，同一规模遵循共同训练方案，仍比直接比较来源不同的官方模型更接近数据控制实验。

当前公开 `reasoning_large.yaml` 还明确设置 `cutoff_len=16384`、BF16、`packing=true`、`neat_packing=true`。训练序列上限 16,384 与评测输出上限 32,768 不同。内置预处理会按长度限制截取输入和目标；拼接在处理后的序列上执行，并给不同样本设置分段注意力标识。不能因为论文说“不把长序列切成多个样本来拼接”，就认定所有超长推理都被完整保留。[固定训练配置](https://github.com/open-thoughts/open-thoughts/blob/e86cf2dbbe69ae178aec302be33a3454a7183457/open_thoughts_3/dcft/train/hp_settings/paper/reasoning_large.yaml)

模板使用 `think` 起止标记，而第一代曾使用 Sky-T1 的 thought/solution 标记。表 11 显示两种格式结果有升有降，例如 LCB 从 41.8 变为 33.6，所以只宜说模板比较未呈现全面一致优势。表 12 的“开启/关闭 reasoning”实验用的是 Nemotron Nano，不能移写成 OpenThinker3 的开关消融。

总体平均领先不意味着每个任务都领先。OpenR1 的 GPQA-D 为 58.9，高于 OpenThinker3 的 53.7；AceReason 的 AIME24 为 71.0，高于其 69.0；HLE 子集上 OpenThinker3 只有 10.2，低于起点的 12.7。论文也指出 HLE 没有随规模稳定改善，AMC23、MATH500 则开始接近饱和。[论文表 1、附录 G](https://arxiv.org/pdf/2506.04178v2)

这组模型对比包含 SFT、RL、SFT+RL，不是等起点、等训练预算的“算法优劣”实验。能支持的结果是，这个只用 SFT 的具体配方在作者列出的同规模模型中取得最高整体平均；不能进一步推出强化学习没有作用。

第一代到第三代的进步同样要按同表口径看。论文表 2 中 7B 系列 AIME24 从 29.3、60.7 到 69.0，GPQA-D 从 44.1、47.0 到 53.7；其他表和当前模型卡的一代结果有所不同，不应把不同评测记录拼成一条无误差的增长曲线。

## 去污染：规则、验证样本与代码差异

论文采用两条规则，任一命中即删除训练样本：字符串相似度达到 75%，或者用 Qwen2-7B-Instruct tokenizer 分词后，共享任意连续 13-token 片段。注意这里指定的是 Qwen2 的 tokenizer，不能自动替换成学生 Qwen2.5 的版本。[论文附录 F](https://arxiv.org/pdf/2506.04178v2)

原文公式为：

$$
S_{\mathrm{paper}}(a,b)=100\frac{\operatorname{LCS}(a,b)}
{\max(|a|,|b|)},
$$

其中 LCS 为最长公共子序列长度。代码 `decontaminate_fuzzy_w_ngram` 则调用 `process_string_pair`，后者使用 RapidFuzz `fuzz.ratio`。该函数的归一化 Indel 相似度对应：

$$
S_{\mathrm{code}}(a,b)=100\frac{2\operatorname{LCS}(a,b)}{|a|+|b|}.
$$

字符串长度不同时，两式不等价。例如说明性字符串 `abc` 与 `abcd` 的 LCS 长度为 3，原文式得到 75，后一式约为 85.7。本文没有假定原文公式与当前实现完全一致；重做去污染时应明确到底使用哪个规则，并保存训练、评测文本及 tokenizer 版本。[调用代码](https://github.com/open-thoughts/open-thoughts/blob/e86cf2dbbe69ae178aec302be33a3454a7183457/open_thoughts_3/dcft/data_strategies/DeepSeekR1/utils.py)、[RapidFuzz 定义](https://rapidfuzz.github.io/RapidFuzz/Usage/fuzz.html#ratio)

人工构造的检查集包含 3,092 个污染样本、3,000 个非污染样本。污染样本包括直接复制、添加外层文字、同义或等价表达替换、格式变化。图 7 给出 3,080 个污染样本检出、12 个漏掉，干净样本中 42 个误删、2,958 个保留。因此污染检出率为 3,080/3,092≈99.6%，非污染误删率为 42/3,000=1.4%。原文把 99.6% 称作 true negative rate；本文按“污染”为正类直接描述检出率，以免混淆正负类定义。[论文图 7](https://arxiv.org/pdf/2506.04178v2)

这些规则在该构造集上工作较好，但并不覆盖所有语义改写，也不证明起始学生或教师的预训练数据没有评测内容。去污染检查与四项“未参与配方选择的评测”解决的是两个问题：前者减少训练文本与题目重合，后者减少直接根据同一评测调整配方。

## 扩展实验补充了哪些边界

### 长推理有用，但裁剪实验包含多种变化

附录 H.3 用 12K 样本比较压缩推理。原始平均长度约 11,593 token，四项平均为 51.4；去除自我反思相关内容后平均长度降到 328，平均分为 26.3。只保留不超过 2,048 token 的样本时为 34.2，放宽到 8,192 时为 42.3。[论文表 22](https://arxiv.org/pdf/2506.04178v2)

前一种处理大幅改变文本内容和长度，后一种还减少样本数量。它们说明这些裁剪方案损害了当前训练结果，但不能把全部下降分离归因于“自我反思词语”或单独的长度。推理链更长也不保证某一道输出更正确：附录 I 的采样分析发现，部分模型的错误回答更长；这是测试时输出与错误的相关性，与训练时选题代理不同。

表 26 的 GPQA 高重复次数实验还显示，“取最短回答”并非普遍优于普通采样：s1 的最短方案为 50.0，普通采样为 52.79；Sky-T1 分别为 40.91、49.99。不能只采用附录文字中“最短通常最好”的概括而略去表中反例。

### 单领域迁移增益没有简单相加

两个代码数据版本单独训练时 GPQA-D 为 47.3 与 36.7，相差 10.6 个百分点；分别混入相同科学数据后，两个模型都变为 52.7。单独观察到的代码到科学迁移优势没有继续叠加。混合后各有 62K 条，而单领域为约 31K，所以这里主要比较两种混合配方之间的差异。[论文表 24](https://arxiv.org/pdf/2506.04178v2)

这个结果与全流程按跨领域平均选择策略的方式有关：局部策略在单领域训练中胜出，不保证放进最终三领域混合后保留同样优势。

### 其他学生与专业任务

100K 数据在 Llama-3.1-8B-Instruct 上同样带来提升，例如 AMC23 从表中隐含的 15.8 提升到 75.2，MATH500 从 43.2 到 83.8；不过 Qwen 起点训练后整体更强。这支持数据效果并非只出现在一种学生架构，不等于已经对所有模型规模验证。[论文表 14](https://arxiv.org/pdf/2506.04178v2)

附录 J 另做 Lawma 法律意见三分类，用 5.44K 训练题、1.52K 测试题。选 2K 训练题、每题 R1 采样五次后，以多数一致保留约 8.3K 条，学生准确率为 81.9%，教师为 73.9%；用专家标签筛选约 7.36K 条时为 82.8%。这是单独专业数据实验，不是 OpenThoughts3 三领域混合在法律任务上的结果，也不能由此推断学生整体超过教师。

### 简单改写与安全行为

附录 N 的 Alice in Wonderland 测试改变问题表述或变量而保持抽象解法不变，使用温度 0.1、每个变体采样 100 次、最多 30,720 输出 token，设置与主表不同。蒸馏模型在这些变体间仍有明显波动。因此，高竞赛分数没有消除简单结构保持变换下的不稳定。

附录 L 则评估安全和过度拒绝：HarmBench 400 个提示由 GPT-4o 评分，报告得到最高有害等级 5 的比例；XSTest 使用 250 个安全提示，报告误拒率。Qwen 起点有害率为 14.5%，OpenThinker3 为 55.5%；误拒率分别为 4.4%、5.6%。第三代没有专门加入安全对齐数据。这是论文实测的局限，并不证明推理能力与安全性必然存在无法消除的权衡，因为未做控制其他因素的安全训练干预。[论文表 30、附录 N](https://arxiv.org/pdf/2506.04178v2)

| 资料 | 固定版本 | 核查范围 |

| OpenThoughts3-1.2M | `61bcf9d4eb38b30295efc2021227a63cc5bb34c8` | 数据卡与元信息；另外抽看公开 Viewer 的十条样本，未下载全部数据做重算 |

固定数据卡列出 1,200,000 条训练记录，压缩下载量约 28.2 GB、逻辑数据量约 59.8 GB。字段包括 `difficulty`、`source`、`domain`、`conversations`。抽看的对话使用 `human/gpt` 角色，回答含 `think` 标记；这些字段不能代替逐条正确性标签，`difficulty` 也不应解释成对全部最终答案质量的评级。[固定数据卡](https://huggingface.co/datasets/open-thoughts/OpenThoughts3-1.2M/blob/61bcf9d4eb38b30295efc2021227a63cc5bb34c8/README.md)

从已有数据训练与重新制作数据，是成本和要求不同的两条路线。前者可固定 revision 加载训练集：

```python
from datasets import load_dataset

data = load_dataset(
    "open-thoughts/OpenThoughts3-1.2M",
    revision="61bcf9d4eb38b30295efc2021227a63cc5bb34c8",
    split="train",
    streaming=True,
)
row = next(iter(data))
print(row["domain"], row["source"])
```

随后按公开训练框架配置数据映射，保留对话角色与回答中的推理标记。31.6K 比较实验应使用 Medium 档；复现完整模型用 Large 档。仓库给出的集群入口形式为：

```bash
python3 -m hpc.launch \
  --train_config_path dcft/train/hp_settings/paper/reasoning_large.yaml \
  --dataset open-thoughts/OpenThoughts3-1.2M \
  --num_nodes 128 \
  --time_limit 48:00:00
```

这条命令表达作者 HPC 启动方式，依赖调度器、集群环境和框架的数据映射，并非在普通电脑上可直接执行的一条复现命令。应先以小数据检查预处理后的 `input_ids`、忽略标签、长度截断和拼接，再投入完整训练。[第三代运行说明](https://github.com/open-thoughts/open-thoughts/blob/e86cf2dbbe69ae178aec302be33a3454a7183457/open_thoughts_3/README.md)

若重新生成数据，还需各来源快照、GPT-4o-mini/GPT-4.1-mini 等筛选服务、QwQ 教师服务或部署资源、失败重试与缺失响应统计。仓库包含大量单项实验 YAML，不能从某一个 QwQ 配置推断整套最终运行参数已统一：本次查看的数学教师消融配置使用 31,600 条、温度 0.999、最多 32,000 输出 token，并允许部分响应缺失；它不是最终每题 16 次、总计 120 万行的独立证明。生成前需用自己的服务配置，核对依赖与输出路径，不直接提交已有实验配置。

复现评测还应明确采用本文八项开发集和四项留出集。第三代 README 的示例命令额外列入 MMLUPro，“Full Eval”示例没有 HMMT，与论文表 13 不完全相同；直接使用该命令得到的平均值不能当作表 1 的十二项平均。当前 AIME24 代码保留十次重复，LiveCodeBench 保留六次；两者读取并解析输出后计分，没有把六次评测自动变成六轮模型修复。[AIME24 实现](https://github.com/mlfoundations/Evalchemy/blob/6ed674159b37f740f2353a86f596f49f6ac13c19/eval/chat_benchmarks/AIME24/eval_instruct.py)、[LiveCodeBench 实现](https://github.com/mlfoundations/Evalchemy/blob/6ed674159b37f740f2353a86f596f49f6ac13c19/eval/chat_benchmarks/LiveCodeBench/eval_instruct.py)

模型卡记录 Transformers 4.46.1、PyTorch 2.3.0、Datasets 3.1.0、Tokenizers 0.20.3，随机种子 42。代码当前依赖并未全部固定，重建环境应保存最终解析的版本清单。模型卡文字写“512 A100 nodes”，但同卡 `num_devices=512`，论文附录 O 则明确为 **128 节点、每节点 4 张 A100，共 512 张 GPU**；本文采用后者，不把设备数当节点数。

算力也需要区分单位。论文报告最终标注约 22,000 H100 GPU 小时，单次完整训练约 25,000 A100 GPU 小时，单次评测约 32 GPU 小时；其中标注和评测运行在 GH200 节点。31,600 条规模的 R1 API 标注每次约 300 美元。25,000 GPU 小时不是 25,000 小时墙钟时间；按 512 张卡粗略换算约 49 小时，与模型卡约 48 小时相近。这些数字也不包含一千多项探索的全部总成本。[论文附录 O；模型卡](https://huggingface.co/open-thoughts/OpenThinker3-7B/blob/864fb9aefbb91f257c4911e4b9f85a6986f8eab2/README.md)

最终数据与模型卡标注 Apache 2.0；原始素材另有自己的许可。附录 Q 列出 StackExchange 的 CC BY-SA、SCP 的非商业共享许可，以及多本教材保留版权等情况。因此，“最终数据卡开放”不能直接解释成所有原始教材都可无限制再分发；使用具体上游材料时应查对应条目。[论文附录 Q](https://arxiv.org/pdf/2506.04178v2)
