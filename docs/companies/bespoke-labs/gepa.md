# GEPA 精读：从执行反馈中改写提示，并保留互补的搜索路径

一个多跳问答系统第一次检索找到了歌曲资料，第二次却继续搜索歌曲，始终没有找到问题真正需要的专辑资料。最终答案错误，只给系统一个零分很难说明哪一步出了问题。GEPA 会把查询、检索结果、模型输出以及遗漏资料的反馈交给负责反思的语言模型，请它修改相应模块的提示，再运行任务检查修改是否有效。搜索过程中，它保留在不同题目上各有优势的候选，而不是始终围绕平均分最高的那一个继续改写。

在论文的六项任务中，Qwen3-8B 使用 GEPA 后的平均分为 54.85，比所测 GRPO 配置高 5.94 个百分点，但 AIME-2025 上仍低于 GRPO。GPT-4.1 Mini 使用 GEPA 的六任务平均分为 65.22，加上模块合并后为 66.36。这里的收益对应指定模型、系统、数据和预算；GEPA 优化提示，主要 GRPO 对照更新 LoRA 权重，两者使用的反馈形式也不同。（论文 §2–4、表 1–2）

## 优化的是一整套系统中的提示

论文把复合 AI 系统写成 $\Phi=(M,C,\mathcal X,\mathcal Y)$。$M$ 是语言模块集合，$C$ 是控制流程，$\mathcal X,\mathcal Y$ 是系统的输入输出结构。某个模块可以负责写查询、压缩文档或生成答案；同一模块也可以被控制流程调用多次。

每个模块有提示 $\pi_i$ 和模型权重 $\theta_i$。记所有提示为 $\Pi$、所有权重为 $\Theta$，任务输入为 $x$，评分材料为 $m$，例如标准答案、测试或评分规则。评价函数 $\mu(\Phi(x),m)\in[0,1]$ 衡量输出质量，则论文的通用目标是：

$$
\max_{\Pi,\Theta}\;\mathbb E_{(x,m)\sim\mathcal T}
\left[\mu\bigl(\Phi(x;\Pi,\Theta),m\bigr)\right],
\qquad \#\mathrm{rollouts}\le B.
$$

这是原文式 1–2 的合并表达。$\mathcal T$ 表示任务分布，$B$ 是可承担的系统运行次数。**GEPA 固定 $\Theta$，只搜索 $\Pi$**；GRPO 对照主要更新权重。GEPA 不要求取得闭源模型的梯度，因此可以优化通过 API 调用的模型。（§2–3）

一次 rollout 指运行完整系统并评分，不等于一次 LLM 请求。多跳任务的一次 rollout 可能包含多个模型模块、检索调用和评分器请求。反思模型生成新提示的调用又是另一类开销。因此“更少 rollouts”首先是任务交互效率，不自动等于同倍数的 token、费用或时间节省。

## 一次反思更新如何发生

GEPA 把任务资料分为反馈集 $D_{\mathrm{feedback}}$ 和候选选择集 $D_{\mathrm{pareto}}$。主实验分别使用训练集和验证集：反思模型可以读取训练题、标签和反馈；验证题内容不进入提示更新上下文，只通过分数影响候选筛选。测试集用于最终报告。（算法 1、§4、附录 E.4）

一次更新可按下面的顺序理解：

1. 从候选池选择一个完整系统，以及其中要更新的模块。主设置对模块轮流更新。
2. 从反馈集取三道题，执行当前系统，保存该模块的输入、输出和相关轨迹。
3. 反馈函数 $\mu_f$ 返回分数和文字解释，例如哪些约束没有满足、哪些支持文档尚未检索到。
4. 反思模型读取现有提示与这批输入输出反馈，提出一份新的模块指令。其余模块保持不变。
5. 在同一批题上重新运行新系统。平均分严格提高时，才进入更大范围的验证评分，并记录父子关系。
6. 预算耗尽后，返回验证集平均分最高的一个完整候选，而不是在测试时为每道题调用所有候选。

设父候选为 $p$，新候选为 $p'$，本轮训练小批量为 $B_t$，那么进入候选池的基本筛选条件为：

$$
\frac1{|B_t|}\sum_{i\in B_t}\mu(p'(x_i),m_i)
>
\frac1{|B_t|}\sum_{i\in B_t}\mu(p(x_i),m_i).
$$

三道题上的提高不是全体验证集提高的保证。GEPA 会保留其中一些平均分不最高、却在特定题上有用的候选。小批量筛选的作用是避免每次改写都支付完整验证成本。（算法 1、第 6 页）

### 执行轨迹与评分反馈提供不同信息

执行轨迹说明系统做了什么：输入了什么查询、模型怎样回答、工具返回了哪些内容。评分轨迹说明为什么得到这个分数：编译器报错、没有满足的输出约束、遗漏的支持文档等。GEPA 将这两类文本一起交给反思模型，帮助定位需要修改的模块。（§3）

HotpotQA 的研究代码不仅告诉反思模型答案不对，还提供正确答案、支持文档及不同检索阶段找到了什么。因此这种监督比一个标量奖励更丰富。GRPO 对照学习于标量回报，GEPA 学习于带标签内容的文字反馈；结果不能解释成“在完全相同信息下，改提示一定优于更新权重”。若实际项目只有一个最终分数，没有解释性反馈，需要重新测量表现。

附录 C 的更新提示要求模型从输入输出中推断任务细节，把有帮助的事实和可复用策略写进新指令。它没有要求产生一个可解析的错误归因图，也没有显式对每个模块计算梯度；“归因”由语言模型在改写过程中完成。

## 为不同题目保留不同候选

只选平均分最高的候选，容易反复细化同一种策略。GEPA 用每道验证题作为一个比较维度。记 $S_{pi}$ 为候选 $p$ 在验证题 $i$ 的分数，先找每题最好的候选集合：

$$
S_i^*=\max_{p\in\mathcal P}S_{pi},\qquad
\mathcal P_i^*=\{p:S_{pi}=S_i^*\}.
$$

经过算法 2 的过滤后，记留下的集合为 $\widehat{\mathcal P}_i^*$。候选 $p$ 的权重是它在多少题上仍属于最佳候选：

$$
f(p)=\sum_i\mathbf1\{p\in\widehat{\mathcal P}_i^*\},
\qquad
\Pr(p\text{被选中})=\frac{f(p)}{\sum_q f(q)}.
$$

这不是按平均分做 softmax，也不是均匀选择所有历史提示。某个候选即使总分不高，只要解决了其他候选没有解决的题，仍可能继续演化。最后部署的仍是一个验证集整体表现最好的候选。（§3.1、算法 2）

**说明示例：**三个候选在三道题上的分数分别为 A=(1,1,0)、B=(0,0,1)、C=(0.6,0.6,0.6)。A 和 B 各有独特的最高分，经过不改变这两者的过滤后，A 的抽样权重为 2，B 为 1。C 虽然在通常的多目标定义下并未被 A 或 B 单独支配，却没有在任何一道题上第一，因此不进入逐题最佳集合。GEPA 的选择不能简单称为“保留完整数学意义上的所有 Pareto 非支配点”。

### 当前代码的过滤还有一个具体差别

当前公开库的 `remove_dominated_programs` 检查的是：移除候选后，其所有获胜题目是否仍由其他候选共同覆盖。它不要求存在**同一个**候选在全部维度上支配被移除者。

本次对固定提交的纯选择函数做了一个不调用模型的算术检查：三个候选分别为 (1,0,1)、(1,1,0)、(0,1,1)，两两都不严格支配。代码仍可移除第一个，因为它赢的两道题分别由后两个覆盖。过滤保住的是每题至少一个最佳候选，并非原封不动保存全部非支配候选。论文算法中的“dominated”描述和实际过滤实现应分开理解；这不影响随后按保留下来的获胜频次抽样。（[当前选择实现](https://github.com/gepa-ai/gepa/blob/15ee314f9c7d34ec153b809d401f42f55c4dcd76/src/gepa/gepa_utils.py)）

## Merge 按模块组合不同分支

GEPA+Merge 在反思改写之外，还尝试把两条演化分支的模块组合起来。如果分支 A 只修改了共同祖先的查询提示，分支 B 只修改了摘要提示，那么新候选可以拿 A 的查询和 B 的摘要，不必让语言模型从头再写一遍。（附录 D.1、算法 3–4）

合并会检查共同祖先、父子关系、已有合并记录和总体分数。某模块只有一个分支相对祖先发生变化时，选择变化后的提示；两个分支都发生了不同变化时，算法 4 选择整体分数更高的分支对应模块，平局随机处理。

附录文字称分支优化“互不相交”的提示集合，但算法 3 实际只需要找到至少一个“一个分支改变、另一个保持祖先”的模块，算法 4 还明确处理双方都改同一模块的情况。所以，不能把方法写成仅允许所有改动完全不重叠。祖先分数检查也允许相等，不是要求两个分支都严格超过祖先。

主实验每轮反思小批量为三题，启用 Merge 时最多调用五次。研究代码的合并小批量默认实验配置来自验证集；合并通过阈值为新分数不低于两个父候选中较高者。这与普通反思更新使用训练集、要求严格提高的筛选不同。合并没有直接把验证文本交给反思模型，但它仍属于基于验证分数的搜索。（附录 E.4；研究仓库 `gepa.py`）

## 六项任务分别在测量什么

论文的 Aggregate 是六个任务分数的算术平均，不是把所有测试题混合统计。各任务的分数虽都映射到 0–100，含义并不相同。

| 任务 | 系统与目标 | 训练 / 验证 / 测试 | 反馈与计分重点 |
| --- | --- | --- | --- |
| HotpotQA | 两轮检索、两次摘要和最终回答；四个可优化语言模块 | 150 / 300 / 300 | 答案标准化精确匹配；反馈包含正确答案与缺失支持资料 |
| IFBench | 先回答，再由第二模块修改到符合约束 | 150 / 300 / 294 | 平均满足约束比例；训练来自 IF-RLVR，测试含未见约束 |
| HoVer | 最多三跳检索，两次查询生成和两次摘要 | 150 / 300 / 300 | 所有必需支持文档是否都被找到，不是最终真假分类准确率 |
| PUPA | 可信模型改写私密请求，发给不可信模型，再整合回答 | 111 / 111 / 221 | 回答质量与个人信息未泄漏比例的组合分 |
| AIME-2025 | 单模块 Chain-of-Thought 解数学题 | 前三年 90 题平分训练验证；2025 年 30 题各运行五次 | 最终答案正确性；150 个测试输出不等于 150 道独立题 |
| LiveBench-Math | 单模块数学解题 | 2025-07-30 快照 368 题，打乱后分三组 | 使用各数学子类对应评分逻辑；需固定数据版本 |

来源为附录 E.1，以及研究仓库的 benchmark 实现。LiveBench 文字称“等分”，实际代码按前 33%、到 66%、剩余部分切分；若输入确为 368 题，对应 121/121/126，而不是三个完全相等集合。代码 `load_dataset("livebench/math")` 没有指定历史 revision，今天直接加载不保证仍是论文的 368 题。

### 检索题不能只看数据集名称

HotpotQA 的代码每次取七篇文档，第一轮用原问题检索；摘要后再生成第二轮查询；最终回答模块使用两份摘要。它有四个语言模块，但只有两次检索，不能把注释中的第三阶段误写为第三次文档检索。

HoVer 的布尔评分为：

$$
\mu_{\mathrm{HoVer}}=\mathbf1\{G\subseteq R\},
$$

其中 $G$ 是标准支持文档标题集合，$R$ 是已检索文档集合。漏一篇必要文档即为零；多检索一些无关文档不会由这个公式直接扣分。因此表中 HoVer 52.33 不是“52.33% 的事实判断正确”。

### IFBench 使用较宽松的约束检查

研究实现对每条约束检查多种回答版本，包括原文、移除星号，以及去掉首行、末行或两者后的版本。只要其中一种通过该约束，就将这一项记为满足；最终取所有约束的平均。它既不是要求整份回答所有约束同时通过，也不是严格只检查未经处理的原文。训练反馈会列出满足和未满足的具体约束。（研究仓库 `ifbench_metric.py`）

这一设置解释了为什么不能把 IFBench 分数直接读成整题通过率。训练/验证集与测试约束的差异，也使得验证集较高成绩不必然转化为同水平测试成绩。

### PUPA 的总分不能当作零泄漏率

公开代码使用 GPT-4.1 Mini 比较新回答和参考回答的质量，并检查外发请求泄漏了多少标注的个人信息。记质量判断为 $Q\in\{0,1\}$、泄漏比例为 $L$，组合为：

$$
\mu_{\mathrm{PUPA}}=\frac{Q+(1-L)}2.
$$

例如质量通过、泄漏一半已标注信息时，组合仍是 0.75；这不是 75% 的用户获得了严格隐私保护。质量判断还会交换答案顺序调用两次 judge，以处理次序和判断不一致问题。它依赖模型判分，不能当作形式化隐私保证。（研究仓库 `papillon_utils.py`）

另一个代码边界是：PUPA 的不可信外部模型和评分器固定为 GPT-4.1 Mini，即使可信处理模块使用 Qwen。因此“Qwen 系统”的所有参与模型并非都必然是 Qwen；复现不能仅凭主模型名称假定没有 OpenAI API 依赖。

## 模型设置、GRPO 对照和预算

论文允许最多 16,384 tokens 的推理上下文。Qwen3-8B 采用 temperature 0.6、top-p 0.95、top-k 20；GPT-4.1 Mini 固定 API 标识为 `gpt-4.1-mini-2025-04-14`，temperature 1.0。研究代码的反思模型在没有指定 teacher 时沿用当前模型设置；因此不能把论文全部实验说成“由更强的 GPT 模型教小模型”。但 PUPA 的固定外部模型和 judge 依赖需要另外保留。（附录 E.2；研究代码）

GRPO 主对照采用多模块训练实现，使用 LoRA：rank 16、alpha 64、dropout 0.05，作用于 q/k/v/o/up/down/gate 投影，bf16。每步四个输入，每个输入采样 12 条，共 48 条；500 步对应 24,000 条训练 rollout。学习率 $10^{-5}$、KL 系数 0.01、梯度范数上限 0.1，梯度累积 20 步，每 20 个训练步验证一次，以验证集选择结果。训练使用一张 H100 或 A100 80 GB，另配推理 GPU。（附录 E.4）

论文没有展开完整 GRPO 损失推导；它在这里是比较对象。其优化信号来自一组输出之间的相对奖励，通过策略梯度更新权重；GEPA 则把自然语言反馈压缩进提示。本文不把通用 GRPO 的某种实现细节补写为论文已确认的配置。

作者还在两跳、单模块 HoVer 设置中比较了全参数 GRPO：八 GPU、全局 batch 32、group size 16、FSDP2、学习率 $10^{-6}$、训练温度 1.0，每五步验证。图 11 仍显示 GEPA 更高，但这不是在表 1 的全部六任务上重做一次全参数对照，也不是与四模块三跳 HoVer 完全相同的系统。

MIPROv2 使用 `auto=heavy`，产生 18 个指令候选和 18 组引导式少样本集合，再用贝叶斯优化选择模块配置。GEPA 按任务对齐 MIPROv2 实际消耗的 rollout 预算，允许的实际差异不超过 10.15%。Trace/OptoPrime 和 TextGrad 使用同样的数据、初始系统和总运行预算；研究者把 DSPy 的签名与解析提示移植到 Trace，未优化系统分数相差不超过 0.5 点。但 Trace 不支持相同的逐模块反馈接口，因此反馈接入方式仍有差别。（附录 E.4）

### 35 倍运行次数差距的计算口径

| 任务 | 表 1 的 GEPA 总优化预算 | GRPO 训练 rollout |
| --- | ---: | ---: |
| HotpotQA | 6,871 | 24,000 |
| IFBench | 3,593 | 24,000 |
| HoVer | 7,051 | 24,000 |
| PUPA | 2,426 | 24,000 |
| AIME-2025 | 1,839 | 24,000 |
| LiveBench-Math | 1,839 | 24,000 |

表 1 图注另外写道：IFBench 的最终选中提示在第 678 次 rollout 已出现，测试分 38.61，高于 GRPO 的 35.88。$24,000/678\approx35.4$，这就是“最多约 35 倍”案例。若比较完整 GEPA 运行的 3,593 次，则比例约为 6.68，而不是 35。

还要分清成本口径：GEPA 的总预算包含大量验证评分，GRPO 的 24,000 是训练 rollout，训练期间另做验证。反思请求不直接等同于任务 rollout；模型训练反向传播、工具服务、judge 等开销也不同。论文另报告“匹配 GRPO 最佳验证成绩所需的运行数”，属于达到特定阈值的比较，不能与完整优化预算或最终测试优势混成一个数字。

附录 N 报告 GEPA 的反思调用数：GPT-4.1 Mini 六任务分别为 24、34、69、21、92、46 次，Qwen 分别为 90、38、64、17、50、38 次，顺序为 AIME、LiveBench、HotpotQA、IFBench、HoVer、PUPA。调用数有限并不意味着每次反思很短，模型需要读取轨迹和已有提示。

### 分数和显著性的边界

主表没有置信区间、配对显著性检验或多次独立优化随机种子的均值方差。AIME 的五次重复是同一批 30 题的生成重复，不是五次完整重做训练和提示搜索。LiveBench 的划分种子固定为 0，也不能代替优化稳定性实验。

因此本文将优势报告为该实验的点估计，尤其不把不足一个百分点的差异写成已证明的稳定优势。六任务平均也把不同性质的指标等权相加，只能表示这组基准上的汇总，不能当成一个通用准确率。

## 优化后的提示具体学到了什么

HotpotQA 的第二跳提示从简单的输入输出声明，变成要求识别尚缺信息、保留连接实体、避免重复第一跳查询。例如第一跳只有歌曲资料时，下一跳应针对专辑等尚未覆盖的对象。这些规则说明 GEPA 可以改变模块在整体流程中的职责理解，而不只是改措辞。（图 2、附录 L.1–L.2）

PUPA 的一条演化分支逐步加入识别个人信息、对地点和日期做抽象、保护内部名词，并解释改写理由。图 5 中从 82.26 到 97.60 是候选在优化过程中的分数，不应替代主表中最终测试值。提示文字中的“零泄漏”是它对解题模型提出的要求，也不是系统已经获得零泄漏保证。（附录 K）

生成的提示也可能过度概括。Qwen 的 IFBench 提示要求先逐字重复用户问题，即使任务未必要求复述；HotpotQA 的提示还会包含训练例中的具体事实与实体。有些模块完全保留初始提示，例如 GPT-4.1 Mini 的某个摘要模块和 PUPA 的后处理模块。算法优化的是整个系统成绩，不保证每个模块都变长、每条生成指令都成为普遍正确的工作原则。（附录 L）

论文把指令提示与 MIPROv2 的少样本示例提示比较，图 18 显示某些配置最多短约 9.2 倍。但附录 I 的“短约 33%”与图 17 图注的“长度低于约 33%”不是同一句话；图 18 还有按任务和模型给出的不同倍数。本文不从这些文字合成统一的“全部实验节省 33%”结论。提示长度只是输入成本代理，整个任务还有检索内容、回答和多轮调用。（第 11、27、30–31 页）

## 扩展实验与主结果的区别

### 推理时搜索 GPU/NPU 内核

主实验是用训练题学提示，再测新题。内核实验则让反馈集和候选评估集都包含待解决任务，允许反复优化这些任务本身；它测的是推理时搜索，不是对未知测试题的泛化。（§5.1）

在早期 NPUEval 的 AMD XDNA2 任务中，GPT-4o 每题最多顺序修复十次，平均向量利用率为 4.25%；加技术手册检索为 16.33%，再加 MIPROv2 为 19.03%。GEPA 的单个最终提示达到 26.85%，按逐题 Pareto 候选获得的结果为 30.52%。后两个数的候选使用方式不同，不能把 30.52 当成统一单提示结果。最高约 70% 是个别内核的向量利用率，不是整体正确率或加速倍数。（图 7、附录 M.1）

KernelBench 使用 35 道代表题，目标 NVIDIA V100，GPT-4o 每题最多五次顺序修复。图 8 中 `fast_1` 超过 20%，表示超过五分之一任务生成了正确且快于 PyTorch eager 的内核；它不是平均加速 20%。作者通过缓存减少相同提示下采样随机性，将预算增长与提示更新区分。这些是初步结果，没有完整展示所有硬件、规模和编译环境下的可迁移性。

附录 M 的优化提示包含具体代码模板和 API 建议；本次阅读没有编译这些模板。生成提示中出现一段代码，与该代码已经在本机验证正确，是不同的证据。

### 反向优化用来检查指令鲁棒性

另一个实验把目标反过来，在保留题目内容的前提下搜索会降低表现的附加指令。使用 AIME 2022–2024 题搜索，再在 2025 年 30 题各生成五次，GPT-5 Mini 的评分从 76% 降至 10%。人工检查发现大量输出把格式占位符原样作为结尾，说明严格答案解析与无关信息组合产生了格式遵循失败。（§5.2）

这个结果不等于模型的数学推理正确率必然下降 66 点；原文明确把大量损失联系到最后答案格式的误解。它也不是主表两个模型之一的训练实验，不能把这一行加入六任务平均。

### 会改变结果的几个默认值

| 核对项 | 论文与公开代码的差别 |
| --- | --- |
| 上下文预算 | 论文说推理窗口最多 16,384；研究配置的 Qwen 启动 `MAX_CONTEXT_LENGTH` 为 8,192，需要确认实际运行日志和服务参数 |
| LiveBench 快照 | 论文指定 2025-07-30 的 368 题；数据加载器未固定 revision，按 0.33/0.66 切分 |
| 验证集 | 当前 `gepa.optimize` 不传 `valset` 时复用训练集，不等于论文的独立验证集 |
| Merge | 当前 API 默认关闭，最大调用数 5；需要明确选择普通 GEPA 还是 GEPA+Merge |
| 现代 AIME 示例 | 当前 `examples/aime_math` 使用 GPT-4.1 Mini 解题、GPT-5.1 反思、500 次 metric 调用，并使用 `optimize_anything`；不能直接当作表 2 的重跑 |
| 研究缓存 | 配置会复用既有优化器缓存；必须保留缓存政策和服务端采样设置，区分请求次数、缓存命中和实际模型执行 |

当前库已经支持优化代码等更广泛文本对象，但这些后续接口不等于 v2 主实验全部测过的能力。对于自己的任务，最小接入需要提供候选提示、训练样本、独立验证样本、执行及评分函数，并显式设定反思模型、批量和预算。评价函数返回的文字反馈应来自训练侧，不应把保留测试答案放进优化上下文。

完整复现应同时保存：数据内容及划分、模型和反思模型标识、每个模块提示、候选父子关系、逐题验证分数、训练/验证 rollout 计数、反思请求数、缓存配置、最终一次性测试结果。仅保存最终提示和一个 Aggregate，无法核对搜索时使用了哪些反馈和预算。

## 阅读覆盖与适用范围

本篇已阅读正文、算法及实验附录，检查搜索树、完整模块提示、内核与对抗扩展实验；查看主表 PDF 版面，核对六任务代码指标、当前候选过滤和研究配置，并做了本地候选选择算术检查。没有训练 GRPO、运行收费模型、编译 GPU/NPU 内核或解压全部实验日志。数字来自论文报告；自拟算例和代码观察已单独注明。

GEPA 的证据支持：在这组任务上，基于执行反馈进行提示搜索可以用较少系统运行取得较好的适配结果；保留逐题互补候选比所测贪心和 beam 策略表现更好。它没有证明所有任务都应放弃权重训练，也未提供足够实验来保证任意模型、反馈质量和预算下都获益。跨随机种子稳定性、所有方法完全等价的成本核算、反馈信息量的独立消融，以及历史外部服务的精确复现，仍需要额外证据。
