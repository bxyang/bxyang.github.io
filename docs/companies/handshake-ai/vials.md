# VIALS：从生命科学图像中读出正确答案

一张生命科学图像可能同时包含曲线、标记、比例尺和空间关系。模型知道它是流式细胞术图或质粒图谱，仍可能选错区域、漏掉一个结构，最后给出内容通顺但数值错误的答案。VIALS 把这类工作整理成 161 道简答题，由有相关领域经验的科学工作者出题和审阅。论文中，直接输入图片和问题时，最高平均准确率为 26.5%；允许模型反复查看图片、执行代码后，最高达到 65.8%，同时每次尝试的 token 用量增加了一个到两个数量级以上。

这里研究的是已有科研图像的解读。任务终点是回答图片中的具体问题，没有测量模型开展实验、安排下一轮研究或完成整个科研项目的能力。

## 从图片到简短答案

VIALS 中的 artifact 指科研工作产生或使用的视觉材料，例如显微图像、条带图、系统发育树，以及结构分析软件显示的分子或蛋白质结构。模型需要从这些材料中定位证据，再按相应的科学表示规则作答。

一个任务包含一个问题、一张或多张图片，以及专家确认的简短参考答案，论文称后者为 ground-truth final answer，简称 GTFA。模型只看到问题和图片，评测端保留参考答案与必要的评分范围。

例如，论文图 3 的流式细胞术任务要求结合图中的多个比例，求背景校正后的数量差，并按要求取整。完成这种题要先找对相应区域，理解比例的参照人群，再进行计算。识别图中几个百分数，并不等于找到了正确的计算输入。其他题目则要求读出树的拓扑关系、识别指定对象或列出满足条件的图像区域。（正文 §1、§3，图 1、3）

这与常见科学问答的区别在于材料和工作环节。MMMU 等基准主要覆盖跨学科知识与学术题目；MicroVQA 集中在显微图像；VIALS 则横跨多种生命科学工作中的视觉材料。论文以此解释新增基准的覆盖范围，没有给出统一条件下所有相关基准的难度排名。

## 161 道题、174 张图与 31 位贡献者

### 任务数与图片数分开统计

公开 Parquet 文件有 161 条任务记录。157 道题各有一张图，另有一道题含八张、一道含五张、两道各含两张，因此图像文件总数为：

$$
157 + 8 + 5 + 2\times 2 = 174.
$$

按图像字节计算的 SHA-256 也有 174 个不同值。这只能说明没有完全相同的图像文件，不能证明不存在相近图像、同源材料或语义重叠。把 161 写成“视觉材料数量”会混淆题目与图片两个统计单位。

论文与公开数据实际对应下面八类。数据卡的文字介绍曾写为九个领域，但其枚举和本次读取的 `domain` 字段均为八类，本文采用逐条数据统计。（正文 §3、表 1；固定版本数据文件）

| 领域 | 任务数 | 三次直接评测的答案数 | 典型读取内容 |

### 资料来源与专家审核

材料来源包括未发表的真实实验图像、用科学软件生成的图像，以及允许使用的公开出版物材料。程序生成的材料覆盖系统发育树、质粒图谱和条带图等；公开来源的署名及许可记录在 `attributions.csv`。因此，不能把整个数据集称作“全部来自未公开实验”，也不能把所有材料归为出版物里的完整论文图。（正文 §3.2—§3.3）

共有 31 位来自 Handshake 专家网络的贡献者。论文报告其中 87% 接受过博士阶段训练，74% 有超过六年的专业工作经验。博士阶段训练不等于每个人都已经获得博士学位。贡献者覆盖多个专业，只制作或审核其熟悉领域的题目。

审核流程把独立求解和质量检查分开：

1. 出题者提交图像、问题、参考答案与依据。
2. 第二位、必要时第三位专家在不看参考答案的情况下独立求解，并解释理由。
3. 其他审核者检查题目是否符合实际工作、信息是否充分、答案是否清楚。
4. 团队结合模型回答和人工尝试检查争议，经过后续沟通达成一致的题目才被保留。

论文报告独立审核平均约需 16 分钟，其中包含书面论证。这不是对所有科学工作者进行的限时考试，也不是只提交最终答案所需时间。论文没有另设一组独立专家，给出与模型直接可比的人类准确率主表。通过共识审核这一入选条件，不能换算成“人类测试准确率 100%”。（正文 §3.4—§3.5）

作者还检查问题是否已在网上出现，并控制任务的多样性。此类检查可以排除一些直接重复题，却无法证明所有基础模型的训练语料都未包含原始图片或相关出版物。公开答案后的后续评测，也需要另外管理训练污染。论文提到正在私下准备数百道新题用于更新，当前发布规模仍为 161 道。

### 专业相关性调查的实际含义

专家对 VIALS 的 161 道题和 HLE 中生物／医学、化学的 118 道视觉问答进行了盲评。HLE 原本有 119 道候选题，其中一道没有审核者认为自己足够熟悉，因此未进入这项调查。（正文 §3.6，图 2，附录 C.4）

| 专家判断 | VIALS | HLE 对应子集 |
| --- | ---: | ---: |
| 材料看起来来自行业或专业工作 | 63% | 22% |
| 自己每周或每天会遇到此类材料 | 33% | 14% |
| 同意该解读任务有商业或经济价值 | 81% | 66% |

这些百分比是调查回答的分布，说明受访专家如何判断材料。论文没有完整公布每道题由几位专家作答、逐题调查记录或相应置信区间，不能直接把百分比乘以题目数当作精确题数。它也没有测量实际节省的工时、实验成功率或经济回报。

附录 B 另用 `text-embedding-3-small` 对问题文本编码，经余弦距离和 UMAP 投影绘制分布。这部分比较使用全部 119 道 HLE 题，与前面的 118 道调查题口径不同。二维嵌入图用于描述题目内容差异，没有构成专业价值的定量验证。

## 评分器只判最终答案

### 从输出中提取答案

直接评测提示要求模型给出简洁的 `REASONING`，最后单独输出 `ANSWER:`。评分器提取最后一个答案块，比较最终答案，不给中间推理分。没有所要求的答案标记，按错误处理。（附录 C.1）

这种设计将“解释是否看起来合理”和“最后是否回答正确”分开。例如，模型列出了大部分正确对象，但遗漏一个必要对象，整题仍可能不通过。相反，只要最终答案与参考答案等价，不会因为没有使用参考解释中的措辞而被扣分。

默认评分模型是 GPT-5 mini。输入包括题目、参考答案、模型最终答案，以及该题是否有专家指定的数值上下界。通常不提供图像：评分器的任务是比较两份答案，而非重新完成科学题目。

评分提示中的主要规则如下：

| 情况 | 判定方式 |
| --- | --- |
| 大小写、一般格式差异 | 可接受 |
| 同义表达 | 必须保留相同对象、含义与具体程度 |
| 无顺序要求的集合 | 顺序变化、重复列举可不影响判定；缺项或增加错误项不接受 |
| 数值答案 | 按题目要求的精度比较；不能自行给“接近正确”加容差 |
| 单位省略 | 只有语境明确且数值一致时才可接受 |
| 空答案、拒答、无法判断 | 不正确 |

公开数据中只有五道题带有明确的数值接受范围。其他计数题不能因为“只差一个”自动通过。有范围的题目则以其范围为准：例如某题参考答案为 6，明确允许 6—7，就不能再用严格等于 6 的比较代替原协议。另有参考值 13、范围 7—13 的记录，进一步说明接受区间来自逐题专家设置，而非全局相对误差。（附录 C.1 评分提示；公开数据 `LeadBoundLower`／`LeadBoundUpper`）

### 少量答案需要重新看图确认对应关系

有时模型用“第几条泳道”作答，参考答案使用实验条件名称；仅凭文字无法确认两者是不是同一对象。此时文字评分器输出 `UNVERIFIABLE:`，再由同一个模型接收图片，进行多模态复判。

复判的目的限于确认称呼或位置映射，仍以参考答案为依据。论文称主实验中不足 1% 的答案需要这一流程。作者还对覆盖全部 161 题的 4,685 个模型回答进行人工核对，报告评分器与人工判断的一致率为 99.9%。（正文 §3 的评分说明，附录 C.1）

这里的 4,685 是人工核对样本数，不是十个模型全部主实验输出的 4,830。论文未给出完整混淆矩阵、精确分歧数及公开审计明细。99.9% 表明自动评分与该批人工判断高度一致，没有测量参考答案本身的无误率，更不是模型的答题正确率。

## 三种成绩分别统计什么

每个模型对每题独立尝试三次。令 $N=161$、$K=3$，$y_{ir}\in\{0,1\}$ 表示第 $i$ 道题第 $r$ 次最终答案是否正确。

主文的平均准确率，也就是附录图 A1 的 Pass@1，为：

$$
\mathrm{Accuracy}=\frac{1}{NK}\sum_{i=1}^{N}\sum_{r=1}^{K}y_{ir}.
$$

每个模型的分母是 $161\times3=483$ 个答案槽位。达到终止条件的失败或拒答仍按错误计入，不应只对正常返回的答案统计。

Pass@3 统计三次中至少对过一次的题目比例：

$$
\mathrm{Pass@3}=\frac{1}{N}\sum_{i=1}^{N}
\mathbf{1}\left[\sum_{r=1}^{3}y_{ir}\ge1\right].
$$

Pass^3 统计三次全部正确的题目比例：

$$
\mathrm{Pass}^{3}=\frac{1}{N}\sum_{i=1}^{N}\prod_{r=1}^{3}y_{ir}.
$$

后两者的分母都是 161 道题。Pass@3 使用“至少一次正确”这一事后条件，不是多数投票，也没有说明部署时如何从三个答案中挑出正确答案。Pass^3 来自逐题三次结果，不能直接把整体准确率立方。三次全对也只描述这三次观测，没有保证以后每次都对。（附录 A.1）

举一个说明指标的自拟例子：三道题的结果依次为 `111`、`100`、`000`，平均准确率为 $4/9$，Pass@3 为 $2/3$，Pass^3 为 $1/3$。三个数字分别回答平均作答、允许重复尝试和重复稳定性的问题。

图 4 的 95% 置信区间是在每个固定任务的三次 rollout 之间做 bootstrap，用来反映“每题重新取一次尝试”时成绩的波动。可将这种统计目标表示为：每次重采样对每题取一个 $r_i\in\{1,2,3\}$，计算 $N^{-1}\sum_i y_{i,r_i}$，再查看重采样分布。论文没有公布 bootstrap 次数和随机种子。这不是从更大的生命科学任务总体重新抽题所得的泛化置信区间，也没有提供模型间显著性检验。

## 直接看图的实验设置与成绩

### 同样的问题和次数，不同的供应商推理机制

主实验评估十个视觉语言模型，每题三次，温度为 1，最大生成长度为 32,768 tokens。提示和图像输入一致，各供应商采用论文所列的默认或原生推理设置：OpenAI 使用默认设置，Claude／Gemini 使用自适应推理，其他支持思考的模型采用相应原生机制；Muse 与 Mistral 使用标准调用。（正文 §4，附录 C.1）

因此，实验统一了输入、重复次数及生成上限，没有把实际思考 token、内部视觉处理或耗时严格匹配。模型名称和接口包括 GPT-5.6 Sol、Claude Opus 5、Gemini 3.1 Pro Preview、Gemini 3.7 Flash，以及经相应接口访问的其他模型。API 别名不都是不可变权重版本，未来使用相同名字不一定复现相同后端。

论文规定异常、拒答或空回复可以额外重试三次，仍失败后计错。Muse Spark 1.2 最终有 13/483 次此类失败，Kimi K3 为 6/483；Grok 和 Mistral 也存在少量失败。Claude Fable 5 因大部分请求被安全机制拦截，未进入排名。这不等于作者实际测得该模型的视觉能力为零。

## 错误分析的分母与归因方式

作者把错误分为七种：视觉计数错误、数值或特征选错、遗漏证据、误读科学表示、定量推理错误、科学原理使用错误，以及编造发现。（正文 §5.2、表 3，附录 C.2）

这张表的统计单位与主准确率不同。对某个模型，只要一道题三次中至少错过一次，就取该题的**第一次错误尝试**，给它分配一个主要类别。一道题错一次或错三次，在该表中都只出现一次。因此“41.8% 的错误属于视觉计数”不是 483 次输出中有 41.8% 计数错误，也不是把全部错误 rollout 分别归类所得的比例。

以 GPT-5.6 Sol 为例：

| 主要错误类别 | 该模型失败题目中的占比 |
| --- | ---: |
| 视觉计数错误 | 41.8% |
| 数值或特征选错 | 14.2% |
| 遗漏证据 | 15.6% |
| 误读科学表示 | 14.2% |
| 定量推理错误 | 6.4% |
| 科学原理使用错误 | 3.5% |
| 编造发现 | 4.3% |

前四类合计 85.8%；跨模型为约 83%—93%。论文据此认为许多失败出现在读取与解释图像证据的过程中。图 5 和附录图 A4—A5 给出具体例子：把树上图形相近的分支当作亲缘更近，用常见结构长度代替图中实际标注，或识别出了一个目标区域却漏掉另一个区域。

分类由 Claude Sonnet 4.5 完成，必要时回退 GPT-4o。分类器接收问题、参考答案、错误回答及其解释，未直接查看图片。论文没有报告这七类标签与人工分类的一致率。分类提示还强调识别领域规则方面的原因，类别因而包含标注者预设的解释框架。

例如附录图 A5 中被列为“定量推理错误”的一个例子，图注说明模型内部的算术是正确的，但读结构时漏了一个取代基。这表明类别之间可能共享上游原因。错误类别可以组织案例，不能单独证明神经网络内部的失败机制，也不能据此把约九成错误都断言为纯视觉问题或纯知识问题。

## 允许执行代码之后，准确率和预算同时改变

### 工具环境与任务终点

工具实验保留同一批题目，让模型在 Linux 环境里访问 `/task` 下的图片，通过代码反复裁剪、放大、转换、测量和查看中间结果。环境包含 NumPy、SciPy、Pillow、OpenCV、scikit-image、Matplotlib 等常见分析库。按论文设置，不允许通过互联网或外部数据库寻找答案。（正文 §5.3，附录 C.3）

模型最后将答案写入 `/task/answer.txt`，同样以 `ANSWER:` 标记供评分。实验考察七个模型、九种模型与代理框架组合，每题仍重复三次。代理框架负责维持对话、执行工具、传回图像或程序输出，因此换框架本身也是实验条件的变化。

## 自报信心的补充实验

附录 A.2 在原提示后增加五级信心评分。模型回答后，评分前会去掉信心行，答案仍按原规则判定。没有合法信心值的回答不进入这项分组分析。

作者把 1—3 级归为低／中信心，4—5 级归为高信心。图 A3 展示九个模型，其中七个有足够的低信心样本作比较。对这七个模型，高信心组的准确率比低信心组高约 6—20 个百分点，但高信心组的准确率最高也只有 30%。

## 公开代码与复现边界

本次检查了固定提交的模型配置、数据加载、答案解析、评分器、主评测循环、汇总逻辑，以及 Harbor 适配器和容器模板。还读取了固定数据版本的全部 161 条任务与图像元数据。**以下根据公开代码整理，尚未复现模型成绩；本次没有发起模型调用。**

### 直接评测入口

仓库要求 Python 3.10 及以上，核心依赖包括 LiteLLM、Pydantic 与 python-dotenv，下载数据还需 Hugging Face 相关依赖。官方入口的形式为：

```bash
pip install -e ".[hf]"
python -m vials.pipeline --model gpt-5.6-sol --hf-dataset --n-samples 3
```

该命令会调用被测模型和评分模型，需要相应供应商凭据并产生费用。它展示入口，不是一条已经固定全部实验依赖的复现命令。代码依赖主要规定最低版本，API 后端、容器镜像和代理框架也需要额外记录。

被测模型通过 LiteLLM 路由。`--reasoning-effort default` 在代码中不传显式 effort 参数，因此结果还受供应商默认行为影响。评分默认使用 `openai/gpt-5-mini`；输出包括逐次 JSONL 和汇总 JSON，可用于复查具体答案与判分原因。

### 数据版本与分母需要显式检查

主下载函数使用 Hugging Face 的数据仓库、配置和 split 加载内容，没有暴露固定 `revision` 参数；已有非空缓存还可能被直接复用。重跑时应先固定数据快照，记录 161 道题和 174 张图的清单，再确认评测目录对应这个版本。本文给出的数据提交是实际读取的数据版本，不是默认命令自动保证的版本。

主流程对没有可用图片的题目会跳过，图片部分缺失时可能继续使用剩余图片。汇总按实际结果计算，不会自动替使用者证明已经评完完整的 161 题。完整复现需要检查每题三次结果是否齐全、跳过或失败的原因，以及最终分母是否为 483。

仓库支持逐题日志和跳过已有结果，但一次新运行的汇总不自动等于历次日志的完整合并报告。恢复运行后，应以明确合并并去重的逐题记录计算最终指标，避免把仅剩任务的准确率当作完整测试集成绩。

### 当前实现与论文协议的几个差异

**重试机制不同。** 论文写的是异常、拒答或空回复额外重试三次；固定代码针对限流采用最多五次总尝试，部分 API 错误只重试一次，另一些请求错误直接失败。正常返回的空内容或拒答也没有统一执行论文描述的三次补试。重跑时必须说明采用哪个协议，不能假设仓库默认行为完全还原论文。

**工具评分缺少多模态复判。** 直接评测的 `_grade` 路径默认支持 `UNVERIFIABLE` 后带图重判；Harbor 的 `template/tests/grade.py` 仅调用文字评分函数，然后把 `correct` 转为奖励，没有接入带图复判。这与论文所述工具实验沿用相同评分流程不完全一致。差异可能影响需要位置与名称映射的回答，不能通过代码静态检查量化其对总分的影响。

**评分器失败也可能被计错。** 文字评分和带图复判各最多尝试三次；耗尽后返回 `correct=False`，并在评分说明中记录 `JudgeError` 或 `MultimodalJudgeError`。主流程的正常判卷分支仍将 `error_class` 设为 `None`，Harbor 则写入零分。重算准确率时需要单独审计 `judge_reasoning` 中的这类记录，区分评分服务失败与被测模型答错；本次未获得原实验日志，不能判断实际影响了多少答案。

**汇总 token 混入判卷调用。** 当前直接评测代码会把 judge token 加入结果中的输入与输出 token 字段。若以这些汇总字段重算“被测模型自身的 token 用量”，就会把评测开销一起算入。与论文成本图比较时，应分别保存作答和判卷用量，说明统计范围。

**工具权限与运行环境需要单独固定。** 适配器默认代理超时为 600 秒、验证器为 300 秒，模板配置了 CPU、内存等资源。网络配置使用允许列表以访问模型服务，并不等于整个容器完全断网；论文“不访问互联网或外部数据库”的含义应结合代理可用的工具和网络地址核对。依赖版本与镜像还存在浮动项，不能只固定 VIALS 仓库提交就认为环境全部固定。

公开主流程计算平均准确率及重复作答指标，但没有提供一套与论文全部分析一一对应的 bootstrap、错误类型标注和信心分析结果包。完整复现还需要逐次输出、错误分类记录、费用明细和实验框架版本，不能只凭一次 summary JSON 复原所有图表。

代码采用 MIT 许可，数据卡声明 CC BY 4.0；材料署名和来源另见 `attributions.csv`。数据卡同时放置基准标识并请求避免将评测内容混入模型训练。引用、再分发和污染管理应分别保留相应说明。[固定代码](https://github.com/Handshake-AI-Research/VIALS/tree/af601504cc02c2a73ca11a83698af4bea1091371) · [固定数据](https://huggingface.co/datasets/handshake-ai-research/VIALS/tree/914d756c22b10dfd2eff263873814425271395cb)

## 这批结果覆盖的范围

VIALS 给出了一个清楚的评测对象：从提供的生命科学图像中提取、解释证据，并提交一个可核对的短答案。专家审核帮助筛去缺乏明确答案的题目，但也使数据偏向熟悉该领域的科学工作者能够较快完成的任务。存在强噪声、多个合理解释或长期研究背景依赖的材料，没有在这里得到系统覆盖。（正文 §6）

161 道题也不能代表全部生命科学工作。各类只有 7—23 题，公开材料、程序生成材料和未发表材料的差异没有分别给出完整成绩；不同来源对结果的影响仍不明确。论文没有用统一预算隔离视觉处理、科学知识与代理规划的贡献，也没有提供工具成绩的完整显著性检验。

因此，主实验可以比较这一版本任务上的模型与代理组合，并展示具体的误读方式；它不能直接给出实验室部署成功率、临床可靠性、人机协作收益，或模型独立完成研究的能力估计。
