# Humanity’s Last Exam：专家题目、自动评分与版本演变

Humanity’s Last Exam，简称 HLE，把跨学科专家能够给出确定答案、而当时模型经常答错的问题整理成统一考试。输入可以包含文字和图片，模型给出解释、最终答案和置信度，再由另一个模型对照参考答案判分。它测量的是困难封闭题上的答题能力与自报信心，不直接评价开放式科研或长期自主工作。[论文 §1–4](https://arxiv.org/pdf/2501.14249v11)

理解 HLE 需要同时记住版本。首发论文写 3,000 题，原始数据后来定版为 2,500 题；Nature 正式版新增了发布后模型成绩，动态分支 HLE-Rolling 又继续增删题目。本文分别解释这些材料，不把不同题集、工具条件或评审器下的分数连成一条未经控制的能力曲线。

## 题目要求专业理解，答案仍保持简短

HLE 的题目需要已有答案，或者能在给定条件下求出确定答案。它不收录要求自由讨论、提出新理论或完成开放式证明的题型；题目可以涉及原创问题、对既有知识的非简单综合，也允许来自尚未发表的研究经验。题干要求使用英语，专业符号与必要条件应当清楚。

约 24% 为选择题，至少五个选项；其余为短答案题，论文称为 exact match。约 14% 需要结合图片理解。**题型与模态是两种分类轴**：一道带图题也可以是选择题，不能把这两个比例相加得到题目覆盖率。比例为论文取整值，本次未读取受限数据逐行确定准确的交叉计数。[论文 §3.1](https://arxiv.org/pdf/2501.14249v11)

正式版图 2 的八个领域比例为：

| 领域 | 占比 |
| --- | ---: |
| 数学 | 41% |
| 生物／医学 | 11% |
| 计算机科学／人工智能 | 10% |
| 物理 | 9% |
| 人文／社会科学 | 9% |
| 化学 | 7% |
| 工程 | 4% |

这些高层类别下面还有一百多个更细的主题，由贡献者选择或填写。整体不是各学科等量采样；数学题约占四成，总体准确率因而会明显受数学表现影响。[Nature 图 2；arXiv 附录 B.4](https://www.nature.com/articles/s41586-025-09962-4)

原文例子展示了这种“理解很难、答案很短”的组合：古典学题要求结合铭文图和转写给出翻译；语言学题要求识别指定发音传统中的闭音节；数学题需要理解范畴论定义，却只要求一个计数。贡献指南还用两个例子区分合格与不合格题：一个研究概念计数题令三个展示模型全部答错，而另一个含微分条件的题被两个模型答对，被视为过于容易。这是投稿示例，不是对所有受测模型的正式统计。[Nature 图 3、补充材料图 1](https://www.nature.com/articles/s41586-025-09962-4)

## 先用模型筛难度，再让专家改题

一次提交包含题干、标准答案或选项、详细解答、学科与贡献者身份。奖金规则为最优 50 题每题 5,000 美元、随后 500 题每题 500 美元，合计 50 万美元，由 Scale 赞助。它是奖金池，不是论文披露的全部标注、审计或推理预算。[Scale 征题说明](https://scale.com/blog/humanitys-last-exam)

模型筛选发生在人工审阅之前。带图题用 GPT-4o、Gemini 1.5 Pro、Claude 3.5 Sonnet 和 o1；纯文本题再加 o1-mini 与 o1-preview。附录 B.1 的操作规则是：短答案题需要难倒所有测试模型；选择题允许最多一个模型答对，以容纳猜中。自动判断在征题阶段使用 GPT-4o，和后续正式评测采用的 o3-mini 不是同一配置。[arXiv 附录 B.1](https://arxiv.org/pdf/2501.14249v11)

流程图中的几个数有不同含义：

| 数量 | 对应环节 |
| --- | --- |
| 超过 70,000 | 平台记录的尝试，不等于 70,000 道最终独立题 |
| 约 13,000 | 通过模型难度检查、进入专家审阅的提交 |
| 约 6,000 | 流程图中的候选题阶段 |
| 2,500 | 定版的公开集 |
| 未公开确切数量 | 保留的私有集及后续收集形成的第二私有集 |

不能用 $6,000-2,500$ 自动认定私有集有 3,500 题，图中还包含组织者与专家的批准过程。作者在公开审稿回复中只确认私有集小于公开集，没有披露完整规模。[Nature 图 4、公开审稿回复第 12 页](https://www.nature.com/articles/s41586-025-09962-4)

人工审阅有两轮。第一轮由具备硕士、博士、JD 等学历的领域审阅者检查题目，提供修改意见，正文报告每题 1–3 次审阅。第二轮由选出的高质量审阅者和组织者结合前轮反馈批准题目。第一轮评分从丢弃到最佳题目，另可选择不确定；第二轮重新区分丢弃、待修改、模型答错但实际过于基础的题，以及可纳入的高质量题。审阅分数不是模型最终成绩的权重。[arXiv §3.2、附录 C.7](https://arxiv.org/pdf/2501.14249v11)

审阅指南要求避免靠大规模机械计算或必须执行代码制造难度，也提醒改善 LaTeX 或把可转写图片变成文字后，模型可能答对。审阅者还要核实模型确实答错，防止字符串匹配失败把正确答案误标为困难题。这个环节测量的是题目是否适合评测，不只是题目能否令某个模型失败。

## 专家审阅、完整求解与数据错误不是同一件事

第一轮指南预计每题审阅约 3–5 分钟，并允许审阅者在缺少专业背景或完整求解超过五分钟时，不核实全部推导。这限制了“经过专家审阅”的含义：它并不等于每条参考答案都由多个独立专家完整求解并确认。[arXiv 附录 B.2、C.7；Nature 补充材料 §2](https://arxiv.org/pdf/2501.14249v11)

作者之后通过错误悬赏、社区反馈和抽样求解审计补充核查。错误报告在组织者、原作者和审计者之间反复确认；容易通过网络直接找到的题也被移除或替换。搜索筛查先找出“带搜索答对、无搜索答错”的题，再人工检查是否容易检索，使用过 GPT-4o mini／GPT-4o search 与 Perplexity Sonar。它不是一次证明所有题永远不可搜索的检验。

附录 B.3 与 Nature Methods 报告两轮各 200 题的审计，第一轮识别问题类型，随后修订类似题，再用新样本开展第二轮。最终给出公开集**专家分歧率估计 15.4%**。另一个生物、化学、健康子集的复核约为 18%；若只要一名审阅者异议就标记，约为 25%。[Nature Methods：Expert disagreement rate](https://www.nature.com/articles/s41586-025-09962-4)

这些是不同审计规则下的分歧估计，不是把 2,500 道题全部重新解完得到的错误率，也不是专家在统一答题条件下的准确率。材料没有完整给出对应的逐题裁决、有效分母与置信区间；15.4% 也不能直接变成“人类成绩为 84.6%”或基准最高只能达到 84.6%。

作者说明，一些分歧涉及冷门文献、作者直接研究经验，或选择题要求在给定选项中选最合适答案。这些因素可以解释审阅困难，但不能代替逐题验证。本文不根据这一说明把所有异议视为审阅者误解，也不把所有异议直接视为标签错误。

## 自动评分比较最终答案，不验证整段推理

模型输入只有题目和必要图片，以及固定的输出格式要求：解释、最终答案、0–100% 的置信度。参考答案和作者解答不交给被测模型。评审器再读取题干、模型回答和参考答案，抽取最终答案并判断是否等价。当前材料采用 `o3-mini-2025-01-31`，用结构化输出返回答案、判定理由、yes/no 与置信度。[arXiv 附录 C.1；Nature Methods](https://arxiv.org/pdf/2501.14249v11)

这里的 exact match 不等于逐字符相同。评审允许数值的小幅误差或数学等价表达，同时要求不重新解题、不提出不同于参考答案的新答案。原文示例中，参考答案和模型答案分别为：

$$
a=\frac{\cos(\pi/n)}{2[1+\cos(\pi/n)]},\qquad
\hat a=\frac{\cot(\pi/n)}{2\cot(\pi/(2n))}.
$$

令 $x=\pi/n$，利用 $\cot(x/2)=(1+\cos x)/\sin x$，在表达式有定义的条件下得到：

$$
\hat a=\frac{\cos x/\sin x}{2(1+\cos x)/\sin x}
=\frac{\cos x}{2(1+\cos x)}=a.
$$

因此评审给 yes。取 $n=3$，两式都为 $1/6$，是对这个等价关系的数值核对。此例说明评分有时需要代数推理，而非只比较文本。[Nature Extended Data Fig. 1；arXiv 附录 C.1](https://www.nature.com/articles/s41586-025-09962-4)

不过，评审被要求信任参考答案。因此错误参考答案不会自动被修复；作者的详细解答主要服务数据审计，不是评分器重新证明答案的依据。公开审稿回复也明确，模型生成的推理过程没有被系统核验。模型可能推导不正确但碰巧给出正确短答案，最终仍按答案正确计分。[公开审稿回复第 11 页](https://www.nature.com/articles/s41586-025-09962-4)

## 准确率与置信度校准各自衡量什么

令 $z_i\in\{0,1\}$ 为第 $i$ 题最终答案是否被判正确，$N$ 为该次评测的题数。准确率为：

$$
A=\frac{100}{N}\sum_{i=1}^{N}z_i.
$$

这是题目等权的总体准确率，不是八个领域准确率的等权平均。只评纯文本模型时，分母应换为纯文本题数，不能将带图题当作这些模型正常完成的试题。

校准衡量模型自报信心与实际正确频率是否一致。把置信度 $c_i$ 缩放到 0–1，按置信度排序后分箱。对第 $b$ 箱，计算平均信心 $\bar c_b$、实际准确率 $\bar z_b$ 和样本量 $n_b$。完整分箱的 RMS 校准误差写为：

$$
\operatorname{RMSCE}=100\sqrt{\sum_b\frac{n_b}{N}(\bar c_b-\bar z_b)^2}.
$$

**说明算例：**某箱 100 题平均自信 90%，实际只答对 10%，且这就是全部样本，则校准误差为 80 个百分点。另一模型即使也只答对 10%，若平均信心为 10%，在这一箱的误差就是零。低校准误差不等于高知识能力，高准确率也不必然意味着校准良好。

HLE 测的是文字中自报的置信度，不是模型内部概率。评审提示规定没有置信度时填 100，这可能使不遵守输出格式的回答显得尤其自信。论文没有列出缺失置信度频率，也没有提供独立的评审器人工一致性验证表。本文将高校准误差解释为自报信心与判分结果不匹配，不直接把它叫作事实幻觉发生率。

## 三个论文版本的结果需要分别读取

首发 v1 的公开集为 3,000 题，评审为 `gpt-4o-2024-08-06`。其表 1 中 GPT-4o 为 3.3%，o1 为 9.1%，DeepSeek-R1 为 9.4%，最后一项只评纯文本。首发成绩和后来的 2,500 题、o3-mini 评审结果不能相减后归因为模型退步。[arXiv v1 表 1、附录](https://arxiv.org/pdf/2501.14249v1)

本地 arXiv v11 的表 1 仍是以下早期模型组：

| 模型 | 准确率 | RMS 校准误差 |
| --- | ---: | ---: |
| GPT-4o | 2.7% | 89% |
| Grok 2 | 3.0% | 87% |
| Claude 3.5 Sonnet | 4.1% | 84% |
| Gemini 1.5 Pro | 4.6% | 88% |
| Gemini 2.0 Flash Thinking | 6.6% | 82% |
| o1 | 8.0% | 83% |

v11 虽在 2026 年更新，不能把这个表称为 2026 年 7 月最新模型排名。它还把 o3-mini 放在“Pre-Release Models”标题下，但其标注快照为 2025-01-31，晚于 1 月 23 日公开发布；这个表头不能用于证明模型从未有机会接触公开 HLE。[arXiv 表 1、表 4](https://arxiv.org/pdf/2501.14249v11)

| 模型 | 准确率，原表报告 | RMS 校准误差 |
| --- | ---: | ---: |
| GPT-4o | 2.7% ± 0.6 | 89% |

误差范围的数值单位是百分点。官方代码使用二项比例的 Wald 近似 $1.96\sqrt{p(1-p)/N}$；以 $p=0.253,N=2,500$ 计算，半宽约为 1.70 个百分点，与表中 GPT-5 的量级一致。这类区间反映题目样本层面的近似不确定性，不包括参考答案错误或重复采样的全部波动。作者在审稿回复中说明，因计算约束没有对每题多次采样。[Nature 表 1、审稿回复；官方评分代码](https://github.com/centerforaisafety/hle/blob/73ae974b1844c3ffa64c3f4343d9f1f259575700/hle_eval/run_judge_results.py)

正式版将发布后模型单列，是因为模型开发者此时已经可以访问公开题集。这不是认定这些模型发生了训练污染，而是提醒成绩可能同时受到能力、训练与评测调优、工具设置等因素影响。

## 纯文本、带图与选择题表现

纯文本子集上，Nature Extended Data Table 1 报告 o1 为 7.8%，DeepSeek-R1 为 8.5%，o3-mini 为 13.4%，o3 为 20.6%，Gemini 2.5 Pro 为 22.1%，GPT-5 为 26.3%。例如 GPT-5 的 26.3% 与主表 25.3% 分母不同，不能当成两次重复实验的波动。

题型分解进一步显示，选择题通常比短答案更容易得分。下表来自正式版 Extended Data Table 3；三列子集有交叉，不能直接平均。

| 模型 | 仅多模态题 | 仅短答案题 | 仅选择题 |
| --- | ---: | ---: | ---: |
| GPT-4o | 5.3% | 1.8% | 5.6% |
| o1 | 9.4% | 6.7% | 12.0% |
| DeepSeek-R1 | 不适用 | 6.9% | 13.8% |
| Claude 4 Sonnet | 8.8% | 6.1% | 13.0% |

| Gemini 2.5 Pro | 19.0% | 19.6% | 28.1% |

DeepSeek-R1 的后两列也是它能评测的纯文本范围。选择题存在猜中机会，但各题选项至少五个、实际数量可不同，不能简单把整套 HLE 的随机基线写成 20%。纯文本与带图、不同题型的题目内容也不同；这些分组结果不是“给同一题移除图片”后的因果消融。[Nature Extended Data Tables 1、3](https://www.nature.com/articles/s41586-025-09962-4)

领域分解也显示总体分数会掩盖差异：o3-mini 的纯文本数学为 18.6%，人文为 5.2%；DeepSeek-R1 的纯文本工程为 14.5%，化学为 5.0%。这些都是各自类别内比例，类别样本较小时相同数量的对错更容易造成百分点变化。本文不据此推断某个模型在整个学科上达到相同水平。[arXiv 表 3；Nature Extended Data Table 2](https://arxiv.org/pdf/2501.14249v11)

## 推理长度分析没有证明统一的最优预算

arXiv 图 5 按领域报告生成 token 均值，包含推理和输出 token。例如 o1、DeepSeek-R1 的数学回答约在八千 token 以上，生物／医学则明显较短；附录图 6 的非推理模型平均输出通常更少。这里没有统一按参数规模、硬件或美元成本归一化，token 数也不能直接等同运行秒数。

Nature 正式版换成另一张图 5：将回答按实际输出 token 长度的 $\log_2$ 分箱，再统计每箱准确率。Gemini 2.5 Pro 和 o3 在约 $2^{14}=16,384$ token 的箱附近达到较高准确率，之后下降；图中 Claude 4 Opus 等模型并不是统一在同一位置达到峰值。[Nature 图 5](https://www.nature.com/articles/s41586-025-09962-4)

这是按观察到的回答长度分组，不是对每道题随机分配不同预算的实验。难题可能同时导致更长推理和更多错误，模型也可能在失败时反复生成。图中未给各箱样本量或置信区间，因此不能将下降段视为“超过 16,384 token 必然有害”，也不能据此给所有模型设置统一最优上限。

这篇工作没有通过重新训练或架构消融解释模型间差距。作者在审稿回复中将这些实验留给后续研究。数据筛选、题型拆分和推理长度分析各自提供描述性证据，不能替代受控训练实验。

## 公开代码的执行流程与实现差异

`run_model_predictions.py` 读取 `test`，将题干和可选图片送给模型，以题目 ID 缓存回答和 token 用量；对名称含 o1 的模型，把格式提示从 system 改放 user。它没有配置搜索、代码执行或其他工具，属于单次作答流程。`run_judge_results.py` 读取这些回答，再用 o3-mini 判断，并缓存评审结果。[固定代码目录](https://github.com/centerforaisafety/hle/tree/73ae974b1844c3ffa64c3f4343d9f1f259575700/hle_eval)

静态检查发现以下情况，复现时需要单独处理：

- **温度参数没有实际传入。**脚本解析 `--temperature`，默认 0，但 API 调用中的该行被注释。README 所述温度 0 和命令行设值不能证明当前请求使用了该温度。论文旧实验则明确：可配置时通常为 0，o1／o3-mini 为 1；更新后的 Gemini 2.0 Flash Thinking 为 0.7，旧图仍用早期版本。
- **纯文本子集没有现成过滤开关。**代码会按数据记录发送图片。若要复现 DeepSeek-R1 或 o3-mini 的纯文本行，需要显式选对题目，并同时让评分分母使用这个子集。
- **小样本预测不自动形成小样本评测。**预测脚本可用 `--max_samples` 限制前若干题，评分脚本却以整个加载数据集的长度为准确率分母。缺失回答或评审失败不贡献正确数，因而会拉低准确率；校准只收集已有评审的回答，两项指标的有效覆盖范围可能不同。
- **缓存以题目 ID 为主，未绑定数据 revision。**若同一路径复用旧回答或旧评审，而题目内容、答案、模型或评审配置已变，可能跳过应当重算的条目。代码也未内置固定 Hugging Face revision 的参数。
- **模型和评审调用失败后会跳过该项。**脚本允许重跑补齐，但必须检查覆盖率；出现结构化输出失败不等于该答案已被判错误或已完成评审。

这里列的是当前固定代码行为，不据此反推作者所有历史运行都采用同样错误配置。论文表 4 固定了 GPT-4o、Claude、o1 等早期快照，但 Grok 使用 `latest`，正式版新增模型的完整日期快照与逐题原始输出未在这些脚本中提供。

### 校准代码遗漏最后一箱

`calib_err` 按置信度排序，用 100 作为目标箱大小。它先构建箱并把尾部剩余样本并入最后一箱，却使用 `range(len(bins) - 1)` 遍历，导致最后一箱不参与误差求和。分母仍为全部有评审样本数。[`calib_err` 实现](https://github.com/centerforaisafety/hle/blob/73ae974b1844c3ffa64c3f4343d9f1f259575700/hle_eval/run_judge_results.py)

本次仅抽取这个纯计算函数做离线测试，没有初始化 API 客户端。令所有题都答错、置信度均为 100%，按完整 RMS 定义应得 100%：

| 离线构造的样本数 | 当前函数返回的校准误差 |
| --- | ---: |
| 50 | `IndexError` |
| 100 | 0% |
| 200 | 约 70.71% |
| 250 | 约 63.25% |
| 2,500 | 约 97.98% |

例如 250 题时，只累计前 100 题，得到 $100\sqrt{100/250}\approx63.25$。这验证了实现与完整分箱公式不同；对于真实模型，高置信度末箱被遗漏的影响需要原始置信度与正确标签才能重算。本文因此保留论文报告的校准值，不声称已修正或复现这些值。代码还在乘 100 前将校准值保留两位小数，打印精度也有限。

## 复现范围与结论边界

本次完成了 arXiv v11 全文与附录、Nature 正式版及补充指南、关键图表与官方代码的核对，并对分箱函数、更新日志和公式算例做了离线检查。没有运行模型评测，也未读取受限数据，因此没有重新计算模型准确率、置信区间或校准表。

一份可比较的复现结果至少需要说明原始 HLE 还是 Rolling、数据 revision、全量还是纯文本、模型日期快照、工具是否可用、采样和 token 上限、最终有效题数、评审版本、缺失项处理及校准分箱实现。论文的奖金池、token 图或代码默认值都不能替代这些运行记录。

HLE 已展示，当模型面对经专家筛选的困难封闭题时，答案正确性与自报信心仍可能明显脱节。它没有提供覆盖所有学科的统一人类考试基线，也没有验证高分模型可以完成自主科研。数据修订、评审误差、选择题猜中和公开后的适应，都需要与模型能力进步一起考虑。
