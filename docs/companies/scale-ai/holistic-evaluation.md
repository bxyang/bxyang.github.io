# 综合评测框架精读：用判断一致性分配人工复核，用分层红队补足覆盖

让大模型给另一组模型的回答打分，可以减少人工工作，但裁判也可能稳定地选错答案。这份报告提出两种人机分工：能力评测中，让裁判反复比较两个回答，再把判断不稳定的样本交给人；安全评测中，先用自动扫描和有经验的通用红队发现问题，再让领域专家判断和深入检查。报告同时提供分类框架、具体流程与小规模实验，没有训练一个新的评测模型，也没有把所有能力和风险压成统一总分。

本文完整阅读了官方 20 页技术报告，包括附录 A–C。原文部分数字、表头和文字解释不一致，下面分别呈现方法、可核对的实验和无法据现有资料确认的结论。[官方报告](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf)

## 先定义覆盖范围，再选择评分方法

报告没有把评测等同于一份固定题库。它先按实际用途划分能力，再区分安全风险与产生风险的方式。这样，团队可以明确本次覆盖了什么，也能看到尚未检查的部分。

### 十类能力的评分重点

| 能力类别 | 报告中的含义与主要检查点 |
| --- | --- |
| 分类 | 依照类别、数值或多选标签归类；检查标签是否正确 |
| 给定文本的信息处理 | 提取、概括或回答材料中的问题；检查忠实性与信息整合 |
| 改写 | 调整风格、视角或修正错误；检查是否遵守改写要求 |
| 内容生成 | 写作、规划、头脑风暴等；检查内容质量及约束 |
| 开放问答 | 不限于给定参考材料的事实、解释和建议；检查事实与领域知识 |
| 推理 | 因果、演绎、归纳、溯因和逻辑问题；检查推导是否成立 |
| 对话 | 交流、游戏、角色对话和情绪回应；检查适当性与交流质量 |
| 不合逻辑的输入 | 无法由条件推出答案或含错误前提的问题；检查是否识别问题所在 |
| 代码 | 生成、重构、调试、解释和语言转换；检查功能与代码质量 |
| 数学 | 解题、证明、解释与数据分析；检查计算和论证 |

原文的 Information retrieval 主要指**对已提供文本的信息处理**，包含摘要和材料问答，不能直接理解成测试向量检索器的召回率。附录 A 进一步给出子类别和示例，但没有公布每类实际抽了多少题、难度分布或各类别的加权方案。作者明确表示，权重应随用途改变。[报告 §2.1、附录 A](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=3)

例如，一个材料摘要任务可以检查是否遗漏关键事实，而一个有格式约束的创作任务还需要检查结构和风格。两者都可能需要人工判断，但需要的判断依据不同。报告的分类帮助组织这些区别，不是经过实验验证、能覆盖所有用途的完备清单。

### 风险描述损害，漏洞描述产生方式

安全部分把用户意图与受害方结合起来，列出五类风险：伤害用户的信息、针对群体的伤害、敏感内容传播、协助恶意行为，以及模型失配或自主行为产生的风险。附录 B 给出更细的定义。它关注模型开发者可在发布前检查的直接风险，并没有覆盖所有社会经济影响。

与这些风险分开的三种漏洞类型是：正常使用时的不可靠输出、对抗提示造成的异常行为，以及有工具权限的 agent 采取偏离用户目标的行动。一个漏洞可能引出多类损害，同一损害也可能来自多种漏洞。因此，评测计划需要同时列明风险与触发方式。[报告 §2.2、附录 B](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=3)

附录 C 归纳了提示注入、编码或风格变换、对话伪装、角色扮演、提示复述、代码包装、训练数据提取和正向回答诱导等类别。这里给的是组织测试的分类，并没有逐类报告完整覆盖率。报告中的实证安全实验只针对 GPT-4 的恶意软件相关对抗对话，不能据此认定已经验证了全部五类风险。

## 能力评测：从十次投票估计判断是否稳定

### 每个回答在前面出现五次

给定同一道问题的两个回答，裁判需要选出人类更可能偏好的回答。报告使用 GPT-4 与 Claude 2.0 作为裁判，参考 MT-Bench／Chatbot Arena 工作的比较提示，要求先解释再作选择；另外介绍了给单个回答打 1–10 分的方式，但没有给出足够的独立结果表来量化单回答评分与成对比较的差距。

主要方法对每个回答对调用裁判 **10 次**，温度为 **1.0**。十次调用中，A 排在前面五次，B 排在前面五次，最后按真实回答身份合并投票。这样做同时观察采样波动和顺序变化，降低单次判断中位置偏差的影响。它不是让十个独立模型投票，也不保证已经消除位置偏差。[报告 §3.1、§4.1.1](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=4)

设第 $i$ 个回答对中，投给 A、B 与未选定一方的次数分别为 $n_{Ai}$、$n_{Bi}$、$n_{Ni}$，总和为 10。第三类是原文的 neither，可能出现于裁判没有按要求作出选择，并不自动表示经过严格定义的质量平局。定义频率：

$$
p_{Ai}=\frac{n_{Ai}}{10},\quad
p_{Bi}=\frac{n_{Bi}}{10},\quad
p_{Ni}=\frac{n_{Ni}}{10}.
$$

报告式 1 对这个三类分布计算熵：

$$
H_i=-\sum_{c\in\{A,B,N\}}p_{ci}\log p_{ci},
\qquad 0\log0:=0.
$$

原文记作 $W_i$，这里换用常见的 $H_i$。熵越低，十次输出越集中。最终判断取票数最多的结果，方法部分说票数相同时随机选择；后面的成本实验又规定把裁判投票平局记为失败，两者需要分别实现，不能混成一个通用评分规则。

### 低熵表示一致，不表示事实正确

以自然对数为说明约定，三组十次投票可以得到：

| A / B / neither 票数 | 熵 | 含义 |
| --- | ---: | --- |
| 10 / 0 / 0 | 0 | 十次都选择 A |
| 9 / 1 / 0 | 约 0.325 | 有一次不同判断 |
| 5 / 5 / 0 | 约 0.693 | 两个回答难分高下 |

这些是公式演算，不是报告额外运行的实验。三类情况下，十次全部输出 neither 也会得到零熵，却没有产生可用的 A/B 偏好。实际实现需要明确这种结果的处理，而不能只检查熵小不小。

原文没有说明对数底数。如果采用自然对数且严格使用这十次离散频率，阈值 $H<0.3$ 只会接受全票一致的情况：最接近一致但仍有分歧的 9/1 分布已达到约 0.325。这个静态计算也解释了图 3 为什么呈阶梯状。更换对数底数、采样次数或输出解析规则，都会改变阈值的数值含义。

### 不确定样本转交人工

给定阈值 $C$，把低熵样本留给裁判，把高熵样本交给人工。可以用下面的说明式表达自动覆盖率：

$$
\operatorname{Coverage}(C)
=\frac{1}{N}\sum_{i=1}^{N}\mathbf1[H_i<C].
$$

自动子集上的一致率则为：

$$
\operatorname{Agreement}_{\mathrm{auto}}(C)
=\frac{\sum_i\mathbf1[H_i<C]\mathbf1[\hat y_i=y_i^{\mathrm{human}}]}
{\sum_i\mathbf1[H_i<C]}.
$$

这里 $y_i^{\mathrm{human}}$ 是人工参考偏好，$\hat y_i$ 是裁判结果。这两式用于解释报告图 3 的统计含义，不是作者发布的评分代码；当自动子集为空时，一致率也不能直接计算。

阈值越宽松，通常能自动处理更多样本，但一致率可能下降。报告扫描多个阈值后建议约 0.3，没有披露独立的阈值选择集和最终验证集。因此这不是带误差保证的选择性分类算法，也不是把熵转换成“判断正确概率”的校准模型。[报告 §3.1、§4.3.1](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=8)

## 数据构造与模型版本的限制

能力题由 Scale 平台人员编写，经历多轮草稿和审核。人工参考由三位独立标注者形成共识。论文没有公布详细招募条件、酬劳、逐题标签和共识解决规则，也没有报告人际一致性。

图 3 展示三组比较：

| 回答组合 | 图中规模 | 主要区别 |
| --- | --- | --- |
| Llama 2 70B Chat 与另一次同模型回答 | 约 500 对 | 同一模型的回答差距较细 |
| GPT-4 与人工改写 | 900 对 | 人工看到 GPT-4 原回答后进行修改，不是独立从零写作 |
| Llama 2 70B Chat 与 Falcon 7B | 约 500 对 | 两种模型的回答差异较大 |

这里保留图中的实际比较对象。§4.1.1 的数据段落先说用 500 道题生成 Llama 和 Falcon 回答，随后却写成每题由 GPT-4 和人类各提供一个回答，再另述 900 道 GPT-4／人工改写题。它与三组图不能逐一无歧义对应。没有原始文件时，不能把三组简单加成 1,900 道互不重复的独立问题。

模型只以 GPT-4、Claude 2.0、Llama V2 70B Chat、Falcon 7B 等名称出现，没有完整 API 日期版本、权重 revision 和全部回答生成参数。结果描述的是 2023 年报告中的实验，不能代表同名产品或模型家族之后的版本。

## 自动子集与整体人机流程的结果不同

### 图 3：自动接受的部分有多可靠

下表是对图 3 的近似读数，不能当作作者公开的逐点数据。

| 回答组合 | 严格低熵区域的一致率 | 低熵区域的样本量 | 放宽到几乎全部样本时 |
| --- | ---: | ---: | ---: |
| Llama 与 Llama | 约 80% | 约 100 对 | 约 57% |
| GPT-4 与人工改写 | 约 74% | 约 300 对 | 约 60% |
| Llama 与 Falcon | 约 97% | 约 450 对 | 约 95% |

图中最明显的差别是，Llama 与 Falcon 这一组在很低熵时就能覆盖大部分回答对；GPT-4 与人工改写则难得多。低熵区域仍有约四分之一的判断与人工不同，不能因为裁判稳定就跳过任务层面的质量要求。[报告图 3，第 9 页](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=9)

正文把 GPT-4／人工改写的这组变化写为约 78% 降至约 65%，与图上约 74% 降至约 60% 不符。本文保留图的近似读数并说明差异，不把两组数字拼接成新结果。

### 图 4：人工接管后，整个数据集的一致率提高

图 4 对低熵题使用模型判断，对高熵题使用人工结果，横轴是相对于全人工的标注时间比例，纵轴是整个集合与人工的一致率。它与图 3 的“只算自动子集”不是同一个分母。

从图上看，GPT-4／人工改写在约 70% 人工标注时间处达到约 92% 整体一致率；Llama／Falcon 用约 10% 人工时间便达到约 97%。Llama／Llama 在约 80% 人工时间处接近 95%。这些仍是近似读图值，并没有误差区间或原始工时文件。[报告图 4，第 10 页](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=10)

正文另概括 GPT-4／人工改写“约 65% 时间、约 90% 一致率”，结论部分又把类似数字用于 Llama／Llama；导言则使用“约 86% 准确、最多自动化 20%”的概述。因此不存在一个可以不区分数据组和阈值直接套用的统一节省比例。

如果仅作说明，并假设所有样本的人工耗时相等、交给人工的部分直接采用同一参考标签，整体一致率可以写为：

$$
\operatorname{Agreement}_{\mathrm{hybrid}}
=(1-a)+a\,\operatorname{Agreement}_{\mathrm{auto}},
$$

其中 $a$ 是自动处理比例。这个关系显示，整体高一致率可以同时依赖大量人工接管；不能拿整体分数当作模型裁判单独的正确率。真实人工可能与共识标签不同，报告没有给出另一组独立人工重标的误差。

**标注时间也不等于总成本。**每个待判断回答对先需要十次裁判调用，之后还要支付人工、复核、失败重试和管理成本。报告没有给出完整 API token、费用、延迟及工时核算方法，不能从“65% 人工时间”推出“总费用下降 35%”。

## 自偏好分析的表格存在无法消除的歧义

报告认为 GPT-4 可能更喜欢自己的回答，于是按参考偏好分组比较两位裁判。表 2 的印刷值如下：

| 标作 Ground Truth 的类别 | GPT-4：数量 / 一致数 / 一致率 | Claude 2.0：数量 / 一致数 / 一致率 |
| --- | --- | --- |
| GPT-4 | 290 / 156 / 53.79% | 250 / 124 / 49.60% |
| 人工改写 | 360 / 274 / 76.11% | 510 / 355 / 69.61% |
| 平局 | 250 / 20 / 8.00% | 140 / 18 / 12.86% |

分数的除法与表中计数相符，但两位裁判面对的所谓参考标签分布不同。如果它们确实在相同 900 对回答上使用相同人工参考，参考类别数量不应随裁判变化。可能涉及表头、分组或样本定义，但没有原始预测与标签就不能确定是哪一种。[报告表 2，第 10 页](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=10)

另一个问题是，作者用“在人类改写被偏好时更准确”支持“偏向自己的回答”，单凭这个条件一致率不能确定偏差方向。若按表中全部行简单汇总，GPT-4 一致数为 $156+274+20=450$，占 900 的 50%；Claude 为 $124+355+18=497$，约 55.22%。这又无法直接支持正文“GPT-4 总体显著更准确”的概括。

因此本页保留作者对自偏好的担忧和表格原值，不将其写成已经用这些数据可靠证明的方向性结论。复现需要统一的人工标签、每个裁判的完整预测、平局处理以及混淆矩阵。

### 低熵错误说明稳定判断仍会失败

表 1 的定性分析发现两类错误：裁判倾向选择保守拒答，而人工更偏好另一条实际回答；对于近期事实，裁判也会稳定支持事实有误的回答。前一类是相对于人工偏好的不一致，不应一律解释为拒答本身错误；后一类则说明裁判知识不足也可能表现为高置信。[报告表 1、§4.3.1](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=10)

错误分析段落还把阈值写成 $C=3.0$，与前后使用的 0.3 不一致。在自然对数三类熵下，最大值为 $\log3\approx1.099$，3.0 不再是严格筛选阈值；不能将这一处直接当成另一个经实验选择的设置。

## 安全评测：自动扫描、通用红队与领域专家

报告借鉴渗透测试的组织流程：先约定范围，再做威胁建模，随后查找并验证漏洞，最后汇总风险及证据。它安排三层人员与工具。

自动扫描覆盖已知模式，通用红队人员发现模型特有的弱点并构造新对话，领域专家判断潜在危害并深入检查。报告讨论了模型生成攻击等更广泛方式，但本次自动实验实际只用了 Garak 的规则探针。框架中列出的能力，不等于每一项都完成了实证对照。[报告 §3.2](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=5)

### 实验配置与样本单位

| 组别 | 人员或输入 | 交互与判断方式 |
| --- | --- | --- |
| 自动扫描 | Garak 生成 240 个提示，每个采样 10 次 | 回答出现代码就计作探针成功 |
| 通用红队 | 14 位有跨项目红队经验的人员 | 最多五轮对话；每轮两条候选中选危害较高的一条继续 |
| 无种子专家组 | 27 位信息安全和计算机相关专家中的一部分 | 与通用红队相同的开放任务 |
| 有种子专家组 | 其余专家；包含有种子与无种子任务 | 接触自动或通用红队的成功案例后继续探查 |

27 位专家在两个组之间如何分配、是否随机分组、各组完成多少段对话没有完整披露。自动扫描按配置为 $240\times10=2400$ 次回答采样，这不同于 2,400 个独立攻击策略。人工每轮有两个候选且最多五轮，查询预算也不与自动组相等。[报告 §4.2](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=7)

人类在结束对话后，自评成功程度和危害程度。成功定义为五分量表中至少 3 分；Garak 则只检查代码存在。二者不是统一的可执行性或真实危害评判标准。受试者背景调查只有约一半回复，小样本与两类人员筛选方式也限制了组间因果比较。

## 成功率、危害和多样性分别衡量不同现象

### 通用红队成功率较高，专家成功案例的危害评分较高

图 5 的近似值如下，危害列只统计成功的人类对话。

| 来源 | 成功率 | 成功案例平均自评危害 |
| --- | ---: | ---: |
| Garak | 约 41% | 未在该图报告 |
| 通用红队 | 约 80% | 约 3.2 |
| 无种子专家 | 约 46% | 约 3.5 |
| 有种子专家项目 | 约 62% | 约 3.6 |

不能因为通用红队的成功率较高，就推断他们发现的每个问题更严重。专家组的平均危害更高，但这是**在各自成功案例上**的自评比较，不是给全部模型输出统一标注后得到的风险率。没有盲评、执行验证、每组原始分母和置信区间时，也无法把图中差距当作已经排除评判习惯差异的结果。[报告图 5、§4.3.2](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=11)

在有种子项目里，专家做未提供种子的任务时成功率为 **52%**，无种子专家项目为 **46%**，差 **6 个百分点**。这一观察与“接触既有案例可能帮助后续探索”相符，但不等于严格随机控制下的纯种子效应，也没有报告按人员聚类后的统计检验。

通用红队成功对话中有 **59%** 被人员标为需要领域知识才能充分判断危害。这里的分母只限成功的通用红队对话，不能写成“全部任务中 59% 已由专家复核”。它支持把发现问题和判断专业正确性分成不同环节。

### 向量距离不能替代漏洞去重

作者把对话嵌入向量空间，比较平均两两距离，称有种子与无种子任务没有显著差别；有种子专家对话与来源案例的平均余弦相似度为 0.52。图 6 展示自动模板较集中，人类对话分布较广。

报告没有给出嵌入模型、具体文本拼接方法、降维算法、统计检验或原始向量。0.52 是给定嵌入下的相似度，不能直接换算为“48% 新漏洞”，也不能证明所有对话都发现了不同漏洞。文本多样性和安全问题的机制多样性需要额外的去重与分类。[报告图 6、§4.3.2](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=12)

### 对话轮数的比较受停止规则影响

图 7 中，从第一轮到第四轮，成功比例大致从 0.21 增至 0.44，第五轮回到约 0.37。图轴写 `% success` 却使用 0–1 小数刻度，本文按比例理解这些近似值，不将 0.44 写成 0.44%。

这些不是同一批对话的累计成功率。成功后允许提前停止，而前面没有成功的对话通常继续到第五轮，所以第五轮保留下来的任务更难。报告本身提醒了这个选择效应。它提示多轮评测的必要性，但不能仅凭柱状图估计给任意对话追加一轮的因果收益。[报告图 7、§4.3.2](https://static.scale.com/uploads/6019a18f03a4ae003acb1113/test-and-evaluation.pdf#page=13)

## 公开实现与复现需要补齐的材料

本次核对了两个官方报告副本、Scale 研究页，以及报告引用的上游资源。未定位到本报告专属的能力题库、人工标签、红队对话、熵计算脚本和完整运行配置。原文说明了可重建的方法，但不足以逐点复原全部图表。

| [Garak](https://github.com/NVIDIA/garak/tree/3f50ea5ff9cd7050099940647c15c39b07a93392) | `3f50ea5ff9cd7050099940647c15c39b07a93392` | 原 `leondz/garak` 地址已转到 NVIDIA；可查探针和检测器，但不是本文 2023 年的已知执行版本 |

复现能力部分，需要固定回答对、三位标注者的独立标签及共识规则，明确哪组问题被复用，记录裁判版本、两种顺序、十次输出、解析失败和平局。随后才能核对熵的底数、阈值边界和自动覆盖率，并在独立数据上选择和验证阈值。成本应同时记录每题人工耗时和十次模型调用费用。

复现安全部分，需要分组及对话数量、任务时间与调用上限、种子来源、统一成功及危害标准，以及专家复核结果。漏洞数量、多样性和成功率应分别统计；如果同一人员完成多段对话，误差估计还需要考虑这些样本并非完全独立。

本次完成全文与附录阅读、关键图表视觉核查、两份官方 PDF 的文本比较，以及熵和表 2 汇总计数的静态演算。**没有调用模型裁判、运行红队探针或重做人员实验，尚未复现报告结果。**

报告能够支持的主要观察是：判断稳定性在这些数据中与偏好一致率有关，模型回答差距也显著影响可自动化程度；通用与专家红队提供了不同类型的评测信息。具体阈值、节省比例和人员配置仍依赖任务与判定标准，不能由这份 2023 年的小规模实验直接推广为所有模型的固定流程参数。
