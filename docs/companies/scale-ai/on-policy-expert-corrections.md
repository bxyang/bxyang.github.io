# OEC 精读：让专家接手学生走到的状态

用专家完成任务的过程训练小模型，学生学到的主要是专家会遇到的状态。实际运行时，学生可能先找错文件、反复查看代码，随后面对训练集中很少出现的历史。OEC 先让学生执行若干轮，再让专家接着完成任务，最后只学习专家接管后的行为。软件工程实验表明，这类纠正轨迹与完整专家轨迹混合，优于相近样本量下只模仿专家；同时，测试通过并不足以保证轨迹适合训练，重复行为筛选和学生片段的损失掩码都会影响结果。[论文，§1–4](https://arxiv.org/pdf/2512.14895v1)

## 1. 多轮模仿学习中的分布偏移

设任务环境不断返回观察 $E_i$，agent 生成思考与工具动作 $A_i$，一条轨迹可以写成：

$$
H=(E_1,A_1,E_2,A_2,\ldots,E_h,A_h).
$$

下一轮动作以此前历史为输入。对软件工程 agent，这个状态既包括仓库实际被改成什么样，也包括模型已经读过的文件、执行过的命令、工具结果与先前生成的文字。学生与专家即使从同一仓库开始，只要前几步不同，之后看到的输入也会不同。[§3](https://arxiv.org/pdf/2512.14895v1#page=3)

行为克隆，也就是 behavioral cloning（BC），使用专家从头完成的轨迹。它教学生在专家历史上继续行动，却没有直接教它从自身常见的偏离中恢复。OEC 借鉴 DAgger 收集学生状态、再由专家提供动作的思路，但采用一次接管后让专家一直执行到结束的做法。

两者不能等同。经典 DAgger 在学生访问的状态上查询专家动作，并在多轮数据聚合中更新策略；OEC 的前缀来自学生，后缀已经由专家诱导，整条轨迹只是部分 on-policy。论文明确承认它没有继承 DAgger 的无遗憾学习保证。数据收集后再固定训练，学生又逐渐偏离采样时的策略，on-policy 也只相对于当时的学生模型而言。[§3.1、局限](https://arxiv.org/pdf/2512.14895v1#page=4)

## 2. 从接管到可训练样本

### 接管保留任务状态与历史

每个任务先随机选一个切换位置，学生执行到该处后，专家接手。本文采用从 0 到 30 的均匀切换范围；公开 `SwitchingModel` 用 `random.randint(0,30)`，包含两个端点，并在下一次模型请求前检查已执行步数是否到达位置。位置为 0 时可以从首次请求就用专家。[算法 1、§4.1](https://arxiv.org/pdf/2512.14895v1#page=4)、[固定版本切换代码](https://github.com/niklaslauffer/on-policy-expert-corrections/blob/422dc7d125ee683d641f7aba2aff70190286ce86/sweagent/agent/switching_model.py)

切换不会把代码恢复到任务起点。系统保留前面的对话和环境状态，但重写系统提示、任务提示及工具调用格式，使其符合专家模型使用的接口。专家没有额外收到“前面是学生做的，请纠错”之类的说明。这里的纠正是专家从既有状态继续解题，不是专门生成一段批评文字。

附录 B 展示了一个 yamllint 配置问题。学生花前 29 轮定位问题，反复分段查看 `config.py`、`linter.py`、`cli.py`；专家接手后制作复现脚本，修改忽略列表的处理，再反复检查路径和规则行为，最后运行测试并提交。它不是接手后一轮就完成，也不能从这个被选中的成功样例推断所有接管都能挽救任务。附录虽称完整轨迹，部分长输出和代码参数在版面中以省略形式呈现，不能直接当作完整可重放日志。[图 1、附录 B](https://arxiv.org/pdf/2512.14895v1#page=12)

### 先筛结果，再筛行为

OEC 与两个主要对照都使用 rejection sampling fine-tuning：先运行任务测试，保留成功轨迹，再做监督微调。OEC 还去除在切换前就已经结束的轨迹，因为它们没有可学习的专家后缀。

作者另外删除两类重复轨迹：相同动作连同参数连续出现三次；或连续至少 20 次执行文件读取命令。后者不是要求始终读取同一个文件，也不是整条轨迹累计读过 20 次就一定删除。[§3.2–3.3](https://arxiv.org/pdf/2512.14895v1#page=5)

测试通过检查的是最终补丁是否满足对应测试。一个 agent 可能长时间重复读文件，最后仍碰巧完成简单任务，这类成功轨迹若照单全收，会让重复行为进入训练。论文因此将“任务成功”和“过程值得模仿”分成两次筛选。

### 学生前缀参与条件输入，不贡献监督损失

训练时屏蔽环境消息，也屏蔽学生生成的前缀，只保留专家后缀的预测损失。为了说明这一目标，可将保留轨迹记为 $\tau$，其中 token 为 $z_u$，$m_u=1$ 表示该 token 属于专家动作或思考：

$$
\mathcal L(\theta)=-\sum_{\tau\in D_{\rm kept}}\sum_u
m_u\log\pi_\theta(z_u\mid z_{<u}).
$$

这个式子是对论文训练描述的数学整理，不是原文另提出的损失公式；论文未完整规定不同长度样本的归一化实现。关键在于 $m_u$ 只控制哪些 token 被要求模仿，不删除其余上下文。比如学生先错误地反复查看某文件，专家随后改查另一个文件，训练学习的是带着这些既有历史转向正确操作，而不是要求学生重新生成那段重复行为。

公开 XML 转换函数输出逐消息的 `mask_input_ids`，当 assistant 消息序号小于 `model_switch_idx` 时置为真；用户与系统消息也置为真。真正训练时还需要 collator 将这个标记落实到 token labels；仅仅把字段写进 JSONL，并不能保证任意通用 SFT 训练器会自动遵守。[§3.2](https://arxiv.org/pdf/2512.14895v1#page=4)、[转换函数](https://github.com/niklaslauffer/on-policy-expert-corrections/blob/422dc7d125ee683d641f7aba2aff70190286ce86/traj_mgr/utils.py)

## 3. 学生已经接受过一次专家训练

论文不是从没有 agent 能力的原始模型直接开始收集纠正数据。

| 设置 | 学生初始化 | OEC 接管专家 | 主要轨迹实验的训练问题 |
| --- | --- | --- | --- |
| 7B | Qwen2.5-Coder-7B-Instruct，先用约 5,000 条 Claude 专家轨迹训练 | SWE-smith 系列的 32B agent 模型 | 从已有专家轨迹提取的 4,121 个 SWE-smith 实例 |
| 32B | Qwen2.5-Coder-32B-Instruct，先用 2,000 条 Claude 专家轨迹训练 | Claude-3.7-Sonnet | 排除学生已训练实例后保留 2,308 个实例 |

约 5,000 条初始专家轨迹来自 SWE-smith 的公开 Claude-3.7-Sonnet 数据。32B 留下另外约 3,000 条，供后续 BC 对照使用。论文选择已由专家完成过的任务作为主要采样来源，因此这一部分不是对所有 SWE-smith 难度的随机抽样。[§4.1](https://arxiv.org/pdf/2512.14895v1#page=6)

三种数据生成方式共享 SWE-agent 框架：BC 全程专家、on-policy 全程学生、OEC 学生前缀加专家后缀。所有方式都采用测试筛选、重复过滤和 SFT；其中“全程学生”的对照并不是 PPO 或 GRPO 等策略梯度强化学习实验，不能将其性能下降概括为强化学习普遍无效。

每个数据量点都从相同的学生初始化模型重新微调，而不是将前一个点的模型接着训练。7B 实验每一组额外混入 1,000 条原始 Claude 轨迹；图 2a 横轴是所改变的数据量，这 1,000 条是额外的。32B 的 OEC 主曲线则将 OEC 与 BC 等量混合，横轴已经包含两者总数。直接比较两张图的横轴会混淆实际样本预算。[§4.2、图 2](https://arxiv.org/pdf/2512.14895v1#page=7)

## 4. 数据量比较与最终模型结果

### 相近样本量下的 32B 对照

论文最清楚的一组比较是：961 条 OEC 加 961 条 BC，共 1,922 条后续训练轨迹，得到 SWE-bench Verified 39.0%；纯 2,000 条 BC 得到 34.4%。前者多完成 23 个问题，即 500 题上的 4.6 个百分点，相对提升约为：

$$
\frac{39.0-34.4}{34.4}\approx13.4\%.
$$

这是相近轨迹数的比较，不是完全相同的专家 token 预算。纯学生轨迹对照即使经过成功筛选与重复过滤，32B 结果仍明显低于初始学生的 31.2%。[§4.2、图 2b、表 3](https://arxiv.org/pdf/2512.14895v1#page=7)

在主要 2,308 题来源上，32B OEC 一次采样的任务解决率为 62.3%。为补充数据，作者又抽取 2,476 个更难的问题，采样解决率仅 12%；这部分只进入图 2b 最后一个 OEC 点，以虚线连接。该点变动了问题来源分布，不能与此前纯 BC 对照解释成只增加轨迹条数的完全控制实验。全程学生数据则以三次遍历生成，报告解决率约为 36%。

7B 的数据量实验在 SWE-bench Lite 上进行。图 2a 中，OEC 末端约 17%，纯 BC 约 14.7%，全程学生数据几乎没有带来改善。其纵轴画成 0.170 这类小数，但轴标题写百分比，应按 17% 理解。摘要所称 7B 相对提升 14%、32B 提升 13% 没有逐一展开分母；不能将它们直接套到下方跨模型主表，或把 7B 的 Lite 曲线当作 Verified 曲线。[摘要、图 2](https://arxiv.org/pdf/2512.14895v1)

### 混合数据比只增加某一种更有效

图 3 固定 961 条 OEC、增加 BC，或固定 961 条 BC、增加 OEC。两条曲线在总量 1,922 条处汇合，对应 39.0%。最好的实验点用 961 条 OEC 加 2,000 条 BC，达到 Verified 40.0%。这支持纠正轨迹与从头完成的专家轨迹相互补充；并不支持把全部 BC 换成 OEC。

32B 最终模型还经历了初始化时的 2,000 条 BC，因此表 1 列总训练量 4,961，而图 3 最后一点的后续数据量是 2,961。两者是不同训练阶段的计数，不能当成表格矛盾。[图 3、表 1](https://arxiv.org/pdf/2512.14895v1#page=5)

| SWE-smith-LM-32B | 5,016 | 28.3% | 36.4% | 本文重测 |

## 5. 掩码、重复过滤与切换时机

### 两种质量控制的作用不同

| 模型及评价集 | 初始学生 | 完整 OEC 配方 | 不屏蔽学生损失 | 不过滤重复轨迹 |
| --- | ---: | ---: | ---: | ---: |
| 7B／Lite | 13.3% | 17.0% | 17.0% | 11.0% |
| 32B／Verified | 31.2% | 40.0% | 31.8% | 36.4% |

表 2 中，移除重复过滤使 7B 下降 6.0 个百分点，甚至低于初始模型；32B 下降 3.6 个百分点。移除学生片段掩码对该 7B 设置没有可见影响，却使 32B 下降 8.2 个百分点，几乎消除全部增益。两种规模使用的专家与数据组合不同，不能仅由这张表断言模型越大越依赖掩码。[表 2](https://arxiv.org/pdf/2512.14895v1#page=8)

在报告的筛选批次中，7B 删除 8.46% 的轨迹，包括 167 条连续读文件、93 条相同动作；32B 删除 3.63%，分别为 43 条和 2 条。这些已是测试通过后的样本，显示最终结果验证没有覆盖所有训练过程质量。过滤比例与最终模型表中的训练量并非同一分母，不应倒推为每个最终训练集都恰好删除相同比例。

### 晚一些接管在这组实验中稍好

作者将约 1,200 条 OEC 按切换位置分为 0–6、7–15、16–30 三组，每组取 372 条，再各加 372 条 BC，形成三份 744 条训练集。Verified 结果分别为 31.0%、32.4%、32.6%。[§4.2](https://arxiv.org/pdf/2512.14895v1#page=8)

晚切换意味着专家看到更长的学生历史，也意味着学生更可能在切换前就结束，从候选 OEC 中被排除。这个比较是在不同位置已经采样成功、已经保留下来的轨迹间进行，没有对同一问题随机固定其他因素；切换范围和成功筛选都可能改变任务组成。结果支持尝试更靠后的接管位置，但没有证明等待越久越好，更没有报告 30 步以后的最优规律。

## 6. 用嵌入距离观察历史分布

论文另取十个 SWE-smith 问题，为每个模型每题生成 50 条轨迹，温度为 0.1。学生使用已有的 SWE-smith-LM-7B、32B，专家为 Claude-3.7-Sonnet。作者用 Qwen3-8B embedding 将每轮历史映射为 4,096 维向量，在每个时间点用包含十条 rollout 嵌入的重复样本拟合高斯分布，再比较学生与专家。[§4.3](https://arxiv.org/pdf/2512.14895v1#page=8)

作为方法解释，均值和协方差分别为 $(\mu_S,\Sigma_S)$、$(\mu_E,\Sigma_E)$ 的两个高斯，其常用 Fréchet/FID 形式是：

$$
\|\mu_S-\mu_E\|_2^2+
\operatorname{Tr}\left(\Sigma_S+\Sigma_E-
2(\Sigma_S^{1/2}\Sigma_E\Sigma_S^{1/2})^{1/2}\right).
$$

第一项比较平均历史表示，第二项比较分布形状。这里是对原文所用高斯距离的解释，不是直接测量错误数量或策略动作概率。相同距离可能对应不同的实际失败行为；嵌入模型、长历史截断和数值正则化都会影响值。

图 4 在前约十几轮先下降，此后总体上升，30 轮附近有明显增长，后半段继续扩大；并非从第一轮起严格单调。附录 E 的高斯 KL 曲线有类似趋势，专家与专家分组的 FD 对照较低。阴影表示作者报告的 95% 区间。[图 4–6](https://arxiv.org/pdf/2512.14895v1#page=31)

要区分这些区间与训练稳定性：它们来自轨迹分布分析，不是表 1 所有模型成绩的多种子训练置信区间。每个高斯重复样本只有十个向量，而维数是 4,096，经验协方差必然低秩；KL 如何正则化、长轨迹后期如何处理已结束样本，都影响复现。当前公开分析入口导入的核心 `compute_turnwise_metrics` 模块未出现在所核仓库文件中，无法仅凭入口脚本还原这些处理。

这组分析证明了既有 BC 学生与专家的历史表示有系统差异，但没有直接展示“OEC 训练后 FD 降低多少”的对照。将性能改善完全归因为 FD 下降，超出了已报告实验。

## 7. 失败分类的分母与信息范围

作者用 GPT-5 对失败轨迹的最后 20 轮进行分类。已经提交补丁却失败的样本，分为方案错误、语法错误、定位错文件、不遵循指令、遗漏边界条件等；没有提交的样本，则分为工具问题、上下文过长和循环。[§4.4、附录 D](https://arxiv.org/pdf/2512.14895v1#page=9)

表 3 的“已提交／未提交”比例限定在未解决轨迹中；提交后的错误类别进一步以提交但失败的样本为分母，循环等类别以未提交样本为分母。比如完整 32B 配方的“未提交 18.1%”不能直接写成全部 500 题的未提交率，“循环 53.7%”也不能写成全部任务一半陷入循环。

| 32B 配方 | 整体解决率 | 失败轨迹中未提交占比 | 已提交失败中不遵循指令占比 | 未提交中循环占比 |
| --- | ---: | ---: | ---: | ---: |
| 初始学生 | 31.2% | 21.3% | 40.8% | 58.0% |
| 加 3,000 BC | 36.0% | 17.6% | 22.8% | 50.0% |
| 加 961 OEC＋2,000 BC | 40.0% | 18.1% | 24.2% | 53.7% |
| 同配方取消学生掩码 | 31.8% | 17.5% | 47.0% | 52.5% |

表 3 中并不是 OEC 的每个条件错误比例都低于纯 BC；分母随总失败数变化，也会改变分类占比。正文将该分析数据写作 SWE-smith，而表注写 SWE-bench Verified；这里按表注保留范围，并将这一来源表述差异留作复现时需核对的问题。[表 3、§4.4](https://arxiv.org/pdf/2512.14895v1#page=9)

论文引用前作中自动分类与人工标签 87% 的一致性，不是重新验证本文 GPT-5 分类的准确率。公开脚本还把问题文本截至约 1,000 字符、每条观察截至 200 字符，因此“最后 20 轮”也不意味着裁判看到了这些轮次的全部内容。较早的定位原因、长测试输出和实际代码可能被遗漏。这是受指定输入范围约束的自动归因，而非完整人工代码审计。[分类脚本](https://github.com/niklaslauffer/on-policy-expert-corrections/blob/422dc7d125ee683d641f7aba2aff70190286ce86/failure_categorization/scripts/qualitative_analysis_by_category.py)

### 公开轨迹有 1,268 条，但没有提供可核验的学生边界

另检查 [ScaleAI/swe-oec-claude-expert](https://huggingface.co/datasets/ScaleAI/swe-oec-claude-expert/tree/a2bc52b11fe7fe4f172652186488082813e1053b)，固定 revision 为 `a2bc52b11fe7fe4f172652186488082813e1053b`。对公开 parquet 全部行做静态统计，得到：

| 核查项 | 结果 |
| --- | ---: |
| 数据行、不同轨迹 ID | 1,268、1,268 |
| 不同任务 ID | 1,122 |
| `resolved=true` | 1,268 |
| Assistant 消息数 | 43,233 |
| Assistant 中 `mask_input_ids=true` | **0** |
| 用户消息数，全部标记为屏蔽 | 43,233 |
| 系统消息数，全部标记为屏蔽 | 1,268 |

数据字段包括消息、任务 ID、成功标记、模型名、轨迹 ID 和补丁；没有单独的 `model_switch_idx`，模型字段全部为 `switching`。成功标记来自发布数据，本次没有重跑任务测试。这份 1,268 条数据也不能直接当作论文每个实验中使用的 961 条子集。

所有 assistant 消息都未屏蔽，意味着仅按现有消息标记训练，会监督所有已存 assistant 内容。公开字段不足以判断学生前缀是否已经在其他处理阶段移除，也不足以恢复每条轨迹的学生／专家边界。因此不能把这份数据直接描述成已经验证具备论文所需的学生损失掩码。

源码能说明这一边界为何必须确认：`transform_traj_xml` 在没有 `model_switch_idx` 时默认取 0。将两个纯文本 assistant 消息组成的自拟样本送入独立抽取的转换函数，缺省边界时二者都不屏蔽；指定边界 1 时才屏蔽第一个。这个轻量检查只验证转换函数的分支行为，没有运行 agent，也没有证明作者原始训练一定缺失掩码。当前仓库未给出从切换日志到该顶层字段的完整预处理链，使用者需要补齐并核验。[转换函数](https://github.com/niklaslauffer/on-policy-expert-corrections/blob/422dc7d125ee683d641f7aba2aff70190286ce86/traj_mgr/utils.py#L86-L126)

所核 parquet 大小为 39,761,793 字节，SHA-256 为 `3832846b6887aed2e748e45cb61a288f6a15813e0d681b60fb656fade4519ea7`。这些是当前公开快照的实测统计，不是对论文训练日志的重建。

### 原样复现仍需要补齐的连接

公开代码已经实现随机模型切换、部分历史格式转换、读取测试结果、消息掩码字段和 GPT-5 分类入口，但还不能把 README 中的命令视为无需修改即可执行的完整配方：

- 示例脚本包含本地目录和待下载任务文件占位；配置中的模型服务端点需要实际部署，不能从参数值推断作者实测成本。
- 数据工具导入 `on_policy_expert_corrections.REPO_DIR`，所核文件树未包含相应模块；分布分析也缺少导入的核心距离计算模块。
- 未找到与论文两条重复筛选规则对应的完整执行脚本，以及全部实验的训练配置、掩码 collator 和精确样本清单。
- `convert_to_sft.sh` 实际走 `collect_trajs`，不要与另一个同名用途的 `convert_to_sft.py` 混淆；后者生成逐轮 prompt-response 对，不能默认具有相同的专家边界处理。
- 当前切换配置在学生侧使用最近五条观察的历史处理，在专家侧切换为缓存控制。保留存档历史，不等于每次模型请求都无截断地看见全部原始工具输出。

这些是固定公开版本的复现缺口，不是对论文实验是否运行过的判断。本文完成全文与全部附录阅读、图表核对、公开数据全量字段统计、配置和相关源码检查；没有启动模型、执行软件任务或进行训练，尚未复现论文解决率。

OEC 的实验证据集中在已有一定能力的 Qwen2.5-Coder 软件工程 agent，以及可由测试筛选成功的任务。它显示接近学生实际历史的专家纠正可以补充传统示范数据；对其他工具环境、不同专家质量、持续在线重采样或没有可靠测试的任务，论文尚未给出对应验证。
