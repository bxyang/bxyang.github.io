# Rubrics as Rewards：把评分细则接入强化学习

数学答案可以匹配，代码可以运行测试，但一段开放式回答往往需要同时满足事实、解释、完整性和表达要求。Rubrics as Rewards（RaR）为每个问题生成一组具体评分细则，再让评审模型依据细则给当前模型的回答打分，将分数用于强化学习。它研究的是怎样制作和使用奖励信号，而不是新设计一种语言模型架构。[论文，第 1—4 页](https://arxiv.org/pdf/2507.17746v2#page=1)

## 每个问题需要一组具体标准

“内容正确、回答完整、表达简洁”可以用于很多问题，但它们没有告诉评审者这道题应该包含哪些事实与推理。RaR 将这种通用评价拆成针对当前问题的检查项。

例如，要解释一个物理系统的机械能变化，评分细则可以分别检查：是否说明适用条件，是否解释动能与势能的转换，是否指出损耗对结论的影响。这个例子只用于说明任务分解；具体的科学事实仍应由原题和参考资料确定。

这种数据的基本单元是“问题—参考答案—评分细则”。参考答案主要用于生成细则，之后同一组细则可以评估当前模型对这道题产生的多种新回答。模型每轮生成不同回答，不需要专家重新为每一对答案写比较标签。[论文 §2—3](https://arxiv.org/pdf/2507.17746v2#page=2)

论文提出四个设计要求：细则有专业知识依据，覆盖多个质量维度，表达不同项目的重要性，并且可以独立判断。“独立判断”意味着尽量写清需要出现的事实，而不是只说“答案符合领域常识”。这是细则生成的目标，不等于全部合成条目已经得到专家逐项验证。

## 两种奖励计算方式

### 显式聚合：逐项判断，再计算总分

设输入为 $x$，当前策略模型为 $\pi_\theta$，采样回答为 $\hat y\sim\pi_\theta(\cdot\mid x)$。问题包含 $k$ 条细则，每条权重为 $w_j$。评审模型判断回答是否满足第 $j$ 条，得到二元值 $c_j(x,\hat y)\in\{0,1\}$。

论文公式 1 将这些判断聚合为：

$$
r(x,\hat y)=\frac{\sum_{j=1}^{k}w_jc_j(x,\hat y)}{\sum_{j=1}^{k}w_j}.
$$

分母用于缩放不同数量和权重的细则，避免一题仅因检查项多就自然得到更大的分数。显式实验按类别统一赋权：Essential 为 1.0，Important 为 0.7，Optional 为 0.3，Pitfall 为 0.9。[论文 §2.2、§4.4](https://arxiv.org/pdf/2507.17746v2#page=3)

以下为自拟的四项计算示例：

| 类别 | 权重 | 回答 A 是否满足 | 回答 B 是否满足 |
| --- | ---: | ---: | ---: |
| 必要结论 | 1.0 | 1 | 1 |
| 关键解释 | 0.7 | 1 | 0 |
| 补充说明 | 0.3 | 0 | 1 |
| 避免常见错误 | 0.9 | 1 | 0 |

A 的奖励为 $2.6/2.9\approx0.897$，B 为 $1.3/2.9\approx0.448$。两者都给出结论，但细则还能区分解释与错误控制。这里只展示奖励计算，不表示这些自拟条目能有效训练某个真实任务。

需要特别区分 Pitfall 的方向：正文脚注将显式实验中的这类项目解释为“避免某项错误”，满足时得正分。公开数据和附录生成提示中则还存在负权重形式，标记应该扣分的错误或遗漏。把原始负权重直接套入上述正权重实验配置，会改变含义和归一化范围；复现前必须统一条目语义和权重映射。[论文第 5 页脚注、附录 A.1 与生成提示](https://arxiv.org/pdf/2507.17746v2#page=18)

### 隐式聚合：提供细则，由评审模型综合打分

隐式版本把问题、回答和全部细则一起交给评审模型，让它给出一个 1—10 的整体分数，再归一化用于训练：

$$
r_{\mathrm{implicit}}(x,\hat y)=f_\phi(x,\hat y,\{d_j\}_{j=1}^{k}).
$$

其中 $f_\phi$ 是评审模型，$d_j$ 是带重要性标签的细则描述。它仍然依据具体标准评分，只是不再由外部代码逐项求加权和。作者提示要求输出包含 `rating` 的 JSON 对象。[论文公式 2、附录 A.6](https://arxiv.org/pdf/2507.17746v2#page=16)

因此，显式版本便于检查每一项贡献；隐式版本把细则之间的综合判断交给模型。论文比较的是这两种奖励组织方式，没有证明其中一种在全部领域都更好。

## 奖励如何进入训练

RaR 采用 on-policy 训练，即每轮用当前策略模型产生回答，再用这些新回答更新策略。完整流程如下：

```text
问题 + 参考答案 → 生成该题评分细则 → 固定细则供后续使用
                                         ↓
当前策略针对问题生成 16 个回答 → 评审模型打分 → GRPO 更新策略
          ↑                                      ↓
          └──────────── 下一轮使用更新后的模型 ────────┘
```

GRPO 利用同一问题下多条回答的相对奖励形成更新信号。RaR 的主要变化在奖励端：用针对问题的细则约束评审，再以该奖励训练，而不是直接让评审模型凭整体印象打分。[论文图 1、§4.2](https://arxiv.org/pdf/2507.17746v2#page=4)

作者还说明了与可验证奖励的形式关系：如果一题只有一个检查项、权重为 1，检查函数是答案匹配或测试执行，那么奖励退化为传统的二元正确性信号。这是统一的数学写法；由语言模型执行多项主观判断，并不会因此获得与程序测试相同的可靠性。[论文 §2.3](https://arxiv.org/pdf/2507.17746v2#page=3)

## 数据制作与公开数据规模

RaR-Medicine 的问题来自 medical-o1-reasoning-SFT、NaturalReasoning、SCP-116K 与 GeneralThought-430K。RaR-Science 使用其中后三个来源，覆盖科学推理主题。生成器读取问题和参考答案，输出题目专属的细则。医学部分使用 GPT-4o，科学部分使用 o3-mini。[论文 §3.2、§4.1](https://arxiv.org/pdf/2507.17746v2#page=4)

生成提示要求每题 7—20 条，包含标题、描述和权重。论文附录统计平均约 7.5 条；提示要求与实际数据分布应分别记录，不能把提示中规定的范围当作所有输出都满足的验证结果。

公开数据每行包含 `question`、`reference_answer`、`question_source`、`rubric`、`rubric_list` 和 `rubric_count`。以下为所核对数据版本中的划分：

| 数据集 | train | val | test | train + val |
| --- | ---: | ---: | ---: | ---: |
| RaR-Medicine | 17,926 | 2,240 | 2,242 | 20,166 |
| RaR-Science | 18,333 | 2,292 | 2,292 | 20,625 |

[医学数据卡，版本 5cafb775](https://huggingface.co/datasets/anisha2102/RaR-Medicine/blob/5cafb775815775bf5b559f6b054a677f230fe1c5/README.md) · [科学数据卡，版本 51052d6c](https://huggingface.co/datasets/anisha2102/RaR-Science/blob/51052d6c54964e1f208deddf7f31e4cbdda89d25/README.md)

论文附录的 20,166 和 20,625 对应 train 与 val 的合计，不是当前公开数据三个 split 的总量。RaR 数据自身的 test 也不等同于论文用来报告泛化表现的 HealthBench 或 GPQA-Diamond。

细则主要通过模型合成，参考答案提供专业知识的代理信号。这项工作没有声称全部约四万道训练问题都由医生或科学家重新编写并逐条人工标注。人工细则用于单独的 HealthBench 消融实验，应与合成训练集区分。

## 训练设置与对照方法

| 设置 | 论文值 |
| --- | --- |
| 策略底座 | Qwen2.5-7B |
| 训练算法 | GRPO |
| 训练时评审模型 | GPT-4o-mini |
| 每题采样回答数 | 16 |
| 有效 batch size | 96 |
| 采样温度 | 1.0 |
| 最大长度 | 3,584 |
| 学习率 | $5\times10^{-6}$ |
| 学习率计划 | 10% 线性 warmup 后保持常数 |
| 更新步数 | 300 |
| 硬件 | 单节点 8 张 H100 |

[来源：论文 §4.2、附录表 10](https://arxiv.org/pdf/2507.17746v2#page=15)

主要对照如下：

| 方法 | 奖励依据 |
| --- | --- |
| Direct-Likert | 仅看问题和回答，直接给 1—10 分 |
| Reference-Likert | 额外提供参考答案，再整体打分 |
| RaR-Predefined | 所有问题共享“正确、完整、简洁、有用”等通用细则，均匀赋权 |
| RaR-Explicit | 每题独立细则，逐项判断并按类别权重聚合 |
| RaR-Implicit | 每题独立细则，由评审模型综合打分 |

Reference-Likert 尤其重要：它同样获得参考答案支持。与它比较，才能进一步观察把参考信息整理成细则的效果；只与不提供参考资料的评分器比较，无法排除额外知识本身带来的收益。[论文 §4.3—4.4](https://arxiv.org/pdf/2507.17746v2#page=5)

## 主实验结果

医学模型在 HealthBench 上评估，按细项标准检查开放式回答；科学模型在 GPQA-Diamond 上评估选择题。后者重复 10 次、每次置换选项顺序，使用贪心解码。选项解析失败时，原文说明会调用 GPT-4o 判断答案文本是否包含正确选项。[论文 §4.5、附录 A.4](https://arxiv.org/pdf/2507.17746v2#page=5)

下面直接摘录 v2 图 2 标出的数值。HealthBench 是归一化评分，GPQA-Diamond 是选择题准确率，两列不是同一个指标。

| 方法 | HealthBench 总分 | GPQA-Diamond 准确率 |
| --- | ---: | ---: |
| Qwen2.5-7B | 7.7% | 31.7% |
| Qwen2.5-7B-Instruct | 22.7% | 35.0% |
| Direct-Likert | 25.5% | 34.8% |
| Reference-Likert | 28.9% | 36.5% |
| RaR-Predefined | 12.5% | 31.7% |
| RaR-Explicit | 29.7% | 36.9% |
| RaR-Implicit | 31.2% | 37.6% |

[来源：论文图 2，第 6 页](https://arxiv.org/pdf/2507.17746v2#page=6)

在这个图中，RaR-Implicit 相比 Reference-Likert 分别高 2.3 和 1.1 个百分点，相比 Direct-Likert 分别高 5.7 和 2.8 个百分点。固定通用细则的版本则没有取得类似效果，说明“加入一份评分清单”本身不足以解释结果，细则与具体题目的对应关系很重要。

原文摘要与正文还写有“最高 31% 和 7% 的相对提升”。这些表述不能由图 2 的上述 Direct-Likert 数值直接复算：$31.2/25.5-1$ 约为 22.4%，$37.6/34.8-1$ 约为 8.0%。本文保留原图数据及绝对差，不将摘要比例与它们混为同一结果。

两种训练后的评估形式不同：HealthBench 仍使用细则评分，GPQA-Diamond 检查最终选项。科学任务的改善表明收益不局限于相同形式的 rubric 打分，但并未验证所有开放式任务的迁移。

## 参考答案与人工细则的消融

作者另从 HealthBench 留出 1,000 题评估，使用其余池中的约 3,500 题训练，对比人工细则、合成细则和无细则方法。它与前面的 RaR-Medicine 主实验不是同一训练与测试划分。

| 训练方式 | HealthBench-1k 总分 |
| --- | ---: |
| 参考答案 SFT | 20.4% |
| Simple-Likert | 23.9% |
| Reference-Likert | 31.7% |
| 无参考答案生成的合成细则 | 32.0% |
| 有参考答案生成的合成细则 | 35.9% |
| 人工细则 | 34.8% |

[来源：论文表 1](https://arxiv.org/pdf/2507.17746v2#page=7)

有参考答案的合成细则比无参考答案版本高 3.9 个百分点，说明参考信息在该实验中有作用。合成细则与人工细则取得接近结果，但这是一组任务上的训练后评估，不能据此认定合成细则的每一条事实都比专家更准确，也不能用 35.9% 与主实验的 31.2% 直接比较方法提升。

## 细则中的哪些组成部分有效

表 2 在另一组 HealthBench-1k 消融配置中比较细则元素：

| 细则配置 | 总分 |
| --- | ---: |
| 只保留 Essential | 34.9% |
| 去掉类别标签 | 38.8% |
| 去掉 Pitfall | 37.2% |
| 全部细则 | 37.2% |

[来源：论文表 2](https://arxiv.org/pdf/2507.17746v2#page=8)

仅保留必要条件低于包含更广泛细则的版本；但保留 Pitfall 没有在这张表中带来分数改善，类别标签也没有表现出稳定收益。作者认为合成的常见错误条目可能不够具体，这是解释而非单独证明的机制。

这些结果限制了对方法的概括：论文支持针对题目制作丰富标准的价值，没有证明标准越多、类别越细或加入负面条目就一定更好。各表的生成器、训练子集与细则配置需分别对应，不能把不同消融表的“全部细则”当成同一个固定实验点。

## 小评审模型与偏好一致性

作者构造了一个成对评估集合：将质量较好的回答与经过受控修改的较差版本配对，再检查评审模型是否给较好回答更高分。附录描述使用 o3 制作修改，并经过人工筛查，最终保留 3,027 对回答，同时排除用于消融的 HealthBench-1k 问题。[论文，附录 A.7](https://arxiv.org/pdf/2507.17746v2#page=17)

这是对受控质量差异的排序能力测试，不是未经加工收集的全部真实用户偏好。正文图 3 显示，提供细则能提高不同规模评审模型在该集合上的区分表现，较小模型收益更明显。

附录表 11 则比较不同评审模型用于 GRPO 后的结果。例如 Qwen-7B-Instruct 作为评审时，RaR-Implicit 为 26.7%，Direct-Likert 为 22.0%。这张表与成对偏好准确率不是同一实验；原文关于表 11 的标签表述也不完全一致，本文不把它当作图 3 的偏好准确率重新引用。[论文，附录 A.8 与表 11](https://arxiv.org/pdf/2507.17746v2#page=15)

## 公开资料能支持怎样的复现

论文公开了两组 rubric 数据、生成提示、评审提示和主要训练参数，并说明使用内部后训练平台 RLXF。所引发布材料没有提供可直接对应全部结果的完整训练脚本、checkpoint 和逐步运行日志。因此，下列数据读取代码是资料检查入口，不是完整复现程序。

```python
from datasets import load_dataset

medicine = load_dataset(
    "anisha2102/RaR-Medicine",
    revision="5cafb775815775bf5b559f6b054a677f230fe1c5",
)
science = load_dataset(
    "anisha2102/RaR-Science",
    revision="51052d6c54964e1f208deddf7f31e4cbdda89d25",
)
```

完整复现至少需要补齐并记录以下内容：

- 细则的正负语义、类别提取与显式权重映射，避免把原始负权重与正向检查混用。
- 策略模型、生成器、评审模型的具体版本，以及 1—10 分归一化的实现。
- GRPO 的裁剪、KL、采样与训练批次定义等未由主超参数表完整规定的细节。
- HealthBench 主实验、HealthBench-1k 消融和成对偏好集合的明确任务划分。
- GPQA 选项置换种子、答案提取逻辑、失败时评审调用及评分预算。
- 每条生成回答、细项或整体奖励、评审失败记录和最终 checkpoint。

本文未运行训练或评估，也没有将论文硬件配置换算成未披露的总训练费用。

## 结论适用范围

RaR 将较强模型与参考答案中的信息转成题目专属评分标准，再交给较小评审模型反复使用。实验表明，这种结构化奖励在医学和科学两类任务上优于所测的若干直接整体评分基线。

奖励仍由模型判断，细则仍可能包含遗漏、错误或与参考答案绑定过紧的要求。论文没有证明其能消除奖励利用行为，也未验证长期工具调用、企业 agent 或全部开放式写作任务。专业问答评分的提高同样不等于真实场景部署效果；本文仅讨论数据与训练方法。[论文 §9](https://arxiv.org/pdf/2507.17746v2#page=9)
