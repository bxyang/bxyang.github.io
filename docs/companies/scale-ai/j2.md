# J2：让模型组织多轮安全测试

原文：[Jailbreaking to Jailbreak](https://arxiv.org/abs/2502.09638v2)，本文依据 2025 年 5 月 29 日的 arXiv v2。

## 0. 作者与机构背景

第一作者 Jeremy Kritz 和第二作者 Vaughn Robinson 均署名 Scale AI，论文没有共同第一作者标注。Scale 在 2025 年 5 月举办的[论文介绍活动](https://learn.scale.com/en/public/events/j2-jailbreaking-to-jailbreak)将 Kritz 的职位列为提示工程师；Outlier 主办的[研究分享](https://lu.ma/p79vtg73)进一步说明，他从事红队测试与合成数据研究。这些工作直接涉及如何组织模型对话，以及如何把测试经验转化为可重复使用的数据与流程。

Robinson 同样参与过 Scale 的模型评测研究，例如 [GSM1k](https://arxiv.org/abs/2405.00332) 所研究的算术能力评估，以及[浏览器代理安全研究](https://arxiv.org/abs/2410.13886)。公开原始资料尚不足以确认他在 J2 发表时的具体职务和教育经历，因此这里仅采用论文能够确认的研究参与信息。

本论文全部作者的机构统一列为 Scale AI，还包括以集体名义署名的 Scale Red Team。它属于公司内部的安全评估研究，结合了模型研究人员与人工红队测试人员的经验；作者顺序本身不能用来推断每个人的具体分工。

## 1. 摘要翻译

以下译自该版本 Abstract。原文采用 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/) 许可；本节为中文翻译，按相同许可提供。

大语言模型可以用于对其他模型开展红队测试，例如通过越狱诱导其生成有害内容。已有工作通常使用开放权重模型或非公开、未受内容限制的模型来实施越狱，因为经过拒绝训练的强大语言模型（例如 OpenAI o3）会拒绝协助越狱；我们的工作则把几乎任何黑盒大语言模型转变为攻击者。由此得到的 J2（jailbreaking-to-jailbreak，即“通过越狱来实施越狱”）攻击者，能够使用多种策略有效突破目标模型的安全防护。这些策略既可以由模型自行创建，也可以来自专业人工红队测试人员。通过这一过程，我们展示了这些模型强大但尚未得到充分研究的越狱能力。

实验表明：第一，用于创建 J2 攻击者的提示可以迁移到几乎所有黑盒模型；第二，J2 攻击者能够使同一模型的另一个实例越狱，而且这种脆弱性在过去 12 个月中快速发展；第三，与其他模型相比，Sonnet 3.7 等推理模型是更强的 J2 攻击者。例如，在测试 GPT-4o 的安全防护时，J2（Sonnet 3.7）的攻击成功率达到 0.975，与专业人工红队测试人员相当，并超过当时最先进的算法式攻击。在 J2 攻击者中，J2（o3）对 Sonnet 3.5 的攻击成功率最高，为 0.605；后者是防护最稳健的模型之一。

## 2. 研究背景与相关研究

拒绝训练让模型在面对有害请求时拒绝回答。红队测试则主动寻找防护失效的输入，帮助开发者理解模型在实际交互中的安全边界。人工测试人员能够根据回应灵活调整对话，但这种方式难以大规模覆盖不同任务与模型。

论文第 2 节将自动化研究分为几条路线。一类方法搜索能够突破防护的特殊输入，例如 GCG 使用模型内部的梯度信息；面对只提供 API 的模型，则需要依赖攻击迁移或大量黑盒尝试。另一类方法让语言模型充当提示设计者，PAIR、Tree of Attacks 等工作会利用反馈修改尝试，Crescendo 等研究进一步关注多轮对话。这类方法希望结合模型的语言能力与自动化测试的规模。

J2 关注的是上述流程开始之前的障碍：具备较强推理能力的模型通常也经过安全训练，会拒绝协助其他模型越狱。因此，一些已有系统采用开放权重模型、专门微调的模型，或不公开的未受限制模型。J2 研究能否让已经过拒绝训练、只能通过 API 访问的模型参与测试，以及它们参与之后能够达到什么效果。

这也形成一种新的安全评估角度：直接拒绝有害请求，并不一定意味着模型不会协助另一个模型产生有害回应。论文在同一框架内研究这种失效方式与自动红队测试的可用性。[原文第 1—2 节](https://arxiv.org/pdf/2502.09638v2)

## 3. 核心贡献

**核心要解决的问题。** 作者希望分别回答两个问题：经过拒绝训练的商业模型能否成为自动红队测试者；在统一的流程下，不同模型的测试能力如何。研究使用黑盒 API 交互，不要求读取模型参数或梯度，也不通过重新训练改变模型。

**核心方案。** J2 先由人工准备引导对话，让模型愿意参与安全测试，然后将它接入固定的“计划—测试—复盘”循环。模型先规划测试方向，与目标模型进行多轮交互，再根据外部判定器的反馈分析失败原因。失败记录保留在上下文中，使下一次尝试能够利用此前观察。这里的改进发生在当前对话里，模型权重没有变化。

测试方向可以由模型自己提出，也可以加入人工红队人员整理的策略。每轮测试后，流程使用一个判定器提供反馈；最终报告成功率时，再用另一个、不会向测试模型提供反馈的判定器复核初步成功案例。这种安排将过程中的反馈与最终评价分开，减少测试模型迎合单一评分器的问题。[原文第 3 节](https://arxiv.org/pdf/2502.09638v2)

**结论。** 在该版本使用的 200 项 HarmBench 文本行为上，J2（Sonnet 3.7）对 GPT-4o 的成功率达到 97.5%；面对防护更强的 Sonnet 3.5，表现最好的 J2（o3）为 60.5%。结果说明，测试能力同时取决于负责测试的模型和目标模型。推理模型往往能更快利用失败记录改进尝试，人工提供的策略也能补充模型自行搜索的不足。

这些结果没有证明 J2 普遍超过人工或所有自动方法。论文明确提醒，不同基线的预算、数据划分与判定方式并不完全一致；在 Sonnet 3.5 上，最强的对照方法和人工仍优于 J2。本文主要证据是：在固定流程和所测试的模型版本中，经过拒绝训练的模型仍可表现出明显的自动红队能力，而保留交互反馈比孤立地生成测试输入更有用。相关成功率描述的是当时模型在指定基准中的表现。[原文第 4—6 节](https://arxiv.org/pdf/2502.09638v2)
