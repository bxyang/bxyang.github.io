# Adaptive Guidance：把带提示的解题经验用于独立推理

一道数学题连续采样八次都没有正确答案时，基于结果奖励的强化学习缺少可以强化的成功轨迹。Adaptive Guidance 先给这类题补充提示，让模型重新尝试，再用不含提示的输入计算训练目标。模型在训练时借助指导探索解法，测试时仍独立作答。论文提出的 Guide-GRPO 在七项数学基准上改善了平均成绩，但不同模型、长度和题目上的收益并不一致；其公开代码也与早期论文中的算法和配置存在差异。

## 从全错的一组回答开始

GRPO 通常对同一道题生成多条回答，根据最终答案计算奖励，再比较组内回答的相对表现。若八条回答有对有错，正确回答能获得正向优势；若八条全部错误，它们的奖励相同，组内比较不能提供有区别的学习信号。Filter-GRPO 会丢弃全错和全对的组，把更新预算留给奖励有差异的题目。

Guide 的处理是保留这个采样过程，并在全部失败时增加带提示的尝试。提示来自能够读取参考解答的教师模型，但学生仍要从头生成完整推理和最终答案。关键训练问题随之发生变化：成功回答是在“题目加提示”下生成的，最终希望优化的却是“只有题目”的模型。论文用跨上下文的重要性权重连接这两个分布。[原文 §2.2、算法 1](https://arxiv.org/pdf/2506.13923v2#page=3)

这里的“自适应”主要指提示出现的时机随学生当时的表现变化。论文使用预先生成的题目级提示，并没有让教师实时阅读每次错误回答后重新设计反馈。

## 论文先区分两种能力变化

在介绍训练方法前，作者做了一组强化学习机制实验。它覆盖 Qwen2.5 的 0.5B、3B、7B、32B、72B 五种规模，以及 514,234 条数学、代码和 STEM 训练数据。随后真正比较 Guide-GRPO 的实验则使用数学数据和 7B、32B 模型。这两组实验不能合并成“Guide 在五种规模、三个领域上都得到验证”。

机制实验把初始单次回答错误的题记为集合 $U$，初始答对的题记为 $S$。训练后，$U$ 中转为答对的数量是 progress；$S$ 中转为答错的数量是 regress。若评测共有 $N$ 道题，准确率变化为：

$$
\Delta\mathrm{Accuracy}=\frac{\mathrm{progress}-\mathrm{regress}}{N}.
$$

这里补出了从题目数量到准确率所需的分母。对 progress，作者进一步检查初始模型多次采样是否已经能答对：初始 Pass@1 失败、但 Pass@$k$ 成功的题，归入自蒸馏；初始 $k$ 次都失败、训练后答对的题，归入 capability gain，即论文所说的能力增长。

这个定义取决于采样预算。有限的 $k$ 次没有成功，不能证明模型给正确答案的概率为零。附录 C 又讨论以 Pass@$k$ 增量趋于平缓来定义更接近“绝对”的能力增长，但没有提供一个能证明完全不可达的有限采样检验。因此，图 1 支持的是给定预算下的有效能力变化。[原文 §2.1、§3.1、附录 C](https://arxiv.org/pdf/2506.13923v2#page=2)

机制实验先用 AMPS 对各模型做一轮监督微调，统一推理输出格式，再训练 256 步 GRPO。因此，“初始模型”是强化学习开始前的模型，不是未经任何后训练的原始权重。数据包括数学 450,000 条、代码 25,276 条、STEM 38,958 条。作者每 16 步评估一次，涉及 GSM8K、MATH500、AIME 2024/2025、AMC、GPQA Diamond、Olympiad，以及 LeetCode、LiveCodeBench、HumanEval。

图 1 中，初始未解集合的规模依次为 3,195、2,150、1,913、1,617、1,532。约四分之一的初始未解题在训练后转为答对，增长主要来自自蒸馏，但各规模都观察到有限采样意义上的能力增长。这个比例描述 progress，尚未扣除原本正确后来错误的题，不能直接称为净准确率提升。

这部分存在两个复现口径需要保留：正文机制分析使用 $k=16$，附录 H 表 9 却列训练每题 8 条轨迹；另外，“10 次试验”的评测说明包含从每题预先生成的回答池中反复抽样，不能据此认定完成了十次独立强化学习训练。正文与附录没有完全统一这两项说明。

## 提示如何形成

Guide 的数学训练使用 OpenR1-Math-220k 的 default 子集，论文记为约 93.7K 道题。教师 GPT-4o 在温度 0 下读取题目和参考解答，生成三到五条逐步具体的提示：先指出关键概念，再给出策略，提醒容易遗漏的条件，最后才提供更直接的引导。指令要求不直接给出最终答案，也不要复制完整解题过程。[原文 §3.2.1、附录 G](https://arxiv.org/pdf/2506.13923v2#page=19)

论文特别区分了参考解答与 OpenR1 中模型生成的长推理：这里用的是数据来源中的参考解答，教师据此生成提示；SFT 基线则直接在参考解答上训练。[OpenR1 数据页](https://huggingface.co/datasets/open-r1/OpenR1-Math-220k)也分别提供 `solution`、`answer` 和 `generations` 等字段，使用时不能把它们混为同一监督来源。

学生收到的输入包括原题、提示，以及要求从头作答、不直接引用提示的说明。附录中的三角形例子把注意力引向面积不变量：平行移动顶点保持面积，最终得到直角三角形后，可以用一条直角边和面积求另一条边。这个例子展示了提示如何改变解题方向，但不能用单个成功案例推断所有提示都正确，或都不存在答案泄漏。论文没有给出完整提示集的人工质量审计、泄漏比例，也没有固定 GPT-4o 的具体 API 快照。

图 2 另做了一个提示有效性实验：从 OpenR1 训练集抽取一万题，比较带提示和不带提示的 Pass@$k$。附录 I.1 指定这里使用参考文献 [41] 训练的 Qwen2.5-Math-7B。它是方法动机实验，不是最终 Guide 模型在保留测试集上的成绩，更不能把带提示结果当作独立推理能力。

## Guide-GRPO 的一次训练更新

设问题为 $q$，提示为 $h$，旧策略为 $\pi_{\mathrm{old}}$，待更新策略为 $\pi_\theta$。按论文算法 1，一次更新包含以下步骤：

1. 对每题在不含提示的上下文中采样 $k$ 条回答，检查最终答案。
2. 只有这 $k$ 条全部失败时，才在 $q,h$ 下额外生成 $k$ 条回答。
3. 对失败题，将原始回答与带提示回答放在一起，重新计算组内奖励统计量和优势。
4. 对无提示轨迹使用普通 GRPO 概率比；对提示轨迹，分子使用无提示上下文，分母使用实际采样时的有提示上下文。
5. 更新模型；评测时撤去提示。

设组内第 $i$ 条回答的奖励为 $r_i$，均值和标准差为 $\mu_r,\sigma_r$。同一回答的每个输出 token 使用同一个结果优势：

$$
\hat A_{i,t}=\frac{r_i-\mu_r}{\sigma_r}.
$$

优势大于零表示该回答优于本题组内平均水平，小于零则相反。实际实现需要处理零标准差；公开代码使用 $10^{-6}$ 的稳定项，并配合准确率过滤。论文形式算法将失败题的两批轨迹合并，因此这一组可达 $2k$ 条；公开默认实现的分组方式并不完全相同，后文单独说明。

**说明示例：**忽略有限样本标准差的实现差别，若原始八条全错，提示后八条中四条正确，合并组的平均奖励为 $4/16=0.25$。正确回答高于这个均值，错误回答低于均值。若只在提示后的八条中计算，均值则为 $4/8=0.5$。两种分组会改变优势大小，不能当作无关紧要的实现选择。

### 跨上下文的重要性权重

对于提示生成的回答，论文式 5 使用：

$$
w_{i,t}=\frac{\pi_\theta(o_{i,t}\mid q,o_{i,<t})}
{\pi_{\mathrm{old}}(o_{i,t}\mid q,h,o_{i,<t})}.
$$

$o_{i,<t}$ 是同一条已生成回答的前缀。分母回答“这个 token 在实际采样上下文下有多大概率”，分子回答“移除提示后，当前模型给同一个 token 多大概率”。因此，训练不是删除已经生成回答中的提示字样，而是对相同输出序列，用不同输入前缀计算概率。

普通轨迹的分母也不含 $h$。两类轨迹统一后，形式上的最大化目标仍包含 GRPO 的裁剪项：

$$
\min\left(w_{i,t}\hat A_{i,t},
\operatorname{clip}(w_{i,t},1-\epsilon,1+\epsilon)\hat A_{i,t}\right)
-\beta D_{\mathrm{KL}}(\pi_\theta\Vert\pi_{\mathrm{ref}}).
$$

$\epsilon$ 控制概率比的裁剪范围，$\beta$ 控制相对参考模型的 KL 正则强度。但论文实验配置令 KL 系数为零，而且正文 §3.2.2、附录 D 报告移除 PPO clipping 后训练更稳定。上面的正式目标不能直接当作最终实验的完整配置。

单 token 概率比也不自动等于整条轨迹的精确分布修正。提示会影响此前生成的 token，若要从完整序列分布建立严格的重要性采样恒等式，还需要处理历史分布及支持集条件。论文算法采用的逐 token 代理目标应与这种完整序列恒等式区分。

### 对概率比再做变换

附录 E 针对提示轨迹补充了一个权重变换。对一条回答中的概率比向量 $\mathbf w$，令 $P_{90}(\mathbf w)$ 为第 90 百分位数，给出的因子为：

$$
f(w)=\frac{1}{P_{90}(\mathbf w)+w}.
$$

若把它乘到原始概率比上，得到 $w/(P_{90}+w)$：大概率比被压缩，不同 token 的相对贡献也改变。这个式子不意味着概率接近零的 token 会自动得到很大的最终更新；分母为正时，$w$ 趋近零，组合权重仍趋近零。

作者称尝试了第 70、80、90 百分位数，90 的表现最好，但没有给出完整逐项数值表，并将这一部分标为初步实验。公开代码在计算范围和梯度上还有明确细节，不能从附录公式直接推断。

## 理论分析中的条件与公式问题

正文给出的直觉是：若某题独立成功概率为 $p_q$，独立采样 $k$ 次全错的概率为 $(1-p_q)^k$；提示对这样的题提供有正向优势的回答，可能增加训练信号。这个解释依赖提示质量，也依赖无提示策略能给这些回答非零概率。

不过，附录 B 的若干等式不足以支持其一般性定理。这里列出可直接按原文核对的问题，而不把理论主张当作实验结果：

- **式 16 将两种上下文的梯度写成逐样本的标量倍数。**对一般神经网络，$\nabla\log\pi_\theta(y\mid q,h)$ 不等于概率比乘上 $\nabla\log\pi_\theta(y\mid q)$。重要性采样的常用恒等式涉及在固定行为分布下加权后的期望，并不保证两个输入上下文的梯度方向一致。式 17 中向量与自身正倍数的夹角为零，不能补足前一个等式。
- **式 21、22 相减不能得到式 23。**按前两个式子，差值中应剩下 $-\eta\sum_q[1-(1-p_q)^k]\tilde A_q^{\mathrm{succ}}p_q$；式 23 却引入了 $\tilde A_q^{\mathrm{fail}}-\tilde A_q^{\mathrm{succ}}$。随后的非正号与“选择性指导更大”的结论也不一致。
- **式 33 到 34 丢掉了不同问题之间的梯度内积。**共享模型参数下，一道题的梯度与全批次梯度求内积通常含有交叉项；原文没有给出使它们消失的条件。

因此，选择性提示优于始终提示，可以引用表 3 的具体实验；“所有满足文字条件的模型都具有更高一步学习效率”则没有被这份推导完整建立。[附录 B，第 15—16 页](https://arxiv.org/pdf/2506.13923v2#page=15)

## 模型、预算和评测方式

主要数学对照包括 Base、在参考解答上训练的 SFT、普通 GRPO、过滤全错及全对组的 Filter-GRPO，以及 Guide-GRPO。7B 基础模型为 Qwen2.5-Math-7B；表 2 增加 8K 上下文和 32B 规模。正文没有为 32B 给出与公开默认脚本同样明确的模型仓库 ID，不宜自行补成一个“Qwen2.5-Math-32B”权重名称。

SFT 基线使用 batch size 32、学习率 $10^{-5}$、两轮训练，附录表 12 的上下文长度原数为 **4,092**，不是通常写法的 4,096。机制实验前的 AMPS SFT 是一轮，不应与这个两轮数学 SFT 基线混写。8K 实验没有披露与 4K 同样完整的单独配置表。

论文计算资源说明列出 GRPO 使用两节点、共 16 张 GPU，约 36—48 小时；SFT 使用一个节点、约 6 小时。它没有给出逐种方法的同等 FLOPs 或完整墙钟成本对照，也没有计入教师提示生成的详细费用。

按形式算法，若一批 $B$ 道题中有比例 $f$ 首轮全错，生成回答数量为 $Bk(1+f)$，最多达到普通一次采样的两倍。这只是忽略过滤补采、长度变化和额外概率前向计算的示意预算。因此，按训练步数展示的进步不能直接换算成同等算力下的加速比。

评测均撤去提示。Pass@1 使用 greedy decoding；Pass@16 使用温度 1，衡量多次采样至少一次成功的覆盖率。表 1、2 说明 Pass@1 对五次结果取平均；附录表 4、5 将其区间称为五次独立 runs 的 95% 置信区间，而 Pass@16 区间来自每题 16 个样本的方差。文中没有充分说明这些 runs 是否包含重新训练，也未提供完整区间计算代码对应关系，不能把它们解释为五次训练种子的稳定性证明。

Macro average 让七个 benchmark 各占相同权重；Micro average 按题目数量加权。两种平均分的分母不同，尤其不能把 AIME 的高方差改善与题量较大的 GSM8K 混成同一种总体变化。

32B、8K 的宏平均单次成绩增加 3.39 个百分点，Pass@16 增加 2.24 个百分点。7B、8K 的单次宏平均仅增加 0.29 个百分点，不能概括为所有配置都提升 1—4 个百分点。这一设置中，AIME 2024 的 Pass@1 从 GRPO 的 26.67 降到 Guide 的 16.67，Pass@16 却从 53.33 升到 63.33。7B Guide 从 4K 到 8K 的单次宏平均也从 51.03 降到 49.58，因而更长上下文并未带来所有指标的单调改善。[表 2](https://arxiv.org/pdf/2506.13923v2#page=8)

附录表 4 中，7B、4K 的 Guide 单次宏平均为 $51.03\pm0.40$，GRPO 为 $49.34\pm0.07$；Pass@16 分别为 $70.15\pm2.00$ 和 $67.06\pm1.96$。这些区间对应论文自身的采样统计口径。论文没有给出逐项多重比较校正或覆盖所有训练随机性的显著性检验，因此不宜把每一个表格差值都称为统计显著提升。

## 消融检查了提示时机和损失形式

表 3 比较三种提示触发条件：首轮全部错误；首轮正确率低于 25%；始终提供提示。

| 指标，% | 全部错误才提示 | 正确率低于 25% | 始终提示 |
| --- | --- | --- | --- |
| 宏平均 Pass@1 | 51.03 | 50.48 | 40.97 |
| 宏平均 Pass@16 | 70.15 | 69.86 | 60.03 |
| 微平均 Pass@1 | 70.66 | 70.14 | 63.18 |
| 微平均 Pass@16 | 83.29 | 83.29 | 80.72 |

在这组配置中，全错再提示的平均成绩最好，接近全错的较宽阈值结果相近，始终提示明显较低。表格支持提示时机影响最终无提示表现，但三种策略消耗提示的次数不同，不能把它当作严格匹配教师预算的因果比较，也不能据此认定所有持续指导都会损害推理。[表 3、图 3](https://arxiv.org/pdf/2506.13923v2#page=9)

图 3 还展示训练准确率、熵和回答长度的变化。Guide 后期的无提示训练准确率超过基线，同时保持较高熵、生成长度增加。熵较高本身并不直接证明推理路径更正确，长度增加也不等于推理效率提高；它们是训练行为的伴随观测。

附录 D 的图 4 比较裁剪相关损失设置，报告去掉 clipping 后避免了训练恶化；附录 E 的百分位数变换没有同等完整的系统消融表。论文没有提供不同教师、提示质量等级、提示数量和真实成本共同控制的全面实验。PPO 版本在附录 A 给出算法及优势估计方式，但主要结果表验证的是 Guide-GRPO。

## 公开代码已经发布，但默认运行不等于论文算法逐字实现

早期 v2 首页仍写代码将来开源。后续[作者官方仓库](https://github.com/vaskar-nath/guide_rl)已提供 VeRL 分支和数学实验脚本。以下静态检查固定在提交 `2f277152b8eaa764591e43995db0d05db377b990`，没有执行训练或调用模型。

**跨上下文概率的计算能够在代码中对应起来。**`ray_trainer.py` 的 `_roll_with_prompt_variant` 保留带提示的 `prompt_variant_input_ids`，同时将原始问题与同一条生成回答拼接回 `input_ids`。`dp_actor.py` 的旧策略概率计算在 `importance_weighted_reroll=True` 时使用前者；更新策略时使用后者。这对应论文重要性权重的分母有提示、分子无提示。

**默认分组与论文算法 1 不同。**`rollout()` 先过滤原始全错和全对的组，再给失败题重采样；默认关闭 `mixin`。因此，失败题原来的八条全错回答不会按算法 1 直接与八条提示回答合并为十六条，提示组还会再次过滤全对和全错。代码把保留下来的原始组与提示组组成训练批次，并补采直到达到目标批量。优势计算按组 ID 聚合奖励。这使得前文“十六条共同归一化”的说明只适用于论文形式算法，不能直接描述默认脚本。

**默认裁剪也有区别。**`guide_grpo_qwen.sh` 没有覆盖 `loss_remove_clip`，配置默认是 `false`；`core_algos.py` 此时裁剪 on-policy 轨迹，off-policy 轨迹不裁剪。也就是说，公开默认配置不是简单“全部移除 clipping”，与论文稳定训练段落的概括需要分别记录。

**P90 的计算范围与梯度均可核实。**代码将当前损失调用中全部 off-policy 比值展平后取第 90 百分位数，将其下限设为 $10^{-4}$，并 `detach` 这个分位数；随后把比值替换成 $w/(w+\gamma)$。取分位数时没有先按输出有效 token 掩码筛选，损失归约才使用掩码。论文附录描述的是每条轨迹自己的 P90。默认 actor micro-batch 为 1，计算时可能只有一条轨迹，但改动 micro-batch 后不能假定仍逐条计算。

代码还让 $w$ 出现在分子和分母中参与求导。在把 $\gamma$ 视为常数时，$w/(w+\gamma)$ 对 $w$ 的导数为 $\gamma/(w+\gamma)^2$。因此它与“仅把一个停止梯度的因子乘到原始策略梯度上”不是同一种计算图。附录文字没有完整规定这种求导细节。[固定版本核心损失](https://github.com/vaskar-nath/guide_rl/blob/2f277152b8eaa764591e43995db0d05db377b990/verl/verl/trainer/ppo/core_algos.py)

最后，公开 7B 脚本的 train batch 为 128、PPO mini-batch 为 64，论文表 11 则为 1,024 和 512；脚本用 `Qwen/Qwen2.5-Math-7B`、每题八条轨迹、两轮训练、1,024/3,072 token 长度。默认入口是单节点，而论文报告两节点。脚本适合作为实现入口，不能在不说明配置变化的情况下称为论文相同预算。[固定版本实验脚本](https://github.com/vaskar-nath/guide_rl/blob/2f277152b8eaa764591e43995db0d05db377b990/verl/experiments/math_reasoning/configs/guide_paper_experiments/guide_grpo_qwen.sh)

## 数据文件与复现边界

仓库链接的 [guide_math_rl_dataset](https://huggingface.co/datasets/vaskarnath/guide_math_rl_dataset) 已公开，本文固定数据提交 `cdbada34f071143a3f0c4cc69bb6fbd02133d22c`。数据服务列出训练 92,703 行、验证 1,024 行、测试 2,909 行，合计 96,636 行。训练加验证为 93,727，与论文约 93.7K 的数量级对应，但仅靠数量不能证明逐条切分和过滤过程与论文完全相同。

公开字段包括 `data_source`、原始 `prompt`、带提示的 `hint`、`ability`、含标准答案的 `reward_model`，以及 `extra_info`。`hint` 是完整对话输入，而不是一列孤立的提示短句。数据集卡只给出简短许可信息，没有详尽说明每个来源标签、去重规则、污染检测和全部拆分算法。公开 test 文件也不能在未核实题目映射时直接等同于主表所有基准的完整集合。

仓库 README 提供 Python 3.10+、`uv_build.sh` 和 `verl/experiments/math_reasoning/run/run_local.sh`。复现前应固定代码与数据提交，核对 CUDA、vLLM、FlashAttention 等依赖，调整数据、模型、检查点路径及日志配置，再明确选择论文式分组还是默认过滤流程。要对照论文主表，还需要补齐 32B 模型身份、8K 设置、评分与统计口径，而不只是启动默认 7B 命令。

本次已检查数据元信息、字段样例、采样和概率计算路径、优势与损失、默认配置及启动脚本；未逐条审计全部数据，未运行强化学习、重新计算 benchmark 或验证置信区间，也未发现官方 README 提供可直接下载的训练后模型权重入口。本文中的复现说明来自公开实现的静态核对。
