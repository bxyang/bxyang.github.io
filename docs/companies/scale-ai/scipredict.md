# SciPredict：实验结果预测与置信度

给出实验装置、操作条件和要测量的量，暂时隐藏论文里的结果，再让模型预测结果，这是 SciPredict 的基本任务。研究者从物理、化学和生物学的近期实证研究中制作了 405 道题，同时要求模型报告对答案的信心、题目的难度，以及不做实验能否推断结果。最好的模型在不提供额外背景知识时得到 25.27% 的正确率；提供专家整理的背景知识后，最高为 27.33%。参与答题的领域专家分别得到 20.25% 和 20.99%。更明显的差别出现在可靠性判断上：专家认为容易在实验前预测的题，确实更容易答对；模型的自评分数通常不能这样清楚地区分答案质量。下面分别解释这些数字的任务范围、评分方式和分母。[论文 §3–5、表 3、表 5](https://arxiv.org/pdf/2604.10718v1)

## 一道题如何形成

附录中的一个数值题来自薄膜铌酸锂调制器研究。题目描述实验条件，要求预测在给定时间点测得的直流漂移。参考答案的可接受区间是 7.2–8.8 dB。因为来源没有提供可直接采用的置信区间或标准差，标注者为约 8 dB 的结果设置了 ±10% 的容差。模型需要给出一个可落入该区间的预测，而不是仅判断“会发生漂移”。这一例子也说明：数值题的判定范围既可能来自测量统计，也可能来自标注规则，不能统一理解为原实验的置信区间。[附录 B，PDF 第 24 页](https://arxiv.org/pdf/2604.10718v1)

另一类题要求预测多个结果的方向。例如，附录中的冷原子束实验同时询问改变激光功率对原子通量和温度的影响。自由回答必须覆盖各项必要结论；只答对其中一个趋势，可能获得部分评分标准，但仍不能计为整题正确。[附录 B，PDF 第 22 页](https://arxiv.org/pdf/2604.10718v1)

一条公开记录把信息拆成实验设置、测量项目、预测问题、参考答案、必要背景知识及来源。参考答案和相关页码留给标注与评分环节；正常答题提示使用领域、子领域、实验设置、测量项目和问题，BK 条件再增加背景知识。代码不会把论文标题、URL 或参考答案作为正常答题提示的字段。因此，数据文件包含论文链接，不等于模型可以据此检索答案。[数据与提示代码](https://github.com/scaleapi/scipredict/tree/e7f60301bdb61f09e8ed1c54a9b47c063cb4a379)

SciPredict 使用已发表实验的结果建立参考答案，没有让模型实际操作实验装置，也没有新做一批实验验证模型提出的方案。图 2 展示的科研流程说明应用位置，论文实验本身仍然是静态文本预测评测。

## 405 道题、33 个子领域与两类专家工作

作者选择首次公开时间晚于 2025 年 3 月 31 日的实证研究，排除只做理论推导或模拟的工作。题目需要提供足以理解实验的条件，同时避免在输入中直接泄露目标结果。专家整理背景知识、参考答案和评分依据，再经过两轮专家审核；检查内容包括实验描述完整性、结果可定位性、背景知识是否泄漏答案、题目是否存在歧义，以及数值范围是否合理。论文另使用规则和语言模型进行辅助检查。[§3、附录 A](https://arxiv.org/pdf/2604.10718v1)

制作数据和参加人类基线答题是不同工作。任务贡献者的学历比例为博士 54.5%、硕士 34.3%、本科 11.2%；答题专家相应为 74.4%、17.9%、7.7%。论文按研究领域匹配答题者，但没有给出可以据这些百分比确定的完整人数及每人的题目分配表。数据制作共投入约 **7,380 个专家工时、336,000 美元**；这笔费用不能当作模型评测的 API 成本。[§3、附录 A](https://arxiv.org/pdf/2604.10718v1)

`main_ds.csv` 有 405 个唯一任务 ID；`human_baseline.csv` 的 ID 与其完全对应；`rubrics.csv` 的 131 个 ID 对应所有自由回答题。后者实际包含 312 条非空评分标准，每题 1–9 条，其中 52 题只有一条。文件预留了十个标准列，不代表每题都有十项。[固定版本数据目录](https://github.com/scaleapi/scipredict/tree/e7f60301bdb61f09e8ed1c54a9b47c063cb4a379/data)

有两个统计边界需要保留。第一，405 是题目数，公开表中只有 397 种 URL 字符串、398 种标题字符串，不能据此写成 405 篇互不重复的论文。第二，论文表 2 列出物理 9、化学 10、生物 14 个子领域，但逐项数量相加分别是 114、109、207，合计 430。表中材料化学和生物化学也跨大领域出现。公开 CSV 的 `FIELD` 有 276 种原始文本，没有给出它们到这 33 个规范子领域的完整映射。因此，表 2 可以展示研究范围，不能直接当作 405 题互斥划分的频数表；上表采用可从 CSV 复核的大领域与题型统计。[论文表 2](https://arxiv.org/pdf/2604.10718v1)

时间筛选用于降低模型见过原论文的可能性，但它不是逐模型的数据污染证明。论文没有提供所有参测模型的训练语料核查结果。人类答题记录的 `PREVIOUS_KNOWLEDGE` 在 405 行均为 `FALSE`，这表示受试者报告没有事先知道相应实验，仍属于自报信息。

## 评分首先判断整题是否正确

### 选择题：完整匹配答案

令 $\mathcal D_{\rm MCQ}$ 为选择题集合，$\hat y_i$ 是模型答案，$g_i$ 是参考答案。论文式（1）为：

$$
\operatorname{Acc}_{\rm MCQ}
=\frac{1}{|\mathcal D_{\rm MCQ}|}
\sum_{i\in\mathcal D_{\rm MCQ}}\mathbf 1[\hat y_i=g_i].
$$

正文用单个选项编号描述 $g_i$，公开数据还包含多选题：162 道选择题中，142 道只有一个正确字母，20 道有多个。代码将字母转为大写、移除格式字符并排序，再要求完整一致。例如 `D,A` 与 `A,D` 相同，少选或多选均为零分。它没有对重复字母去重，`A,A` 也不会被当作 `A`。因此不能把全体 MCQ 的随机基线统一设为四选一的 25%。[式（1）与评分实现](https://github.com/scaleapi/scipredict/blob/e7f60301bdb61f09e8ed1c54a9b47c063cb4a379/src/eval/main_qa_judge.py)

### 自由回答：所有必要标准同时满足

自由回答由语言模型裁判结合参考答案和专家标准判定。若第 $i$ 题有 $K_i$ 项标准，记每项判断为 $b_{ij}\in\{0,1\}$，公开代码对应的整题得分可以写成：

$$
s_i=\mathbf 1\left[\sum_{j=1}^{K_i}b_{ij}=K_i\right],
\qquad
\operatorname{Acc}_{\rm FF}
=\frac{1}{|\mathcal D_{\rm FF}|}\sum_i s_i.
$$

这展开了论文式（2）中二元裁判函数的含义。例如一题有三条标准，回答满足两条，代码记录满足项数为 2，但主指标仍计零分。代码为标准生成哈希 ID，让裁判分别输出 `satisfied` 与理由，再汇总为整题得分。表 4 另外报告部分标准的成绩，不能把这一列和整题正确率直接比较。[论文式（2）、表 4；评分脚本](https://github.com/scaleapi/scipredict/blob/e7f60301bdb61f09e8ed1c54a9b47c063cb4a379/src/eval/main_qa_judge.py)

正常评分提示传入的是 `answer`，不会自动把另一个 `reasoning_for_answer` 字段一起交给裁判。因而“评估科学推理”在实现中指回答内容是否满足标准，并不意味着模型生成的所有解释文本都被完整评分。

### 数值题：落入接受区间

论文式（3）为：

$$
\operatorname{Acc}_{\rm NUM}
=\frac{1}{|\mathcal D_{\rm NUM}|}
\sum_{i\in\mathcal D_{\rm NUM}}
\mathbf 1[L_i\leq\hat y_i\leq U_i].
$$

$[L_i,U_i]$ 是专家依据实验精度和波动确定的接受范围。附录还给出从图中读取范围的例子，因此复核一道数值题时，需要同时查看问题、单位和范围来源，而非只比较数值字符。[式（3）、附录 B](https://arxiv.org/pdf/2604.10718v1)

代码额外支持大于、小于、单值及逗号分隔的多个范围。闭区间包含端点，单值采用 `numpy.isclose`。预测也可以是一个范围，但正常实现意图是整个预测范围被参考范围包含，而非只要相交就算对。本次离线函数检查还发现：代码没有验证预测区间的下界小于上界，因而 `8-2` 会被参考区间 `3-7` 接受。这是解析边界问题，并非论文推荐的答案形式；没有原始输出日志，无法判断它是否影响已报告成绩。

### 总成绩与分组成绩

主表的总正确率按题计算。若三个领域的正确率分别为 $a_{\rm Bio},a_{\rm Chem},a_{\rm Phys}$，则：

$$
a_{\rm all}
=\frac{203a_{\rm Bio}+102a_{\rm Chem}+100a_{\rm Phys}}{405}.
$$

它不是三个领域的简单平均。同样，选择题、自由回答和数值题的总合并需要按 162、131、112 题加权。题型和领域难度不同，因此局部成绩的变化不能直接代替全体成绩。

## 五种背景知识条件

论文没有训练一个新的科学模型，而是改变同一个预测任务提供的信息。各条件都保留实验设置、测量项目和预测问题，差别如下。[§4.3、图 3](https://arxiv.org/pdf/2604.10718v1)

| 条件 | 增加的内容 | 对照目的 |
| --- | --- | --- |
| NBK | 不加额外背景知识 | 检查仅凭题目与模型已有知识的预测 |
| BK | 专家整理的必要背景知识 | 检查提供这些知识后的变化 |
| SBK | 模型自己生成的背景知识 | 检查自行补充上下文的效果 |
| SABK | 专家背景知识与模型自生成知识合并 | 检查继续增加上下文是否有帮助 |
| FBK | 根据背景知识问答探测，补入模型未正确掌握的事实 | 检查只补缺失知识的效果 |

专家背景知识被拆成原子事实。FBK 先把事实变成问答，再让模型回答，以判断哪些事实需要补充。表 7 显示，模型在这类事实问答上的正确率为 71.86%–95.01%，明显高于实验结果预测。例如 Gemini 3 Pro 为 1,268/1,350，即 93.93%；Claude Opus 4.5 为 1,277/1,344，即 95.01%；Llama 3.1 8B 为 955/1,329，即 71.86%。这些分母属于生成后的知识问题，不能与 405 道实验题混用；不同模型的分母也不完全一致。[表 7](https://arxiv.org/pdf/2604.10718v1)

这里的“掌握知识”有具体操作含义。代码在背景知识答题时仍提供实验设置和测量信息，所以这不是完全无上下文的记忆测试。裁判还输出正确与否及覆盖程度，但仓库没有完整实现如何根据这些输出构造最终 FBK 子集。不能仅凭表 7 推断模型内部已经拥有完成预测所需的一切知识，也不能把 FBK 理解为一个已公开完整执行的知识检索系统。

SBK 同样是模型生成文本，没有联网检索。其提示要求产生约 3–6 条背景事实，输入领域、子领域、实验设置和测量项目；当前生成提示没有单独传入目标预测问题。该细节会影响它选择哪些事实，复现时应保留。

## 模型、专家与评测预算

研究评测 15 个模型，采用零样本提示，并明确关闭所有模型的网页搜索。主评分使用 Gemini 3 Pro 处理需要语义判断的回答；作者又以 GPT-5.2 重复裁判检查，报告差异不显著。论文还描述了 temperature 在 0–1、top-p 为 0.9、0.95、1.0 的采样检查，报告总体结论稳定，但没有给出足以逐项重建所有运行的完整配置与统计检验结果。[§4.5、附录 C](https://arxiv.org/pdf/2604.10718v1)

表中的非零误差项来自三次运行，写作均值 ± 一个标准差，**不是置信区间**。附加背景知识条件的多行结果显示 ±0.00，公开日志不足以据此判断每个条件的实际重复与生成复用方式。模型名也不能替代精确 API 快照：仓库未提供论文中全部模型的固定端点、推理预算、最大输出长度与逐次运行记录。

人类基线先在 NBK 条件回答，再看到背景知识修订答案。公开记录分别保存首次与修订答案、推理、信心和难度，只有一列可预测性评价。它是同题两轮答题，不是两组独立随机分配的人类受试者。因此，两轮的变化同时处于“增加信息”和“已经思考过这道题”的流程中。论文没有提供把这两种作用分离的对照实验。[人类评测协议、公开记录](https://github.com/scaleapi/scipredict/blob/e7f60301bdb61f09e8ed1c54a9b47c063cb4a379/data/human_baseline.csv)

| GPT-5.2 | 20.58 | 22.80 | 19.01 | 22.96 | 19.51 |
| Llama 3.1 8B | 14.65 | 15.80 | 15.06 | 14.81 | 16.05 |

按表 3 的均值逐项比较，SBK 比 NBK 低的模型有 **8/15**，其余 7 个并未降低。SABK 比 BK 高的有 Gemini 3 Flash 和 GPT-5.2；FBK 比 BK 高的有 Gemini 3 Flash 和 Llama 3.1 8B。因而作者概括的“额外知识可能干扰预测”和“完整背景通常优于只补缺失知识”有整体趋势，也有明确例外；这些均值比较本身不等于逐模型的显著性检验。

FBK 往往低于 BK，与“即使模型能回答某条知识，直接把它放入当前上下文仍可能有用”相容。但这一实验还涉及知识问题生成、裁判判断及筛选误差，没有把这些因素分别控制，不能据此唯一确定下降的内部原因。

## 答案形式会改变成绩

表 4 在 NBK 条件下区分三种原生题型，并为自由回答列出部分与完整评分。代表结果如下，均为百分比：

| 模型 | MCQ 整题 | NUM 整题 | FF 部分评分 | FF 整题 |
| --- | ---: | ---: | ---: | ---: |
| Gemini 3 Pro | 36.21 | 12.80 | 37.70 | 22.39 |
| Claude Opus 4.5 | 33.54 | 13.99 | 34.69 | 17.81 |
| Claude Sonnet 4.5 | 29.01 | 16.07 | 35.75 | 20.10 |
| GPT-5.2 | 28.81 | 12.50 | 33.80 | 17.30 |
| 人类专家 | 26.54 | 8.93 | 36.09 | 22.14 |

原生选择题通常更容易，但这些列包含不同问题，不能单靠它们把差异全部归因于输出形式。作者进一步把 MCQ 改写成匹配的自由回答题，在图 9 比较同一批预测内容。多数模型在去掉选项后明显降低，说明给定候选答案会改变任务难度；图中也有个别例外，不能写成所有模型必然下降。[表 4、图 9](https://arxiv.org/pdf/2604.10718v1)

公开转换脚本先筛选 MCQ，再让语言模型按提示改写，保存结果供后续使用。这种设计比跨原生题型比较更接近控制内容的实验，但它仍然引入了自动改写与新的评分流程。仓库没有随附论文所用完整转换产物及逐题人工等价性复核记录，不能假定转换绝对不改变语义。

## 自评分数与实际可靠性

每道题除答案外，还要求报告三个 1–5 级分数：

- **信心**：认为自己的答案有多大把握，预期分数越高，正确率越高。
- **难度**：在给定上下文中回答有多难，预期分数越高，正确率越低。
- **可预测性**：不实际做实验能否推断结果，预期分数越高，正确率越高。

这些都是有序等级，不是明确的概率。不能把 5 级信心当作 100% 概率，或把 4 级当作 80%。论文主要观察分组正确率与等级的关系，没有把结果报告成概率校准常用的 Brier score 或 ECE。[§4.2、图 7](https://arxiv.org/pdf/2604.10718v1)

以信心等级 $c$ 为例，分组正确率的含义是：

$$
A(c)=\frac{\sum_i\mathbf 1[c_i=c]s_i}
{\sum_i\mathbf 1[c_i=c]}.
$$

分母是模型实际分到这一档的题目数，不是固定的 405。不同模型使用等级的方式不同，低信心档甚至可能没有题目；高档的小样本正确率也可能很不稳定。因此，表 5 同时列出分数和题量比单看曲线更有解释力。

例如，Qwen3 235B 在 NBK 下平均有 312 道题被打为最高信心档，正确率为 16.99%；Gemini 3 Pro 把约 233.67 道题放在信心 4 档、171 道放在 5 档，正确率分别为 24.70% 和 26.11%。题量带小数是三次运行的平均值，不是存在半道题。这里最高信心没有筛出一组高正确率答案。不过，不能进一步说每个模型的自评都完全没有信息；部分模型和条件存在上升趋势。[表 5](https://arxiv.org/pdf/2604.10718v1)

专家的可预测性分组差异更明显：

| 专家可预测性等级 | 题数 | 人类 NBK 正确率 | 人类 BK 正确率 |
| --- | ---: | ---: | ---: |
| 1 | 65 | 3.08% | 3.08% |
| 2 | 135 | 5.93% | 5.19% |
| 3 | 49 | 12.24% | 12.24% |
| 4 | 107 | 27.10% | 28.97% |
| 5 | 49 | 75.51% | 79.59% |

最高档的两个结果分别是 37/49 和 39/49；最低档都是 2/65。论文中“约 5% 到约 80%”是这个趋势的概括，不是整个数据集的正确率。人类所有自评曲线也不严格单调，例如 NBK 难度 1 档的正确率低于 2 档，BK 信心 2 档也低于 1 档。较强的整体关系与每个相邻档都单调是不同陈述。[表 5](https://arxiv.org/pdf/2604.10718v1)

把同一组专家可预测性标签用于划分模型答案，模型也通常在高档题上答得更好。例如 Gemini 3 Pro 的 NBK 成绩从专家 1 档题的 20.00% 上升到 5 档的 41.50%，BK 相应为 20.00% 和 46.94%。这说明专家标签在这批数据中提供了有用的任务分层信号。它尚未验证真实科研流程里，专家在未知实验结果之前进行独立筛选所能带来的收益，也不是已经上线的自动弃答策略。[表 6](https://arxiv.org/pdf/2604.10718v1)

## 错误分析与其他对照

作者让语言模型裁判把错误答案标成 16 种细分错误，再合并为五大类。图 8 中，事实与信息提取错误的平均发生率为 80.14%，逻辑与推理错误为 87.42%，科学严谨性问题约 47.9%，理解错误约 10%，格式问题约 0.6%。这里的分母是各模型的**错误回答**，而不是全体题目；同一答案可以获得多个标签，类别之间会重叠，不能把这些比例相加后当作错误的互斥构成。[图 8、附录错误分析提示](https://arxiv.org/pdf/2604.10718v1)

常见细分标签包括无依据假设、虚构信息、事实矛盾、表现出不适当的确定性，以及未说明预测限制。具体提示把“错误确定性”定义为在不确定问题上作绝对断言，不能简单替换成“自报信心为 4 或 5”。当前错误分析代码还会从主数据补入专家背景知识，这意味着裁判在分析 NBK 答案时可能看到答题模型没看到的事实。它提供的是事后分类，不是已控制变量的失败原因实验。

图 13 进一步查看专家可预测性为 4 或 5 的题，共 156 道；错误比例仍只在模型答错的部分计算，因此各模型用于该图的样本数不同。论文没有提供这套错误标签的完整人类一致性验证，不能把语言模型归因当作确定的因果解释。

图 11 将 SciPredict 与 HLE 文本成绩比较，报告 Pearson 相关系数约 0.46。正文 Finding 9 称其为强相关，但图注称为中等相关；按实际数字，本页保留“中等正相关”的描述。该图比较不同模型的成绩，没有控制模型训练数据、规模或采样预算，也没有通过相关性分离出独立的“科学预测能力”成分。[图 11](https://arxiv.org/pdf/2604.10718v1)

## 公开文件与复现需要补齐的部分

本次静态核查固定在官方 GitHub 提交 [`e7f60301bdb61f09e8ed1c54a9b47c063cb4a379`](https://github.com/scaleapi/scipredict/tree/e7f60301bdb61f09e8ed1c54a9b47c063cb4a379)。已逐行统计三份 CSV，检查生成、评分、背景知识问答、MCQ 改写、错误分析、提示模板和配置；只执行数据统计与独立评分函数的离线检查，**没有调用模型，也没有复现论文成绩**。

Hugging Face 数据另固定为 [`6f022aad7c89c8f257d3293c6114e8a0ce4ab095`](https://huggingface.co/datasets/ScaleAI/SciPredict/tree/6f022aad7c89c8f257d3293c6114e8a0ce4ab095)。它也有 405 行，三个领域与题型数量相同，但只有 12 列，不含任务 ID、规范答案和逐题评分标准；背景字段名称也不同。两份文件不是可以互换的副本：按完全相同的实验设置文本匹配，只能配到 345 条；两份文件中完全相同的预测问题文本有 352 种。已配对条目中仍有测量描述、问题或答案文本差异。本页的数据统计和代码检查明确使用 GitHub 版本，复现时不能直接把 Hugging Face 文件换进同一脚本。数据卡标注 MIT，GitHub 快照根目录未找到独立许可证文件；数据卡许可声明也不自动代表来源论文采用同一许可。[数据卡](https://huggingface.co/datasets/ScaleAI/SciPredict)

脚本入口的职责是：

| 文件 | 作用 |
| --- | --- |
| `src/eval/main_qa.py` | 生成实验预测及三个自评等级 |
| `src/eval/main_qa_judge.py` | 规则评分 MCQ/NUM，语言模型评分 FF |
| `src/eval/generate_bkg.py` | 生成背景、把事实转为问题、回答知识题、裁判知识题 |
| `src/eval/convert_mcq_to_ff.py` | 把选择题改写为自由回答 |
| `src/eval/analyze_errors.py` | 对错误答案进行多标签分类 |

当前公开快照存在几处会直接影响执行的接口差异：

1. `main_qa.py` 的必需字段列表包含 `PDF_FILE`，但发布的 `main_ds.csv` 没有该列，直接运行会在字段断言处失败。
2. 默认配置指向 `data/rubric.csv`，实际文件名是 `rubrics.csv`；评分器又以 `prev_task_id` 连接标准表，但文件只有 `TASK`。需要明确字段映射，而不能只改文件名。
3. 评分代码合并表时使用的后缀与自由回答提示读取的 `_x` 字段不一致，实验设置、问题等上下文可能变成空值。修复连接后还必须检查真正发给裁判的输入。
4. README 的部分命令指向 `src/pipelines/`，实际脚本在 `src/eval/`；背景知识流程实际把回答和裁判拆成两个步骤，并使用 `run.input_path`。README 中合并步骤的名称不能直接当作可运行入口。
5. 仓库没有完整公开把知识问答结果筛成 FBK、把 SBK 与 BK 合成 SABK 并重新输入主流程的连接逻辑，也没有重建所有表图的完整汇总脚本。

默认配置还限制为 5 条数据，运行键为空，模型指向本地 Llama 3.1 8B 端点；不能把默认值当作论文的 15 模型全量评测方案。正常客户端传递 temperature，但没有完整暴露论文提到的 top-p、最大输出长度和推理预算设置。生成脚本有重试与错误保存逻辑，背景生成失败时还可能丢弃条目，因此重新实现汇总时必须保留任务 ID，检查每个条件实际覆盖了多少题，并明确失败计零还是排除。[固定版本代码与配置](https://github.com/scaleapi/scipredict/tree/e7f60301bdb61f09e8ed1c54a9b47c063cb4a379)

一个可核对的复现过程应先修正并记录这些数据接口，生成一份包含 405 个任务 ID 的运行清单；然后固定模型端点、提示、采样参数、知识条件和裁判版本，保留原始输出与失败记录；最后按题型评分，按题数汇总，并为自评曲线同时输出正确数和分组题数。它还需要补充论文没有完整披露的转换产物、筛选结果和运行预算。公开代码提供了多数独立环节，但当前快照不足以直接重建全部已发表结果。

## 这项评测覆盖的范围

SciPredict 同时测量实验结果预测与对预测可靠性的判断。它的证据来自三个学科中经过筛选的 405 道题、给定的语言模型版本、关闭搜索的提示流程，以及规则和语言模型混合评分。背景知识改善了所有参测模型的主表均值；自生成或筛选知识的效果不一致；专家可预测性标签比多数模型自评更清楚地分开高低正确率任务。

这些结果没有验证联网检索、主动追问实验条件、调用模拟工具、多轮专家协作或真实实验闭环，也没有衡量一次错误预测在科研决策中的实际代价。新结果是否落在给定接受区间、答案是否满足全部专家标准、预测是否具有实际科研价值，是关联但不同的判断。使用这份基准时，需要保留它的题目选择与评分边界。
