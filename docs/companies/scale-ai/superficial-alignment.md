# 重新检验表层对齐：后训练改变格式，也改变任务表现

一个模型可以学会分步骤作答、写出整齐的解释和结尾，却仍然算错题。这篇论文从这种差别出发，增加监督微调样本，分别观察任务正确率、格式错误和推理错误。在 Llama、Mistral 的实验中，较少样本便能明显改善格式，数学和多跳问答的正确率却继续随数据增长。作者还用 100 个新事件比较知识微调与直接提供事件上下文的效果，发现先做多跳问答训练的模型更善于利用这些信息。研究覆盖的是特定任务的监督微调，并未测试 RLHF 或真实检索系统。（原文 §3—5）

## 三组实验分别考察数据、错误和新知识

“表层对齐假说”来自 LIMA 一类研究：模型的大部分知识和能力已在预训练中形成，后训练主要教会它以合适的形式表达，少量优质示例就可能产生良好的对话体验。本文将相关主张整理为三个可以分别检验的方面：增加样本后任务表现是否很快饱和、改善是否只有回答形式，以及模型能否利用预训练之后的新知识。

这不是直接复现 LIMA 的全部实验。作者把重点移到数学、代码、约束指令遵循和多跳问答，并使用任务分数；其“100 个样本改善格式”等结论，也只指本文的模型、数据和格式要求。不能由这些实验反推所有对话场景都需要相同的数据量。

全篇的后训练方法是监督微调（SFT）。给定提示 $x$ 和参考回答 $y=(y_1,\ldots,y_T)$，其常见目标可以写成：

$$
\mathcal L_{\mathrm{SFT}}=-\frac{1}{M}\sum_{i=1}^{M}\sum_{t=1}^{T_i}
\log p_\theta(y_{i,t}\mid x_i,y_{i,<t}).
$$

这里 $M$ 是训练样本数。这是解释监督微调的标准形式；论文没有公开训练实现，因此提示 token 是否参与损失、回答长度如何归一化等细节不能由这个公式代替实际配置。本文没有奖励模型、偏好优化或强化学习实验。（原文 §3.1、§7、附录 A.5）

### 数学回答要求显式拆解和最终答案

Socratic 版本把解答写为子问题与回答，最后以 `####` 分隔最终数值。原文例子是先计算五月售出的数量，再与四月相加。这样的固定输出结构让作者能够单独检查“有没有按结构回答”和“答案是否正确”。

GSM8K 的最终数值答案可作客观核对，但本文没有给出采用的评估脚本提交、提取正则和完整生成记录。代码实验采用 HumanEval+，含比原始 HumanEval 更丰富的测试；论文未说明采样候选数和具体 pass@k 配置，不能自行补为多候选搜索成绩。IFEval 图轴写的是指令级准确率，未明确 strict／loose 变体；它是可检验约束的评测，并非让人主观选择较喜欢的回答。（原文 §3.1、图 1—2、附录 A.3.1）

### SubQA 先按原始多跳题划分，再扩展训练项

原始 SubQA 含 1,000 道来自 HotpotQA 的桥接式多跳问题，每题配两道人类验证的单跳子问题。作者随机留出 100 道多跳题测试，对剩余 900 道题保留原题及两道子题，得到：

$$
900\times(1+2)=2700
$$

条训练问题，其中 900 条多跳、1,800 条单跳。测试分母是 100 道留出多跳题，不是 2,700 条训练项。论文没有公开这次划分清单，无法进一步核查跨题实体或相同子问题的重叠。

评分时，GPT-4o 接收问题、参考答案和模型回答，判断回答是否真正回答了问题，并允许不同措辞。它输出 `Error` 或 `No Error`，避免把“在长篇文字中提到答案”一律视为正确。这比纯字符串包含更贴近语义，但依然是模型评分，不是全部由确定性程序判定的客观测试；论文未给出评分器与人类复核的一致性统计。（附录 A.3.2）

附录样例本身有一处标签不一致：原始问题答案写作 **Chief of Protocol**，随后构造的推理链和 SubQARecall 样例却改成 **Chief of Staff**。本页不把后者作为正确训练样例复述。没有作者实际转换数据，尚不能判断这是展示笔误还是也进入了实验文件。

### Conifer 对照改变的是任务匹配程度

Conifer 原始对话逐轮增加约束。作者选取至少四轮的对话，将第一轮分别抽为 ConiferEasy，最后一轮抽为 ConiferHard；二者在本文中都是单轮提示—回答样本。Dolly 则包含更一般的指令，较少呈现 IFEval 式的明确限制。

附录图 7 中，同等样本数下，Hard 的 IFEval 分数通常高于 Easy，二者又高于 Dolly。这里所谓更高“质量”与约束数量、任务匹配和文本内容同时变化，不是经过统一人工打分后只改变质量一项的实验，也没有控制等 token 预算。（附录 A.3.3）

## 模型、训练预算和生成设置

实验从基础模型出发，避免现成 instruct 模型已接受大量相关任务训练：Llama 3 8B／70B、Llama 2 7B／13B／70B，以及 Mistral 7B。论文没有为所有模型给出可唯一定位的 Hugging Face revision；部分图例写作 Mistral-v3-7B，不能据此自动确定每次运行所用文件。

正文列出的数据档位为 0、100、500、1,000、5,000、10,000，直到耗尽相应数据集。0 表示未微调基线。每次从基础模型开始做三个 epoch 的全参数微调，不使用 LoRA 等参数高效方法；学习率为 $10^{-5}$，以余弦调度降到 0。（原文 §3.1、附录 A.5）

| 样本数 | 附录标作“8B 与 13B”的模型 | 70B 模型 |
| --- | ---: | ---: |
| 1—100 | batch size 2 | 16 |
| 101—1,000 | 8 | 32 |
| 1,001 及以上 | 16 | 128 |

原表第一档写 0—100，0 是不训练的对照；表头没有单独写 7B 如何归档。正文概括同族模型超参数相同，但实际表 6 的大模型 batch size 明显不同，应以已披露的具体表格为准。

三 epoch 相同不代表计算预算相同。增加样本意味着处理更多训练文本，跨档位还改变批大小；论文没有隔离更多独立样本与更多总训练计算的效果。70B 训练成本较高，作者明确减少了这些模型的实验次数，没有公布完整 GPU 小时或费用。

测试为零样本提示，temperature 为 0.4、top-p 为 0.95、repetition penalty 为 1.1，不是贪心解码。论文未报告每个训练点的多种子均值、标准差、置信区间、所有长度上限或生成重复次数。小测试集上的单点差值不应被当作已经做过显著性检验的结果。

## 幂律是实验区间内的拟合

作者把任务表现 $P$ 与微调样本数 $D$ 拟合为：

$$
P(D)=aD^{1/b},\qquad
\log P=\log a+\frac{1}{b}\log D.
$$

$P$ 在表中以百分数计，$a$ 是比例系数，$1/b$ 是对数坐标下的斜率。$b$ 越小，倍增数据时的相对增长因子越大。它拟合的是任务得分，而不是预训练常用的交叉熵损失。（原文 §3.2、附录 A.6）

| Llama 3 8B 任务 | 表 7 的 $a$ | 表 7 的 $b$ |
| --- | ---: | ---: |
| 数学 | 19.47 | 7.66 |
| 多跳问答 | 11.54 | 7.77 |
| 代码 | 27.14 | 23.43 |
| IFEval／Conifer | 31.06 | 11.90 |
| IFEval／Dolly | 30.94 | 21.12 |

用数学这一行作公式演算，$D=100$、1,000、5,000 的拟合值分别约为 35.52%、47.97%、59.19%。这些是代入系数的计算值，不是重新取得的实验观测。样本翻倍的比例因子为 $2^{1/7.66}\approx1.095$，即拟合分数相对提高约 9.5%，不是固定增加 9.5 个百分点。

这个形式也有边界：$D=0$ 时不能进入对数拟合，而真实基础模型得分并不为零；一直外推还会超过 100%。论文没有说明未微调点在对数图中的处理、拟合目标、残差、区间或外推验证。图 1—2 在 $10^0$、$10^1$ 附近也画有点，与正文列出的档位不能逐一对应，不能据图擅自添加“用一条样本训练”的配置。

表 7 与表 8 对同一 Llama 3 8B 数学曲线给出不同系数：19.47／7.66 与 18.18／7.28，分别对应数据规模图和模型规模图。复现时需要两组具体观测及拟合脚本，不能把系数混合使用。图 1 的 Mistral 多跳问答小数据点还有回落，幂律线描述总体趋势，不代表每个观测都严格递增。

大模型在图 2 的这些任务上通常有更高得分，但不能把作者“更大模型增益更快”的概括当作统一指数定律。例如 Llama 3 数学的 $b$ 从 8B 的 7.28 变成 70B 的 9.07，后者的幂指数反而更小。起点、系数、绝对增益和相对斜率是不同概念。

## 同样 1,000 个样本，偏好胜率与正确率可能相反

作者在 Llama 3 8B 上比较两个方向：用 1,000 条 LIMA 数据进行通用对话微调，或用 1,000 条 GSM8K／SubQA 数据进行任务微调。两者控制了样本条数，但没有证明 token 数或任务内容相同。（原文 §3.3、表 2）

| 测试任务 | LIMA-1k 正确率 | Task-1k 正确率 | LIMA-1k 偏好胜率 | Task-1k 偏好胜率 | Neither |
| --- | ---: | ---: | ---: | ---: | ---: |
| GSM8K | 14.7% | 46.5% | 84.4% | 0.24% | 14.2% |
| SubQA | 21% | 36% | 20% | 57% | 23% |

数学任务中，任务微调正确率高出 **31.8 个百分点**，GPT-4o 使用 LIMA 的比较提示时却更常选通用对话模型。多跳问答没有同样的方向反转，任务模型同时有更高正确率和胜率。

这里的胜率来自 **GPT-4o 评判**，不是本文另行收集的人类偏好投票。它说明这个比较提示和评分器的偏好不能代替任务正确率；实验未隔离答案长度、措辞、候选顺序与评分器误判等因素，不能把差异全部归因于格式。

表 2 数学行的三项胜率合计只有 **98.84%**，不是 100%。本页照录原值，没有把 0.24% 自动改成某个猜测数字。原文也未附此处完整比较提示、逐条胜负记录及缺失类别说明，因此无法重算剩余 1.16 个百分点的来源。

## 格式很快改善，错误分析仍不是因果分解

作者取未微调、100 条、1,000 条及全量任务微调模型，先找出测试集中的错误回答，再用 GPT-4o 分别标注错误类型。数学检查格式、算术和推理，多跳问答检查格式和推理。每种错误独立判断，同一回答可以同时算错、推理错和格式错，柱状图不能相加当作错误总数。（原文 §4、图 3、附录 A.4）

格式检查只判断是否出现解释、分隔符或分步链，不要求答案正确。数学推理检查刻意不评算术；算术检查也不要求判断推理是否成立。多跳推理检查则提供中间子问题和子答案作参考。

图 3 中，100 条样本已消除大部分格式错误，而后续数据仍减少总错误和推理、计算错误。不过“100 条后饱和”不是严格不再变化：数学的格式错误仍会继续下降。图中既有 8B 也有 70B，尽管 §4.1 的文字主要介绍 8B；全量图例写数学 8,000、多跳 3,000，与表 1 的约 7,500／2,700 不同，本文不把图例数字当成新的精确训练集大小。

作者报告 Llama 3 8B 的总错误与推理错误之间 $r^2$ 为数学 0.98、多跳 0.99；与格式错误之间为 0.93、0.83。这里是少数训练档位上的相关性，而且推理错误本来就是从错误回答中标注出来的，不能据此识别“训练创造了新的内部推理机制”。能够直接观察到的是任务表现改善、生成步骤中的错误减少；新增能力与更有效调用已有能力并未通过内部机制实验区分。

评分还依赖 GPT-4o 的分类可靠性，没有报告人工抽查、多评分器对照或标注一致性。尤其这些柱子只统计错误答案，不说明正确答案是否也存在无效推理或格式问题。

## Facts100 区分记住事件和利用事件

作者人工整理 100 个 2023 年 3 月之后的新闻事件，涉及娱乐、体育、商业、政治和科学。每个事件配一条直接问题及一条需要再推一步的多跳问题，共两组各 100 题。该日期被本文用作 Llama 3 8B 基础模型的知识截止点，但并没有逐条证明这些事件完全未进入模型训练语料。（原文 §5.1）

图 4 的例子先给出某首歌在 2023 年 Spotify 播放量中的位置。直接题问歌手，多跳题再问这位歌手的父亲。它把“新近事件中的实体关系”与既有背景知识连起来，没有要求从零学会所有后续知识。

对照的两个起点分别是 Llama 3 8B 基础模型，以及在 **SubQARecall** 上做过微调的模型。SubQARecall 要求先回忆相关事件，再输出子问题链和最终答案；事件文字由 GPT-4o 根据原子问题链补出。作者认为旧版 SubQA 不包含截止日之后的新事件，因此这一步主要改变问答与回忆行为。

| 尚未引入新事件 | 直接题正确率 | 多跳题正确率 |
| --- | ---: | ---: |
| 基础模型 | 8% | 12% |
| SubQARecall 后训练模型 | 32% | 27% |

这是表 3 的基线。后训练模型在直接提供事件之前已经能答对一部分题，因而不能把所有题都描述成“模型绝无相关知识”；训练也可能改善它利用已有线索的方式。

### 两种知识引入方式

**Event SFT** 将直接问题作为输入，将事件叙述加答案作为训练输出。之后既测直接题，也测相关多跳题。因此，直接题与知识注入训练存在重叠；较高直接题分数不代表对全新提问的泛化。多跳题没有按同样方式直接作为 Event SFT 目标，更接近测试新事件能否与其他知识组合。

**Event RAG-Oracle** 在推理提示中直接放入正确事件，不执行检索。作者这样做是为了排除检索失误。它检验“信息已经可用时能否利用”，没有测索引、召回率、文档选择或真实检索成本，也不能据此推导模型参数已永久记住该事件。（原文 §5.2）

| 起点与知识引入 | 直接题正确率 | 多跳题正确率 |
| --- | ---: | ---: |
| 基础模型＋Event SFT | 65% | 37% |
| 后训练模型＋Event SFT | 81% | 55% |
| 基础模型＋RAG-Oracle | 49% | 34% |
| 后训练模型＋RAG-Oracle | 86% | 71% |

表 4 显示，同样 Event SFT 下，先做 SubQARecall 微调的多跳成绩高 18 个百分点；同样 Oracle 上下文下，高 37 个百分点。后训练模型中，Oracle 的多跳正确率比 Event SFT 高 16 点；基础模型却是 Oracle 34%、SFT 37%。因此，不能把原文对 RAG 的概括改写为“对每个模型，RAG 都好于 SFT”。

每个百分比对应约 100 道问题的结果。论文未报告这部分的重复运行区间，不能把几个百分点的差距视为已验证的稳定优势。

### 持续预训练和组合方法的对照

附录 A.2 直接用事件文本训练三个 epoch，作为持续预训练对照；另比较 LIMA 先训练，以及 Event SFT 与 Oracle 上下文同时使用。（原文表 5）

| 方法 | 直接题 | 多跳题 |
| --- | ---: | ---: |
| 基础模型＋持续预训练 | 35% | 16% |
| 基础模型＋LIMA＋RAG | 58% | 48% |
| 基础模型＋Event SFT＋RAG | 100% | 51% |
| 后训练模型＋持续预训练 | 34% | 39% |
| 后训练模型＋Event SFT＋RAG | 100% | 71% |

表 5 的直接题 100% 由作者明确解释为已经训练过该直接问题所带来的记忆，不能作独立泛化证据。后训练模型的多跳成绩仍为 71%，与只加 Oracle 的表 4 相同；这组结果没有显示再加 Event SFT 还能继续提升多跳分数。

持续预训练对照只是少量事件、三个 epoch 的具体实现，不足以评价所有持续学习方案。LIMA＋RAG 的 48% 也高于基础模型直接 RAG 的 34%，说明通用对话微调并非完全无效，只是在这套设置下低于专门的 SubQARecall 路线。

## 新事实的错误仍可能来自回忆和推理

Facts100 错误分析分别检查事件是否被错误回忆或使用，以及随后推理链是否有错误。两种标注也允许重叠。附录的推理提示还规定：如果没有推理链，就输出 `No Error`。因此，“没有推理错误”不等于“给出了正确推理”，可能只是没有生成可检查的步骤。（附录 A.3.4、图 5）

图 5 的整体趋势是后训练与正确事件上下文减少错误，但不清零。该图也有与表格不一致之处：未引入事件的后训练模型错误柱约为 69，而表 3 多跳正确率 27% 对应 73 个错误；基础模型＋Event SFT 的错误柱约为 65，表 4 的 37% 对应 63 个错误。由于未公开逐条结果，本页不把这些图读数修成精确计数，也不把图表强行合并计算新的比例。

## 消融支持的范围
