# GSM1k 精读：用新编应用题检查公开数学基准上的过拟合

模型在公开应用题上得分很高，可能来自一般的解题能力，也可能受到训练时接触过题目、相似解题材料或反复按榜单选模型的影响。GSM1k 请人工重新编写与 GSM8K 风格和难度接近的题目，再用相同评测设置比较新旧两套题。

最终论文使用 1,205 道新题。部分模型在新题上下降最多约 8 个百分点；另一些模型在两套题上的成绩接近。成绩下降说明模型对公开基准的表现没有完全迁移到这套新题，但单凭下降不能证明某一道测试题确实进入过训练数据。论文进一步检查题目似然、人工难度和提示变化，尝试缩小解释范围。

## 比较新题与旧题，而非只替换题目数字

GSM8K 的任务是用基础四则运算解决文字应用题。GSM1k 保留这种任务形态，但要求人工创作新的情境，不允许借助语言模型，也不允许将示例简单改写。它与只改变同一模板里数字的做法不同：希望覆盖新的叙述与组合，而不只检验模型能否重新计算熟悉的题型。（§2—3）

一个用于解释任务的自拟例子是：某班买了 6 箱练习本，每箱 24 本，给 32 位学生每人分 3 本，求剩余本数。解题需要先算总量，再算已分出的数量，最后相减：

$$
6\times24-32\times3=48.
$$

这是说明示例，不是 GSM1k 的原题。评测只检查最后的答案是否匹配，不能通过一个正确数字确认全部推理步骤也正确；猜中、过程错误但结果碰巧一致，也会被最终答案指标接受。

论文借鉴了重新采集 ImageNet 测试数据来检查过拟合的思路。理想比较是“同一分布下从未公开的新测试集”；现实中，重新组织作者、写作规范和筛选过程也可能改变分布。因此，GSM1k 的难度匹配是研究成立的重要条件，不能当作已经精确复制了 GSM8K 的全部分布。

## 从 2,108 道候选题到 1,205 道测试题

作者让标注者参考三道 GSM8K 示例，按照指定的解题步数编写新题。要求只用加减乘除，中间可以出现简单小数，最终答案为正整数；题目中说明单位。附录 B 一处写成“非负整数”，但正文与完整标注要求排除了零，本次读取公开数据也确认最小答案为 1。（§3，附录 B—C）

题目通过三个复核层次：先由表现稳定的审阅者检查正确性、格式与数学范围；再由未看到原解答的另一组人独立求解，两个答案不一致就丢弃；最后由 Scale 的专门质量团队审计。

| 阶段 | 保留数量 | 数量的含义 |
| --- | ---: | --- |
| 最初创作 | 2,108 | 初始候选题 |
| 通过独立二次求解 | 1,419 | 独立求解与原答案一致；论文未单列第一层后的数量 |
| 通过质量审计 | 1,375 | 继续满足质量要求 |
| 按答案大小匹配后 | 1,205 | 最终报告的 GSM1k 测试题 |

最后一次筛选按答案数值大小调整分布。作者观察到新编题目的答案原本略大，而较大的数可能让语言模型更容易算错，因此删去部分题目，使新旧数据的答案大小分布更接近。（§3.1—3.2，图 3）

这一步意味着最终数据不是所有合格题的随机子样本。保留规则服务于与 GSM8K 的比较，不代表一般学校应用题的自然分布；它也只约束最终答案，不能保证中间计算中的所有数值都同分布。

附录 B 说明标注者均在美国，时薪约 20—25 美元，总报酬约 18 万美元。这笔费用包括编题、解题、质量检查和难度比较实验，不宜除以 1,205 后称为单道题纯写作成本。旧版官网补充了教师及教育、数据分析、计算机、物理和经济等背景，但没有将每个标注者与最终题目一一对应公开。

## 难度匹配的三组证据

### 解题步数与答案量级

作者通过 GSM8K 解答里的计算器标签估计运算次数，以此向标注者分配目标步数。附录图 13 展示 GSM8K 训练集与测试集的步数分布，新题制作参考二者合并后的分布。

标签计数只是近似值：同一次逻辑推断可能对应多个运算，某些答案也没有统一标签。步数相同不意味着阅读负担、隐含条件或算术难度相同。它与答案量级筛选共同控制部分可观察差异，并非完整的题目难度模型。（§3.2）

### 人工辨别题目来源

每组展示五道题，其中四道来自 GSM8K，一道来自 GSM1k，让没有参与创作的人找出新题。19 位参与者共尝试 1,205 次，正确辨别比例为 21.83%，随机猜测为 20%。（§3.2.1）

这个结果说明新题没有很容易被人一眼识别的风格差异。它不等于两套题数学难度相同，也不能把多次来自同一参与者的判断全部当成互不相关的独立人类样本。

### 限时解题和早期模型对照

14 位未参与编题的人分别在 15 分钟内尽量解题。GSM8K 平均解出 $4.07\pm0.93$ 题，GSM1k 为 $4.36\pm1.11$ 题；这里的误差是标准差。指标是限时完成题数，不是对固定题数的正确率。点估计显示 GSM1k 略容易，但没有等价性检验或完整个体数据，不能将“没有明显更难”改成“统计上证明难度完全一致”。（§3.2.2）

作者还使用 GPT-2 与 GPT-NeoX-20B 检查两套题的表现，基于其训练资料早于 GSM8K 公开的判断，观察到很小的差距。这里应区分资料时间与模型发布日期：GPT-NeoX-20B 于 2022 年发布，不能按论文的概括措辞写成两个模型都在 GSM8K 之前发布。此外，早期模型本来就很少答对，接近低分端的相似性对中高难度差异的约束有限。（§3.2.3，图 12）

## 主评测的提示、生成和评分

| 设置 | 论文说明 |
| --- | --- |
| 框架 | EleutherAI LM Evaluation Harness 的修改版 |
| 对照 | 同一模型分别回答 GSM8K 与 GSM1k |
| 主提示 | 每道测试题随机抽取 5 道 GSM8K 训练题作为示例，包含解答；示例随测试题变化 |
| 最大生成长度 | 正文称从 256 提高到 1,000 tokens，减少推理被截断 |
| 开放模型 | temperature 0；兼容模型用 vLLM，否则用 Hugging Face |
| API 模型 | 经 LiteLLM 请求，结果来自 2024 年 4 月 16 日至 7 月 10 日；正文称使用默认设置 |
| 重复采样 | 主结果不是多次生成后择优或多数投票的分数 |
| 自动评分 | 提取回答中最后一个数值，与标准答案进行规范化后的字符串匹配 |

标准提示已经含逐步解答。因此，附录 E 名称含 chain-of-thought 的替代提示，不能简单描述为“开启思维链”的实验。不同答案短语、示例来源和示例数也在变化。（§4，附录 D—E）

自动评分的具体实现会影响得分。比如模型先给正确答案，随后又补充一个数字，最后数字提取可能取错；`24.0` 与 `24` 也不一定被字符串匹配视为相等。框架去掉逗号、货币符号等格式，但没有通用数值等价判断。模型不按提示格式回答，就可能因为输出提取失分。

因此，主表的绝对成绩同时反映解题和该设置下的回答格式。作者统一提示来比较两套题，没有为每个模型寻找其最高分提示；主表与各模型发布者自己的 GSM8K 成绩不同，并不自动表示重跑出了错误。

## 成绩差距与代表结果

令旧题正确率为 $\hat p_8$，新题正确率为 $\hat p_1$，定义：

$$
\Delta=\hat p_8-\hat p_1.
$$

$\Delta>0$ 表示新题成绩较低，$\Delta<0$ 表示新题更高。以下摘录附录 F 的标准提示结果，准确率单位为百分数；差距优先保留论文 Diff 列，因为从已舍入的准确率相减可能差 0.1 个百分点。

| 模型 | GSM8K | GSM1k | 论文差距／百分点 |
| --- | ---: | ---: | ---: |
| Yi-6B-Chat | 43.7 | 35.7 | 8.0 |
| Math-Shepherd-Mistral-7B-RL | 82.6 | 75.4 | 7.2 |
| Phi-2 | 56.6 | 50.4 | 6.3 |
| Llama-3-8B-Instruct | 75.2 | 69.0 | 6.2 |
| Phi-3-medium-128k-instruct | 86.9 | 82.5 | 4.4 |
| Mixtral-8x7B-v0.1 | 59.1 | 55.7 | 3.5 |
| Mistral-7B-v0.1 | 39.1 | 36.4 | 2.7 |
| Llama-3-70B-Instruct | 91.4 | 90.0 | 1.4 |
| GPT-4o | 93.1 | 92.9 | 0.2 |
| Mistral Large | 85.3 | 85.4 | −0.1 |
| Claude-3-Opus-20240229 | 80.2 | 82.4 | −2.2 |

“下降 8%”在论文这里对应约 8 个百分点：43.7% 降到 35.7%。按旧成绩计算的相对降幅约为 $8/43.7\approx18.3\%$，两种说法不能混用。

一些模型家族在多个尺寸和版本上持续出现正差距，这比只看一个模型的单次名次更有说服力。但不是每一行都达到相同的统计标准，某些模型在替代提示下也会改变差距大小和方向。这里的“前沿模型”只指论文在 2024 年评测的型号，不能当作当前模型榜单。

Phi-2 在新题上仍答对约一半，Math-Shepherd 也超过 75%。因此，大幅下降并不支持“模型完全不会推理，只会背答案”的说法。实验揭示的是旧基准高估某些模型在新题上的成绩程度。（§5.1—5.3）

## 统计检验中的单尾与双尾差异

附录 F 称使用双尾两比例 Z 检验。为解释这一检验，设两套题分别有 $n_8,n_1$ 道，答对 $k_8,k_1$ 道，合并比例为：

$$
\hat p=\frac{k_8+k_1}{n_8+n_1},\qquad
z=\frac{\hat p_8-\hat p_1}{\sqrt{\hat p(1-\hat p)(1/n_8+1/n_1)}}.
$$

它在独立二项样本等近似条件下检验两组正确率相等。双尾 p 值应为 $2[1-\Phi(|z|)]$，其中 $\Phi$ 为标准正态分布函数；只检验“旧题更高”的单尾值为 $1-\Phi(z)$。

原表存在需要明确保留的冲突：Yi-34B-Chat 的 $z=1.883$、p=0.030，与单尾计算约 0.02985 一致，双尾约为 0.05970；Claude Opus 的 $z=-1.421$、p=0.922 也符合相同的单尾方向，双尾约为 0.15532。本次对显示的 Z 值进行了独立算术复核，不将表中 p 列直接称为已经核实的双尾结果。

这会影响接近 0.05 的个别结论。表中显示 0.000 也只是舍入，不表示概率精确为零。论文没有报告针对大量模型比较的多重检验调整，也没有通过这个检验证明两套题完全同分布。现有结果适合结合差距大小、家族趋势和消融一起读，不能只按 p 列把每个模型分成“确定污染”和“确定干净”。

## 用题目似然寻找记忆的迹象

作者进一步计算模型生成 GSM8K 测试文本的概率。设文本经过 tokenizer 得到 $x_1,\ldots,x_T$，字符数为 $c$，论文式 1 为：

$$
\ell(x)=\frac{1}{c}\sum_{i=1}^{T}\log p(x_i\mid x_{<i}).
$$

对数概率通常为负；越接近零，说明模型给该文本越高概率。除以字符数是为了减弱不同 tokenizer 切分带来的不可比性，不能把它替换为每 token 平均概率。它也不是让模型实际生成整题、再统计逐字复制成功率。

§5.4 报告，题目似然与 $\Delta$ 的 Spearman 秩相关为 0.36，p=0.03；还列出 Pearson $r^2=0.26$、Kendall $\tau=0.29$。摘要把 Spearman 写作 $r^2$，正文另有混用，本文采用正文明确的“秩相关 0.36”表述，不把它解释成记忆说明了 36% 的成绩差异。报告拟合关系为差距每增加一个百分点，字符归一化对数似然约增加 $1.2\times10^{-2}$。（式 1，图 5）

这个正相关与“部分模型更熟悉公开测试文本”相容，但它不是训练数据成员身份的证明。通用语言建模能力、训练风格以及指令微调也会改变似然。论文专门讨论了几类例外：

- Mixtral-8x22B 的基础版与指令版似然差异很大，成绩差距却相近。
- Math-Shepherd 的差距较大，但题目似然较低；作者推测过程奖励训练可能带来间接熟悉，而非逐字看过原题。
- Llemma 的似然较高、成绩差距较小；其资料中少量 GSM8K 内容的存在也没有自动造成显著过拟合。

这些例外说明，直接接触题目既不是产生差距的唯一途径，也不是一定产生差距的充分条件。按公开测试集选检查点、反复优化相近训练材料，都可能产生类似结果；但本研究没有获得每个模型的完整训练日志，无法逐一确定原因。

## 提示与人工提取消融

### 替代提示同时改变多个要素

附录 E 改用八道非 GSM8K 的固定示例，并用另一种答案短语。附录 K 再将两组 GSM8K 题改成类似格式，附录 L 将标准提示示例数从 1 扫描到 10。整体上，受重点检查的模型家族在很多设置下仍有差距；具体分数和排序却明显依赖提示。

| 模型 | 标准提示：旧题／新题 | 替代提示：旧题／新题 |
| --- | --- | --- |
| Math-Shepherd-Mistral-7B-RL | 82.6／75.4 | 82.0／74.6 |
| Llama-3-8B-Instruct | 75.2／69.0 | 77.4／75.1 |
| DeepSeek-Math-7B-RL | 18.7／21.7 | 76.0／69.6 |
| Phi-3-medium-128k-instruct | 86.9／82.5 | 87.0／87.6 |

尤其是 DeepSeek 的分数和差距方向变化很大，说明不能将“整体趋势保持”写成所有模型对提示都不敏感。替代提示也同时改变示例数、来源和答案格式，不能从这一组比较单独测出某个因素的贡献。（附录 E—F）

附录 K 的排版还有复现障碍：几条含百分号的题目在 PDF 中截断；第 42 页的回收报纸示例题干写六个班，解答却按四个班计算。本次查看页面图像确认这些不是纯文本提取造成的缺字。不能把排版后的提示原样复制，就认定还原了实际实验输入；仍需原始提示文件和运行日志。

### 人工提取明显改变绝对成绩

附录 J 请人工识别最终答案，避免模型因多写说明或数字格式失分。以该附录自己的数据为准：

| 模型 | GSM1k 自动／人工 | GSM8K 自动／人工 |
| --- | --- | --- |
| Claude 3 Opus | 82.5／95.2 | 80.2／95.5 |
| GPT-4o | 92.8／94.9 | 93.3／96.2 |
| CodeLlama 34B Instruct | 36.6／37.5 | 41.5／42.2 |

Claude Opus 的绝对分数变化尤其大，说明主表自动提取并不只测数学能力。这项消融支持所选模型的新旧差距没有随人工提取而全部消失；但参与模型偏向新题高分模型，不是覆盖所有主表型号的随机抽样。

附录 J 的部分自动成绩与附录 F 不同，例如 Opus 新题为 82.5% 对 82.4%，Llama-3-70B-Instruct 旧题为 89.6% 对主表 91.4%。它的 Gap 方向又是新题减旧题，与主表 Diff 相反。本文直接保留该表两套数据的成绩列，不跨表拼接，也不将差值的末位舍入当成新的实验发现。

## 完整数据已公开，默认代码仍指向 50 题

本次读取的官方数据快照为 [`ScaleAI/gsm1k@bc09569`](https://huggingface.co/datasets/ScaleAI/gsm1k/tree/bc09569d09a614b9b530edc7f076fb214ac10493)。2025 年 4 月 1 日的提交包含测试集文件，本次实际读取 Arrow 后确认：

- 1,205 行、1,205 个不同的问题文本。
- 仅有 `question` 与 `answer` 两列，实际类型为字符串和 int64。
- 答案范围为 1—390,740，没有零或负数。
- 公开文件包含最终答案，没有逐步标准解答、标注者记录或全部筛选日志。

数据卡把答案类型写成 string，而 Arrow 实际为 int64，应按实际文件处理。论文曾承诺在不同基础模型谱系的三个开放模型达到 95%，或最迟 2025 年 6 月时公开；公开后的数据不能继续被当作所有后续模型都未见过的秘密测试集。原研究关于“新题”的判断依赖当时的时间与保密条件。

官方代码固定为 [`39294c6f31855aca8255b6174b22fc3a6311be0b`](https://github.com/scaleapi/gsm1k_eval/tree/39294c6f31855aca8255b6174b22fc3a6311be0b)。README 仍说明只有 50 个样本，两个 GSM1k 任务 YAML 也指向 `ScaleAI/gsm1k_public_50`，所以原样运行 `--tasks gsm1k` 不等于评测完整 1,205 题。

直接把数据路径改成完整集也不够：标准任务把 `train` 用作 few-shot split，而完整集只有 `test`。需要另接 GSM8K 的训练题作为示例来源，避免误用新测试题充当上下文答案；替代提示的答案提取模板还对答案调用字符串方法，整数答案要先进行相应转换。

## 代码检查得到的复现细节

复现时应先固定论文口径，再将当前可取得的资源接到这一口径上。本次检查了任务 YAML、示例采样、答案提取、几个后端的生成参数及似然绘图脚本，没有运行任何模型。

| 检查项 | 所读代码的行为 | 与复现有关的处理 |
| --- | --- | --- |
| 输出长度 | vLLM 默认 1,000，Hugging Face 默认 256，LiteLLM 默认 4,096 | 显式指定正文要求的上限，并核对每个后端实际收到的参数 |
| few-shot | 从任务配置指定的 split 随机抽样，每题重新组装上下文 | 固定 GSM8K train revision、随机种子、样例序列与顺序 |
| 自动提取 | 正则取最后一次数值匹配，再规范化字符串 | 保存原始输出及提取结果，区分算错与提取失败 |
| API 异常 | LiteLLM 重试后仍失败时，追加字符串 `0` | 报告失败数；不能把服务故障一律当成模型数学错误 |
| 当前任务数据 | 默认公开 50 题配置 | 明确区分演示检查与完整测试集结果 |

数据的答案均为正整数，因此 API 故障产生的 `0` 会按错题计入。这是本次静态看到的行为，原论文没有报告它在实际运行中触发多少次；不能反推历史结果一定受了多大影响。[任务与后端代码](https://github.com/scaleapi/gsm1k_eval/tree/39294c6f31855aca8255b6174b22fc3a6311be0b/lm_eval)

依赖方面，README 使用 Python 3.10，要求的 vLLM 为 0.4.2、FlashAttention 为 2.5.8；Transformers 等多项依赖没有为所有模型统一精确锁定。论文附录 M 列出当时不兼容 vLLM、改用 Hugging Face 的模型，不能因为今天支持就改称论文全部通过同一后端。API 名称也可能随时间改变，旧别名的当前调用不自动重建 2024 年的响应。

### 似然图的公开 CSV 与主表不是同一组数据

仓库提供 `loglikelihood/averages.tsv`、`scale_diff.csv` 和绘图脚本。本次按脚本的模型名称匹配方式，用字典读取后连接得到 52 个模型，重算 Spearman 约 0.288、p≈0.0387，未得到正文的 0.36。公开差距文件本身也与附录 F 不同，例如 Math-Shepherd 约为 0.1345，而最终主表为 0.072。

因此，这项本地检查只说明所发布 CSV 的统计值和最终论文并不完全对应，不是独立复现了论文的全部似然分析，更不能用新算出的系数悄悄替换原文结果。若要重建图 5，需要最终模型列表、精确输入文本、逐题似然及其聚合规则、与之对应的成绩差距文件。公开脚本主要做数据连接和画线，没有完成所有统计来源的闭环。

## 证据适用范围

GSM1k 同时控制题目难度与评测设置，对新旧数据进行比较。人工新编、独立二次求解和答案分布匹配使成绩差距更难简单归因于粗糙出题；提示与提取消融又显示，一些家族的差距并非只由单一输出格式造成。

但新旧集合不是严格同分布，似然是记忆的间接线索，模型完整训练资料通常不可见，统计表还存在需要核实的检验口径。研究可以支持“公开数学基准上的成绩可能高估部分模型在新题上的表现”，不能逐题裁定污染，更不能由没有差距证明从未接触过公开题目。

本次完成 45 页全文与全部附录阅读，检查关键图表和官方源码，并实际读取公开数据、重算部分统计算术。未训练模型、执行推理、调用付费 API 或复现主评测成绩。原文提到使用八张 A100 的节点评测，但没有足以核算全部运行成本的逐模型 GPU 小时与 API 账单。
