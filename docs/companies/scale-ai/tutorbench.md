# TutorBench：教学解释、反馈与提示

学生已经写出解题过程，只在某一步产生误解。此时，模型需要识别这个误解，保留学生做对的部分，再给出适合当前进度的解释或提示。TutorBench 把这种教学支持拆成三类情境，用专家编写的逐题评分标准评估模型的最后一条回复。论文包含 1,490 个高中和 AP 课程样本；表 1 中最高综合分为 Gemini 2.5 Pro 的 55.65%。这个分数是教学要求的加权满足程度，不能解读为学生学会知识的比例。[原文 §2–3、表 1](https://arxiv.org/abs/2510.02663v1)

## 从解题结果转向学生当前遇到的困难

论文讨论的前作包括直接检查知识和解题能力的测试，以及针对辅导对话的教学评价框架。TutorBench 的具体变化是：每道题附带学生的已有思路和当前困难，再为这个情境单独编写评价标准。模型即使算出正确答案，也可能因为忽略学生的误解、跳过必要解释，或在只需要提示时泄露最终答案而失分。

三类任务采用不同的输入和输出要求：

| 情境 | 给模型的材料 | 要生成的回复 |
| --- | --- | --- |
| 适应性解释 | 原题、已有教师解释、学生追问 | 针对追问重讲困难部分，调整解释方式 |
| 评估与反馈 | 原题、以学生口吻写出的错误解答 | 指出正确和错误步骤，说明错误原因并给出可操作反馈 |
| 主动学习支持 | 原题、学生部分完成或有误的解题过程 | 给出下一步提示或引导，不直接完成整道题 |

这些材料可以是文字，也可以包含手写答案、图示、排版后的题目或截图。评测给定一段固定历史，让模型生成待评分回复；它没有真实学生继续回应，也没有测量学生经过辅导后的考试成绩。[原文 §2.1–2.2、附录 A.1/A.6](https://arxiv.org/abs/2510.02663v1)

附录图 10 的统计题能说明反馈任务的要求。学生使用回归式 $\hat w=-350.3+3.7455x$，代入胸围 $x=145.9$，却把乘积粗略写成 545.0，再把实际体重 204.3 与预测值相减，得到约 10 千克的残差。重新计算得到：

$$
3.7455\times145.9=546.46845,\qquad
\hat w=196.16845,\qquad
204.3-\hat w=8.13155.
$$

对应评分标准分别检查是否定位过早舍入、给出正确乘积和预测值、解释残差的正号，以及说明残差不需要除以预测值。这些项目把“最终数值正确”和“说明学生为什么算错”分开。图中 GPT-5 API 回复识别了算术错误，但仍未满足“提供避免舍入错误的具体策略”这一条；不能仅凭答案正确认为全部要求都已满足。[原文附录 A.4、图 10](https://arxiv.org/abs/2510.02663v1)

## 数据由专家编写，再用模型筛选困难情境

参与编写的专家具有相关学科本科或更高学历，并有辅导或专业工作经验。专家先写问题及对应情境，再写一份理想教学回复，据此形成评价标准。错误答案和部分解答使用学生角色编写，不能当作从真实课堂直接采集的学生作业。

随后，作者让 Gemini 2.5 Pro、o3、Claude 3.7 Sonnet、DeepSeek-R1 和 Llama 4 Maverick 回答候选样本，并按对应标准评分。只有至少三个模型的加权得分低于 50% 的样本才被保留。因此，最终集合经过困难样本筛选，并非高中课程问题的随机抽样。部分筛选模型又出现在正式评测中，结果反映的是这个筛选后集合的表现。[原文引言、附录 A.1](https://arxiv.org/abs/2510.02663v1)

原文没有给出筛选前候选总数、每个环节的淘汰数或专家逐人任务分配。它也没有充分说明不支持图像的 DeepSeek-R1 如何参与多模态候选的五模型筛选，不能据此补写图像转文字或跳过规则。

## 逐题评分的权重、分母与负分

论文共编写 15,220 条评价标准，每题 3–39 条，由 Claude Sonnet 4 判定回答是否满足。重要的正向标准权重为 5，普通标准为 1；用于处罚不希望出现的行为时，重要标准可取 −5，例如在只要求提示的任务中直接给出答案。

令 $N_j$ 为第 $j$ 个样本的标准数，$w_i^j\in\{-5,1,5\}$ 为权重，$r_i^j\in\{0,1\}$ 为判定结果。把原文式 (1) 的二值指示量展开，可写成：

$$
\mathrm{ARR}_w^j=
\frac{\sum_{i=1}^{N_j}w_i^j r_i^j}
{\sum_{i=1}^{N_j}w_i^j\mathbf 1[w_i^j>0]},
\qquad
S=\frac{1}{M}\sum_{j=1}^{M}\mathrm{ARR}_w^j.
$$

分母只累计正权重。负向标准对应不良行为被触发时，分子扣分；实现时必须把标准文字的极性与二值判定方向对齐。整体得分先在每题内部计算，再对 $M$ 个样本等权平均，不是把全部标准汇总成一个大分母。[原文 §2.3、§3.1、式 (1)](https://arxiv.org/abs/2510.02663v1)

用一个自拟的算术示例说明：三条标准权重为 $5,1,-5$，前两条满足、负向行为未发生，得分为 $(5+1)/6=1$；若负向行为也发生，得分降为 $(5+1-5)/6=1/6$。如果两条正向要求都未满足，却触发负向行为，式 (1) 给出 $-5/6$。

这里有一处原文未交代清楚的实现细节：§2.3 称最终分数归一化到 $[0,1]$，但式 (1) 本身允许负分，没有写截断操作。公开入口也未提供评分实现来确认是否额外截断。复现时应明确选择并报告这一规则，不能把自行加入的 `max(0, score)` 当作论文公式。

## 标签分析使用另一种统计口径

每条标准还带有评价维度、教学技能、显式或隐式要求、客观或主观要求等标签。八个评价维度覆盖指令遵循、风格语气、事实正确性、视觉推理、视觉感知、简洁相关性、学生水平适配和情绪回应。附录表 2 把事实正确性限定为内容是否准确，并不把遗漏内容或格式错误都计入该维度。

教学技能包括定位核心误解、识别正确步骤、识别错误步骤、陈述必要知识、提供替代解法、使用例子或类比、提出引导问题，以及分步帮助。作者人工查看 600 条标准来归纳技能，再用 LLM 给全部标准标注适用技能；这些技能标签并非全部经过逐条人工标注。[原文 §2.4、§3.5、附录表 2](https://arxiv.org/abs/2510.02663v1)

维度和技能图报告相关标准的平均通过率，不能直接当作加权综合分。附录图 11 中，客观与主观标准分别为 13,673、1,547 条，显式与隐式分别为 11,437、3,783 条。评价维度还有多标签情况：虽然正文使用“一个维度”的表述，图 12 的维度计数合计超过标准总数，公开数据也能看到一个 `eval_dimension` 字段含多个逗号分隔标签。因此，各维度计数不能相加当作互斥分区。

另一组标签按 Bloom 分类标记记忆、理解、应用、分析、评价和创造。Gemini 2.5 Pro、Claude Sonnet 4、GPT-5 三个标注模型至少两个一致时才赋标签，覆盖超过 97% 的样本。这里测量的是标注模型的一致性，不是学生实际做题难度的人工验证；对应结果是在同一类别样本内平均加权分。[原文 §3.4、图 4、附录图 11–12](https://arxiv.org/abs/2510.02663v1)

## Study Mode 的分数反映固定回复协议

作者从网页手工收集 GPT-5 Study Mode 的输出；该界面不能像 API 一样直接设置系统提示，因此附录 A.6 给出的是用户侧前置说明。它常通过继续询问学生来推进教学，而 TutorBench 在固定历史之后评分一条回复。作者因此将它排除在主排行榜外，单独报告综合 46.94±1.06、文本 48.19、多模态 45.93。[原文 §3.6、附录 A.4/A.6](https://arxiv.org/abs/2510.02663v1)

相对 API GPT-5 的 55.33，综合分差是 8.39 个百分点。它混合了界面、提示方式、回复完整度和交互协议差异，不能当作只开关 Study Mode 的受控消融，更不能推导为真实课堂学习效果下降 8.39%。

附录图 8–10 展示两类具体原因：有的回复先问一个引导问题，尚未展开标准要求的全部内容；也有回复对学生的错误判断不准确。前者涉及单条回复评价对交互教学的适配，后者是该实例中的内容问题。论文没有报告两类原因各自解释了多少总体失分。

## 人工评审验证的三个分母

评审可靠性实验抽取 250 个样本、2,475 条标准，每条收集三个人工判定，共涉及 69 位专家。§3.7 对每位专家负责的标准，比较其判定与另外两人的判定，报告平均人际一致率 0.75；LLM 与人工判定的一致率为 0.78。这不是“78% 的整题教学回复完全正确”。

图 6 的图注把参照写成三人多数票，而正文在描述人际一致率时写的是与另外两人比较；两处表述不完全一致。阅读结果时需保留这个差异，不应把它们无条件当作同一统计程序。

随后，作者讨论重要标准，写出 1,900 条、每条三票，以多数票为参考得到 LLM 的 F1=0.82。该句使用了容易歧义的 “filter out”，但上下文和公司说明把实验描述为针对重要标准；公开材料没有这批逐条人工票，无法独立重建筛选。§2.3 的提前介绍另写 F1=0.81，本页采用更详细实验段的 0.82，并保留差异。[原文 §2.3、§3.7、图 6](https://arxiv.org/abs/2510.02663v1)

最高单个人工专家 F1 为 0.91，但分母只有其负责的 321 条标准，并非同一完整 1,900 条集合。这个数不能与评审模型分数作等规模、同分布比较。多数票也来自有限专家，不是独立外部真值。原文未完整披露 F1 的正类或平均方式、类别分布、混淆矩阵及其置信区间。作者称 Claude Sonnet 4 在候选评审器中最符合人工，但没有公开完整候选比较表，因此不能量化更换评审模型的影响。

前三种可以依据论文语义对应 5、1、−5，但 `deleted` 的处理规则没有在论文评分式中定义。复现者应先确认是否排除以及如何处理分母，不能不加说明地给它分配权重。它也说明“公开标准总数”与“实际参与评分的标准数”需要分别报告。分片名 `train` 是发布格式，不代表论文在这批样本上训练过模型。

## 复现需要保留的协议

附录 A.6 公开了各情境的生成提示。适应性解释要求解释学生追问；反馈任务要求评价已有解答；主动学习要求提供下一步提示而不透露完整答案。一个容易改变输入含义的细节是：纯文本反馈任务把学生解答放在对话历史的模型回复位置，因此系统提示要求评估“第一条回复”。重建历史时，不能把角色顺序随意改成另一个协议。

基于当前材料，可以准备以下复现步骤：

1. 固定数据提交并记录任务 ID、情境和标准清单，先解决 1,473 与 1,490 的集合差异，以及 `deleted` 标准的去留。
2. 按附录恢复不同情境的历史、系统提示和图像输入，逐一记录历史 API 模型版本的可用性。
3. 保存每次生成的实际参数、输出、终止原因和 token；使用 Claude Sonnet 4 逐标准评价时保存完整判定，而非仅保存综合分。
4. 明确负向标准极性、负分截断与否、失败请求处理，再先算每题分数后平均。图文子集和技能通过率另外计算。
5. 单独设计并公开置信区间、重复次数和人工抽检协议，不声称这些自行补充的细节就是论文原设置。

在本文核查的官方论文页、数据仓库和排行榜入口中，未找到完整生成与判分代码、完整评审提示、全部历史模型输出或人工三票文件。原文也没有充分给出温度、输出上限、推理 token 预算、API 重试、每题采样次数和费用。因而当前公开材料支持重建任务和主要评分思路，尚不能保证逐数重现表 1。本文完成的是原文阅读、图表核对和结构化数据审计，未进行模型重跑。

## 结论覆盖的范围

TutorBench 覆盖高中和 AP 的六个 STEM 学科，评价固定情境下的解释、反馈与提示。它没有检验长期学习保持、真实学生后续表现、完整多轮互动、出题能力、图像生成教学或人文学科辅导。困难筛选、具体评分标准、单个自动评审器和公开版本差异都需要随结果一起保留。[原文 §5、附录 A](https://arxiv.org/abs/2510.02663v1)
