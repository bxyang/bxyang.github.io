# VisualToolBench：让模型处理图像，再继续推理

一张菜单中的价格、尺寸和附加收费可能分散在不同位置。模型需要找到对应区域，放大辨认，再把提取的信息组合起来计算。VisualToolBench（VTB）把这种过程做成评测：模型不仅接收图像，还可以编写 Python 裁剪、旋转、增强图像，看见处理结果后继续推理。论文包含 1,204 项开放式任务，以逐项评分标准检查回答；在 2025 年所测的 16 个模型配置中，最高整体通过率为 18.68%。这项数字对应当时的实验，不能代表后续更新榜单上的最好成绩。[论文 §2–3](https://arxiv.org/pdf/2510.12712v3)

本页保留原来的 `/iris` 地址，但将名称改为原论文、Scale 研究页和官方数据集共同使用的 **VisualToolBench**。这些来源没有把该工作称为 IRIS。原介绍中的“603 个单图、601 个多图”也已纠正：它们实际是单轮和多轮对话任务数量。

## 任务要求模型主动寻找可用的视觉证据

传统视觉问答往往把图像作为固定输入。VTB 允许模型修改图像的呈现方式，并将新图像再次加入上下文。工具可以让很小的文字变得容易辨认，也可能裁掉关键线索、强化噪声，或把错误观察带进后续计算。因此，调用过工具并不等于正确理解图像。

这里的工具使用要求主要是隐含在问题中的。用户不会逐步指示“先旋转、再裁剪哪个区域”；模型需要判断何时操作图像、何时调用计算或检索，以及何时已有足够证据作答。主实验的系统提示则明确鼓励主动使用工具，二者不是同一个层面的要求。

论文设计了五类任务，其中“任务类型”与“知识领域”是两条不同轴线。

| 任务类型 | 数量 | 需要完成的过程 |
| --- | ---: | --- |
| Region-Switch Q&A，单轮 | 281 | 从同一图像的多个位置提取信息，再组合推理 |
| Hybrid Tool Reasoning，单轮 | 322 | 将图像处理与计算、代码执行或网页检索结合 |
| Follow-up Test，多轮 | 198 | 识别首轮信息不足，提出必要澄清，再利用后续补充信息 |
| Temporal Visual Reasoning，多轮 | 205 | 对不同轮次的图像进行比较，追踪变化或状态 |
| Progressive Visual Reasoning，多轮 | 198 | 围绕图像回答相互依赖的问题，保持前后结论一致 |

五个领域分别是 STEM 238 项、医疗 238 项、金融 243 项、体育 240 项、通用 245 项。总计 603 项单轮任务和 601 项多轮任务，多轮包含 2–5 轮。论文表 2 另外报告 2,893 张图像、7,777 条 rubrics。任务数、用户轮次数、图像数和评分条目数不能相互替代。[论文表 2、§2.1](https://arxiv.org/pdf/2510.12712v3)

澄清类的例子是一张没有线路编号的轨道交通图。用户要求从“七号线最北端”到“一号线最南端”的最少站数，首轮正确行为是指出编号与颜色的对应关系缺失并追问，而不是猜测。第二轮补上编号后，再定位起终点并计算路线。这个例子评测的是已编写好的多轮任务，不是一个能够生成任意后续回复的开放用户模拟器。[附录 E，第 38–39 页](https://arxiv.org/pdf/2510.12712v3)

## 数据如何构建和筛选

贡献者需要提交提示、图像、参考答案、参考工具使用过程以及 rubrics。任务首先交给 o3、Gemini-2.5-pro 和 o4-mini 作答，贡献者按标准评分，只有至少两个模型失败的任务才进入后续流程。

接着，第一位审阅者检查场景是否合理、是否确实需要动态图像推理、参考答案是否正确、评分标准是否合适。小问题可修改，根本不成立的任务被剔除。第二位独立审阅者再次确认，之后才纳入数据集。[论文 §2.2](https://arxiv.org/pdf/2510.12712v3)

这一筛选过程解释了数据集为何困难，也限定了低分的含义：它刻意保留能难住指定模型的任务，不是对普通用户视觉问题的随机抽样。o3、Gemini-2.5-pro、o4-mini 还参与了题目筛选，因此它们的最终结果应与这一选择条件一起理解。

论文称贡献者有不同领域经验并经过培训，但未给出具体人数、资格分布、每人题量、初始投稿量、剔除率、审阅一致性统计，以及跨任务图像去重或污染检查的完整过程。参考轨迹提供一条可行解题路径，不表示所有模型必须使用完全相同的操作顺序。论文也没有将这些轨迹当成一次新模型训练的数据来报告训练收益。

## 图像工具的核心是把结果送回模型

### 六个工具及其接口

| 工具 | 输入与用途 |
| --- | --- |
| `python_image_processing` | `code` 字符串；用 PIL、NumPy 或 OpenCV 操作图像，保存处理后的 PNG |
| `python_interpreter` | `code` 字符串；通用计算，通过标准输出返回结果，异常写入错误输出 |
| `web_search` | `query` 与结果数量；描述为 Google 检索，默认 5 条，可指定 1–10 条 |
| `browser_get_page_text` | `url`；读取网页文字 |
| `historical_weather` | `location` 与 `YYYY-MM-DD` 日期；查询历史天气 |
| `calculator` | `expression`；执行算术与所列数学函数 |

两个 Python 接口的 schema 都将代码长度限制在 1–5,000 个字符。图像工具要求从工作目录的图像列表选择输入，把处理结果保存到指定目录，使用 `transformed_image_i.png` 命名并递增计数，避免覆盖旧图。接口禁止用 matplotlib 仅展示而不保存图像。它没有把操作限制为固定的“裁剪”按钮，而是允许一段代码组合多种图像操作。[附录 D.1、D.4](https://arxiv.org/pdf/2510.12712v3)

### 一次调用后的消息序列

模型通过 LiteLLM 的 function-calling 接口提出工具调用。普通工具返回文本，作为 `tool` 消息加入对话。图像处理后，评测程序另加一条带有编码图像的 `user` 消息，让模型真正看到新图。

作者发现，把图像编码直接放进 `tool` 消息，未能让所用模型感知结果。因而“模型能写裁剪代码”和“模型能看到裁剪图”是两个需要分别实现的环节。额外的图像回传消息不应被误计成数据集中新的用户任务轮次。[论文 §3，Evaluation Setup](https://arxiv.org/pdf/2510.12712v3)

每项任务最多 20 次工具调用，人类参考轨迹通常少于 5 次。该上限按调用次数计，不按图像操作次数计。一段 Python 可以裁剪、调整对比度并保存多张图：附录 D.3 的 GPT-5-think 示例一次调用保存六张不同处理结果，之后这些结果仍会占用上下文和视觉编码预算。

所以，20 次调用并不意味着模型之间的 token、图像数、执行时间或费用相同。论文没有给出每种模型的总视觉 token、总生成 token、CPU 时间、API 金额或完整墙钟耗时，也没有公开用来检查每次执行隔离、超时和文件状态的完整服务实现。

## APR 与 ARS 分别衡量通过和部分完成

设第 $i$ 个任务有 $m_i$ 条标准，第 $j$ 条权重为 $w_{ij}\in\{1,2,3,4,5\}$，判定结果为 $z_{ij}\in\{0,1\}$。任务的 rubric 分数是：

$$
s_i=\frac{\sum_{j=1}^{m_i}w_{ij}z_{ij}}{\sum_{j=1}^{m_i}w_{ij}},
\qquad
\mathrm{ARS}=\frac{1}{N}\sum_{i=1}^{N}s_i.
$$

ARS 先在每个任务内部按权重归一化，再对任务等权平均。它不是把全部数据集的标准放到一起计算一个加权比例，因此标准更多的任务不会仅因为条目多就获得更大任务权重。[附录 B.1，式 1–2](https://arxiv.org/pdf/2510.12712v3)

按正文 §2.3 与 §3 的定义，关键标准集合为 $C_i=\{j:w_{ij}\geq4\}$。全部关键标准通过才算任务通过：

$$
p_i=\prod_{j\in C_i}z_{ij},
\qquad
\mathrm{APR}=100\%\times\frac{1}{N}\sum_{i=1}^{N}p_i.
$$

这是将文字规则写成公式，APR 并非达到某个 ARS 阈值的比例。模型可以获得不错的部分分，却因为一项关键事实出错而失败。

图 2 的披萨例子包含权重 3、4、3、5、2 的五项标准。模型正确识别单配料、加上无麸质饼底费用并解释计算过程，却把基础价格读错。它获得 $8/17\approx0.47$，但两个关键项未满足，因此任务失败。这个例子区分了“计算过程形式正确”和“从图片读到的数字正确”。

### 关键标准的文字规则与数据字段不完全一致

公开数据同时保留 `weight` 与 `critical` 字段，它们不能默认互相推导。论文附录就有反例：第 33 页 Americano 标准中，一项权重为 4 却标记 Critical=No；第 42 页识别当前比分的一项权重为 3，却标记 Critical=Yes。

此外，多轮数据按轮保存 rubrics，正文公式却只使用“任务”下标，没有给出先逐轮平均、还是合并全部轮次权重的完整实现，以及任务通过是否对全部轮次关键项取合取。本文按论文文字解释主指标，但在复现时必须明确关键集合和多轮聚合规则；不能自行选一种实现后称其精确复现了官方 APR。

## 裁判看见哪些材料，人与模型的一致性如何

主实验使用 o4-mini 作自动裁判。每次只判断一条标准，输入包括原问题、参考答案、当前标准和模型回答，返回 JSON 中的解释及 `Met` / `Not Met`。附录所列裁判输入没有原图和完整工具轨迹，因此这种评分不是由裁判重新读取原图、独立验证所有视觉事实。[附录 C.3](https://arxiv.org/pdf/2510.12712v3)

提示特别要求各标准独立判断：若标准只要求展示推理，最终答案错误并不必然使这条标准失败；表达风格适度宽松，允许合理的隐含表达。五个评分维度是视觉理解、真实性、指令遵循、推理和呈现，一条标准可以关联多个维度。

表 8 使用数据子集上的人类标注检查一致率：

| 裁判 | 总体一致率 | 客观标准 | 主观标准 |
| --- | ---: | ---: | ---: |
| o4-mini | 88.07% | 91.70% | 73.96% |
| GPT-4.1 | 88.18% | 89.83% | 81.77% |
| GPT-4o | 87.01% | 89.16% | 78.65% |

o4-mini 在客观项上更高，但总体与主观项均不是表内最高。论文没有提供足以重建这张表的子集大小、每类正负标签数量、混淆矩阵或置信区间。一致率也不等于任务通过判定准确率：APR 要求多条关键标准同时满足，单项误判如何传到任务级结果需要单独评估。[附录 B.7，表 8](https://arxiv.org/pdf/2510.12712v3)

## 工具调用次数、执行成功和任务成功是三回事

对任务 $i$，记调用集合为 $T_i$，任务总数为 $N$。论文报告：

$$
\mathrm{Proactivity}=\frac{1}{N}\sum_i\mathbf1\{|T_i|>0\},
\qquad
\mathrm{Volume}=\frac{1}{N}\sum_i|T_i|,
$$

$$
\mathrm{ToolSuccess}=\frac{\sum_i\sum_{c\in T_i}\mathbf1\{\operatorname{valid}(c)\}}{\sum_i|T_i|}.
$$

Proactivity 是至少调用一次工具的任务比例，Volume 是每任务平均调用数，ToolSuccess 的分母则是全部调用次数。正文称成功需要符合 schema 且非空；附录 B.4 的具体判定描述是“错误消息记失败，其余输出记成功”。这两个描述的严格程度不同，公开材料没有实现代码来消除歧义。无论采用哪一个，它都不是结果内容正确率。

表 7 的代表数据如下，比例已换成百分比：

| 模型 | 总调用数 | 单轮主动率 / 成功率 / 每题调用 | 多轮主动率 / 成功率 / 每题调用 |
| --- | ---: | ---: | ---: |
| o3 | 16,116 | 94.53% / 85.87% / 9.98 | 97.50% / 36.96% / 16.80 |
| GPT-5 | 10,212 | 96.52% / 85.55% / 6.46 | 98.83% / 35.48% / 10.53 |
| GPT-5-think | 13,429 | 99.00% / 86.60% / 7.45 | 99.50% / 31.05% / 13.79 |
| Gemini-2.5-pro | 3,366 | 80.60% / 73.31% / 1.94 | 92.51% / 31.91% / 3.66 |
| Claude-opus-4.1 | 6,538 | 95.36% / 95.24% / 3.83 | 99.00% / 41.51% / 7.03 |

Claude-opus-4.1 工具主动率很高、单轮调用成功率也高，但 APR 只有 4.71%。o3 调用更多，却没有超过 GPT-5。这些结果反对“多调用就一定更好”的简单解释。正文图 4 周围将 Claude 概括为工具使用较少，与附录表 7 的高主动率不完全一致；本文以具体表格说明，而不沿用这个笼统归纳。

这张表的部分总量也无法与分组均值对齐。例如，按 603 项单轮与 601 项多轮计算，GPT-5-think 的 $603\times7.45+601\times13.79\approx12,780$，不同于 Total 列的 13,429，差值远超保留两位小数产生的误差。论文没有解释这些行的运行或分母是否不同，因此表内数字可以分别引用，不宜再用它们推算精确总成本。

图 5 则给 o3、GPT-5、Gemini-2.5-pro 的工具类别饼图，图注总调用数分别为 6,004、3,805、1,082，显然不是表 7 的全表总数。正文还将其中 GPT-5 写成 GPT-5-think，与图注不一致。缺少统一统计范围时，这些占比不应与全任务总数相乘制造新的调用量。[论文 §3.2、附录 B.4–B.5](https://arxiv.org/pdf/2510.12712v3)

## 消融显示工具收益取决于模型和提示

图 7 比较四种设置：强系统提示、弱系统提示、移除图像工具、移除全部工具。强提示要求主动找视觉线索、裁剪或增强、保存结果、反复查看并核对；弱提示仅说明模型是能够使用工具的视觉助手。

GPT-5 的图中强提示基线约为 24.8%，弱提示、无图像工具、无全部工具分别下降约 11.4、11.8、14.4 **个百分点**。原图标作百分号，但箭头表达的是 APR 绝对差，不是相对下降百分比。Gemini-2.5-pro 在没有全部工具时反而比强提示设置高约 2.7 个百分点；Claude-opus-4.1 移除全部工具下降约 2.0 个百分点。

图 7 的 GPT-5 强提示基线并不是表 3 的整体 16.96%，图中 Claude、Gemini 的基线也与主表 Overall 不同。它们接近单轮结果，但论文没有明确提供该消融的样本数和完整汇总口径。因此，这里只比较图内四种条件，不将其差值直接加到主表整体成绩上。[论文 §3.4、图 7](https://arxiv.org/pdf/2510.12712v3)

论文把模型差别推测为工具训练经历不同，但未公开相应训练数据或做因果验证。消融能支持的观察是：在该评测设置里，改变工具和系统提示会产生不同方向的结果。它没有证明某模型所有失败都来自工具训练不足，也没有测试一套统一的最优工具策略。

## 失败分析与评分样例的边界

表 4 将失败分成视觉感知、推理、计算和其他四类：

| 模型 | 视觉感知 | 推理 | 计算 | 其他 |
| --- | ---: | ---: | ---: | ---: |
| GPT-5 | 71.73% | 11.56% | 2.79% | 13.92% |
| Gemini-2.5-pro | 78.01% | 12.24% | 5.74% | 4.01% |
| Claude-opus-4.1 | 82.11% | 9.36% | 1.84% | 6.69% |

分母是被归类的失败案例，不是全部任务。其他类包括未完成、拒答和耗尽工具调用等情况。论文未给出该分析的样本数量、分类者和多原因错误的归类规则，因而这些比例不能直接转成可核对的错误条数。

感知错误占比高并不表示后面的推理已经可靠。一旦菜单价格读错，计算工具仍可能正确算出错误数字的和；这类例子说明需要区分证据提取与运算。

附录中的展示本身也有需要保留的矛盾。图 9 展示模型最终给出 `BC=0.072`，右侧关键标准却要求约 `-0.0088`，仍标作通过；该页图像和文字均如此，不能当作可靠的通过样例。另一个流程图例子中，参考答案写循环终止条件 $x\geq4$，随后 rubric 写 $x>4$。这些是可定位到具体页面的差异，不足以估计整套数据的错误率，但复现前应检查参考答案、标准和裁判输入是否一致。[附录 E，第 32–34 页](https://arxiv.org/pdf/2510.12712v3)

## 公开数据与复现入口

### 固定数据快照

官方数据为 `ScaleAI/VisualToolBench`，本次固定 revision `28de4fbd42a69fa86878f0d9f17b2e991d17fd5c`，更新时间为 2025 年 12 月 16 日，晚于论文 v3。仓库提供 `test.parquet`、数据卡和 `manifest.json`，只有 test 拆分，包含 1,204 个任务。全部媒体文件约 7.81 GB。[固定数据目录](https://huggingface.co/datasets/ScaleAI/VisualToolBench/tree/28de4fbd42a69fa86878f0d9f17b2e991d17fd5c)

每行包含任务 ID、单轮或多轮标签、轮次数、领域、任务类型，以及按轮保存的提示、参考答案、参考工具轨迹、rubrics 和图像。`rubrics_by_turn`、`turn_tool_trajectories` 的元素是 JSON 字符串，需要再次解析；`images` 是展平后的图像列表，`images_by_turn` 保留轮次分组，不能将二者同时当作独立图片重复统计。

```python
import json
from datasets import load_dataset

revision = "28de4fbd42a69fa86878f0d9f17b2e991d17fd5c"
data = load_dataset("ScaleAI/VisualToolBench", revision=revision, split="test")
row = data[0]
first_turn_rubrics = json.loads(row["rubrics_by_turn"][0])
```

上述是数据加载入口，不是完整评测程序；本次没有下载全部图像，也没有运行生成或评判模型。

本次通过官方数据查看服务逐行读取了全部 1,204 行结构化记录，未下载图片；返回记录无单元格截断，图片资源地址均对应上述 revision。任务类型、五个领域合并后的数量及 7,777 条 rubrics 与论文一致。原始领域字段有九个取值，因为 STEM 拆成了 engineering、physics、maths、biology、chemistry，不能据此把论文说成九个领域。

| 当前数据检查项 | 实际数量 |
| --- | ---: |
| 1 / 2 / 3 / 4 / 5 轮任务 | 603 / 506 / 83 / 7 / 5 |
| `num_images` 求和 | 1,917 |
| 展平 `images` 条目求和 | 1,917 |
| 按轮 `images_by_turn` 条目求和 | 1,917 |
| rubric 总条数 | 7,777 |
| `weight≥4` 与 `critical=yes` 判断不一致的条目 | 2,357 |
| 包含至少一条上述不一致的任务 | 961 |

当前快照的图像条目数 1,917 与论文表 2 的 2,893 不同。这是按记录数统计，并非对像素内容去重后的独立图像数量；公开材料没有解释这一差异。

关键标准的不一致中，2,138 条为权重 1–3 但标为 yes，219 条为权重 4–5 但标为 no。每轮两种规则下都存在至少一条关键标准，没有发现空关键集合，但选择不同规则会改变判定条件。这里报告的是字段冲突数量，不是已经测得 961 道题判错，也无法据此重新计算各模型 APR。数据发布晚于论文，需要原始评分实现或作者说明才能确认实际采用的规则。

### 工具 schema 已公开，完整执行器仍有缺口

论文附录公开了工具接口和多段模型生成的图像处理代码，但其中有省略路径和展示用排版，它们是轨迹样例，不是一份可直接运行的评测仓库。截至本次核查，论文、Scale 研究页、官方榜单和数据卡没有提供可确认的完整官方执行器代码链接，不能把第三方适配仓库当作作者原实现来固定 commit。

根据论文重建执行环境，需要实现保存图像及回传 `user` 消息、完整多轮状态、20 次调用预算、六个工具后端、逐 rubric 裁判和结果汇总。还需保存实际端点日期、搜索结果与网页快照、错误消息、图像文件以及每轮输出，才能检查一次失败发生在观察、执行还是评分环节。

尚未确定的关键点包括关键标准阈值与 `critical` 字段的优先级、多轮 APR/ARS 聚合、追问类后续输入的调度规则、模型最大输出长度、图像编码与缩放、工具超时和搜索后端设置，以及主表、工具表和消融统计范围的对应关系。本文进行了论文与公开资料的静态核对，尚未复现模型成绩。
