# 搜索时的数据污染：联网评测中的答案泄漏

## 1. 摘要内容概述

该版本采用 [CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/) 许可，限制传播改编版本。本节提供摘要内容概述，**不是逐句翻译**。[原摘要](https://arxiv.org/abs/2508.13180v1)

作者发现，联网智能体可能在答题过程中检索到公开题库，连同题目一起取得标准答案。这种测试阶段的泄漏会干扰能力评测。论文通过检索日志与来源过滤实验展示了这一现象，并讨论公开执行记录、检查来源和改进基准设计等应对方法。

## 2. 研究背景与相关研究

传统的数据污染主要发生在训练时：测试题混入训练数据，模型因此可能记住答案。搜索智能体则增加了另一条路径，即使训练时没见过题目，也可能在测试时直接找到题库及答案。

论文的引言和第 2 节回顾了这两类问题的关系。GSM1k 等工作关注训练集与测试集重合造成的能力高估；联网评测常继续使用 HLE、SimpleQA 等原本用于知识与推理测试的题库，但这些题库本身已在网上公开。数据副本还可能出现在第三方仓库、博客或论文中。

搜索正常资料完成任务，与直接取用测试集答案，是不同的信息来源。本文将“答案线索来自评测集本身”的情况称为搜索时数据污染，并通过日志检查来识别。作者也讨论了 BrowseComp、Mind2Web 2 等更贴近信息检索任务的基准，认为评测应与联网系统实际要完成的工作相匹配。（原文第 1—2 节）

## 3. 核心贡献

作者运行三个 Perplexity Sonar 搜索系统，检查它们在 HLE、SimpleQA 和 GPQA 上的检索记录，识别是否访问了对应测试集的 Hugging Face 副本。部分记录中，智能体明确发现了标准答案，并选择它而不是自己先前推导的结果。这为测试阶段答案泄漏提供了直接实例。（原文第 3.1 节）

不同基准的检出率并不相同：HLE 约为 3.3%，SimpleQA 低于 1.2%，GPQA 则随系统在约 1.9%—4.2% 之间变化。这些数字仅覆盖论文检测到的特定 Hugging Face 来源，不能当作全部互联网来源的污染比例。

作者进一步重新测试已检出的样本，并比较屏蔽 Hugging Face、只允许该站点、不允许搜索及限制网页日期等条件。屏蔽来源后，部分污染子集的准确率下降，支持检索到答案会影响评测的判断；但不同基准和系统的效果并不一致，GPQA 没有呈现同样的增益。来源过滤也会改变一般可用信息，因此不能把所有分数变化都归为答案泄漏。（原文第 3.2 节）

论文的结论是，联网评测除了报告最终分数，还需要说明搜索权限、过滤设置和污染检查方法，并保留可供复查的执行记录。单独封禁一个网站无法解决全部问题：第三方副本和其他答案来源仍可能存在。本文提出的是一种需要持续检查的评测失真现象，未测得适用于所有智能体与基准的统一污染率。（原文第 4—5 节）
