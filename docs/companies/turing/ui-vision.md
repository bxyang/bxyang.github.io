# UI-Vision：桌面界面的视觉理解与动作预测

原文：[UI-Vision: A Desktop-centric GUI Benchmark for Visual Perception and Interaction](https://arxiv.org/abs/2503.15661v2)，ICML 2025，本文依据 arXiv v2。

## 1. 摘要翻译

以下为 Shravan Nayak 等人论文 arXiv v2 摘要的完整中文翻译，原文采用 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可。

能够操作图形用户界面（GUI），自动执行文档编辑、文件管理等任务的自主智能体，可以大幅改善计算机工作流程。现有研究主要关注在线场景；而对于许多专业任务和日常任务都至关重要的桌面环境，由于数据收集困难和许可问题，仍缺乏充分研究。我们提出 UI-Vision，这是首个面向真实桌面环境、采用宽松许可，对计算机使用智能体进行离线细粒度评估的综合基准。与在线基准不同，UI-Vision 提供：（i）覆盖 83 款软件应用的人类示范密集高质量标注，包括边界框、界面标签以及点击、拖拽和键盘输入等动作轨迹；（ii）从细粒度到粗粒度的三个任务——元素定位、布局定位和动作预测，并为其定义清晰的指标，严格评估智能体在桌面环境中的表现。我们的评估揭示了 UI-TARS-72B 等先进模型的关键局限，包括理解专业软件、空间推理以及处理拖放等复杂动作方面的问题。这些发现表明，开发完全自主的计算机使用智能体仍面临挑战。通过将 UI-Vision 开源，我们希望推动能够完成真实桌面任务的更强智能体的发展。

## 2. 研究背景与相关研究

桌面软件的操作不仅是识别按钮文字。绘图、建模或开发工具往往包含密集的小图标、可拖动区域和功能面板，完成任务还需要知道这些控件之间的空间与功能关系。相比网页，桌面软件缺少统一的自动化接口，收集覆盖多种软件的操作数据也更困难。[论文第 1 节](https://arxiv.org/html/2503.15661v2)

作者将 GUI 智能体方法分为两类：一类把 HTML、无障碍树或 OCR 结果转成文本交给语言模型；另一类直接利用截图等视觉输入，将指令对应到屏幕位置。后者更接近人类看着界面操作，但需要足够详细的视觉标注。

在基准方面，MiniWoB++ 等工作推动了网页交互研究，后续评测分别关注元素定位、下一步动作或导航。作者认为，桌面界面的整体布局和功能分区仍缺少系统测试，因此 UI-Vision 把局部控件、区域结构和动作预测放在同一套数据里。这里的前作定位依据论文第 2 节。

## 3. 核心贡献

**核心问题是区分桌面操作中的几种不同能力缺口。** 找不到正确按钮、认不出整个工具栏，以及知道目标却预测错动作，是不同的问题。只看任务最终完成与否，较难判断错误来自哪里。

**核心方案是从真实人类操作中构建三层离线测试。** 标注团队在 83 款软件中执行任务，录制操作视频和动作坐标，再标注关键帧上的界面元素。研究团队据此构建 450 段视频对应的数据，以及 8,267 组查询与标签。[论文第 1、3 节](https://arxiv.org/html/2503.15661v2)

元素定位要求根据名称、功能描述或相对位置找到控件；布局定位要求识别“格式工具栏”等具有共同功能的区域；动作预测则给出任务、当前截图与历史操作，预测接下来的点击、拖拽或键盘动作。三者分别检查局部感知、结构理解与行动选择。动作预测使用已录制的界面状态，不是在真实软件里持续运行到任务结束。

**主要结论是，论文测试时的模型在细粒度桌面理解上仍有明显不足。** 小控件、密集界面和专业软件尤其容易出错，拖拽也是普遍难点。将动作规划与专门的定位模型结合，能够改善部分点击预测，说明“决定做什么”和“准确落到哪里”可以分别影响结果。[论文第 4 节](https://arxiv.org/html/2503.15661v2)

UI-Vision 的主要产出是数据与诊断性评测，而不是一个已经解决桌面操作问题的新智能体。论文结论限于离线截图和示范轨迹上的测试；扩展为能执行动作、接收新状态并纠错的在线环境，是作者提出的后续方向。[论文第 5—6 节](https://arxiv.org/html/2503.15661v2)
