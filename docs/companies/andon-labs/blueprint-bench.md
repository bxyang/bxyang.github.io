# Blueprint-Bench 精读：从室内照片推断房间连接与大小顺序

看完一套公寓的二十张照片，人可以尝试拼出哪些房间相连、哪个空间更大，以及同一扇门从两个方向看是否对应同一个位置。Blueprint-Bench 要求模型完成类似任务，并画成规定格式的二维平面图。评分程序不直接比较两张图的像素，而是提取房间与门的连接，再结合房间大小顺序计算相似度。实验显示这项任务对当时的通用模型较难，但成绩也受到绘图格式、房间编号和执行方式影响，不能直接当成纯粹的空间理解分数。[论文 §1–3](https://arxiv.org/pdf/2509.25229v1)

## 五十套公寓，每套给一组照片

数据包含 50 套公寓，每套约 20 张室内照片。参考平面图由房源原有平面图改画成统一格式。模型只接收室内照片和作图规则，不能直接读取参考图。（§2.1）

它需要解决的并非单张图上的房间识别。例如，一张照片从客厅看向走廊，另一张从走廊拍向卧室，模型要判断它们是否属于同一段连接；对开放式厨房与客厅，也要依据任务里的房间划分规则处理。论文没有提供逐类难度、遮挡程度或照片覆盖率的量化分布，因此这些是任务所需判断的说明，不是额外报告的实验分类。

数据来自房源材料，论文未完整披露城市、房屋类型、采样方式、房间数量分布、参考图与照片拍摄时间的一致性，或人工改图的误差率。模型面对的是这批精选公寓，不能将结果直接外推到所有室内空间。

多数数据不公开，作者希望减少针对测试集合的过拟合。公开生成仓库只提供一个 `example_house`：本次文件检查得到 18 张输入照片、原始平面图与标准参考图，以及少量示范输出。这是一个公开样例，不是全部 50 套数据的镜像。保留私有测试也不等于已经完成基础模型训练污染审计。

## 输出格式决定评分程序能否读懂图

不同系统必须输出同一种简化平面图。论文给出九条规则，可归纳为：

| 部分 | 要求 |
| --- | --- |
| 墙 | 黑色、笔直、3 像素宽 |
| 门 | 用覆盖在墙上的绿色线段表示，不画开门弧线 |
| 房间 | 边界完全闭合，每个封闭空间恰有一个 10×10 像素红点 |
| 背景和颜色 | 纯白且不透明，只使用纯黑、纯白、纯红、纯绿 |
| 省略内容 | 不画家具、窗户、出口等额外细节 |
| 空间划分 | 步入式衣帽间计为房间，普通衣柜不计 |

规则还用可达性强调闭合要求：从一个红点到另一个红点，必须跨过黑色或绿色像素。这里的绿门既属于阻挡分区的边界，又是房间连接的标记。（§2.1）

这种格式降低了自动提取的难度，却也把遵循指令的能力纳入结果。房间布局大致正确，但漏放一个红点、背景透明或墙边有缺口，提取器可能得到错误的房间数和连接图。论文承认这一取舍；它没有另报“格式完全有效的输出子集”成绩来独立测量空间推断。

### 三类系统用不同方式交付同一种结果

语言模型接收照片后输出 SVG 代码，再转换为图像。图像生成模型直接生成图片。agent 则在 Docker 中运行，可以反复查看照片、写程序和修改图片，最终把结果保存到指定位置。（§2.2）

这些途径统一了交付格式，但没有统一推理过程、工具能力、调用次数或计算预算。因此可以在同一评分接口下比较结果，不能称为除了架构之外其他条件都相同的受控实验。

## 先把图片转换成房间图

论文描述的提取流程包含五个环节：（§2.3、图 3–4）

1. 在 HSV 颜色空间检测红色连通区域，找到房间中心。
2. 把黑墙和绿门视为边界，从红点向周围填充，得到各房间像素区域。
3. 沿边界寻找绿色门段，判断它连接哪两个区域。
4. 记录门的位置及水平或垂直方向，并按区域像素数估算面积。
5. 按面积从大到小给房间编号，最大的房间编号为 1，再输出房间连接图等结构化信息。

这里的节点不是“客厅”“卧室”等语义标签，而是大小顺序编号。评分也没有要求恢复每个房间的真实平方米面积。

**说明示例：**参考图中房间按大小编号为 1、2、3，门连接为 `{(1,2),(2,3)}`。若预测的面积排序把两个房间颠倒，即便实际相邻关系画得合理，转成编号后的边也可能发生变化。这就是作者明确指出的连带惩罚：大小顺序错误会同时影响连接评分。

从照片恢复准确尺寸与恢复大小排序并不是相同任务。参考图与预测图采用不同整体比例，只要提取出的大小排序和其他统计量相同，评分可能仍然很高。相反，接近等大的两个房间稍有误差，也可能交换编号。

## 六个分量构成一个相似度分数

令参考图与预测图的提取结果分别为 $G^*$、$G$。论文使用以下加权形式：

$$
S(G,G^*)=0.50s_E+0.20s_D+0.10s_\rho+
0.10s_R+0.05s_N+0.05s_O.
$$

| 分量 | 论文含义 | 权重 |
| --- | --- | ---: |
| $s_E$ | 房间连接边的 Jaccard 相似度 | 50% |
| $s_D$ | 房间连接度数的相关性 | 20% |
| $s_\rho$ | 图密度的一致程度 | 10% |
| $s_R$ | 房间数量的一致程度 | 10% |
| $s_N$ | 门数量的一致程度 | 5% |
| $s_O$ | 门方向分布的一致程度 | 5% |

论文称最终分数归一化到 0—1，越高越相似。0.431 表示平均复合相似度，不能写成“43.1% 的公寓重建正确”或“43.1% 的房间画对”。（§2.3）

对边集合，Jaccard 的通常定义为：

$$
s_E=\frac{|E\cap E^*|}{|E\cup E^*|}.
$$

**说明示例：**参考边为 `{(1,2),(2,3)}`，预测边为 `{(1,2),(1,3)}`，交集一条、并集三条，边相似度为 $1/3$，它在总分中贡献约 $0.50/3=0.167$。这只是边分量的教学计算，没有设定其余五项的值。

原文没有完整给出其他分量的公式。例如度数相关性使用哪种相关系数、负相关怎样映射到 0—1，房间数不同时如何对齐，以及空图、单节点、面积相等和零分母如何处理，都需要实际评分代码。不能仅凭分量名称补出自己的公式，再声称重现了论文评分器。

### 高分不保证几何形状完全正确

分数没有直接比较房间轮廓、精确长宽、房间语义类型或整体位置。两幅平面图可能有相同连接与大小顺序，却具有不同几何形状。因此 1 分也应理解为这些所测结构的一致，而不是完整三维空间或精确二维几何都恢复正确。

作者曾尝试沿墙取点，再计算双向最近邻距离，但认为这种办法会对小误差施加不稳定的强惩罚，于是没有采用。另一个尝试是让语言模型提取房间语义与连接；模型会把相邻但无门的房间误判为相连，也会过度依赖“客厅应当最大”的先验。论文没有给出这些替代方案的完整定量消融，因此本文将其作为方法选择过程，而不是已验证的普遍算法优劣结论。（§2.4）

## “随机基线”实际上是不看照片生成典型户型

作者让语言模型和图像模型在没有输入照片时画一套典型公寓，用作称为 random baseline 的对照。公开脚本确实把图片列表设为空，并改为“生成典型公寓平面图”的指令。（§2.2、`random_baseline.py`）

它不是从所有可能连接图中均匀抽样，也不是一个数学上固定的猜测下限。模型仍可利用常见户型先验和作图能力，分数还与测试公寓的结构有关。完整 50 套中的基线为 0.279，人类对照的 12 套子集中为 0.272，两个数字不能混用。（图 5、图 7）

公开脚本按模型和重复轮次生成基线图片，但没有提供这些图片怎样与全量参考图配对、不同生成模型怎样汇总为同一基线的评分实现。当前配置只设一轮，不足以证明原文全部图表也只运行了一轮。

### 人类成绩只来自十二套公寓

图 7 对 12 套子集比较人类、模型与基线，人类均值为 0.547。原文描述一位人类执行者反复查看照片、修改图纸；没有完整说明其经验、每套时间、重复次数或是否有额外信息。

这 0.547 不能直接减去全量 GPT-5 的 0.431，作为严格同题的人机差距；应当在图 7 的相同 12 套子集内比较。图中人类高于全部模型，但精确子集模型均值未在论文文字表中逐项列出，本文不从柱高猜到小数点后三位。

作者观察到人类图纸的实际房间连接都正确，失分主要与大小排序有关。它说明评价规则可以对局部排序错误产生连带惩罚，也提醒读者：相似度 0.547 不等于人类只正确连接了 54.7% 的房间。该判断来自作者检查，本文没有取得十二份完整人类输出独立验证。（§3、图 7）

## agent 的反复修改没有消除这些问题

Codex CLI 在这批实验中查看照片后写程序生成图片，作者称它没有再查看自己生成的结果。Claude Code 则确实尝试发现错误并修改，图 8 展示了三次绘图：修复房间未闭合的问题，再调整过多红点，最后宣称各房间已经闭合，但输出仍存在缺口。（§3、图 8）

同一 GPT-5 的单次 SVG 方式均值为 0.431，Codex CLI 为 0.388；Opus 4.1 单次方式为 0.286，Claude Code 为 0.355。前者降低、后者提高，不能把两个 agent 的点估计都说成没有变化。作者的整体结论是当前 agent 流程没有带来足够强的改善。

这不是严格控制所有条件的“只增加迭代次数”消融。工具、提示、输出方式和预算可能同时不同；也没有在同一系统里固定首稿后比较有无视觉反馈。因而它不能证明迭代修图普遍无效，更不能确定剩余差距只来自模型内部空间表示。

这类错误还涉及格式执行。例如缺口使洪泛填充连通两个空间，即使 agent 在文字里声称“每个房间封闭”，提取结果仍可能不符合它的描述。文本自检结论不能替代对最终图片的实际检查。

## 公开代码能复现到哪一步

本次固定仓库提交为 `6e9b9a62eeb5dc0a43718045a2b1e79b41725eaa`。已阅读生成、agent、无照片基线、图片转换、配置、依赖与容器文件；未调用任何模型 API 或启动 agent 环境。[固定仓库](https://github.com/AndonLabs/Blueprint-Bench-generation/tree/6e9b9a62eeb5dc0a43718045a2b1e79b41725eaa)

| 文件 | 实际作用 |
| --- | --- |
| `predict.py` | 遍历公寓、模型与重复轮次，生成图片 |
| `utils.py` | 准备输入，调用各供应商接口，提取 SVG 并转换 PNG |
| `agent_predict.py` | 用 Inspect 与 inspect-swe 在 Docker 中运行 agent，取出结果文件 |
| `random_baseline.py` | 不提供照片，生成典型户型 |
| `config.py` | 绘图规则、模型列表、并发、重复轮次和重试次数 |

**仓库没有论文描述的房间提取与六项相似度评分器。** `agent_predict.py` 虽有一个叫 scorer 的函数，实际只是读取 `/root/output.png`、保存到本地，再返回 `Score(value=0.0)`。这个零是占位结果，不是提取器判断 agent 得了零分，也不能作为论文图表的重算入口。

### 有图像文件不等于通过绘图规则

普通模型生成后，代码尝试从文本提取 SVG，通过 CairoSVG 转为 PNG。单次转换失败会重试同一份 SVG；外层最多 20 次尝试会重新调用模型。它保留的是第一次成功转换或读取的图片，没有执行九条规则检查，也没有根据结构相似度选择最好结果。

因此这里不是 best-of-20 的质量择优。原文所称单次生成，也需要与接口或格式失败重试区分。全部重试后仍无结果如何计入最终统计，公开生成仓库没有回答。

如果输出文件已存在，程序会跳过生成，并把返回 `None` 计入运行成功数。这个终端计数衡量脚本是否完成或跳过工作，不能当成模型任务成功率。模型输出、解析成功、格式有效和结构得分应分别记录。

### 输入顺序与模型参数没有完全统一

普通生成的图片读取按文件扩展名遍历，没有显式排序；agent 的输入文件收集则排序。原始顺序未保存时，重跑可能面对不同的照片排列。

Anthropic 文本调用设置最多 4,000 输出 token，Grok 设置温度 0，OpenAI 与 Google 的对应调用未显式设置同一组生成参数。图片接口、agent 与 SVG 生成也没有统一成本上限。当前 `config.py` 的 `EPOCHS=1` 只描述该公开快照的默认值，不能补齐原论文所有重复实验。

agent 配置通过工具列表禁止 `web_search`，但不能仅据这个工具名就声称整个 Docker 网络被隔离。文件映射只把 `imgs` 下的照片交给 agent，没有把公开样例中的参考平面图映射进去。模型与环境权限必须依据这段实际配置描述。

### 复现前需要固定的条件

依赖文件没有锁版本，其中 Inspect 直接从 Git 安装；Docker 基础镜像也没有固定 digest。直接使用当前依赖重跑，未必对应 2025 年的执行行为。要恢复相同实验，需要保存模型快照、SDK、agent 与容器版本、输入照片顺序、提示、预算、重试和原始输出。

完整评分还需要作者提供提取实现、六个分量的精确公式、无效图片策略、全量参考数据，以及按公寓和重复轮次聚合的规则。只有一个样例和生成器，不能声称已经复现 50 套公寓的排行榜。

论文没有训练新模型，也没有报告需要展开的优化器或训练损失。相关资源主要是生成 API、agent 运行和人工制图；未公布的总费用、耗时和人类预算，本文不按其他项目经验补估。

## 这项结果的适用范围

Blueprint-Bench 给出了从多张自然照片推断房间结构的一种可操作任务，并把语言模型、图像模型和 agent 接到同一种交付格式上。它所测的是房间连接、大小排序和若干图统计的综合表现，同时受到图像格式与提取规则影响。

公开结果显示，这些模型在该任务上仍有明显失误，人类子集表现更高。它没有证明一个单一的空间智能能力解释了全部差距，也没有覆盖全部几何精度、专业空间重建系统或真实建筑用途。后续改进若只提高格式合规，也可能提高总分，因此分析时应同时报告提取有效率与结构分项。

本次完成了 11 页全文与附录阅读、主要及逐公寓图表的版面检查、公开样例文件核对和生成代码审阅；没有运行模型、另写替代评分器或重算论文成绩。
